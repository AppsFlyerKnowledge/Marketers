> **At a glance:** IDFV — это уникальный идентификатор, который iOS присваивает приложениям одного и того же поставщика. Его можно использовать для атрибуции установок, полученных из кампаний перекрестной рекламы, и регистрации тестовых устройств.

IDFV (Identifier for Vendor) — это уникальный идентификатор, который iOS генерирует при установке первого приложения, принадлежащего поставщику. Когда на том же устройстве устанавливается другое приложение этого же поставщика, ему присваивается тот же IDFV. Если с устройства удалены все приложения поставщика, IDFV также удаляется, а при повторной установке приложений этого поставщика генерируется другой идентификатор.

Согласно Apple: "Идентификатор поставщика (IDFV) можно использовать для аналитики в приложениях одного и того же поставщика контента." В этом случае использование [ATTrackingManager](https://developer.apple.com/documentation/apptrackingtransparency/attrackingmanager/authorizationstatus/) не требуется. IDFV нельзя объединять с другими данными для отслеживания пользователя в приложениях и на сайтах, принадлежащих другим компаниям. Вы по-прежнему несете полную ответственность за то, чтобы сбор и использование IDFV соответствовали применимому законодательству."

IDFV используется в AppsFlyer следующим образом:

* [Атрибуция кампаний перекрестной рекламы](/docs/idfv-attribution-and-test-device-registration#idfv-в-атрибуции-кампаний-перекрестной-рекламы)
* [Регистрация тестовых устройств](/docs/idfv-attribution-and-test-device-registration#idfv-для-регистрации-тестового-устройства)

## IDFV в атрибуции кампаний перекрестной рекламы

IDFV можно использовать для сопоставления в сценарии атрибуции кампаний перекрестной рекламы. В этом сценарии пользователю показывается реклама в приложении, принадлежащем вашей компании. Реклама продвигает другое приложение, также принадлежащее вашей компании.

<div id="how-does-crosspromotion-attribution-using-idfv-work" />

<Accordion title="Как работает атрибуция кампаний перекрестной рекламы с использованием IDFV?">

1. В одном из приложений поставщика показывается реклама продвигаемого приложения. Поставщику также принадлежит продвигаемое приложение.
2. При клике по рекламе или ее просмотре SDK уведомляет AppsFlyer о соответствующем событии клика или показа. SDK связывает IDFV **продвигающего** приложения с событием (SDK автоматически собрал IDFV, когда продвигающее приложение было впервые запущено).
3. После установки и открытия продвигаемого приложения SDK уведомляет AppsFlyer о событии установки. Это событие включает IDFV **продвигаемого** приложения.
4. Получив событие установки, AppsFlyer пытается сопоставить его с соответствующим взаимодействием в виде клика или показа. Если у обоих событий одинаковый IDFV, событие установки атрибутируется кампании перекрестной рекламы.

</Accordion>

<div id="a-few-examples-of-idfv-attribution" />

<Accordion title="Несколько примеров атрибуции кампаний перекрестной рекламы по IDFV">

Сопоставление IDFV используется для атрибуции кросс-промо в следующих сценариях:

* **Собственные кампании по электронной почте и СМС:** Пользователям других приложений, принадлежащих тому же вендору, что и продвигаемое приложение, отправляется электронное письмо или СМС. Это сообщение содержит атрибуционную ссылку, содержащую IDFV, собранный из события установки исходного приложения вендора. Затем AppsFlyer сопоставляет этот IDFV с IDFV, назначенным событию установки продвигаемого приложения.
* **Кампании с push-уведомлениями:** Push-уведомление, инициируемое SDK приложения, принадлежащего тому же вендору, что и продвигаемое приложение, содержит атрибуционную ссылку со встроенным IDFV. AppsFlyer сопоставляет IDFV в push-уведомлении с IDFV, связанным с событием установки продвигаемого приложения.

</Accordion>

<div id="idfv-for-test-device-registration" />

## IDFV для регистрации тестового устройства

Во время онбординга в AppsFlyer рекламодатели проводят тесты, чтобы убедиться, что их приложение может успешно регистрировать и отправлять события установки. IDFV служит уникальным идентификатором, который позволяет AppsFlyer распознавать устройства, используемые для тестирования.

<div id="why-identify-devices-as-test-devices" />

<Accordion title="Зачем определять устройства как тестовые?">

AppsFlyer по-разному обрабатывает события установки, поступающие с тестовых устройств, чтобы поддерживать несколько установок одного и того же приложения. Это часто необходимо для целей интеграционного тестирования. Чтобы AppsFlyer распознавал эти события как поступающие с тестовых устройств, IDFV тестового устройства регистрируется на странице **Test Device** , доступной через меню **User Account** .

</Accordion>

<div id="why-use-idfv-as-an-identifier-in-test-device-registration" />

<Accordion title="Зачем использовать IDFV в качестве идентификатора при регистрации тестового устройства?">

Тестовое устройство также можно зарегистрировать с помощью IDFA. Однако приложение iOS не имеет доступа к IDFA, если в приложении не реализован App Tracking Transparency (ATT) или если пользователь не дал согласие на передачу персональных данных. В таких случаях для идентификации тестового устройства можно использовать доступ к IDFV, поскольку он не зависит от ATT.

</Accordion>
