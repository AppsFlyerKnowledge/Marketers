## Обновление данных и поддержка часовых поясов приложений

<div id="data-freshness" />

### Актуальность данных

П[латформа AppsFlyer использует различные типы обновления данных,](/docs/about-data-freshness-and-timezone-support#data-freshness-types) например ежедневно и в реальном времени. Они используются для представления и предоставления данных. У каждого типа свой [показатель обновления данных](/docs/about-data-freshness-and-timezone-support#data-freshness-rates-and-timezone-support).

Пример: показатели обновления данных на дэшборде событий:

* Метрики KPI: в реальном времени
* Средние KPI: ежедневно

<div id="time-zones" />

### Часовые пояса

На платформе AppsFlyer день начинается в 00:01 и заканчивается в 24:00. Часовой пояс по умолчанию — UTC (GMT). Вы можете изменить значение по умолчанию, установив <Anchor target="_blank" href="/marketers/ru/docs/changing-app-time-zone-settings">часовой пояс для приложения.</Anchor>

<Accordion title="Принципы даты и часового пояса">

Время UTC является постоянным и не имеет летнего/зимнего времени.

Полушария

* Восточные: часовые пояса, обозначенные как UTC+ , находятся к востоку от UTC.
* Западное: часовые пояса, обозначенные как UTC-, расположены к западу от UTC.

<div id="app-specific-time-zone" />

#### Часовой пояс приложения

Вы можете установить часовой пояс приложения. Это значит, что данные будут сгруппированы по дням с использованием местного времени вместо UTC.

Пример:

**Пекин:** если в качестве часового пояса приложения установлен Пекин (UTC+8), то день начинается в 16:01 UTC и заканчивается в 16:00 UTC следующего дня.

**Лос-Анджелес**: если в качестве часового пояса приложения выбран Лос-Анджелес (UTC-8), то день начинается в 08:01 UTC и заканчивается в 08:00 UTC следующего дня.

<div id="time-zone-guidelines" />

#### Рекомендации по часовым поясам

* Согласуйте часовой пояс приложения с часовым поясом, который вы установили для других поставщиков атрибуции, таких как Meta Ads и Google.
* Если у вас более одного приложения, рекомендуется установить для всех приложений один и тот же часовой пояс. Чтобы просмотреть настройки часового пояса приложения, перейдите в раздел **Настройки** > **Настройки приложений.**
* Большинство инструментов для отчетов и извлечения данных поддерживают часовые пояса приложений. Это относится и к отчетам по нескольким приложениям, если для всех приложений задан один и тот же часовой пояс.

<div id="daily-processing" />

#### Ежедневная обработка

Некоторые отчеты и раскрывающиеся списки обрабатываются один раз в день, это называется ежедневным обновлением или ежедневной обработкой. Вот принципы ежедневной обработки:

* Данные, относящиеся к определенному дню, например, понедельнику, собираются в *корзину*. День начинается в 00:01 и заканчивается в 24:00 по времени приложения.
* Данные, полученные в течение двух часов после полуночи, включаются в корзину за этот день. То есть данные, полученные до 02:00 вторника, включаются в корзину понедельника.
* В 02:00 по местному времени корзина закрывается, и в нее нельзя больше добавлять данные.
* Данные, полученные после 02:00, помещаются в следующую доступную корзину независимо от даты события.
* Ежедневная обработка закрытой корзины начинается через два часа после полуночи по UTC независимо от часового пояса приложения. Для простоты мы указываем, что обработка начинается в полночь по UTC. Это означает, что в зависимости от местного часового пояса обработка корзины начнется только в полночь по UTC.

**Восточное полушарие и часовой пояс UTC**:

![[ТРЕБУЕТСЯ ОПИСАТЕЛЬНЫЙ ALT-ТЕКСТ — ПОДТВЕРДИТЕ]: диаграмма времени ожидания ежедневной обработки для часовых поясов Восточного полушария](https://files.readme.io/cbea9d910695b39f59b342da6f56fa51df76afc910c4eea60f6dd49fbee2a0d6-8272818122769.png)

* С момента окончания дня (по местному времени) до начала обработки может пройти до 11 часов. Например:
  * Пекин (UTC+8): необходимо подождать восемь часов до начала обработки
  * Берлин (UTC +1): необходимо подождать один час до начала обработки
  * UTC: время ожидания отсутствует.
* В зависимости от типа отчета данные доступны через 8-20 часов после начала обработки. Например, данные для Пекина доступны с 16:00 по местному времени. Данные для Берлина доступны с 09:00.

**Западное полушарие:**

![[ТРЕБУЕТСЯ ОПИСАТЕЛЬНЫЙ ALT-ТЕКСТ — ПОДТВЕРДИТЕ]: диаграмма времени ожидания ежедневной обработки для часовых поясов Западного полушария](https://files.readme.io/ac5e3046b3f55916bb73732801c7e0bdef714cc45b89b6c4d70bbc2009cd64c8-8272698121489.png)

* С момента окончания дня (по местному времени) до начала обработки может пройти до 23 часов. Например:
  * Лос-Анджелес (UTC -8): необходимо подождать 16 часов до начала обработки
  * Нью-Йорк (UTC -5): необходимо подождать 19 часов до начала обработки
* В зависимости от типа отчета обработанные данные доступны через 8-20 часов после начала обработки. Например, данные для Лос-Анджелеса доступны с 00:01 по местному времени через два дня после события. Данные для Нью-Йорка доступны с 03:01 по местному времени через два дня после события.
* Пример:
  * События происходят в понедельник по времени Лос-Анджелеса (UTC-8), ежедневная обработка данных начинается в полночь вторника по Гринвичу. В Лос-Анджелесе это 16:01 вторника.
  * Обработка данных завершается восемь часов спустя, в среду в 00:01 по времени Лос-Анджелеса. С практической точки зрения, данные за понедельник доступны для рекламодателей в Лос-Анджелесе, когда они начинают работу в среду утром.
