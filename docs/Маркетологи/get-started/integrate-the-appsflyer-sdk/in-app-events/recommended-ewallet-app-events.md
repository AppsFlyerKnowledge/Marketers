> **Краткий обзор.** Если у вас игровое приложение, регистрация следующих внутренних событий позволит измерять качество пользователей на протяжении всего их пути.

## <Image alt="InApp_Events_eWallet.png" src="https://files.readme.io/4d2ed4994bbe8e8eca7009b8ec8f5dbf22a626421a7a1efb213ddb4a12c7b487-4402543191825.png" width="67px" /> eWallet

Приложения электронных кошельков позволяют пользователям совершать цифровые платежи или покупки со своих устройств. К типичным событиям, которые мы предлагаем записывать, относятся пополнение счета, просмотр контента, выбор продавцов, просмотр рекламных акций и осуществление транзакций.

Регистрация этих событий поможет вам определить следующее:

* Какой контент и акции пользуются популярностью у пользователей, чтобы затем предложить им аналогичные или связанные продукты.
* Для оплаты каких услуг пользователи наиболее часто используют электронный кошелек.
* Какие продавцы пользуются наибольшей популярностью

## Рекомендуемые структуры для предопределенных событий

В следующем разделе представлен список структур для событий, характерных для вертикали электронного кошелька. В каждую структуру входят предопределенное название события и рекомендуемые параметры события. Обратите внимание, что внутренние события приложения могут содержать любые параметры событий, отвечающие потребностям вашего бизнеса.

<div id="complete-registration-af_complete_registration" />

<Accordion title="Завершение регистрации (af_complete_registration)">

**Цель**

Узнать, сколько пользователей установило приложение и зарегистрировалось, какие способы регистрации предпочитают пользователи.

**Триггер**

Пользователь завершает процесс регистрации.

**Параметры события**

| Имя | Описание | Пример значения |
| --- | --- | --- |
| af\_метод\_регистрации | Тип способа регистрации | Email, Facebook, Google |

</Accordion>

<div id="login-af_login" />

<Accordion title="Авторизация (af_login)">

**Цель**

Проанализировать метрику удержания зарегистрированных пользователей.

**Триггер**

Успешный вход пользователя в систему.

**Параметры события**

Можно отправлять без каких-либо дополнительных параметров.

</Accordion>

<div id="content-view-af_content_view" />

<Accordion title="Просмотр контента (af_content_view)">

**Цель**

Определить частоту просмотров конкретного контента. Это событие поможет вам:

* Понять, какой тип контента наиболее популярен среди ваших пользователей, а затем постараться оптимизировать свои маркетинговые кампании.
* Соотнести просмотры товаров с продавцами.

**Триггер**

Просмотр пользователем определенного товара или контента категории

**Параметры события**

| Имя | Описание | Пример значения |
| --- | --- | --- |
| Товар | Тип товара | билет в кино |
| merchant\_name | Имя продавца | cineplex |

</Accordion>

## Рекомендуемые структуры для настраиваемых событий

В следующем разделе представлен список структур для событий. В структурах указаны имена настраиваемых событий и рекомендуемые параметры событий. Обратите внимание, что внутренние события приложения могут содержать любые параметры событий, отвечающие потребностям вашего бизнеса.

<div id="wallet-complete-topup-wallet_complete_topup" />

<Accordion title="Полное пополнение кошелька (wallet_complete_topup)">

**Цель**

Баланс счета может использоваться для приобретения пакетов или услуг, предлагаемых в приложении. Регистрация этого события и его сопоставление с другими данными позволяет узнать больше о пользователях. Например, можно узнать, какие суммы пользователи готовы внести на счет, и использовать суммы пополнения для таргетинга этих пользователей в рамках их бюджетов.

**Триггер**

Пополнение пользователем электронного кошелька с банковского счета или кредитной карты

**Параметры события**

| Имя | Описание | Пример значения |
| --- | --- | --- |
| top\_up\_amount | Сумма платежа | 100 |
| top\_up\_method | Тип способа оплаты | Банковский перевод |

</Accordion>

<div id="payment-transaction-completed-payment_transaction_completed" />

<Accordion title="Платежная операция завершена (payment_transaction_completed )">

**Цель**

Это событие поможет вам:

* Выделить пользователей, которые завершили оплату транзакции.
* Выявить крупные транзакции, а затем ретаргетировать пользователей, пополнивших счет на большую сумму.

**Триггер**

Завершение транзакции по совершению определенной покупки

**Параметры события**

| Имя | Описание | Пример значения |
| --- | --- | --- |
| Товар | Оплаченный товар | пополнение предоплаченной карты |
| количество | Сумма платежа | 1 |
| transaction\_amount | Сумма транзакции | 50 |

</Accordion>

<div id="bill-payment-success-bill_payment_success" />

<Accordion title="Успешная оплата счета (bill_payment_success)">

**Цель**

Это событие поможет вам определить наиболее популярный тип услуг, для оплаты которых пользователи используют электронный кошелек (например, счета за воду, электричество или пополнение кредитных карт).

**Триггер**

Использованием пользователем электронного кошелька для совершения платежей, например, оплаты счетов, получения выписок по кредитным картам или покупки билетов в кино.

**Параметры события**

| Имя | Описание | Пример значения |
| --- | --- | --- |
| merchant\_name | Имя продавца | Поставщик электроэнергии |
| payment\_amount | Сумма платежа | 100 |
| category | Тип услуги | Электричество |

</Accordion>

<div id="promo-promo" />

<Accordion title="Реклама (акции)">

**Цель**

Это событие поможет вам определить следующее:

* Популярна ли предлагаемая акция среди пользователей
* Помогает ли акция в перекрестных продажах дополнительных продуктов пользователям

**Триггер**

Выбор пользователем доступной акции в приложении

**Параметры события**

| Имя | Описание | Пример значения |
| --- | --- | --- |
| promo\_type | Тип предлагаемой акции | Скидка 30% |

</Accordion>

<div id="voucher-redeem-voucher_redeem" />

<Accordion title="Использование ваучера (voucher_redeem)">

**Цель**

Это событие поможет вам определить следующее:

* Сколько пользователей используют промокоды
* Какие ваучеры и скидки предпочитают пользователи

**Триггер**

Применением пользователем промокода

**Параметры события**

| Имя | Описание | Пример значения |
| --- | --- | --- |
| voucher\_ID | Идентификатор ваучера | 1735103 |
| merchant\_name | Имя продавца | cineplex |

</Accordion>

<div id="select-merchant-select_merchant" />

<Accordion title="Выбор продавца (select_merchant )">

**Цель**

Это событие поможет вам определить, какой продавец пользуется наибольшей популярностью для дальнейшего использования эти данных с целью привлечения аналогичных продавцов к сервису электронного кошелька.

**Триггер**

Выбор пользователем продавца из списка доступных продавцов

**Параметры события**

| Имя | Описание | Пример значения |
| --- | --- | --- |
| merchant\_name | Имя продавца | cineplex |
| type | Тип предприятия | кинотеатр |
| сумма | Валюта, используемая рекламодателем | USD (доллар США) |
| merchant\_ID | Определенный закрепленный за предприятием идентификатор который указывает системам обработки платежей, участвующим в транзакции, куда направлять средства | 123456 |

</Accordion>

<div id="scan-barcode-success-scan_barcode_success" />

<Accordion title="Успешное сканирование штрих-кода (scan_barcode_success )">

**Цель**

Это событие поможет вам:

* Понять, когда пользователь совершает конкретную транзакцию с продавцом
* Определить, какие продавцы пользуются наибольшей популярностью

**Триггер**

Сканирование пользователем QR-кода каждого продавца, которого он посетил при помощи приложения электронного кошелька

**Параметры события**

| Имя | Описание | Пример значения |
| --- | --- | --- |
| merchant\_name | Имя продавца | cineplex |
| merchant\_ID | Определенный закрепленный за предприятием идентификатор который указывает системам обработки платежей, участвующим в транзакции, куда направлять средства | 123456 |

</Accordion>
