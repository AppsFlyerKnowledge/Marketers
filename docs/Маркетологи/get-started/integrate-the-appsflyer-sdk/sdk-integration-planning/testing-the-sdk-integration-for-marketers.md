> **At a glance:** **Краткий обзор:** Проверьте интеграцию вашего приложения для Android или iOS с AppsFlyer.

## Обзор

После завершения интеграции SDK вы можете убедиться, что SDK успешно взаимодействует с серверами AppsFlyer. Маркетологи могут выбирать между двумя методами тестирования:

* C использованием страницы **тестирования интеграции SDK** , которая позволяет:
  * <Image alt="" src="https://files.readme.io/16b90e430d7beea0eaa1530130d094d590c0a202f6c6ad298a88aac9508fee7a-31828933593745.png" width="30px" /> [Просматривать события в режиме реального времени](#view-live-events) по мере их возникновения в тестируемом приложении.
  * [Тестировать неорганические установки](#h_01HYX9R15931HJEA06SY3K47W5)
  * [Тестирование диплинков (ретаргетинг)](#h_01HYX9R159DDNJW53AWTWT4C2Z)
* [Использовать ссылки атрибуции при тестировании](#тестирование-с-помощью-ссылок-атрибуции)

Разработчики могут проводить тестирование интеграции в своей среде разработки. См. <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/integration-testing">статьи по тестированию интеграции на Dev Hub</Anchor>.

Также можно протестировать приложения CTV, (см. [Тестирование CTV](#тестирование-ctv)).

## Тестирование на странице Тестирование интеграции SDK

Используйте страницу **Тестирование интеграции SDK** для просмотра в реальном времени событий, которые происходят в вашем приложении, таких как установки, доход от рекламы и внутренние события приложения. Вы также можете протестировать неорганические установки, внутренние событий приложения и диплинкинг (ретаргетинг), а также выявлять любые проблемы с интеграцией. Средство просмотра событий в режиме реального времени заменяет устаревший инструмент тестирования событий в приложении.

> 📘 **Note**
>
> Страница «Тестирование интеграции SDK» работает только в тех приложениях, где SDK фиксирует идентификатор устройства.
>
> * **iOS:** Убедитесь, что пользователь предоставил разрешения App Tracking Transparency (ATT), чтобы IDFA мог фиксироваться. Вы можете протестировать приложения, не реализующие АТТ, используя [эту процедуру](https://dev.appsflyer.com/hc/docs/testing-ios#apps-that-dont-implement-att).
> * **Android:** Хотя идентификатор устройства (GAID) обычно фиксируется автоматически, мы рекомендуем проверить, собирает ли его SDK.

### **Подготовьте тестовое устройство.**

1. Подготовьте устройство (Android или iOS), на котором не установлено приложение. При необходимости удалите приложение с устройства.
2. <Anchor target="_blank" href="/marketers/ru/docs/registering-test-devices">Зарегистрируйте устройство как тестовое.</Anchor>

### Проведение тестирования интеграции

На странице **тестирования интеграции SDK** представлены следующие три теста:

<Accordion title="Просмотр событий в режиме реального времени">

Live Event Viewer (просмотр событий в режиме реального времени) - это инструмент тестирования, отображающий в режиме реального времени данные, отправляемые из SDK в AppsFlyer, такие как события установки, доход от рекламы и другие внутренние события приложения. Для каждого зафиксированного события вы можете просмотреть журнал событий и подробную информацию.

> 📘 **Note**
>
> Средство просмотра Live Events также поддерживает события в приложении и сессии, созданные на тестовом устройстве, отправленные на ваш сервер и загруженные в AppsFlyer через API S2S. Убедитесь, что события S2S включают идентификатор устройства (IDFA для iOS, GAID для Android) зарегистрированного тестового устройства.

**Для просмотра событий в Live Event Viewer:**

1. В AppsFlyer в боковом меню выберите **Настройки** > **Тестирование интеграции SDK**.

   [![](https://files.readme.io/c4f39fb2ddf1de510d9a03e292b05fab444600a8584c0a23e7b3e613c7077799-31828925846033.png)](https://files.readme.io/c4f39fb2ddf1de510d9a03e292b05fab444600a8584c0a23e7b3e613c7077799-31828925846033.png)
2. Нажмите **События в режиме реального времени.**

   [![](https://files.readme.io/6ec1edba14e51bb27babf80d2d6f4873dbaa5113752217b4fb13399f7a1c61f1-31828925849489.png)](https://files.readme.io/6ec1edba14e51bb27babf80d2d6f4873dbaa5113752217b4fb13399f7a1c61f1-31828925849489.png)
3. В списке **приложений** выберите приложение, которое вы хотите протестировать.
4. В списке **тестовых устройств** выберите устройство, которое вы хотите использовать для тестирования своего приложения. Если у вас нет тестового устройства, вы можете зарегистрировать его, нажав на ссылку **Добавить тестовое устройство**.
5. Нажмите **Продолжить**, чтобы начать запись событий приложения.
6. Запустите приложение и используйте его, чтобы создавать сеансы и внутренние события приложения.

   [![](https://files.readme.io/72b8822197dc626c1b28a9f8d43bb3c1a91f99e600ae0d8d1f74829bc62dcce6-31828933607313.png)](https://files.readme.io/72b8822197dc626c1b28a9f8d43bb3c1a91f99e600ae0d8d1f74829bc62dcce6-31828933607313.png)
7. Щелкните элемент события, чтобы просмотреть сведения о событии на панели справа.
8. Если вы хотите остановить запись событий, нажмите **Стоп**. Нажмите кнопку **Пуск** еще раз, когда захотите продолжить.

</Accordion>

<Accordion title="Тестирование неорганических установок:">

**Чтобы протестировать неорганические установки:**

1. В AppsFlyer в боковом меню выберите **Настройки** > **Тестирование интеграции SDK**.

   [![](https://files.readme.io/c4f39fb2ddf1de510d9a03e292b05fab444600a8584c0a23e7b3e613c7077799-31828925846033.png)](https://files.readme.io/c4f39fb2ddf1de510d9a03e292b05fab444600a8584c0a23e7b3e613c7077799-31828925846033.png)
2. Нажмите Тестирование **неорганических установок**.

   [![](https://files.readme.io/34440ab6d328e2d519f759f3c2a1b17dbcbee55af32b47bdbd52bb9f537c6735-31828933612177.png)](https://files.readme.io/34440ab6d328e2d519f759f3c2a1b17dbcbee55af32b47bdbd52bb9f537c6735-31828933612177.png)
3. В списке **приложений** выберите приложение, которое вы хотите протестировать.
4. В списке **тестовых устройств** выберите устройство, которое вы хотите использовать для тестирования своего приложения. Если у вас нет тестового устройства, вы можете зарегистрировать его, нажав на ссылку **Добавить тестовое устройство**.
5. Если тестируемое приложение установлено на вашем тестовом устройстве, удалите его.
6. Установите флажок **Я удалил приложение с тестируемого устройства**.
7. Нажмите **Продолжить** и следуйте инструкциям мастера.

**Если по приложению не регистрируется неорганическая установка, возможной причиной этого может быть следующее:**

* IDFA доступен, но тестовое устройство не <Anchor target="_blank" href="/marketers/ru/docs/registering-test-devices#регистрация-тестового-устройства-ios">зарегистрировано с этим идентификатором на странице Тестовые устройства</Anchor>.
* На тестовом устройстве установлено несколько ваших приложений, помимо тестового, но тестовое устройство не <Anchor target="_blank" href="/marketers/ru/docs/registering-test-devices#регистрация-тестового-устройства-ios">зарегистрировано с этим IDFV на странице Тестовые устройства</Anchor>.
* Зарегистрирована органическая установка.
* Протестирована версия приложения без SDK.

В случае ошибок интеграции обратитесь к разработчику.

</Accordion>

## Тестирование с помощью ссылок атрибуции

В следующем разделе описаны процедуры тестирования установок с помощью ссылок атрибуции. Эти тесты можно проводить, даже если приложение все еще находится на рассмотрении (т. е. еще не опубликовано в Google Play или Apple App Store).

<Accordion title="Тестирование атрибуции установок">

Тестирование установок позволяет выяснить, верно ли SDK AppsFlyer атрибутирует установки различным медиа-источникам.

**Чтобы протестировать атрибуцию установок:**

1. Скопируйте ссылку (для Android или iOS) и внесите следующие изменения:

   1. Значение **app\_id** : Добавьте идентификатор вашего приложения в AppsFlyer.
   2. Параметр **pid** : Укажите название медиа-источника, которому атрибутирована установка.
   3. Параметр **c** : Укажите название кампании.
   4. Если вы тестируете приложение из стороннего магазина Android: добавьте <Anchor target="_blank" href="/marketers/ru/docs/set-up-multi-store-android-attribution#single-dashboard-attribution-links">параметр af\_r</Anchor> к ссылке атрибуции.
   5. Вместо GAID, IDFA или IDFV укажите идентификатор своего устройства.

   <Tabs>
   <Tab title="Android;">

   ```
   https://app.appsflyer.com/<app_id>?pid=Test&c=Test&advertising_id=<GAID>
   ```

   </Tab>

   <Tab title="https://files.readme.io/f28d0aac1797ee18fdc6083d9ea6d5d2f87d37a894a6c27ab0ea9b6ca51c53a1-49839256665233.png">

   IDFA

   ```
   https://app.appsflyer.com/<app_id>?pid=Test&c=Test&idfa=<IDFA>
   ```

   IDFV

   ```
   https://app.appsflyer.com/<app_id>?pid=Test&c=Test&idfv=<IDFV>
   ```

   </Tab>
   </Tabs>

   Далее приведены примеры ссылок атрибуции со значениями:

> 📘 **Note**
>
> Если вы тестируете приложение для iOS, не <Anchor target="_blank" href="/marketers/ru/docs/registering-test-devices">зарегистрировав тестовое устройство</Anchor>, ваш тестовый клик может быть отмечен Protect 360 как мошеннический.
>
> Чтобы данное событие не было распознано как фрод, добавьте в ссылку следующий параметр запроса: `pid=ios_testing`

1. Скопируйте обновленную ссылку, отправьте ее на тестовое устройство и затем перейдите по ней.

> 📘 **Note**
>
> В iOS воспользуйтесь iMessage или электронной почтой, чтобы отправить ссылку на устройство. Не вставляйте ссылку в приложение заметок iOS Notes, чтобы затем перейти по ней. Иначе ссылка может не работать.

1. Выполните одно из следующих действий:

   * Если приложение опубликовано, перейдите к установке.
   * Если приложение находится на рассмотрении, отображается следующее сообщение: *Приложение, которое вы ищете, пока не доступно на рынке.*Это ожидаемый результат. Поскольку приложение неактивно, ссылка атрибуции не ведет ни в один магазин приложений. Тем не менее, ссылка атрибуции по-прежнему действительна для целей атрибуции, и вам следует установить приложение следующим образом:
     * **Для Android:** Из APK-файла (или Android Studio для разработчиков)
     * **Для iOS:** Из TestFlight (или Xcode для разработчиков)

   Установка, атрибутированная тестовой кампании, должна появиться в данных медиа-источника **Test**. Данные об установке обычно отображаются на дэшборде приложения в течение 30 минут.

   [![Test_Install_Attribution_Link](https://files.readme.io/1771da27f7b8c5334d68c3d7c8361e91e0e35a3a08abf60e3d711f83de9ad22d-31828925861265.png)](https://files.readme.io/1771da27f7b8c5334d68c3d7c8361e91e0e35a3a08abf60e3d711f83de9ad22d-31828925861265.png)

> 👍 **Tip**
>
> Альтернативные способы проверки результатов теста:
>
> * Если у вас есть доступ к отчетам с сырыми данными, скачайте отчет <Anchor target="_blank" href="/marketers/ru/docs/raw-data-reporting-overview">Installs</Anchor> (Установки). Скачивание отчета занимает несколько минут. **Чтобы скачать отчет:**
>   1. В AppsFlyer в боковом меню выберите **Отчеты** > **Экспорт сырых данных**.
>   2. Из списка **User acquisition (non-organic)** (Привлечение пользователей (неорганические)) выберите **Installs** (Установки) и скачайте отчет.
> * Если у вас есть доступ к журналам отладки, вы можете получить результаты атрибуции по конкретной установке через <Anchor target="_blank" href="https://dev.appsflyer.com/hc/reference/gcd-get-data">API для получения данных о конверсиях</Anchor>.

</Accordion>

<Accordion title="Тестирование атрибуции внутренних событий приложения">

Тестирование внутренних событий приложения позволяет выяснить, отображается ли связанный с ними доход, и атрибутируются ли они медиа-источнику, принесшему установку.

**Чтобы протестировать атрибуцию внутренних событий приложения:**

1. Запустите приложение и создайте в нем несколько внутренних событий.
2. Откройте дэшборд активности приложения и проверьте, появились ли там события.  
   Здесь должны быть видны события, доход от них (если с ними связан доход) и медиа-источники, с которым они связаны. Данные о событиях появляются на дэшборде в течение 60–70 минут.

**Совет.** Рекомендуем скачать <Anchor target="_blank" href="/marketers/ru/docs/raw-data-reporting-overview">отчет с сырыми данными по внутренним событиям приложения</Anchor>, чтобы проверить правильно ли атрибутированы события. Скачивание отчета занимает несколько минут.

**Чтобы скачать отчет:**

1. В AppsFlyer в боковом меню выберите **Отчеты** > **Экспорт сырых данных**.
2. В разделе **Raw Data Reports** (Отчеты с сырыми данными) скачайте отчет по внутренним событиям.

</Accordion>

<Accordion title="Тестирование ссылок OneLink">

OneLink позволяет настроить единую ссылку атрибуции для Android и iOS. OneLink распознает устройства пользователей и перенаправляет их в соответствующий магазин приложений.

Кроме того, ссылку OneLink можно использовать для диплинкинга. Диплинкинг позволяет направлять пользователей на определенное действие в приложении, одновременно предоставляя им индивидуально подобранный контент.

Подробные сведения см в нашем Руководстве по <Anchor target="_blank" href="/marketers/ru/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#testing">тестированию URL-адресов ссылок OneLink</Anchor>.

</Accordion>

## Тестирование ретаргетинга с помощью ссылок атрибуции

В следующих разделах описаны процедуры тестирования атрибуции ретаргетинга.

<Accordion title="О тестах ретаргетинга">

Атрибуция ретаргетинга происходит, когда в рамках ретаргетинговой кампании пользователь кликает по ссылке атрибуции ретаргетинга. В результате имеет место событие реатрибуции или повторного вовлечения. Дополнительные сведения см. в <Anchor target="_blank" href="/marketers/ru/docs/retargeting-attribution-guide">Руководстве по атрибуции ретаргетинга</Anchor>.

Тесты ретаргетинга включают в себя следующее:

* [**Для реатрибуции:**](/docs/testing-the-sdk-integration-for-marketers#test-reattribution) Удаление и переустановка приложения. Проверка регистрации установки на дэшборде.
* [**Для повторного вовлечения:**](/docs/testing-the-sdk-integration-for-marketers#test-reengagement) переход по ссылке атрибуции ретаргетинга или диплинку и выяснение, корректно ли повторное вовлечение атрибутировано медиа-источнику.

</Accordion>

<Accordion title="Необходимые условия для проведения тестов ретаргетинга">

Перед проведением тестов ретаргетинга необходимо задать следующие настройки:

* Ретаргетинг должен быть активирован для тестируемого приложения.
* Создайте ссылку для конкретного приложения или получите настраиваемую ссылку OneLink. Эти ссылки должны содержать параметр ретаргетинга.

**Чтобы настроить тесты ретаргетинга:**

1. Включите ретаргетинг в настройках приложения.

   На дэшборде приложения нажмите **App Settings** (Настройки приложения) и активируйте переключатель **Enable retargeting attribution** (Включить атрибуцию ретаргетинга).

   ![Set_Reattribution_window](https://files.readme.io/1fe0c8c4add90c75237b0c5c97b6ff26d8f08ff95bd952912ef746fdec2e9f3d-31828933628561.png)
2. Выполните одно из следующих действий:
   * Создайте ссылку атрибуции для приложения. Обязательно включите параметр ретаргетинга, `is_retargeting=true`и рекламный идентификатор. Чтобы просмотреть GAID, IDFA или IDFV, следуйте инструкциям <Anchor target="_blank" href="/marketers/ru/docs/registering-test-devices">по регистрации тестового устройства</Anchor>.    
     Ниже приведен пример ссылки атрибуции, которая включает специфичный для Android параметр в качестве идентификатора устройства (GAID). Дополнительные сведения о добавлении параметров идентификаторов устройств, таких как IDFA или IDFV, см. в статье <Anchor target="_blank" href="/marketers/ru/docs/about-link-structure-and-parameters#ios-специфичные-параметры">Структура и параметры ссылки атрибуции</Anchor>.

     ```
     https://app.appsflyer.com/<app_id>?pid=Test&c=Test&is_retargeting=true&advertising_id=<GAID>
     ```
   * Получите <Anchor target="_blank" href="/marketers/ru/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#создание-ссылки-onelink">настраиваемый длинный URL-адрес</Anchor> из <Anchor target="_blank" href="/marketers/ru/docs/create-a-onelink-template#создание-шаблонов-onelink">шаблона OneLink</Anchor>. Обязательно активируйте <Anchor target="_blank" href="/marketers/ru/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#general-settings">Retargeting campaign</Anchor> (Ретаргетинговая кампания). На следующем изображении показан пример пользовательского длинного URL-адреса: ![Testing_LongLink_en-us.png](https://files.readme.io/19c706b0cc11b83a5cb08d51b3418654c6fa1e597ee7ff9e631db21c33c00b82-31828933632401.png)

Теперь можно переходить к тестированию реатрибуции и повторного вовлечения.

</Accordion>

<Accordion title="Тестирование реатрибуции">

**Прежде чем начать:**

* Следуйте [инструкциям](/docs/testing-the-sdk-integration-for-marketers#prerequisites-to-run-retargeting-tests) по настройке тестов ретаргетинга.
* Убедитесь, что ваше тестовое устройство **НЕ** зарегистрировано.

**Чтобы протестировать реатрибуцию:**

1. Удалите приложение с устройства. Если вы удалили приложение только что, подождите несколько минут.
2. Скопируйте ранее созданную [ссылку атрибуции](/docs/testing-the-sdk-integration-for-marketers#prerequisites-to-run-retargeting-tests): ссылку атрибуции конкретного приложения или настраиваемую длинную ссылку из шаблона OneLink, отправьте ее на тестовое устройство и затем перейдите по ней.

> 📘 **Note**
>
> В iOS воспользуйтесь iMessage или электронной почтой, чтобы отправить ссылку на устройство. Не вставляйте ссылку в приложение заметок iOS Notes, чтобы затем перейти по ней. Иначе ссылка может не работать.

1. Выполните одно из следующих действий:
   * Если приложение опубликовано, перейдите к установке.
   * Если приложение находится на рассмотрении, установите его следующим образом:
     * **Для Android**: Установка из Android Studio или APK-файла.
     * **Для iOS:** Установка из TestFlight.
2. Откройте дэшборд приложения и в поле **View type** (Тип представления) выберите **Retargeting** (Ретаргетинг).
3. В поле **Attribution type** (Тип атрибуции) выберите **Re-attributions** (Реатрибуция).

   Здесь установка должна быть атрибутирована медиа-источнику и кампании. Данные об установке, выполненной в результате ретаргетинга, появятся на дэшборде в течение 30 минут.

   [![Testing_SDK_Reattribution](https://files.readme.io/c5c59709b199262cbefd5cd70ee9fe0db2c788612a8ae6b598c7b2188b696345-small-31828925870609.png)](https://files.readme.io/c5c59709b199262cbefd5cd70ee9fe0db2c788612a8ae6b598c7b2188b696345-small-31828925870609.png)

> 👍 **Tip**
>
> Альтернативные способы проверки результатов теста:
>
> * Если у вас есть доступ к отчетам с сырыми данными, скачайте отчет <Anchor target="_blank" href="/marketers/ru/docs/raw-data-reporting-overview">Conversions</Anchor> (Конверсии). Скачивание отчета занимает несколько минут. **Чтобы скачать отчет:**
>   1. В AppsFlyer в боковом меню выберите **Отчеты** > **Экспорт сырых данных**.
>   2. В списке **Ретаргетинг** нажмите **Конверсии (повторное вовлечение и реатрибуция)**, а затем загрузите отчет.
> * Если у вас есть доступ к журналам отладки, вы можете получить результаты атрибуции по конкретной установке через <Anchor target="_blank" href="https://dev.appsflyer.com/hc/reference/get_app-id-2">API для тестирования интеграции SDK</Anchor>.

</Accordion>

<Accordion title="Тестирование повторного вовлечения">

**Прежде чем начать:**

* Следуйте [инструкциям](/docs/testing-the-sdk-integration-for-marketers#prerequisites-to-run-retargeting-tests) по настройке тестов ретаргетинга.
* В целях тестирования в качестве минимального интервала между конверсиями укажите **None** (Нет). Так, во время тестирования будут регистрироваться и атрибутироваться все конверсии повторного вовлечения. ![Testing_Reattribution_window](https://files.readme.io/ec8c7c923093dbed0e99aa5ef57d0239217ead5a9db41f42fe4af8a70eb04551-4406211661841.png)
* Убедитесь, что приложение установлено на вашем тестовом устройстве и уже несколько раз было запущено. Если вы удалили приложение только что, подождите несколько минут.

**Чтобы протестировать повторное вовлечение (прямой диплинкинг):**

Убедитесь, что в приложении настроен <Anchor target="_blank" href="/marketers/ru/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#deep-linking-and-deferred-deep-linking">диплинкинг</Anchor>, после чего выполните следующую <Anchor target="_blank" href="/marketers/ru/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#testing">процедуру</Anchor> тестирования.

**Чтобы протестировать повторное вовлечение (непрямой диплинкинг):**

1. Скопируйте ранее созданную [ссылку атрибуции](/docs/testing-the-sdk-integration-for-marketers#prerequisites-to-run-retargeting-tests): ссылку атрибуции для конкретного приложения или настраиваемую длинную ссылку из шаблона OneLink.
2. Отправьте ссылку на тестовое устройство и перейдите по ней.
3. Откройте приложение одним из следующих способов:

   * Нажмите **Открыть** в магазине приложений.
   * Запустите приложение со своего устройства.

   На дэшборде повторное вовлечение должно быть атрибутировано медиа-источнику и кампании. Данные о повторном вовлечении появятся в течение 30 минут.

   [![Testing_SDK_Re-engagement](https://files.readme.io/5b64b671c8071f871d9835e8df4d89c18d06c85fe996f7227b6ddf429552fccd-small-31828933643153.png)](https://files.readme.io/5b64b671c8071f871d9835e8df4d89c18d06c85fe996f7227b6ddf429552fccd-small-31828933643153.png)

**Совет.** Рекомендуем скачать отчет с сырыми данными по конверсиям, чтобы проверить корректно ли повторное вовлечение атрибутировано медиа-источнику. Скачивание отчета занимает несколько минут.

**Чтобы скачать отчет:**

1. В AppsFlyer в боковом меню выберите **Отчеты** > **Экспорт сырых данных**.
2. В разделе **Retargeting** (Ретаргетинг) скачайте отчет **Conversions (re-engagements & re-attributions)** (Конверсии (повторное вовлечение и реатрибуция)).

</Accordion>

## Тестирование CTV

К специальным тестовым случаям относятся следующие:

* **Android TV:** SDK совместим со смарт-телевизорами на базе Android. Маркетолог или любой член команды может тестировать приложения для таких ТВ, следуя инструкциям из этой статьи.
* **Apple TV (tvOS):** SDK совместим с Apple TV (tvOS). Маркетолог или любой член команды может тестировать приложения для таких ТВ, следуя инструкциям из этой статьи.
* **Неопубликованные приложения tvOS:** Требуется взаимодействие маркетолога и разработчика (см. <Anchor target="_blank" href="/marketers/ru/docs/testing-tvos-integration-before-publishing">Тестирование интеграции tvOS перед публикацией</Anchor>).
* **Amazon Fire TV:** Маркетолог может [протестировать интеграцию](/docs/testing-the-sdk-integration-for-marketers#testing-from-the-dashboard), используя метод тестирования Android SDK на дэшборде AppsFlyer. (Подробнее об атрибуции <Anchor target="_blank" href="/marketers/ru/docs/setting-up-amazon-fire-tv-ad-attribution">Amazon Fire TV</Anchor>).
* **Веб-события PBA:** Требуется взаимодействие маркетолога и разработчика (см. <Anchor target="_blank" href="/marketers/ru/docs/test-pba-web-sdk-integration">Тестирование интеграции веб-SDK PBA</Anchor>).
