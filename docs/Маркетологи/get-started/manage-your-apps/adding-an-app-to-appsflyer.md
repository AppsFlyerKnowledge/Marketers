> **Вкратце:** Узнайте, как добавить ваше приложение в AppsFlyer, чтобы получать данные атрибуции по установкам и событиям в приложении, а также анализировать эти данные с помощью различных инструментов AppsFlyer.

<div id="overview" />

## Обзор

Если вы ещё не добавили приложение в свой дэшборд, при входе в AppsFlyer отобразится страница ознакомления с приложением. Процесс ознакомления с приложением проведет вас через все этапы добавления вашего приложения и подготовки его к атрибуции.

<div id="entering-the-wizard-for-adding-an-app" />

### Вход в мастер добавления приложения

Вы можете воспользоваться мастером добавления приложений с платформы или через страницу ознакомления с приложением (только для приложений Android и iOS).

**Для входа в мастер через страницу ознакомления с приложением:**

* На этапе **Добавьте ваше приложение** нажмите **Добавить приложение** и следуйте инструкциям.

<div id="note" />

> 📘 **Примечание:**
>
> Если страница ознакомления ещё не открыта, в верхней панели выберите из раскрывающегося списка адресов электронная почта, электронное сообщение пункт **Ознакомление с приложением**.

![onboarding page.png](https://files.readme.io/8903839c25f12df28e1c4b488699670e2dadca83af9ddfebfc0cf4eacd2ce744-33198275479953.png)

**Для входа в мастер добавления приложения с платформы:**

* В верхней строке меню > **Мои приложения**, нажмите **+ Добавить приложение**.
* На главной странице AppsFlyer нажмите **+ Добавить приложение**.
* На верхней панели откройте меню учетной записи (раскрывающийся список адресов электронная почта, электронное сообщение) > **Ознакомление с приложением**, нажмите **+ Ознакомить с другим приложением**.

## Добавление приложения

После того как вы [войдете в мастер добавления приложения](#вход-в-мастер-добавления-приложения), выполните следующие действия:

1. [Введите информацию о приложении](#ввод-данных-приложение).
2. [Введите дополнительную информацию](#введите-дополнительную-информацию-не-относится-к-веб-приложениям).
3. Нажмите **Добавить мое приложение**.
4. Скопируйте ключ разработчика, который будет использоваться в <Anchor target="_blank" href="/marketers/ru/docs/getting-started-onboarding-for-marketers#шаг-2-интеграция-sdk--api">интеграции SDK (пакет средств разработки ПО)</Anchor> (позже его можно будет получить на странице <Anchor target="_blank" href="/marketers/ru/docs/app-settings#общие-настройки-приложения">Настройки приложения</Anchor>).
5. Нажмите **Готово** или **+ Добавить другое приложение**, чтобы добавить больше приложений. Повторите процесс для добавления дополнительных приложений.

<div id="note-1" />

> 📘 **Примечание**
>
> * Добавлять приложения могут только администраторы и <Anchor target="_blank" href="/marketers/ru/docs/user-management">пользователи аккаунта с необходимыми разрешениями</Anchor>.
> * При выполнении шагов по добавлению приложения (ниже) доступные опции будут зависеть от ранее выбранных вами параметров.

После регистрации Приложение появится на дэшборде. Чтобы установки и события в приложении регистрировались и приписывались правильным медиа источникам, необходимо:

* Интегрировать SDK (пакет средств разработки ПО)
* Подключите Приложение к Партнёрам в Marketplace партнёров

Ознакомьтесь со <Anchor target="_blank" href="/marketers/ru/docs/getting-started-onboarding-for-marketers">всеми шагами</Anchor> для завершения процесса ознакомления.

<Accordion title="Веб">

Используйте платформу Web, чтобы создать новое веб-приложение и измерять посещения сайта и конверсии с помощью Web Performance Measurement.

<div id="before-you-begin" />

#### **Прежде чем начать**

* Устаревшие веб-приложения Legacy People-Based Attribution (PBA) отображаются в разделе “**Web (PBA)**” с пометкой Legacy.
* Если вы переходите с устаревшего веб-приложения PBA Web, вы можете использовать существующий ключ разработчика PBA Web.

<div id="to-add-a-web-app" />

#### **Примечание**

1. Перейдите в раздел **Мои приложения** > **Добавить приложение**.
2. Выберите **Вебсайт**.
3. Введите следующее:

**Название приложения**: Название, которое вы выбрали для своего веб-приложения.

* Примечания:
* **Допустимые символы:** Буквы (любого языка), цифры, пробелы (не в начале и не в конце) и специальные символы: . - \_ :
* **Недопустимые символы:** ; \`{ }\` $ &lt; > \` \

**Пример:** My Online Store, Corporate Website 2024, E-Commerce\_Production

**Основной домен (полный URL-адрес)**: Основной домен вашего сайта. Он задается при создании веб-приложения и не может быть изменен позже.

* **Формат:** Только допустимое доменное имя (без протокола, пути или порта)
* Подробные требования см. в предыдущей строке Ожидает подтверждения / не опубликовано
* **Обработка:** AppsFlyer автоматически
  * Удаляет http:// или https://
  * Удаляет завершающие косые черты
  * преобразует домен в нижний регистр
* **Неизменяемость:** После создания приложения редактирование недоступно

**Важно:** Чтобы изменить основной домен, необходимо удалить и заново создать веб-приложение, что приведет к потере непрерывности исторических данных.

**Пример:**

* https://shop.example.com/checkout → Сохраняется как shop.example.com → ID приложения: website-shop.example.com
* example.com/ → Сохраняется как example.com → ID приложения: [website-example.com](http://website-example.com)

**ID приложения**: Уникальный ID, который AppsFlyer создает для веб-приложения на основе основного домена.

* Автоматически создается в формате: website-`<primary_domain>`
* Пример: website-shop.example.com

**Web SDK ID**: Идентификатор ID, который Web SDK использует для атрибуции (ранее назывался web\_dev\_key).

Два варианта при создании приложения:

**Вариант 1: Создать новый (по умолчанию)**

* Автоматически создает новый Web SDK ID
* Формат: website-`{yourdomain.com}`
* Пример: website-shop.example.com
* **Сценарий использования:** Новые реализации веб-атрибуции

**Вариант 2: Повторно использовать существующий ключ разработки PBA**

* Выберите в выпадающем списке существующие ключи разработки PBA (People-Based Attribution) для веб-приложений
* Обеспечивает бесшовную миграцию без изменения кода сайта
* **Сценарий использования:** Миграция с устаревшего PBA на новое решение для веб-атрибуции

**Примечание:** Повторное использование ключа разработки PBA позволяет выполнить миграцию с PBA на новое веб-приложение **без внесения каких-либо изменений в реализацию вашего сайта**.

Каждый ключ разработки PBA можно назначить только **ОДНОМУ** веб-приложению. После использования ключа разработки PBA для веб-приложения он больше недоступен для других веб-приложений.

* **Длина:** 1–550 символов
* **Неизменяемость:** Нельзя изменить после создания Приложения
* **Миграция PBA:** В выпадающем списке отображаются только ключи разработки из PBA веб-Приложений вашей учетной записи

**Валюта**: Валюта, используемая в отчетности приложения.

* Стандартный код валюты ISO 4217 (например, USD, EUR, GBP, ILS)
* Выбирается из выпадающего списка
* Обязательное поле

**Часовой пояс**: часовой пояс, используемый для отчетности приложения.

* Формат часового пояса IANA (например, America/New\_York, Europe/London, Asia/Tokyo)
* Выбирается из раскрывающегося списка
* Обязательное поле

4. Нажмите **Создать приложение**.

**Характеристики и ограничения**

* После создания приложения **основной домен нельзя изменить**.
* Основной домен автоматически добавляется в **Excluded Domains** с типом **PRIMARY**.

Каждый устаревший **Web Dev Key можно повторно использовать только для одного** нового веб-приложения.

### Введите дополнительную информацию (не относится к веб-приложениям):

<Image alt="" src="https://files.readme.io/561aea51bbfaa733721040706cac2b9520e35cfe71027fa34d08ed7890baf00c-33198323448081.png" width="559px" />

<div id="select-currency" />

#### **Выберите валюту**

Выберите валюту, в которой данные этого приложения будут отображаться на дэшборде. События выручки и расходования конвертируются в эту валюту с использованием обменного курса, действительного на момент события. <Anchor target="_blank" href="/marketers/ru/docs/app-settings#localization-currency">Узнать больше</Anchor> о настройке валюты приложения и ее воздействии.

<div id="important-2" />

> 🚧 **Важно!**
>
> Будьте внимательны при выборе валюты, которую вы хотите использовать в приложении. Изменение будет невозможно после того, как стоимость и выручка будут зафиксированы.

<div id="select-timezone" />

#### **Выберите часовой пояс**

Синхронизируйте выбранный здесь часовой пояс с часовым поясом, который вы установили у других партнеров по атрибуции (таких как реклама Meta и Google Ads). Это обеспечивает максимальное сходство данных, представленных на дэшборде AppsFlyer, с данными, которые вы получаете от этих партнеров.

<div id="note-5" />

> 📘 **Примечание:**
>
> * После установки часового пояса, он остается фиксированным и не может быть изменен до следующего дня.
> * <Anchor target="_blank" href="/marketers/ru/docs/changing-app-time-zone-settings">Узнать больше</Anchor> о настройке часового пояса приложения и её воздействии.

<div id="define-app-audience" />

#### **Определите аудиторию приложения**

Выберите **Да** или **Нет**, чтобы указать, предназначено ли ваше приложение для детей или для смешанной аудитории (и детей, и взрослых).  
Если вы выбрали **Да:**

1. Откройте и прочитайте <Anchor target="_blank" href="https://www.appsflyer.com/gatedpdfs/KidsAppsComplianceGuide_03_22.pdf">руководство</Anchor> по соблюдению правовых норм в приложениях, ориентированных на детей.
2. Установите флажок, чтобы подтвердить, что вы прочитали руководство и будете применять указанные в нём элементы управления.

<div id="note-6" />

> 📘 **Примечание:**
>
> * Две недели спустя после добавления приложения вы получите уведомление с просьбой подтвердить, что реализовали элементы управления конфиденциальностью для приложений, ориентированных на детей. После подтверждения вы получите сообщение о подтверждении. Вы всегда можете получить доступ к сообщению о подтверждении из Центра уведомлений или просмотреть детали подтверждения в <Anchor target="_blank" href="/marketers/ru/docs/audit-log">журнале аудита</Anchor>.
> * Смотрите <Anchor target="_blank" href="/marketers/ru/docs/child-directed-apps-faq">часто задаваемые вопросы о приложениях, ориентированных на детей</Anchor>.

<div id="manage-your-apps-in-bulk-via-api" />

#### Управляйте своими приложениями массово через API

Администраторы учётных записей могут <Anchor target="_blank" href="https://dev.appsflyer.com/hc/reference/app-management-v2-overview">управлять несколькими приложениями одновременно</Anchor> с помощью специального API, который поддерживает основные функции интерфейса. Это включает добавление и удаление приложений, а также обновление настроек приложений. API также включает те же механизмы проверки ошибок.

<div id="note-7" />

> 📘 **Примечание:**
>
> На данном этапе добавление приложений и обновление настроек через API возможно только для мобильных приложений. Удаление приложений возможно для всех платформ.

<div id="add-a-debug-or-testing-app" />

### Добавьте отладочное или тестовое приложение

Если ваш разработчик создает **отладочное**, **песочничное** или **тестовое приложение**, вы должны добавить приложение на дэшборд. Когда ваш разработчик начнет тестирование с помощью приложения, данные будут отображаться на дэшборде приложения.

<div id="note-8" />

> 📘 **Примечание**
>
> Для приложений iOS, которые еще не опубликованы в App Store и пока не имеют действительного App Store ID, вы все равно можете продолжить тестирование SDK, добавив приложение с помощью **фиктивного iOS App Store ID**. Это позволяет выполнять интеграцию и тестирование SDK без необходимости в реальном листинге в App Store.

Инструкции для разработчиков по созданию отладочного приложения и его добавлению на дэшборд см. здесь:

* <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/testing-android#creating-an-android-debug-app">Имя пакета Android</Anchor>

<div id="about-pending-apps" />

## Об ожидающих приложениях

Работа с приложением в статусе ожидания полезна при его отладке для тестирования SDK (пакет средств разработки ПО) AppsFlyer.

Статус приложения как ожидающего на дэшборде не влияет на сбор и измерение данных. Независимо от того, находится ли приложение в состоянии ожидания или уже доступно в магазине приложений, если пользователи устанавливают и взаимодействуют с ним, данные об установке и внутренние события приложения регистрируются на дэшборде.

Когда ваше ожидающее приложение будет опубликовано, AppsFlyer определит и автоматически обновит его статус, так что вам не нужно будет добавлять его снова. <Anchor target="_blank" href="/marketers/ru/docs/why-is-my-app-still-pending">Узнать больше</Anchor> об ожидающих приложениях и о возможности ручного обновления статуса.

<div id="troubleshooting" />

## Устранение неполадок

Найдите решения для некоторых распространённых проблем:

<div id="app-wasnt-added" />

<Accordion title="Приложение не было добавлено">

Если возникла эта ошибка, свяжитесь с вашим менеджером по клиентам или отправьте электронную почту, электронное сообщение по адресу [hello@appsflyer.com](mailto:hello@appsflyer.com).

</Accordion>

<div id="app-not-in-the-store" />

<Accordion title="Приложение отсутствует в магазине">

Убедитесь, что вы правильно скопировали URL-адрес магазина, используя соответствующее имя/идентификатор приложения.

</Accordion>

<div id="cant-access-marketplace" />

<Accordion title="Нет доступа к маркетплейсу">

Эта ошибка иногда возникает при добавлении приложения Android из магазина, не принадлежащего США. Чтобы устранить эту ошибку, выполните следующие шаги:

1. Добавьте приложение с статусом **Ожидает одобрения/не опубликовано**, как указано выше.
2. Перейдите на страницу **Настроек приложения** в AppsFlyer.
3. Измените страну **магазина приложений** на правильную (например, Япония).

</Accordion>

<div id="something-went-wrong" />

<Accordion title="Что-то пошло не так. Пожалуйста, попробуйте снова.">

Одной из возможных причин этой ошибки может быть попытка добавить Android-приложение без кода страны (для приложений, **не** указанных в магазине Google Play США). Полную информацию о решении этой проблемы смотрите [выше](/docs/adding-an-app-to-appsflyer#in-store).

</Accordion>

<div id="my-ios-app" />

<Accordion title="Мое iOS-приложение было удалено из App Store. Почему я до сих пор вижу установки?">

Это происходит потому, что пользователи могут повторно установить приложение через операционную систему, если оно было установлено на их устройстве ранее. Даже если приложение больше не доступно в App Store, пользователи все равно могут установить его, и эти установки будут учитываться в AppsFlyer.

</Accordion>
