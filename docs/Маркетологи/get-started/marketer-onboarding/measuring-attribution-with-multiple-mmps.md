> **Краткий обзор.** Узнайте, какие медиа-источники могут измерять атрибуцию при одновременной работе с несколькими MMP, чтобы вы могли сравнить результаты атрибуции между AppsFlyer и другими MMP.

<div id="overview" />

## Обзор

При переходе с другого MMP (партнера по измерению эффективности мобильной рекламы) на AppsFlyer рекламодатели могут захотеть одновременно сравнить показатели обоих MMP по одним и тем же медиа-источникам и кампаниям. Для этого необходимо выполнить следующие требования:

* В тестируемое приложение должны быть **интегрированы SDK обоих MMP**
* Медиа-источники должны быть **настроены на поддержку атрибуции с двумя MMP**

Однако не все медиа-источники поддерживают измерение с помощью более чем одного MMP.  

<div id="details-and-limitations-of-media-source-measurement" />

## Детали и ограничения измерения медиа-источников

Ниже приведены подробности и ограничения измерения медиа-источников при одновременной работе с несколькими MMP.

<div id="self-reporting-networks" />

### Сети с самостоятельной атрибуцией

| СРН | Детали и ограничения | Поддержка измерения |
| --- | --- | --- |
| Apple Search Ads | ASA поддерживает измерение нескольких MMP без ограничений. Когда запрос на вызов API поступает от нескольких MMP, данные отправляются на соответствующие MMP. | ✓ |
| DV360 (GMP) | Можно использовать несколько MMP, но в настройках кампании должны быть отдельные элементы строки для каждого отслеживания floodlight (Link ID). | ✓ |
| Google реклама | Google Ads поддерживает измерение нескольких MMP:<ul><li>Рекламодатели могут привязать несколько идентификаторов ссылок MMP к одному аккаунту Google Ads и получать постбэки от каждого MMP.</li><li>Google Ads может получать постбэки от нескольких MMP</li><li>Можно измерить эффективность нескольких MMP</li></ul>**Примечание.** После того как данные перейдут к новому MMP, Google Ads рекомендует прекратить существующую интеграцию. | ✓ |
| Meta Ads | Meta ads получает запросы данных от нескольких MMP. Однако они настоятельно рекомендуют **не** иметь более одного MMP по следующим причинам:<ul><li>Meta ads могут обрабатывать дедупликацию только для установок, но не для событий. Поэтому события должны отправляться только от одного MMP</li><li>При вставке нескольких SDK от MMP очень высока вероятность возникновения проблем и вторичных ошибок в процессе дедупликации</li><li>Когда в Meta ads отправляется большое количество данных, в их системы оптимизации и измерения могут попасть дублированные данные.</li></ul>Таким образом, атрибуция нескольких MMP может быть поддержана только на короткий срок. | С ограничением |
| Snapchat | Передача данных между Snapchat и несколькими MMP возможна. Тем не менее, рекомендуется свести к минимуму перекрытие периода миграции. При получении данных от нескольких MMP отсутствует возможность оптимизации путем выбора конкретного MMP. Это означает, что оптимизация проводится для всех MMP и вероятность перекрытия данных очень высока. | С ограничением |
| TikTok для бизнеса | Отправка постбэков в TikTok for Business поддерживается только для одного MMP. При переходе с другого MMP, чтобы AppsFlyer мог атрибутировать конверсии к TikTok for Business, вам сначала нужно отключить постбэки от другого MMP, а затем настроить AppsFlyer. | X |
| Twitter | X Ads не поддерживает интеграцию нескольких MMP | X |

### SKAN

Отправка <Anchor target="_blank" href="/marketers/ru/docs/skan-conversion-studio#основы-работы-с-skan-conversion-studio">постбэков по конверсиям SKAN</Anchor> **не поддерживается для нескольких MMP**. Только один SDK может инициировать отправку постбэков SKAN партнерам. Это означает, что если в ваше приложение интегрировано несколько SDK, постбэки SKAN будут отправляться только в один SDK.

<div id="non-srn-ad-networks" />

### Рекламные сети без собственной атрибуции (не SRN)

Ссылки атрибуции MMP фиксируют интеракции пользователей в рекламных сетях не-SRN, и впоследствии используются для атрибуции интеракций, которые становятся фактическими установками. Чтобы включить атрибуцию для нескольких MMP одновременно, рекламная сеть должна убедиться, что соблюдены следующие требования:

| Требование рекламной сети | Подробности |
| --- | --- |
| Данные для одной интеракции должны быть отправлены обоим MMP | <ul><li>**Клики:** Поскольку ссылки атрибуции перенаправляют пользователей в магазин приложений, можно использовать только одну ссылку атрибуции. Мы рекомендуем продолжать использовать ссылку атрибуции от существующего MMP, <Anchor target="_blank" href="/partners/ru/docs/redirecting-users-to-the-app-store#обзор">отправляя данные об атрибуции по кликам в AppsFlyer</Anchor>.</li><li>**Показы:** Поскольку показы не перенаправляют пользователей в магазин приложений, рекламная сеть должна отправлять данные о показах в оба MMP.</li></ul> |
| Полученные постбэки по установкам должны быть дедуплицированы | Рекламные сети получают постбэки по установкам от обоих MMP. Чтобы избежать двойных расходов, рекламная сеть должна дедуплицировать один из этих постбэков. |
| Полученные постбэки по внутренним событиям должны быть дедуплицированы | Когда каждый из MMP настроен на отправку постбэков о событиях в приложении, рекламные сети получают постбэки о событиях в приложении от обоих MMP. Чтобы избежать двойной атрибуции, приводящей к двойным расходам, рекламная сеть должна дедуцировать один из этих постбэков. Если рекламная сеть не может дедуплицировать двойные постбэки о событиях в приложении, убедитесь, что постбэки о событиях в приложении настроены только в одном MMP. |

<div id="owned-media" />

### Метрики заголовка

Как и в случае с рекламными сетями не-SRN, атрибуция установок из собственных медиа требует использования ссылок атрибуции MMP. Однако для некоторых типов собственных медиа, таких как рассылки по электронной почте, СМС или QR-коды, MMP могут отправлять данные об одном взаимодействии только один раз. Решение AppsFlyer для <Anchor target="_blank" href="/marketers/ru/docs/convert-your-mobile-web-visitors-to-app-users">атрибуции из мобильного сайта в приложение</Anchor> позволяет измерять количество **установок, пришедших с веб-сайта или целевой страницы**. Преимущество использования собственных медиа для сравнения атрибуции MMP заключается в том, что не требуется дедупликация установок или событий.

<div id="avoiding-attribution-discrepancies" />

## Избегание расхождений в атрибуции

Когда MMP используют разные модели атрибуции для измерения трафика, это может привести к расхождениям. Минимизировать расхождения можно с помощью следующих действий:

* Убедитесь, что оба MMP используют один и тот же часовой пояс для приложения. Вот как <Anchor target="_blank" href="/marketers/ru/docs/changing-app-time-zone-settings">установить часовой пояс приложения в AppsFlyer</Anchor>.
* Для не-SRN и собственных медиа: обязательно настройте ссылку атрибуции, используя те же значения параметров. Например, установите одинаковое окно атрибуции в обоих MMP.
* При сравнении данных на дэшбордах или в отчетах MMP убедитесь, что они соответствуют одним и тем же критериям, например, трафик из одного и того же диапазона дат и географического положения.
