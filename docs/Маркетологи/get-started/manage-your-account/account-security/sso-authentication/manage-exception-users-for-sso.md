> **Кратко:** Пользователи-исключения — это пользователи, которым не требуется вход в систему через SSO. SSO по-прежнему остается обязательным для учетной записи, а администраторы могут предоставить отдельным пользователям доступ к назначенному альтернативному методу входа в систему.

## **Об исключенных пользователях**

Пользователи-исключения обеспечивают контролируемый доступ для пользователей, которым нужен метод входа в систему без SSO. Например, администраторы могут использовать пользователей-исключения для аварийного доступа (break-glass) или для пользователей, которые не могут использовать поставщика удостоверений учетной записи.

Пользователи-исключения могут входить в систему через SSO или с помощью назначенного им альтернативного метода входа в систему. Пользователи, не добавленные в список исключенных, должны входить в систему через SSO.

Мы рекомендуем добавить как минимум одного доверенного администратора в качестве исключенного пользователя при первоначальной настройке SSO. Если конфигурация SSO неверна, администратор может войти в систему с помощью назначенного ему альтернативного метода входа в систему и обновить конфигурацию.

## **Требования**

* Для учетной записи должен быть настроен SSO.
* Чтобы управлять SSO и пользователями-исключениями, у вас должно быть разрешение **Безопасность входа** со значением **Управление**.

<div id="add-exception-users-during-sso-setup" />

<Accordion title="Добавление исключенных пользователей при настройке SSO">

**Рекомендуется:** Добавьте как минимум одного доверенного администратора в качестве исключенного пользователя до активации SSO. Это поможет избежать блокировки доступа к учетной записи, если конфигурация SSO неверна.

Чтобы добавить исключенных пользователей:

1. На шаге **Add exception users** нажмите **Add exception users**.
2. Найдите пользователя по имени или электронной почте.
3. Выберите пользователя, которого хотите добавить.
4. В раскрывающемся списке **Alternative login method** выберите один из следующих вариантов:
   * **Имя пользователя & пароль**
   * **Приложение-аутентификатор**
5. Повторите шаги 2–4 для каждого пользователя, которого хотите добавить.
6. Наличие этого символа приведёт к сбою входа в систему.
7. **Вход только с SSO (Force SSO)** [Рекомендуется]: этот метод обеспечивает более безопасный вход в систему.

Если вы не добавите исключенных пользователей, после активации все пользователи учетной записи должны будут входить в систему через SSO.

</Accordion>

<div id="add-login-methods-for-multiple-users" />

<Accordion title="Добавление методов входа в систему для нескольких пользователей">

Чтобы добавить один и тот же альтернативный способ входа в систему для нескольких пользователей:

1. Установите флажки напротив пользователей, которых нужно обновить.
2. Нажмите **Задать способ входа в систему для выбранных пользователей**.
3. Выберите один из вариантов:
   * **Примените имя пользователя и пароль для всех выбранных пользователей**
   * **Применить приложение-аутентификатор для всех выбранных пользователей**

</Accordion>

<div id="edit-exception-users-after-sso-activation" />

<Accordion title="Редактирование пользователей-исключений после активации SSO">

После активации SSO можно добавлять исключенных пользователей, удалять их или обновлять для них альтернативные способы входа в систему.

Чтобы редактировать пользователей-исключений:

1. Перейдите в раздел **Центр безопасности** > **Безопасность входа в систему**.
2. Нажмите на иконку **Редактировать** <Image alt="edit-icon.jpg" src="https://files.readme.io/d32f150cb5d0271c5504fb3c107e23f73e59c9a3be1630769ad309edf4e79ea0-31780971794321.jpg" width="24px" /> справа в разделе **Единый вход SAML (SSO)**.
3. Откройте раздел **Пользователи-исключения**.
4. метаданные поставщика услуг (метаданные AppsFlyer) – детали могут быть получены;
5. Добавляйте пользователей, удаляйте их или обновляйте альтернативные способы входа в систему.
6. Нажмите **Save** (Сохранить).
7. Выберите **Сохранить изменения**. Будет показано сообщение, подтверждающее статус изменений.

Ранее добавленные исключенные пользователи отображаются с их текущим альтернативным способом входа в систему.

</Accordion>

<div id="delete-exception-users" />

<Accordion title="Удаление пользователей-исключений">

Чтобы удалить исключенного пользователя:

В диалоговом окне «Редактирование пользователей-исключений» найдите пользователя, которого хотите удалить.

Нажмите значок удаления.

Пользователь сразу удаляется из списка.

</Accordion>

<div id="alternative-login-methods" />

<Accordion title="Установите метод входа в систему">

| **метод входа в систему;** | **Description(Описание)** |
| --- | --- |
| Имя пользователя & пароль | Позволяет исключенному пользователю входить с именем пользователя и паролем AppsFlyer. |
| Приложение-аутентификатор | Позволяет исключенному пользователю входить с помощью приложения-аутентификатора. СМС не поддерживаются. |

</Accordion>

<div id="handle-partial-activation-failures" />

<Accordion title="Обработка частичных сбоев активации">

В некоторых случаях активация SSO проходит успешно, но один или несколько исключенных пользователей не добавляются.

Когда это происходит:

* SSO остается активным.
* Пользователи, которые не были добавлены в список исключений, должны входить в систему через SSO.
* Администраторы могут добавлять или обновлять пользователей в списке исключений в разделе **Edit SSO**.

</Accordion>

<div id="reset-passwords-for-sso-accounts" />

<Accordion title="Сброс паролей для учётных записей SSO">

Все пользователи могут запустить процесс восстановления пароля. Однако только пользователи из списка исключений, которым назначен альтернативный метод входа **Username & password**, могут войти в систему с новым паролем.

Пользователи, не входящие в список исключений, должны по-прежнему входить в систему через SSO.

</Accordion>

<div id="migrate-from-legacy-unforce-sso" />

<Accordion title="Переход с устаревшего Unforce SSO">

Для учетных записей, перенесенных с устаревшего Unforce SSO на уровне учетной записи, существующие пользователи, которые входили в систему по имени пользователя и паролю, добавляются в список исключений, а в качестве альтернативного метода входа для них задается **Username & password**.

Новые пользователи, созданные после миграции, должны входить в систему через SSO, если только администратор явно не добавит их в список исключений.

</Accordion>

<div id="traits-and-limitations" />

<Accordion title="Спецификации и ограничения">

| **Специфика** | **Description(Описание)** |
| --- | --- |
| Принудительное применение SSO | Для учётной записи по-прежнему принудительно применяется SSO. Пользователи-исключения – это управляемые исключения, задаваемые на уровне отдельных пользователей. |
| Поддерживаемые альтернативные методы входа | Пользователи из списка исключений могут использовать **Username & password** или **Authenticator app**. |
| Аутентификация по СМС | СМС не поддерживается в качестве альтернативного метода входа в систему. |
| Требуемые разрешения | Чтобы управлять пользователями-исключениями, у администраторов для разрешения **Безопасность входа** должно быть установлено значение **Управление**. |
| Разрешение только на просмотр | Администраторы с доступом только на просмотр могут просматривать существующих пользователей из списка исключений, но не могут их изменять. |
| Новые пользователи после миграции | Новые пользователи должны входить в систему через SSO, если только администратор не добавит их в список исключений. |

</Accordion>
