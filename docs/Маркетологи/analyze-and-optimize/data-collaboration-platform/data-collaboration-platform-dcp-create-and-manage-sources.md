## Об источниках DCP

В платформе Data Collaboration Platform (DCP) источник — это набор данных, обычно загружаемый в AppsFlyer из вашего облачного хранилища. Эти источники составляют основу любого сотрудничества, предоставляя данные, которые ваши участники совместной работы могут использовать для создания и активации аудиторий. В этой статье содержится все, что вам нужно знать о создании источников и управлении ими, включая:

* [Требования к данным источника](#требования-к-данным-источника)
* [Создание источников](#создать-источник)
* [Управление источниками](#управляйте-своими-источниками)

## Требования к данным источника

Рекомендуется <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-prepare-source-data-for-ingestion">подготовить данные источника</Anchor>, чтобы максимально повысить процент совпадений между наборами данных участников совместной работы и оптимизировать результаты сотрудничества. Кроме того, все источники **должны соответствовать следующим требованиям**.

<Accordion title="Формат данных (относится ко всем источникам)">

Данные в источниках должны отвечать следующим требованиям:

* **Дата** (только): yyyy-mm-dd (например, `2023-04-18`)
* **Дата и время:**
  * **Формат:** гггг-МММ-дд чч:мм:сс (*например,* `2023-APR-18 15:30:35`)
  * **Часовой пояс:** UTC
* **Числа:** до 2 символов после десятичного разделителя
* **Длина строки:** до 256 символов
* **Ограничение по количеству символов:**
  * **Для имен полей (заголовки столбцов):** без пробелов или специальных символов
  * **Все прочие данные:** без ограничений (все символы действительны)

</Accordion>

<Accordion title="Столбцы таблицы (актуально только для источников в хранилищах данных)">

В дополнение к данным, предоставляемым для обработки, таблицы источника в BigQuery или Snowflake должны содержать 2 дополнительных столбца: один для **даты** и один для **версии:**

* **Дата:**
  * **Заголовок столбца:** `dt`
  * **Тип столбца:** дата
  * **Формат даты:** гггг-мм-дд (*например,* `2023-04-18`)
  * **Дополнительно:** Таблицы BigQuery должны быть <Anchor target="_blank" href="https://cloud.google.com/bigquery/docs/partitioned-tables">разграничены</Anchor> по этому столбцу.
* **Версия:**
  * **Заголовок столбца:** `v`
  * **Тип столбца:** строка
  * **Формат данных:** число (например, `1`, `2`, `3`, `10`).
  * **Важно!** Новая версия отчета запускается каждый раз, когда DCR обнаруживает новое значение в этой колонке. Чтобы обеспечить полноту отчета, обязательно заполняйте таблицу источника полным набором данных при каждом изменении значения столбца.

</Accordion>

<Accordion title="Имя и формат файла (актуально только для источников в бакетах облачного хранилища)">

Исходные файлы, хранящиеся в Amazon S3 или GCS, должны соответствовать этим требованиям к именам и форматам файлов:

* Названия файлов должны соответствовать <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-set-up-your-cloud-services#dcr-naming-requirements">требованиям DCR к именам</Anchor>
* Формат CSV или GZIP.
  * Файл внутри архива GZIP должен иметь формат CSV.
* Количество файлов источника данных на <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-add-connections#snowflake-outbound">папку с данными</Anchor>:
  * **CSV:** не более 1
  * **GZIP:** не более 1 цельного файла. Поддерживаются составные файлы GZIP со следующими именами: `filename_part01.csv.gz`, `filename_part02.csv.gz` и т. д.

</Accordion>

## Создать источник

**Предварительное условие:** Перед созданием источника <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-set-up-your-cloud-services">настройте облачные сервисы</Anchor>, которые AppsFlyer DCP будет использовать для получения данных вашего источника. Если эти подключения не настроены, во время создания источника вам будет предложено это сделать.

**Чтобы создать источник в DCP, выполните следующие шаги:**

<Accordion title="Шаг 1: Откройте DCP Sources">

1. В AppsFlyer, из бокового меню, выберите **Сотрудничество** > **Data Clean Room**.

   <Image align="center" alt="Click Data Clean Room.png" src="https://files.readme.io/2dc54e035b17aafa17b7eb4c526643284aa7979919f8caa0add13b7e6ae19e0c-41945704690065.png" width="644px" />
2. Нажмите **+ Новый источник** (на главной странице или на вкладке **Источники**).

   <Image align="center" alt="sources empty state cropped.png" src="https://files.readme.io/629d8c7c68bfbce7c2307306128b0d0cc430886dc2a58200cb635bc0044d2bd7-33193030142609.png" width="482px" />
3. Следуйте пошаговым инструкциям **New source** :

</Accordion>

<Accordion title="Шаг 2: Задайте название источника">

Введите название источника. Это может быть любое уникальное название, которое поможет вам идентифицировать источник. Вы также можете добавить описание источника (необязательно), чтобы было проще понять, что в нем содержится (например, «Все покупки за 2025 год»).

<div id="requirements-and-guidelines" />

#### Требования и рекомендации

* Убедитесь, что **название источника** уникально среди всех остальных источников в вашем аккаунте. В противном случае вы не сможете сохранить источник.
* Оно не обязательно должно совпадать с именем файла.
* Требования к названию источника:
  * Длина: 2–80 символов.
  * Допустимые символы:
    * буквы `(A–Z, a–z)`
    * цифры `(0-9)`, *не могут быть первым символом имени;*
    * Подчёркивание `"_"`
  * Недопустимые символы:
    * пробелы
    * все остальные символы или специальные символы

</Accordion>

<Accordion title="Шаг 3: Задайте местоположение источника">

**Чтобы указать расположение источника:**

1. Выберите <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-set-up-your-cloud-services#overview">подключение</Anchor>, в котором будет создан (или уже создан) источник.
   * Если подключения в аккаунте не определены, откроется диалоговое окно **Новое подключение** с предложением создать подключение. Чтобы создать его, следуйте <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-add-connections">этим инструкциям</Anchor>.
   * Если у вас уже есть подключения, но вы хотите использовать новое, нажмите **+ New connection** и следуйте <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-connections">этим инструкциям</Anchor>, чтобы создать его.
2. Продолжайте выполнять соответствующие инструкции ниже в зависимости от того, где находятся данные для вашего источника.

**Примечание:** Для наилучшей производительности при большом объеме данных часть ваших данных может храниться отдельно. Эти данные будут обновляться при каждом обновлении источника и удаляться при удалении источника.

<div id="source-locations-in-bigquery" />

#### Расположение источника в BigQuery

**Чтобы завершить указание расположения источника для источника в BigQuery:**

1. Выберите набор данных, в котором находится таблица источника.
2. Выберите таблицу, в которой находятся исходные данные.

Списки, из которых вы делаете эти выборы, содержат доступные наборы данных и таблицы, соответственно, в проекте BigQuery, который вы указали при создании подключения.

<div id="source-locations-in-snowflake" />

#### Расположение источника в Snowflake

**Чтобы завершить указание расположения источника для источника в Snowflake:**

1. Выберите ресурс, содержащий исходные данные.
2. Выберите схему, в которой находится исходная таблица.
3. Выберите таблицу, в которой находятся исходные данные.

Списки, из которых вы делаете эти выборы, содержат общие ресурсы, схемы и таблицы, соответственно, в аккаунте Snowflake, который вы указали при создании подключения.

<div id="source-locations-in-cloud-storage-buckets" />

#### Расположение источника в облачных корзинах

Расположение источника в Amazon S3 или GCS состоит из облачного бакета, указанного в подключении, и пути к папке, из которой DCR считывает исходный файл при каждом его обновлении.

После указания подключения AppsFlyer может автоматически генерировать необходимый путь к базовой папке в рамках процесса создания источника.

* Позволив AppsFlyer генерировать папки, можно упростить процесс. Однако вместо этого вы можете создать их вручную, следуя инструкциям, <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-set-up-your-cloud-services">подробно описанным здесь</Anchor>.

Если AppsFlyer генерирует папки, единственная необходимая дополнительная информация — это имя, которое вы хотите дать **папке источника.** (Это папка верхнего уровня, в которой вы обновляете источник каждый раз, когда хотите использовать его для запуска новой версии отчета). Вы также можете указать, хотите ли вы, чтобы папка источника была создана под родительской папкой, часто называемой **input.**

**Чтобы завершить указание расположения источника в облачной корзине, введите имя папки источника.**

* По умолчанию отображенное имя папки источника:
  * Основано на [имени, которое вы присвоили источнику](#h_01K1ZHNZEQWRP7ZBK7XJP5F9HA). Вы можете изменить название папки в соответствии со своими потребностями при условии, что оно соответствует <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-set-up-your-cloud-services#dcr-naming-requirements">требованиям DCR к именованию</Anchor>.
  * Указывает, что оно будет сгенерировано в родительской папке под именем **input.** Эта папка служит родительской папкой для всех источников, загруженных в DCR.
    * Папка **входные данные** не является обязательной, и вы можете удалить ее или назвать иначе, при условии что она соответствует <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-set-up-your-cloud-services#dcr-naming-requirements">требованиям к именованию DCR</Anchor>.
    * Хотя эта папка и не является обязательной, наличие папки **input** (или аналогичной папки с другим именем) считается правильным вариантом. Такой подход является еще более предпочтительным, если вы используете одну и ту же корзину и для загрузки файлов с данными (input), и для получения отчета (output).

<div id="important" />

> 🚧 **Двоеточие (:)**
>
> Если вы создали путь к папке вручную, убедитесь, что подключение и путь, которые вы вводите в разделе **Расположение источника**, соответствуют созданному вручную пути.

#### Расположение источника: локальные файлы

Вы также можете загрузить исходные данные из локального файла. Однако **настоятельно рекомендуется указать облачный сервис в качестве расположения источника** (это критически важно для больших наборов данных и автоматических обновлений). Локальный файл в основном используется для тестирования и ознакомления с функциями платформы.

**Чтобы загрузить исходные данные из локального файла:**

При выборе расположения источника нажмите **Local file system**, а затем **Next** — появится возможность загружать локальные файлы с вашего устройства.

<div id="note" />

> 📘 **Примечание:**
>
> * Поддерживаемые типы файлов: файлы .CSV и .GZ (максимальный размер — 5 GB).
> * Данные, загруженные из локального файла, будут храниться 180 дней.
> * Обновления необходимо выполнять вручную.

</Accordion>

<Accordion title="Шаг 6. Настройте способ обновления источника">

При настройке источника в Data Collaboration Platform (DCP) необходимо выбрать, как будут обрабатываться обновления этого источника. DCP поддерживает два метода синхронизации: **Snapshot** и **Append**. Каждый метод подходит для разных сценариев использования и потоков данных:

* **Snapshot** — при каждом обновлении источника этот метод загружает полный набор данных и полностью заменяет старый набор новым. Выбирайте этот метод только в том случае, если ваши загружаемые файлы всегда содержат полный и актуальный набор данных.
* **Append** — этот метод загружает только новые или измененные данные, а не полный набор данных. Старые наборы данных не удаляются и не обновляются. Идеально подходит для периодических загрузок, таких как ежедневные или еженедельные отчеты. Преимущества включают меньший объем загрузок (что может снизить стоимость облачного хранилища), более высокую скорость загрузки данных, более удобное управление записями и многое другое.

<Image align="center" alt="Delta Generate folders.png" src="https://files.readme.io/105f55ff555565e97b82ecf86d58cfd2cf2a0340f83d6261fd3bd1c084b13889-38096875288977.png" width="637px" />

<div id="important-1" />

> 🚧 **Двоеточие (:)**
>
> Прежде чем выбирать, определите, какой метод подходит лучше всего. После выбора варианта и нажатия **Generate folders** в выбранном облачном сервисе создается путь к файлу вместе с инструкциями по обработке загрузок данных. Чтобы избежать дублирования папок и ошибок, **изменить метод синхронизации можно только один раз** после первоначального выбора.


<div id="snapshot-upload-requirements" />

#### Требования к загрузке снимков

Используйте этот метод, чтобы загружать полный самодостаточный файл, который при каждом обновлении источника полностью заменяет предыдущий набор данных.

<span id="h_01K2A7MAWT05K506384QHYA0FN"></span>**Поддерживаемые облачные сервисы**

* Amazon S3
* Google Cloud Storage
* BigQuery
* Snowflake

**<span id="h_01K2A7MAWTCYF3VAWJRRRJFNN5"></span>Следуйте этим рекомендациям для метода обновления снимка:**

1. **Путь к исходной папке**

   Когда вы регистрируете в DCP источник в облачном хранилище, для него задается корневой путь (например, `input/my_source_folder/`). При каждом обновлении набора данных вы загружаете в эту папку **полный снимок** — файл, содержащий все текущие строки. Это гарантирует, что DCP всегда обрабатывает самые актуальные и полные данные.
2. <span id="h_01K2A7MAWTPJ621MGBBG40N8H4"></span>**Загрузка файлов полного снимка**

| Рекомендация | Почему это важно | Как соблюдать |
| --- | --- | --- |
| **Полный набор данных** | DCP должен полностью заменять предыдущее состояние | Создайте экспорт, который включает все записи, а не только изменения |
| **Папка с разделением по дате (**`dt=`) | Позволяет фильтровать по диапазону дат & управлять удержанием данных | Размещайте каждый снимок в папке `dt=YYYY‑MM‑DD/` |
| **Подпапка версии (**`v=`) | Позволяет хранить несколько снимков в один день | Первую загрузку поместите в `v=1/`; для повторных попыток используйте `v=2/`, `v=3/` и т. д. |
| `data/` **подпапка** | Упорядочивает файлы | Храните в этой папке файлы Parquet / CSV / Avro |
| `_SUCCESS` **маркер** | Сигнализирует DCP о начале загрузки данных | После загрузки всех файлов данных загрузите пустой файл с именем `_SUCCESS` в папку `v=` |
| **Поддерживаемые тип и размер файла** |  | <ul><li>Поддерживаемые типы файлов: .csv или .gz</li><li>Максимальный размер файла: 5 ГБ</li></ul> |

<div id="important-2" />

> 🚧 **Двоеточие (:)**
>
> Файл полного снимка (BI-data.csv на снимке экрана ниже) должен быть размещен в следующей папке:
>
> ```
> /v=1/data/
> ```
>
> Затем, когда файл данных будет загружен, поместите пустой файл `_SUCCESS` в:
>
> ```
> /v=1/
> ```

**Структура папок:**

```
s3://af-dcr-xyz/abcd9876/input/source_name1/dt=2025-mm-dd/v=1/data/\n└ бакет ┘ └ tenant ┘ └ ingestion ┘ └ источник ┘└ дата снимка ┘└ ver ┘└ files ┘
```

| Ссылка | Описание | Цель |
| --- | --- | --- |
| `af-dcr-xyz` | Бакет S3 / GCS | Контейнер верхнего уровня для всех данных DCP |
| `abcd9876/` | ID тенанта / рабочего пространства | Изолирует данные каждого клиента |
| `вход/` | Зона загрузки данных | Место, куда попадают исходные загрузки перед обработкой |
| `source_name1/` | Название источника | Логический набор данных, зарегистрированный в DCP |
| `dt=2025-mm-dd/` | Дата снимка | Представляет полное состояние набора данных на этот день |
| `v=1/` | Версия (необязательно) | Поддерживает повторные попытки или дополнительные снимки |
| `вашего бизнеса/` | Файлы | Файлы снимков Parquet / CSV / Avro |

<span id="h_01K2A7MAWTYFHBANCV9F2NKNCV"></span>**Пример структуры снимков за два дня:**

```
source_name1/
  dt=2025-08-10/
    v=1/
      data/
        snapshot.parquet
      _SUCCESS
  dt=2025-08-11/
    v=1/
      data/
        snapshot.parquet
      _SUCCESS
```

#### Требования к загрузке методом append

Используйте этот метод, чтобы загружать только данные, которые изменились или были добавлены с момента предыдущей загрузки.

Зачем использовать Append?

* **Эффективность** – загрузки меньшего объема
* **Целостность данных** – сохраняет полную историю изменений для анализа временных рядов
* **Соблюдение правовых норм в области конфиденциальности** – упрощает удаление записей & управление согласиями

**Поддерживаемые облачные сервисы:** AWS S3 и Google Cloud Storage (GCS)  
**Примечание:** BigQuery и Snowflake не поддерживаются для метода Append и требуют использования метода Snapshot.

**Следуйте этим рекомендациям для метода обновления Append:**

<span id="h_01K2A7MAWT8E6AX95VG86APXBB"></span>1. **Настройка папки источника**

| Step | Описание |
| --- | --- |
| **Создать / назначить бакет** | Используйте существующий бакет S3 / GCS или позвольте AppsFlyer подготовить его для вас |
| **Указать корневой путь** | Путь в области тенанта (например, `s3://af‑dcr‑xyz/abcd1234/`) настраивается как входной каталог |
| **безопасность** | Предоставьте сервисному пользователю разрешение на запись только для этого пути |

<span id="h_01K2A7MAWT86J2S65D99BC66PQ"></span>2. **Загрузка файлов добавления (дельта-файлов)**

| Рекомендация | Почему это важно | Как соблюдать требования |
| --- | --- | --- |
| **Частота загрузки** | Сохраняет низкими стоимость передачи & операционные расходы | Загружайте файлы ежедневно или объединяйте папки за 7 дней и загружайте их еженедельно |
| **Одна папка в день** | Позволяет фильтровать по дате & избегать сканирования больших пакетов | Помещайте дельту за каждый день в `dt=YYYY‑MM‑DD/` |
| **Уникальные имена файлов** | Предотвращает случайную перезапись | Давайте файлам уникальные названия по следующему шаблону:`events_2025‑08‑04.parquet` `events_2025‑08‑05.parquet` |
| **Обязательные столбцы** | Позволяет отслеживать изменения | Файл должен включать:<ul><li>Столбец с датой, чтобы привязать записи к периоду отчетности.<ul><li>Столбец версии для отслеживания исправлений данных.</li></ul></li></ul>**Примечание:** Если в файлах отсутствуют эти столбцы, в DCP возникнет ошибка загрузки. |

<span id="h_01K2A7MAWTV3FY1GZSXQFNX4JS"></span>**Структура папок:**

```
s3://af-dcr-xyz/abcd1234/input/source_name/dt=2025-08-10/\n└ бакет ┘ └ тенант ┘ └ входные данные ┘ └ источник ┘ └ дневной раздел ┘
```

| Ссылка | Цель |
| --- | --- |
| `af-dcr-xyz` | S3/GCS бакет клиента |
| `abcd1234/` | Тенант или идентификатор рабочего пространства |
| `вход/` | Необработанные загрузки, ожидающие обработки |
| `источник_name/` | Логический источник DCP (например, CRM\_Events) |
| `dt=2025-08-10/` | Папка ежедневного раздела |

<span id="h_01K2A7MAWTRSYFTTDKG4G0TPZR"></span>**Пример структуры папок для еженедельной дельты:**

```
source_name/\n  dt=2025-08-04/\n  dt=2025-08-05/\n  dt=2025-08-06/\n  dt=2025-08-07/\n  dt=2025-08-08/\n  dt=2025-08-09/\n  dt=2025-08-10/
```

<span id="h_01K2A7MAWT5NDJQAYD16NRZSAQ"></span>**Краткая памятка:**

| Требования | Почему | Например |
| --- | --- | --- |
| **Еженедельный пакет (необязательно)** | Меньше push-отправок — та же детализация | Загрузите один пакет с семью соседними папками `dt=` |
| **Ежедневные разделы** | Ускоряет запросы & UI-фильтры | `s3://your‑bucket/source/ dt=2025‑08‑04/ ... dt=2025‑08‑10/` |

**Ключевые выводы:** Даже при еженедельной загрузке всегда организуйте данные по дневным папкам `dt=YYYY‑MM‑DD`.

</Accordion>

#### 1. Загрузите поля источника

Поля источника загружаются автоматически. Если требуется загрузка вручную, следуйте инструкциям ниже в зависимости от расположения источника:

**Источники в локальном хранилище данных**

Чтобы загрузить поля из источника, расположенного в хранилище данных (BigQuery или Snowflake), нажмите **Загрузить поля из источника**.

<div id="important-3" />

**Источники в облачных корзинах**

Чтобы загрузить поля из источника, расположенного в облачном хранилище (Amazon S3 или GCS), необходимо загрузить файл прототипа источника.

Для сопоставления полей источника с полями DCP:

* Можно загрузить макетную версию источника из локального файла.
  * Если вы выбираете эту опцию, AppsFlyer всегда автоматически использует путь папки источника.

                                                                ВСЕ ЗАГЛАВНЫЕ

* Вы можете загрузить прототипную версию файла источника напрямую из подключенного облачного бакета.
  * Важно!
    * Разрешите AppsFlyer автоматически создать облачную папку для файла источника или
    * [Создайте облачную папку для файла источника вручную](#h_01HPKB2ERVZ88MJ35JC66YDPAB)

**Чтобы загрузить макетный файл источника, следуйте инструкциям в соответствующей вкладке ниже:**

<Tab title="Локальный файл">

1. В разделе **Сопоставление полей источника** нажмите **Загрузить поля из источника**.

#### 2. Настройте поля источника

После загрузки полей источника каждому полю источника (столбцу) сопоставляется поле DCP. Проверьте каждое поле источника и сопоставьте его с соответствующим полем DCP из раскрывающегося списка рядом с ним. Обратите внимание на следующее:

<div id="note-1" />

> 📘 **Примечание:**
>
> * Когда обе стороны предоставляют свои данные источника, **как минимум одно поле должно быть задано как идентификатор**, чтобы можно было сопоставлять данные на уровне пользователя между соответствующими источниками. Идентификатор — это поле, которое однозначно идентифицирует пользователя приложения (например, CUID, идентификатор AppsFlyer или хешированный email).
> * Хотя настраивать каждое из загруженных полей источника (столбцов) необязательно, это важно для категоризации, эффективной интерпретации данных, помощи в создании аудиторий, формирования инсайтов и эффективного выполнения валидации.

<div id="ai-assisted-field-type-detection" />

#### Определение типа поля с помощью ИИ

DCP может с помощью ИИ предложить поле DCP для каждого столбца источника на основе имени столбца.

**Чтобы включить определение с помощью ИИ:**

1. В разделе **Сопоставление полей источника** найдите баннер: «Нужна помощь, чтобы быстро сопоставить поля? **Активировать ИИ-помощник DCP**.» Кликните **Активировать ИИ-помощник DCP**.
2. Когда поля загрузятся, нажмите **Автоматически определить типы полей**. DCP анализирует имя каждого столбца и предлагает для него поле DCP.
3. Перед сохранением проверьте каждую рекомендацию. Вы можете принять рекомендацию как есть или вручную изменить сопоставление, как при редактировании любого другого поля.

Каждое поле получает один из следующих статусов:

* **Сопоставлено:** AI нашел одно точное совпадение. Проверьте его и примите или измените вручную.
* **Не удалось сопоставить:** AI не смог определить поле. Сопоставьте его вручную или оставьте без сопоставления.

<div id="limitations" />

#### Характеристики и ограничения

* **Лимит столбцов:** обнаружение AI поддерживается для не более чем 100 столбцов на источник. Для источников с большим числом столбцов отображается сообщение «лимит превышен».
* **Длина имени поля:** для обнаружения AI не поддерживаются имена столбцов длиной более 100 символов.

#### **Идентификатор vs. список идентификаторов:**

Типы идентификаторов содержат одно значение в каждой строке (например, один адрес электронной почты или один CUID в строке). Типы «Список идентификаторов» содержат массив значений в каждой строке (например, одна строка может содержать несколько хешированных адресов электронной почты или идентификаторов устройств) — используйте этот тип, если источнику нужно сопоставлять более одного идентификатора на запись.

<div id="important-5" />

> 🚧 **Двоеточие (:)**
>
> Если источник включает любое поле, сопоставленное с **List of...** , тип (список идентификаторов, список чисел или список текста), файл источника необходимо загрузить или подключить в формате Parquet. Форматы CSV и GZ не поддерживают столбцы с типом массива, поэтому поля списка могут некорректно загружаться из этих форматов.

#### Перезагрузить поля источника

Если конфигурация одного из ваших файлов данных изменилась, вы можете обновить исходный файл, чтобы отразить эти изменения.

>
> Перезагрузка источника сбрасывает названия столбцов в источнике, чтобы они соответствовали обновлённым именам файлов. При этом будут перезаписаны все имена полей в списке и их тип.

**Чтобы перезагрузить обновленные поля из файла:**

2. Выберите соответствующие сведения о расположении.
3. [Необязательно] [Проверить источник](#4-тестирование-данных-источника).
4. Нажмите кнопку **Сохранить.**

<div id="edit-the-field-mapping" />

#### Изменение сопоставления полей

1. Перейдите к сопоставлению полей и внесите необходимые изменения: измените поле или обновите сопоставленное с ним поле DCP.
2. Нажмите **Save** (Сохранить).

<div id="important-6" />

> 🚧 **Двоеточие (:)**
>
> Не забудьте внести изменения, отражающие новую структуру источника, во все отчеты, в которых он используется:
>
> * Удаленные поля, поля с удаленным сопоставлением и поля, сопоставление которых было изменено, автоматически исключаются изо всех отчетов, в которых они используются.
> * Вновь добавленные или сопоставленные поля не включаются в существующие отчеты автоматически, пока вы не измените определения отчетов и не добавите их туда.

</Accordion>

<Accordion title="Удаление источника">

Вы можете удалить любой источник, если только он не используется в аудитории. В этом случае в уведомлении будут указаны аудитории, использующие этот источник. Чтобы удалить источник, сначала необходимо удалить связанную с ним аудиторию. Что касается источников, к которым вам предоставили доступ, их может удалить только владелец источника.

1. Перейдите на вкладку **Sources** (Источники) в **Data Clean Room.**
2. В списке источников наведите курсор на строку с источником, который вы хотите удалить.
3. Нажмите значок удаления ![delete_button.png](https://files.readme.io/10fbd4d4f09ddb56823a2824629f8bb9362b34c95038b3d9e747ffcde7b30381-24740010666129.png) справа от строки.
4. В диалоговом окне нажмите **Удалить** для подтверждения.

</Accordion>

## Информация

В этом разделе приведены дополнительные ссылки и полезная информация.

<Accordion title="Ручное создание структуры папок в бакете хранилища (необязательно)">

В целом, проще всего позволить AppsFlyer автоматически генерировать необходимую структуру папок в процессе создания источника. Однако если вы хотите создать эти папки вручную, вы можете сделать это следующим образом.

<div id="create-a-dcr-key-folder" />

#### Создайте папку для ключа DCR

Чтобы обеспечить максимальный уровень безопасности, имя папки, расположенной непосредственно в корзине («папка ключа DCR») должно содержать 8-значный буквенно-цифровой **ключ DCR**, присвоенный вашему аккаунту (например, `01bcc5fb`). *Обратите внимание, что он отличается от любого другого пароля или ключа, связанного с вашим аккаунтом AppsFlyer.*

Папка с ключом DCR обычно создается вручную через интерфейс выбранного вами облачного сервиса.

**Чтобы получить ключ DCR для своего аккаунта:**

* Нажмите меню с 3 точками (действия) в правом верхнем углу и выберите **DCR key**.

[<Image align="center" alt="DCR key.png" src="https://files.readme.io/b892831ad68cffb5b8084949d759f402780536c7176aa27733c867aff6560684-43750165616657.png" width="1141px" />](https://support.appsflyer.com/hc/article_attachments/49929194881425)

После создания папки с ключом DCR, структура корзины и папок будет выглядеть следующим образом:

<Image align="center" alt="dcr_file_structure_dcr_key_folder.png" src="https://files.readme.io/a57ba8076a2af5ef1f5a8339ac6b24e1ab6f8ff60956013a0a6547320a13072f-16571304308497.png" width="308px" />

<div id="top-level-input-folder" />

#### Папка верхнего уровня для входных данных

Хотя это не обязательно, рекомендуется создать папку верхнего уровня для входных данных непосредственно в папке с ключом DCR. Эта папка предназначена только для файлов, которые вы загружаете в DCR.

Папка верхнего уровня для входных данных обычно создается вручную через интерфейс выбранного вами облачного сервиса.

* Такой подход является еще более предпочтительным, если вы используете одну корзину и для загрузки файлов с данными (входные данные), и для получения отчета (вывод).
* Этой папке можно присвоить любое имя, соответствующее <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-set-up-your-cloud-services#dcr-naming-requirements">требованиям DCR к именам</Anchor>. Для удобства ее обычно называют `input/`.

После создания папки верхнего уровня для входных данных структура корзины и папок будет выглядеть следующим образом:

<Image align="center" alt="dcr_file_structure_input_folder.png" src="https://files.readme.io/cb7249ee0cbc0b4721c701f7d735c73eb7acc0a2a9e73de102b5a5ec9a6a79fd-16571312292753.png" width="308px" />

<div id="second-level-folder-for-each-data-source" />

#### Папка второго уровня по каждому источнику данных

Вы можете регулярно загружать для обработки в DCR файлы с данными из различных источников. Каждому из таких источников данных должна быть назначена отдельная папка («папки источников данных»).

Например, если вы планируете ежедневно загружать на обработку в DCR два файла: *BI-data.csv* и *CRM-data.gzip*, каждому из этих источников данных нужно выделить папку. Соответствующие папки можно назвать, например, `BI-data/` и `CRM-data/`.

Папки источников данных обычно создаются вручную через интерфейс выбранного вами облачного сервиса.

После создания папок для двух источников данных структура корзины и папок будет выглядеть следующим образом:

<Image align="center" alt="dcr_file_structure_source_folders.png" src="https://files.readme.io/f4624a213b79978d8ec080551649fae72d04d2f58a78344fc9df74a859881549-16571312297361.png" width="307px" />

В каждой папке источника данных [должны создаваться вложенные подпапки по дате и версии](#nested-subfolders-for-each-date-and-version) при каждом обновлении источника.

</Accordion>
