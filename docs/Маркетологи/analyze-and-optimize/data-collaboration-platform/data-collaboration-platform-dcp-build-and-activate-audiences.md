## Об аудиториях DCP

Процесс создания аудиторий из обширного набора данных включает в себя объединение наборов данных для генерации обогащённых данных, которые можно использовать для достижения именно тех потребителей, которых вы хотите достичь. В зависимости от необходимых разрешений, аудитория может основываться на объединённых наборах данных от обеих сторон или только от данных одной стороны. После создания аудитории вы можете отправить её своим медиапартнёрам для активации, либо в свой облачный сервис.

## Выстраивайте свою аудиторию

Для создания аудиторий вам доступны следующие инструменты:

* **Визуальный инструмент построения аудиторий:** визуальный инструмент построения аудиторий – это удобный инструмент, который позволяет пользователям без технических навыков создавать сегменты аудитории без навыков работы с SQL. Он позволяет выполнять развёрнутую сегментацию аудиторий в графическом интерфейсе.
* **SQL-мастер создания аудиторий:** SQL-запрос, позволяющий выполнять запросы данных без ограничений. Требуется знание SQL.

#### Сводка (панель предварительного просмотра справа)

Панель «Сводка» обновляется в реальном времени по мере того, как вы определяете свою аудиторию. На ней отображается **примерный диапазон уникальных пользователей**, которых можно активировать, на основе идентификаторов, доступных в выбранных источниках данных, и степени их пересечения.  
Поскольку активация аудитории зависит от того, какие идентификаторы медиапартнеры используют во время выполнения, размер аудитории отображается в виде диапазона, а не одного числа.

**Строки источника vs. уникальные пользователи**

Исходные данные могут содержать несколько строк для одного пользователя.  
Например, один и тот же человек может появляться несколько раз по следующим причинам:

* Несколько событий
* Множество устройств
* Несколько идентификаторов (например, CUID, email, телефон)

  Оценка размера аудитории в DCP всегда основана на количестве уникальных пользователей, а не на количестве необработанных строк.

**Идентификаторы и примерный диапазон пользователей**

Один источник может включать несколько идентификаторов для одного и того же пользователя (например, и CUID, и хешированный email), поскольку разные медиапартнеры поддерживают разные идентификаторы, а DCP не может предсказать, какой идентификатор будет использоваться во время активации.

DCP оценивает размер аудитории как диапазон от минимума до максимума:

* **Минимум:** предполагается максимально возможное пересечение идентификаторов
* **Максимум:** предполагается, что идентификаторы представляют разных пользователей

Фактическая активированная аудитория будет находиться где-то в пределах этого диапазона в зависимости от возможностей партнеров и сопоставления идентификаторов.

**Как понимать панель «Сводка»:**

**Всего пользователей**  
Показывает максимальное число уникальных пользователей, доступных во всех выбранных источниках до учета пересечений.

Если у вас нет разрешения на активацию аудитории, аудитория отправляется вашему соавтору для активации с его стороны.

**Оценочный пул данных**  
Показывает примерное число уникальных пользователей, общих для разных источников, и выражается как:

* Диапазон пользователей
* Процент вашего вклада в исходный источник

Этот пул определяет максимальную аудиторию, которую можно активировать совместно.

**Оценочный размер аудитории**  
Оценочный размер аудитории отражает ожидаемый диапазон уникальных пользователей, соответствующих определению вашей аудитории и доступных для активации. Диапазон:

* Учитывает дублирование идентификаторов
* Учитывает пересечение между источниками (если применимо)
* Динамически корректируется при изменении фильтров, источников или правил

#### Работа с источниками транзакционных данных

Источники транзакционных данных, такие как покупки, заказы или события, которые содержат несколько записей на пользователя, нельзя напрямую использовать в визуальном конструкторе аудиторий. Это связано с тем, что использование транзакционных данных без агрегации может привести к некорректному подсчету аудиторий, завышенному размеру аудиторий и неожиданным результатам сегментации.

Чтобы использовать транзакционные данные для создания аудиторий, сначала необходимо агрегировать их в набор данных на уровне пользователя с помощью инструмента Data View. **Чтобы агрегировать данные:**

1. Откройте инструмент <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-create-customized-data-views">**Обзор данных**</Anchor> и создайте Обзор данных на основе источника транзакционных данных.
2. Примените функции агрегации (например, Count, Sum или Average), чтобы получить одну строку на пользователя.
3. Свяжите агрегированный Data View с совместной работой.
4. Используйте агрегированный Обзор данных в качестве источника в конструкторе аудиторий.

<Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-create-customized-data-views#transactional-data-sources">Узнайте, как агрегировать транзакционные данные с помощью Data View</Anchor>

<div id="transactional-data-in-sql-queries" />

#### Транзакционные данные в SQL-запросах

При работе с источниками транзакционных данных в SQL-конструкторе применяются следующие шаблоны запросов.

**Поддерживаемые шаблоны запросов**

| Шаблон | Обзор |
| --- | --- |
| <span id="single-transactional-source-with-aggregation"></span>Один транзакционный источник с агрегацией | Запрос, который агрегирует транзакционный источник в одну строку для каждого пользователя. Например, агрегирование записей о покупках, чтобы получить общее количество покупок для каждого пользователя. |
| <span id="transactional-source-joined-to-a-profileuserlevel-source"></span>Транзакционный источник, объединенный с источником уровня профиля/пользователя | Допустимо, если транзакционная часть агрегируется до объединения. Например, агрегирование истории покупок по пользователю, а затем объединение результата с набором данных профиля клиента. |
| <span id="aggregated-transactional-output-in-downstream-joins"></span>Агрегированный результат транзакционных данных в последующих объединениях | После агрегации до уровня пользователя результаты можно использовать в дальнейших объединениях и рабочих процессах построения аудиторий; при этом они обрабатываются аналогично набору данных уровня профиля. |

**Неподдерживаемые шаблоны запросов**

| Шаблон | Описание |
| --- | --- |
| <span id="transactional-source-joined-directly-to-another-transactional-source"></span>Транзакционный источник, объединенный напрямую с другим транзакционным источником | Прямые объединения между двумя транзакционными наборами данных, например между покупками и заказами, не поддерживаются. Такие объединения блокируются до выполнения, потому что они могут умножать записи, приводить к некорректным результатам по аудиториям и вызывать транзакционное разрастание. |
| <span id="nonaggregated-transactional-query"></span>Неагрегированный транзакционный запрос | Запросы, которые используют транзакционные записи напрямую, без агрегации, не поддерживаются. |

## Отправить аудиторию для активации

После создания аудитории активируйте ее там, где она может приносить результат. Выберите назначение, например медиапартнеров для таргетинга кампании или бакет облачного хранилища для последующего использования, и DCP будет ежедневно обновлять и доставлять аудиторию на основе последних данных источника и <Anchor target="_blank" href="/marketers/ru/docs/data-collaboration-platform-dcp-create-and-manage-sources#разрешения-на-доступ">разрешений</Anchor>.

* [**Подключить аудиторию к медиапартнёрам**](#h_01J8HNKQ08EVKXA75C9MZB7AW9) – платформы медиапартнёров включают в себя Meta Ads, Google Реклама и многие другие. Подключите свою аудиторию к медиапартнёрам, когда хотите запустить платные кампании, ремаркетинг или расширение по похожим аудиториям.
* Подключите свою аудиторию к облачным сервисам, когда вам нужен файл в BI моделях, CDP или внутренних каналах обогащения.

<div id="note-6" />

> 📘 **О DCP**
>
> * Данные, отправляемые для активации, представляют собой список идентификаторов пользователей. Этот список постоянно обновляется и ежедневно отправляется в выбранные места назначения.
> * С каждым обновлением исходных данных аудитория автоматически перенаправляется в выбранные назначения.

У аудитории может быть один из статусов ниже:

* **Активно:** аудитория была успешно отправлена на целевую платформу(-ы) и доступна для использования в кампаниях.
* **Черновик:** аудитория была сохранена как черновик (она не была подключена, экспортирована или доставлена).
* **Недействительно**: указывает на то, что источник или представление данных, использованные для аудитории, больше недействительны, были удалены или исключены из сотрудничества.

* **Пауза**: Аудитория была поставлена на паузу вручную и не будет отправлена, когда новые данные станут доступны.
* **Приостановлено**: Совместная работа и связанные с ней аудитории были приостановлены.
