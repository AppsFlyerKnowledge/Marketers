> **Краткий обзор:**  Для начала работы с совместными измерениями, изучите его основные положения и процедуру настройки.

<div id="the-three-data-sources-of-measurement" />

## Три источника данных для измерений

Модель измерения DCP относит события конверсии к событиям вовлечённости, происходящим в контексте сотрудничества. Для этого процесса необходимы данные из трёх ключевых источников: конверсии, вовлечённость и синхронизация кампаний. Каждый источник играет важную роль в потоке атрибуции.

<div id="conversions" />

<Accordion title="Конверсии">

Данные о конверсии содержат подробную информацию о действиях пользователя, таких как покупки и связанные с ними товарные позиции (SKU) или товары широкого потребления. Каждый случай конверсии представляет собой одно событие конверсии, фиксирующее такую инфомацию, как SKU, идентификатор пользователя и время события.

**Пример параметров конверсии**

| **Поле** | **Значение** |
| --- | --- |
| `app_id (идентификатор приложения)` | FoodDelivery |
| `user_id` | 5abe2ddccca43000af58f0b |
| `время_события` | 2024-08-21T16:06:32.393Z |
| `имя_события` | покупка |
| `sku` | 8711327623057 |
| `sku_revenue` | 6.94 |
| `sku_quantity` | 1 |

AppsFlyer предоставляет доступ к конверсиям в приложении через интеграцию с вашим приложением с помощью SDK AppsFlyer или через пользовательские источники данных, предоставляемые партнёрами. События конверсии в вебе и в магазине также могут быть предоставлены с помощью пользовательских источников данных.

</Accordion>

<div id="engagements" />

<Accordion title="Типы взаимодействия">

Источник вовлечённости показывает данные о взаимодействии пользователей с рекламой, например клики и показы. Каждый случай представляет собой событие вовлечённости и включает такие атрибуты, как идентификатор кампании, медиа-источник и тип касания (например, клик или показ).

**Пример параметров вовлечённости**

| **Поле** | **Значение** |
| --- | --- |
| `appsflyer_id` | 1727548724223 |
| `медиа-источник` | google |
| `campaign (кампания)` | grc\_web\_ftu\_seq |
| `attributed_touch_time` | 2024-09-28T17:05:34 |
| `attributed_touch_type (атрибутированный тип взаимодействия)` | impression |
| `имя_события` | start\_game |

Чтобы получить доступ к данным о вовлечённости во [внутренних кампаниях](#onsite-and-offsite-campaign-measurement), вы можете создать новые внутренние события с данными об атрибуции в параметре `event_value` с помощью AppsFlyer SDK, либо передать данные через пользовательский источник.

Во [внешних кампаниях](#onsite-and-offsite-campaign-measurement) данные о вовлечёности поступают со стороны, а не через события в приложении или пользовательский источник.

</Accordion>

<div id="campaign-mapping" />

<Accordion title="Синхронизация кампаний">

Источник сопоставления кампаний позволяет определить вовлеченность, которая привела к каждой конверсии. Запись сопоставления кампаний связывает события конверсии с событиями вовлеченности, сопоставляя SKU или CPG с идентификаторами кампаний. Поток атрибуции в DCP связывает события конверсии с событиями вовлечения, сопоставляя SKU из конверсий с вовлечением в рекламу этих SKU.

**Пример параметров сопоставления кампаний**

| **Поле** | **Значение** |
| --- | --- |
| `collaborator_name` | fashion\_site |
| `collaborator_id` | 10079 |
| `campaign_id (идентификатор кампании)` | 49fd77a2-8b64-4c9d... |
| `campaign_name` | off\_season\_25\_1 |
| `conversion_targets` | 8711327621978, 8711327622289, 8711327623057 |

Информация о сопоставлении кампаний передаётся AppsFlyer как пользовательский источник данных.

</Accordion>

<div id="on-site-vs-off-site-campaigns" />

## Кампании on-site и off-site

DCP измеряет кампании по-разному в зависимости от того, где они запускаются: на собственном сайте партнера (on-site) или на платформе медиапартнера (off-site). Эти различия влияют на то, как охватываются аудитории, как собираются данные и как выполняется атрибуция.

<div id="offsite-campaigns" />

<Accordion title="Кампании off-site">

Кампании off-site предполагают вовлеченность пользователей на сторонних платформах (например, Meta или Google), при этом конверсии происходят в собственных ресурсах партнера и атрибутируются этим off-site-вовлечениям.

* **Пример:** бренд запускает рекламу в Facebook с таргетингом на сегментированные данные о клиентах CMN. Когда пользователи видят рекламу в Facebook и нажимают на нее, они переходят на страницу товара CMN.
* **Атрибуция:** DCP передает события конверсии третьей стороне, которая выполняет собственную атрибуцию; затем DCP получает агрегированные результаты через API отчетности этой третьей стороны.

</Accordion>

<div id="onsite-campaigns" />

<Accordion title="Кампании on-site">

Кампании on-site предполагают вовлеченность пользователей и конверсии, которые происходят в собственных ресурсах партнера (например, в его приложении или на сайте), при этом конверсии атрибутируются on-site-вовлеченности.

* **Пример:** бренд продвигает продукт на сайте Commerce Media Network. Аудитория включает прошлых покупателей платформы CMN, сегментированных по таким параметрам, как интерес к категории или история покупок. Когда пользователи видят баннер кампании и кликают по нему, они переходят на страницу сведений о продукте на том же сайте.
* **Атрибуция:** DCP напрямую атрибутирует конверсии кампаниям on-site, используя данные о вовлеченности первой стороны с сайта или из приложения соавтора.

<div id="combined-onsite-and-offsite-campaigns" />

<Accordion title="Комбинированные кампании on-site и off-site">

Комбинированные кампании предполагают вовлеченность пользователей как on-site, так и off-site, при этом конверсии происходят в собственных ресурсах партнера и атрибутируются вовлеченности из любого источника с использованием унифицированного измерения и дедупликации.

* **Пример:** бренд продвигает продукт на сайте CMN, а также запускает рекламу в Facebook с таргетингом на клиентов CMN. Вовлеченность и конверсии как из кампании on-site, так и из кампании Facebook фиксируются, дедуплицируются и измеряются вместе.
* **Атрибуция:** DCP объединяет данные конверсии из каналов on-site и off-site в общую таблицу атрибуции, применяя логику дедупликации, и представляет единые метрики по каждой кампании и SKU.

</Accordion>

</Accordion>

<div id="the-dcp-measurement-process" />

## Процесс измерения в DCP

Процесс измерения DCP определяет, как записи о конверсиях из in-app событий SDK и пользовательских файлов источников проверяются, нормализуются и сопоставляются с вовлеченностью в рамках [кампаний on-site и off-site](https://www.notion.so/Collaboration-measurement-Overview-255b7b13af5f80fa83d2dc77e337c960?pvs=21).

<div id="onsite-measurement-flow" />

<Accordion title="Процесс измерения on-site">

В процессе измерения кампаний на сайте DCP обрабатываются события в приложении и записи из пользовательских источников, собранные из мобильного приложения или с сайта CMN либо рекламодателя. DCP атрибутирует эти конверсии внутри системы с помощью логики атрибуции AppsFlyer.

Поток on-site измерения обрабатывает данные о конверсиях и вовлеченности, поступающие из двух основных источников:

* **События в приложении (IAE)** собираются через SDK AppsFlyer, встроенный в мобильное приложение соавтора.
* **Пользовательские файлы событий источника** отправляются соавторами в AppsFlyer.

Оба типа событий нормализуются в единую структуру и обрабатываются одним и тем же механизмом атрибуции.

<div id="1-configure-measurement-sources" />

### 1. Настройка источников измерения

Выбор варианта организации совместной работы, подходящего для вашей организации.

* **События в приложении:** Соавторы определяют, какие события в приложении (например, purchase, signup) следует измерять как конверсии или вовлеченность. Эти события уже должны собираться через SDK AppsFlyer, а названия приложения и события должны быть явно выбраны в конфигурации DCP.
* **Пользовательские файлы событий из источников:** Соавторы настраивают доступ к внешним файлам данных (например, из BigQuery, S3 или Snowflake) и сопоставляют ключевые поля, такие как user\_id, campaign\_id и SKU, со схемой DCP для поддержки атрибуции.

<div id="2-prepare-and-map-conversion-data" />

### 2. Подготовка и сопоставление данных конверсии

DCP соединяет каждое событие конверсии, которое было сопоставлено с кампанией, с событием вовлечения с тем же идентификатором пользователя и идентификатором кампании, создавая атрибутированную запись конверсии, содержащую данные о кампании и конверсии.

* Источник синхронизации кампаний связывает конверсии с вовлечениями через сопоставление SKU из события конверсии с идентификатором кампании из события вовлечения.
* Конверсии, которые не удается сопоставить ни с одной кампанией, помечаются как **органические**.

<div id="3-link-conversions-to-engagements" />

### 3. Связать конверсии с вовлеченностью

DCP связывает сопоставленные конверсии с вовлеченностью по следующим критериям:

* Общий **идентификатор ID пользователя**
* Один и тот же **идентификатор ID кампании**

В результате формируются атрибутированные записи о конверсиях, дополненные метаданными кампании и вовлеченности.

<div id="4-split-multi-sku-conversions" />

### 4. Разделение конверсий с несколькими SKU

Если событие конверсии включает несколько SKU:

* DCP разделяет запись на несколько записей с **одним SKU**.
* Каждая запись отражает атрибуцию для одной **цели конверсии**.

<div id="5-filter-non-target-skus" />

### 5. Отфильтруйте SKU, не относящиеся к таргетингу

Чтобы сохранить только релевантные конверсии:

* DCP отфильтровывает записи для SKU, которые не являются целями по конверсии для кампании.

<div id="6-deduplicate-conversion-events" />

### 6. Удалите дубликаты событий конверсии

Перед атрибуцией DCP удаляет дубликаты:

* Дубликаты записей из одного и того же пользовательского источника (например, при повторной загрузке) отбрасываются.
* Если существует совпадающее событие в приложении (IAE), оно заменяет запись из пользовательского источника.

<div id="7-apply-attribution-logic" />

### 7. Примените логику атрибуции

DCP применяет модель атрибуции AppsFlyer по последнему взаимодействию в соответствии со следующими правилами:

* **Несколько взаимодействий на одну конверсию**: выбирается **последнее взаимодействие** на основе шкалы приоритетов AppsFlyer.
* **Одно взаимодействие связано с несколькими конверсиями**: только **первая** конверсия атрибутируется этому взаимодействию; остальные конверсии остаются без атрибуции.

> Дополнительные сведения см. в разделе Приоритеты метода атрибуции (Водопад атрибуции).

<div id="8-output-attributed-conversion-dataset" />

### 8. Результат: набор данных атрибутированных конверсий

Итоговый результат включает:

* Атрибуция одного взаимодействия с кампанией на конверсию
* Очищенные и проверенные записи конверсий на уровне SKU
* DCP агрегирует атрибутированные конверсии, включая общие конверсии, для проведения анализа.
* Записи конверсий, готовые для аналитических дэшбордов и экспорта

</Accordion>

<div id="offsite-measurement-flow" />

<Accordion title="Процесс внешнего измерения">

**События внешней конверсии** предоставляются участниками через **файлы пользовательских источников** и должны включать необходимые для атрибуции идентификаторы, такие как идентификатор клика Google (`gclid`) или идентификатор клика Facebook (`fbclid`). Эти события передаются на внешние платформы, такие как Google и Meta, которые сопоставляют данные со своими записями кампаний и возвращают **обогащенные метаданные**, включая идентификаторы кампании, группы объявлений и креатива.

<div id="1-prepare-conversion-data" />

### 1. Подготовьте данные конверсии

Записи конверсий стандартизируются на основе настроек сотрудничества:

* Участники сопоставляют пользовательские поля с унифицированной схемой конверсий DCP.
* Для Google Ads и Meta Ads требуются определенные поля; правила валидации проверяют, что сопоставления соответствуют стандартам каждого партнера, прежде чем процесс продолжится.

<div id="2-deduplicate-conversion-events" />

### 2. Удалите дубликаты событий конверсии

Перед атрибуцией DCP удаляет дублирующиеся записи из одного и того же пользовательского источника (например, записи, повторно загруженные в систему).

<div id="3-filter-for-sharing-eligibility" />

### 3. Фильтр по критериям возможности передачи

DCP проверяет, соответствуют ли офлайн-конверсии критериям для передачи:

* Присутствует действительный идентификатор канала (например, GCLID, FBCLID).
* Конверсия соответствует определенному действию кампании или SKU.
* Конверсия попадает в окно атрибуции:
  * Meta: 1, 7 или 28 дней как для клика, так и для просмотра.
  * Google: определяется в платформе; переопределение через API не поддерживается.

Конверсии, не соответствующие любому из критериев, исключаются из передачи партнёрам.

<div id="4-filter-according-to-last-touch-attribution" />

### 4. Фильтрация по атрибуции последнего касания

Атрибуция назначается на основе самой недавней точки взаимодействия:

* Если действительный идентификатор ID клика Google или Meta является более недавним, атрибуция присваивается этому партнёру и передаётся только ему.
* Если у конверсии есть оба идентификатора ID клика, приоритет получает самый недавний.

<div id="5-share-with-google-and-meta" />

### 5. Передача в Google и Meta

Подходящие конверсии безопасно передаются через API партнеров:

* **Meta:** Conversions API (CAPI)
* **Google:** Offline Conversion API (OCI)

Каждая конверсия отправляется только одному партнеру. Соавторы должны настроить аккаунт назначения (идентификатор ID набора данных Meta или идентификатор ID действия конверсии Google).

<div id="6-google-and-meta-response-enrichment" />

### 6. Обогащение ответов Google и Meta

Google и Meta возвращают обогащённые данные атрибуции через свои API инсайтов, включая:

* Строка
* ID набора рекламных объявлений
* Идентификатор
* Идентификатор креатива

AppsFlyer выполняет атрибуцию на основе обогащенных записей.

<div id="7-output-attributed-conversion-dataset" />

### 7. Результат: набор данных с атрибутированными конверсиями

Итоговый результат включает:

* Очищенные и проверенные записи конверсий на уровне SKU
* DCP разделяет записи конверсии с атрибуцией, содержащие несколько SKU, на отдельные записи, каждая из которых содержит один SKU.
* Записи о конверсиях готовы для аналитических дэшбордов и экспорта

</Accordion>

<div id="combined-onsite-and-offsite-measurement-flow" />

<Accordion title="Комбинированный процесс измерений on-site и off-site">

В этом потоке показано, как Data Collaboration Platform (DCP) AppsFlyer обрабатывает данные конверсии из нескольких источников, включая:

* **On-site конверсии**, которые включают события в приложении и пользовательские записи источников, собранные из CMN или из мобильного приложения либо с веб-сайта рекламодателя. DCP атрибутирует эти конверсии внутри платформы, используя логику атрибуции AppsFlyer.
* **Off-site конверсии**, где данные конверсии поступают из пользовательского источника и передаются внешним платформам, таким как Google и Meta. Эти платформы сопоставляют данные со своими записями кампаний и возвращают расширенные метаданные, включая идентификаторы кампании, группы объявлений и креатива.

Поток off-site и on-site атрибуции DCP удаляет дубликаты, атрибутирует, обогащает и объединяет все данные конверсии, чтобы сформировать единый набор данных об эффективности.

<div id="1-on-site-and-off-site-record-processing-is-performed" />

### 1. Выполняется обработка записей on-site и off-site

Записи о конверсиях стандартизируются на основе настроек совместной работы:

* On-site обработка до шага 6 включительно в on-site атрибуции.
* Off-site обработка до шага 4 включительно в off-site атрибуции.

<div id="2-apply-last-touch-attribution" />

### 2. Применение атрибуции по последнему касанию

Атрибуция назначается на основе самой недавней точки взаимодействия:

* Если событие CMN (on-site) произошло последним, конверсия атрибутируется CMN и не передается в Meta или Google.
* Если действительный идентификатор клика Google или Meta новее, атрибуция назначается этому партнеру и передается только ему.
* Если у конверсии есть оба идентификатора клика, выигрывает самый недавний.

<div id="3-share-with-google-and-meta" />

### 3. Передача в Google и Meta

Подходящие конверсии безопасно передаются через API партнеров:

* **Meta:** Conversions API (CAPI)
* **Google:** Offline Conversion API (OCI)

Каждая конверсия отправляется только одному партнеру. Рекламодатели должны настроить учетную запись назначения (идентификатор ID набора данных Meta или идентификатор ID действия-конверсии Google).

<div id="4-off-site-response-enrichment" />

### 4. Обогащение off-site ответов

Google и Meta возвращают обогащенные данные атрибуции через свои API Insights, включая:

* Строка
* ID набора рекламы
* Идентификатор
* Идентификатор креатива

<div id="5-on-site-and-off-site-conversion-merge" />

### 5. Объединение внутренних и внешних конверсий

DCP объединяет эти внешние конверсии с внутренними конверсиями в итоговый набор данных, где каждая конверсия:

* Атрибутируется одному источнику: Google, Meta или CMN
* Обогащена метаданными кампании
* Готова для дэшбордов, экспорта и аналитики эффективности
