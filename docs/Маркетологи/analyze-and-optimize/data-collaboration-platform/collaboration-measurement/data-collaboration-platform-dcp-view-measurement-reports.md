> **Кратко:** настройте отчеты по измерениям, задав поля отчета, уровни агрегации, расписания и подключения к облачным сервисам.

Отчеты по измерениям в Data Collaboration Platform (DCP) содержат метрики верхнего уровня, такие как клики, показы и ROAS по кампаниям. Они также могут включать дополнительные метрики и параметры в зависимости от предоставленного доступа.

Отчеты отправляются напрямую в подключенное облачное хранилище или хранилище данных. Вы можете получать отчеты в предустановленном формате или настраивать их, добавляя необходимые метрики и параметры.

<div id="what-are-dimensions-and-metrics" />

<Accordion title="Что такое параметры и метрики?">

Отчет по измерениям для совместной работы — это агрегированный отчет, в котором данные обобщаются путем группировки и объединения отдельных записей. Он дает инсайты высокого уровня, а не сырые данные на уровне пользователя.

Поля отчета делятся на два типа: *параметры* и *метрики*. Каждый из них можно дополнительно разделить на *базовые поля* и *вычисляемые поля*.

<div id="dimensions" />

### Аспекты

Параметр — это категория группировки, которая агрегирует данные на уровне событий в записи отчета. Например, если в качестве параметра отчета выбран медиаисточник, каждая строка будет содержать агрегированные данные по всем событиям, атрибутированным этому медиаисточнику. Количество строк равно количеству медиаисточников.

Добавление дополнительных параметров повышает детализацию группировки. Например, при выборе полей «Дата события», «Медиаисточник» и «Кампания» формируется одна строка для каждой уникальной комбинации этих полей.

<div id="metrics" />

### метрика

Метрика — это числовые данные, сгруппированные на основе выбранных параметров.

Например, если в качестве метрики выбран доход, а единственным параметром является медиаисточник, отчет показывает общий доход по каждому медиаисточнику.

Если выбрано несколько параметров, например «Дата события», «Медиаисточник» и «Кампания», доход группируется по комбинации этих полей.

При выборе метрики выберите для нее функцию агрегации. Например, для метрики дохода следует выбрать функцию **SUM**.

<div id="what-are-basic-and-calculated-fields" />

### Что такое базовые и вычисляемые поля?

Параметры и метрики могут быть как базовыми, так и вычисляемыми полями.

* **Базовые поля:** базовые поля содержат сырые данные из источников или событий в приложении.
* **Вычисляемые поля:** вычисляемые поля используют базовые поля для расчета значений с помощью заданных функций.

</Accordion>

## Создать предопределенный отчёт

Чтобы сгенерировать предопределенный отчёт, выполните следующие действия:

1. В AppsFlyer в боковом меню выберите **Сотрудничество** > **Data Clean Room**.
2. На странице **Платформа для совместной работы с данными** выберите соответствующую коллаборацию.
3. На странице совместной работы нажмите **Создать отчёт.**
4. В появившемся диалоговом окне нажмите **Подтвердить отчет.** Отчёт отправляется в подключенный облачный сервис с предопределенным именем и по расписанию.

4. В появившемся диалоговом окне нажмите <Image alt="" src="https://files.readme.io/317ded6d0dbe6b0acfee8d3b8c7898dbab1c9b7ae621802fa867f2a6069f5d79-34061156893457.png" width="2.92%" /> **Customize**.
5. На странице **Новый отчёт** выполните перечисленные шаги.

</Accordion>

<div id="2-set-the-report-type" />

<Accordion title="2. Задайте тип отчёта">

На шаге **Тип отчёта** выберите <Image alt="" src="https://files.readme.io/c94890451d831a5a3f1f12b6f42c1c86de1453c175c40cc450e915f6f1f128ad-34061156898449.png" width="3.47%" /> **Commerce media measurement,** затем нажмите **Далее.**

<div id="3-set-the-report-scope" />

<Accordion title="3. Задайте область отчёта">

На шаге **Фильтры и источники данных**:

1. В поле **Имя отчёта** введите имя для отчёта.
   * Это может быть любое имя, которое позволит вам идентифицировать этот отчет на платформе DCR.
   * **Важно!** Убедитесь, что имя отчёта отличается от имен всех других отчётов в вашем аккаунте, иначе вы не сможете <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-creating-attribution-data-reports#set-the-report-destination-and-save-the-report">сохранить отчёт</Anchor>.
   * Требования к имени отчета:
     * Длина: 2–80 символов.
     * Допустимые символы:
       * буквы **(A-Z, a-z)**
       * цифры **(0-9)**, *имя не может начинаться с цифры*
       * дефис (-), *не может быть первым символом в имени*
     * Недопустимые символы:
       * пробелы
       * все остальные символы или специальные символы
2. В поле **Имя совместной работы** выберите соответствующую коллаборацию.
3. В ползунке **Временной интервал** задайте период отчета в днях (1-180). В отчете будут отображаться только атрибутированные события конверсии, произошедшие в пределах выбранного периода. Период отсчитывается назад от дня, за который сформирован отчет.
4. Создайте информативное название для эксперимента, затем нажмите **Далее**.

</Accordion>

<div id="4-set-the-report-dimensions-and-metrics" />

<Accordion title="4. Настройте параметры и метрики отчета">

Если вы хотите настроить отчет, можно выбрать его [параметры и метрики](#what-are-dimensions-and-metrics). Полный список полей отчета см. в [схеме отчета](#схема-отчета) в этой статье.

Чтобы настроить параметры и метрики отчета, выполните следующие действия:

1. На шаге **Structure** в списке **Dimension from sources** выберите поля, которые нужно включить в отчет.
2. Если вы хотите создать [вычисляемое поле](#что-такое-базовые-и-вычисляемые-поля), нажмите **+ Calculated field** и см. раздел [Create calculated field](#создание-вычисляемого-поля) в этой статье.
3. Поле можно включить в отчет как параметр или как метрику.
   * Чтобы включить поле в отчет как параметр, нажмите **Set as dimension**.
   * Чтобы включить поле в отчет как метрику, нажмите **Set as metric**.
4. Если вы задаете поле как метрику, выберите для него функцию агрегации:
   * **Sum:** Значение метрики — это сумма значений на уровне события, агрегированных в записи отчета. Например, метрика дохода — это сумма  `sku_revenue` по всем событиям, сгруппированным в записи.
   * **Count:** Значение метрики — это количество значений на уровне события, агрегированных в записи отчета. Например, метрика конверсий — это количество всех конверсий, включенных в сгруппированную запись.
   * **Count distinct**: Значение метрики — это число уникальных значений для заданного поля среди событий, сгруппированных в записи отчета. Например, если выбранная метрика — это count-distinct для `sku` и сгруппированная запись включает 10 событий с 4 разными SKU, значение метрики будет равно **4**.
5. Чтобы изменить отображаемое имя поля, наведите указатель на поле и нажмите **Edit display name.**

<div id="create-calculated-field" />

#### Создание вычисляемого поля

Вычисляемые поля содержат значения, рассчитанные из базовых значений с помощью указанной функции.

Чтобы создать или отредактировать вычисляемое поле, выполните следующее:

1. Чтобы создать или отредактировать вычисляемое поле, выполните одно из следующих действий
   * **Create**: Нажмите **+ Calculated field.**
   * **Edit**: Наведите указатель на вычисляемое поле и нажмите меню действий → Edit calculated field.
2. В диалоговом окне **Edit** или **New calculated field** выполните следующее:
   1. <span class="af-ol-a"></span>В поле **Field** введите имя поля.
   2. В списке **Set function** выберите функцию, которая используется для вычисления нового значения.
3. Задайте функцию в соответствии с таблицей ниже: 

| **Функция** | **Description(Описание)** | **Пример расчета** | **Описание примера** |
| --- | --- | --- | --- |
| `ДОБАВИТЬ` | Сумма двух чисел | `Клики + показы` | Общее количество взаимодействий (клики + показы рекламы). |
| `ARRAY SIZE` | Преобразование массива строк JSON в его размер | `ARRAY_SIZE(Products_Clicked)` | Количество продуктов, по которым пользователь кликнул в кампании (из JSON). |
| `CASE WHEN` | Возвращает значение, если выполнено первое условие, или ELSE | `CASE WHEN Conversions > 0 THEN 'Successful' ELSE 'Failed' END` | Классифицирует эффективность кампании на основе конверсий. |
| `CONCAT` | Объединение двух строк | `CONCAT(Campaign_Name, ' - ', Region)` | Объединяет название кампании с регионом для отчетности. |
| `CONST` | Возвращает свой параметр | `CONST('Marketing Budget Cap: $5000')` | Возвращает постоянное значение для справки по бюджету. |
| `DATETIME DIFF` | Период в выбранных единицах между `start` и `end` | `DATETIME_DIFF(End_Date, Start_Date, 'day')` | Вычисляет длительность кампании в днях. |
| `MAX` | Максимальное из двух чисел | `MAX(Click_Through_Rate, Conversion_Rate)` | Находит большее значение между CTR и коэффициентом конверсии. |
| `MIN` | Минимальное из двух чисел | `MIN(Budget_Remaining, Daily_Spend_Limit)` | Гарантирует, что расходы не превысят дневной бюджет. |
| `MULTIPLY` | Умножение двух чисел | `Conversions * Avg_Order_Value` | Вычисляет общий доход от конверсий. |
| `REGEX EXTRACT` | Извлекает первую группу с помощью regex | `REGEX_EXTRACT(Ad_Text, 'PromoCode: (\\w+)')` | Извлекает промокод из текста рекламного объявления с помощью регулярного выражения. |
| `SUBSTRING` | Подстрока строки с индекса `start` до `end` | `SUBSTRING(Campaign_ID, 0, 5)` | Извлекает первые 5 символов идентификатора кампании. |
| `SUBTRACT` | Вычитание двух чисел | `Budget_Allocated - Budget_Spent` | Вычисляет оставшийся бюджет кампании. |


</Accordion>

<div id="5-manage-dimension-priority" />

<Accordion title="5. Управление приоритетом размерностей">

Группы измерений с очень небольшим количеством событий на уровне пользователя могут противоречить требованиям конфиденциальности данных.

Чтобы решить эту проблему, **DCR объединяет небольшие группы** с более крупными, исключая измерения с наивысшей специфичностью.

По умолчанию измерения удаляются в порядке, обратном их положению в списке **Report dimensions**. Однако вы можете изменить порядок по умолчанию и задать другой приоритет группировки, чтобы сохранить наиболее важные для вас параметры. Чтобы узнать больше, посмотрите <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-creating-attribution-data-reports#сохранение-конфиденциальности-при-группировке-по-параметрам-перегруппировка">пример перегруппировки</Anchor>.

**Чтобы изменить приоритет измерений:**

1. На шаге **Manage dimension priority** нажмите **Manage dimension priority**
2. Перетащите измерение, чтобы изменить порядок.
   * Измерение, помеченное как **Highest priority** (в верхней части списка), будет исключено последним, если потребуется перегруппировка.
3. [Необязательно] Чтобы применить перегруппировку к параметрам из пользовательского источника:
   1. <span class="af-ol-a"></span>Нажмите **Использовать расширенные настройки для уточнения группировки**.
   2. Выберите параметры из пользовательского источника, к которым вы хотите применить перегруппировку.
   3. Выбранные измерения добавляются в **Manage dimension priority** список.
      * По умолчанию эти измерения добавляются в конец списка как **Lowest priority** для перегруппировки. Однако вы можете изменить их порядок так же, как и у измерений данных атрибуции, как описано выше.
4. Нажмите **Далее** , чтобы сохранить изменения.
   * Список **Report dimensions** на главном экране остается в исходном порядке, но измененный порядок сохранен. (Нажмите еще раз на кнопку **Управление приоритетом параметров** , чтобы просмотреть или изменить свой выбор.)

</Accordion>

<div id="6-set-the-report-schedule-and-destination" />

<Accordion title="6. Настройте расписание отчета и место назначения">

DCP передает отчеты в выбранные вами облачные сервисы с помощью <Anchor target="_blank" href="/marketers/ru/docs/data-locker-for-marketers">AppsFlyer Data Locker</Anchor>. Таким образом, указание места назначения отчета подразумевает выбор или создание соединения с Data Locker.

**Чтобы настроить расписание и место назначения для отчёта:**

1. На этапе **Settings** в разделе **Schedule** выберите расписание отчёта (ежедневно, еженедельно или ежемесячно).
2. В зависимости от выбранного интервала выберите час, день недели или месяц для отчёта.
3. В разделе **Destination** выберите из списка подключений Data Locker, доступных в вашем аккаунте AppsFlyer.
   * Если в вашем аккаунте не определены подключения:
     * В вашем браузере откроется новая вкладка (со страницей AppsFlyer Data Locker)
     * Откроется диалоговое окно **Новое подключение** . Следуйте <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-connections#завершить-подключение">этим инструкциям</Anchor> для создания подключения.
   * Если у вас уже есть подключения, но вы хотите использовать новое, нажмите **+ Новое подключение в Data Locker**:
     * В вашем браузере откроется новая вкладка (со страницей AppsFlyer Data Locker)
     * Откроется диалоговое окно **Новое подключение** . Следуйте <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-connections#завершить-подключение">этим инструкциям</Anchor> для создания подключения.
     * После создания подключения вернитесь на вкладку DCP в браузере и выберите новое подключение из списка подключений Data Locker.
4. Чтобы получать уведомления о статусе отчета через API, включите **Уведомления о статусе отчета**, а затем в поле конечная точка API введите URL-адрес API.
5. Нажмите **Сохранить** , чтобы сохранить отчет.
6. Новый отчет теперь отображается на вкладке **Отчеты** .

</Accordion>

## Схема отчета

Отчет включает следующие измерения и метрики, сгруппированные в вычисляемые поля и поля атрибуции:

<div id="calculated-fields" />

<Accordion title="Вычисляемые поля">

| **Поле** | **Description(Описание)** |
| --- | --- |
| `clicks (клики)` | Общее количество кликов по рекламному объявлению. |
| `CTR` | Показатель кликабельности (клики, разделённые на показы). |
| `event_date (дата события)` | Дата, когда произошло событие. |
| `impressions (показы)` | Количество показов рекламного объявления. |
| `total_revenue` | Общий доход, полученный по всем событиям. |
|  |  |

</Accordion>

<div id="attribution-fields" />

<Accordion title="Поля атрибуции">

| **Поле** | **Description(Описание)** |
| --- | --- |
| `ad_id (идентификатор объявления)` | Уникальный идентификатор для рекламного объявления. |
| `ad_name` | Название рекламного объявления. |
| `тип_рекламы` | Тип рекламного объявления (например, баннер, видео). |
| `adset_id (идентификатор группы объявлений)` | Уникальный идентификатор набора рекламы. |
| `adset_name` | Название набора объявлений. |
| `рекламный_идентификатор` | Идентификатор устройства с возможностью сброса пользователем (например, GAID). |
| `android_id` | Постоянный ID устройства Android. |
| `app_id (идентификатор приложения)` | Уникальный идентификатор приложения. |
| `имя_приложения` | Имя приложения. |
| `версия_приложения` | Версия приложения. |
| `appsflyer_id` | Уникальный идентификатор, назначенный AppsFlyer. |
| `campaign_id (идентификатор кампании)` | Уникальный идентификатор кампании. |
| `campaign_name` | Название кампании. |
| `Дата, когда было обнаружено мошенничество с атрибуцией.` | Канал медиаисточника (например, YouTube). |
| `город` | Город пользователя на основе геолокации по IP-адресу. |
| `код_страны` | Код страны по стандарту ISO 3166-1 alpha-2 (например, US, GB). |
| `cuid` | Уникальный идентификатор клиента/пользователя. |
| `категория_устройства` | Тип устройства (например, телефон, планшет). |
