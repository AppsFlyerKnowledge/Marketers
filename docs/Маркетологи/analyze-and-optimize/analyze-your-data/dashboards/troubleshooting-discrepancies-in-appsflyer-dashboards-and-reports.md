> **Краткий обзор:** Узнайте о причинах появления различий и несоответствий при сравнении данных из разных дэшбордов и отчётов. Зачастую это связано с тем, что в одном месте данные отражают пожизненную ценность клиента (LTV), а другом активность. Данные LTV относятся к установкам, которые произошли в течение указанного диапазона дат. Данные по активности – это события, которые произошли в рамках указанного диапазона дат.

<div id="about-data-differences-and-discrepancies" />

## О различиях в данных и несоответствиях

При сравнении данных из различных дэшбордов и отчётов основной причиной несоответствий является то, что возможно вы сравниваете разные типы данных. Вот краткий чек-лист, который поможет вам убедиться, что вы ваше сравнение корректно:

* одинаковая платформа приложений (Android, iOS, CTV и т. д.);
* одинаковые идентификаторы приложений;
* одинаковые фильтры дэшборда/данных;
* одинаковая валюта;
* одинаковый часовой пояс;
* одинаковая <Anchor target="_blank" href="/marketers/ru/docs/about-data-freshness-and-timezone-support">актуальность данных</Anchor>;
* данные <Anchor target="_blank" href="/marketers/ru/docs/aggregated-and-analytics-reporting-overview#toolapi-comparison">агрегированные</Anchor> или <Anchor target="_blank" href="/marketers/ru/docs/raw-data-reporting-overview">сырые</Anchor>?
* данные LTV или активности?

Одной из самых распространенных причин различий в данных является связана с тем, что сравниваются дэшборд или отчёта по LTV с дэшбордом или отчётом по активности. Далее мы более подробно расскажем об LTV и активности.

<div id="ltv-vs-activity" />

## Сравнение LTV и активности

Есть два основных метода анализа данных о событиях пользователей. Данные о событиях – это данные о действиях пользователей, выполненных после установки, таких как покупки в приложении, регистрация, прохождение уровней. В AppsFlyer данные о событиях сгруппированы по дате привлечения пользователя или по дате событий.

* Данные событий после установки, сгруппированные по дате привлечения пользователя, называются LTV (пожизненная ценность клиента).
* Данные о событиях после установки, сгруппированные по дате события, называются активностью.

**Примечание**: Данные об установках не относятся ни к данным об активности, ни к данным LTV.

Рекламодатели считают полезными оба типа данных, но для разных целей. Поэтому оба типа доступны в AppsFlyer.

<div id="ltv-data" />

### Данные LTV

* Данные LTV – это события, выполненные одним пользователем, который совершил конверсию / установил приложение в течение определенного календарного периода. Диапазон дат относится к пользователям, которые установили приложение в рамках указанного периода времени, и показывает, какую ценность они привносят, будучи клиентами. Если конверсия/установка приложения произошла до указанной даты, то даже если события произошли в рамках указанного диапазона дат, то пользователь не отображается в дэшборде и отчётах LTV.
* Данные LTV – это инструмент для изучения **качества пользователей** из разных медиа-источников. Именно поэтому для оптимизации кампании нужны данные LTV.

<div id="activity-data" />

### Данные об активности

* Данные об активности показывают, что делали пользователи в течение указанного диапазона дат. Данные активности показывают, что пользователи делали в течение указанного диапазона дат, то есть какие события были выполнены активными пользователями приложения в течение указанного диапазона дат. Не имеет значения, если конверсия/установка произошла вне указанного диапазона дат.
* Поскольку данные об активности показывают распределение событий во времени, эти данные можно использовать для измерения совокупной эффективности медиа-источников за определенный календарный период. Например, используйте данные об активности, чтобы узнать, сколько событий покупки было совершено всеми пользователями приложения в течение определенного месяца.
* С помощью данных об активности можно сравнить поведение пользователей в текущем месяце и в прошлом.

### Дэшборды и отчёты AppsFlyer – LTV или активность?

Дэшборды предоставляют маркетологам возможность оптимизировать свой неорганический трафик. Большинство панелей основаны на LTV, так как маркетологи обычно измеряют эффективность на основе LTV. Все агрегированные отчеты данных основаны на LTV, а все отчеты сырых данных основаны на активности.

Следующая таблица показывает, какие панели и отчеты являются LTV, а какие — активностью.

| --- | --- |
| Обзорный дэшборд | Показатель LTV |
| Мои дэшборды | Показатель LTV |
| Обзор SKAN | Показатель LTV |
| Установки в Protect360 | Показатель LTV |
| Внутренние события в Protect360 | Активные |
| Дэшборд активности | Активные |
| Дэшборд событий | Показатель LTV |
| Кастомизируемые панели управления | Показатель LTV |
| Удержание | Показатель LTV |
| Ретаргетинг | Показатель LTV |
| Отчеты о производительности агрегированных данных | Показатель LTV |
| Отчеты по сырым данным | Активные |
| Отчеты по ретаргетингу | Показатель LTV |
| Отчеты о предотвращении мошенничества Protect360 | Активные |

## Сравните данные между различными панелями и отчетами

Следующие разделы объясняют, как вы можете сравнивать данные между различными панелями и отчетами, эффективно смягчая и устраняя причины, по которым вы можете видеть различия или несоответствия в данных.

<div id="compare-ltv-and-activity-data-in-appsflyer" />

<Accordion title="Сравнение данных LTV и данных об активности в AppsFlyer">

При сравнении данных AppsFlyer учитывайте, что при сравнении данных LTV и данных активности есть 2 различия, которые следует учитывать:

1. Данные об активности включают события, которые произошли в результате **установок, выполненных до начала** этого календарного периода.
2. Данные LTV включают **события которые произошли после** этого календарного периода.

Чтобы правильно сравнивать два типа данных, нам нужно устранить эти отличия. Для этого нужно извлечь данные LTV из данных об активности или наоборот. **Примечание**: Небольшие различия между аналогичными источниками все же возможны из-за того, что отчеты созданы в разное время.

<div id="to-retrieve-ltv-data-out-of-raw-activity-data" />

#### Чтобы извлечь данные LTV из сырых данных активности:

1. В AppsFlyer в боковом меню выберите **Отчеты** > **Экспорт сырых данных**.
2. Укажите **сегодняшний день в качестве последнего дня** календарного периода (отличие 2 преодолено).
3. Загрузите отчет с сырыми данными по внутренним событиям приложения.
4. Используя столбец **Install Time** (Время установки), отфильтруйте установки, которые были выполнены до начала календарного периода (отличие 1 преодолено).

<div id="to-retrieve-activity-data-out-of-ltv-data" />

#### Чтобы извлечь данные активности из данных LTV:

1. **Выбрать источники, которые начали отправку установок в AppsFlyer в течение заданного календарного периода** (отличие 1 преодолено).  
   Таким образом можно исключить из данных об активности события, произошедшие в пределах календарного периода, которые относятся к установкам, выполненным до начала календарного периода.
2. Укажите **сегодняшний день в качестве последнего дня** календарного периода (отличие 2 преодолено).  
   Таким образом можно исключить из данных LTV события, произошедшие после окончания календарного периода, которые относятся к установкам, выполненным в течение календарного периода.

</Accordion>

<div id="compare-different-appsflyer-aggregated-data-dashboards-and-reports" />

<Accordion title="Сравните различные агрегированные панели и отчеты данных AppsFlyer">

При сравнении данных между различными агрегированными панелями и отчетами данных AppsFlyer, LTV против активности может быть причиной несоответствий.

Если вы агрегируете данные по географии, другой причиной несоответствий может быть то, что в панелях AppsFlyer агрегирование по географии означает географию, где произошла установка, в то время как в отчетах сырых данных это означает географию, где произошло событие.

Тем не менее, учитывайте, что могут быть и другие причины. <Anchor target="_blank" href="/marketers/ru/docs/aggregated-and-analytics-reporting-overview#toolapi-comparison">Смотрите сравнение методов агрегированной отчетности для получения дополнительной информации</Anchor>

</Accordion>

<div id="compare-appsflyer-data-with-external-data" />

<Accordion title="Сравните данные AppsFlyer с внешними данными">

Подавляющее большинство источников данных, в том числе Google и Apple, предоставляют данные об активности, а не данные LTV. Таким образом, для сравнения данных из внешних источников с данными AppsFlyer, как правило, следует использовать данные об активности, которые AppsFlyer предоставляет в отчетах по сырым данным.

Обратите внимание, что Meta Ads предоставляет данные LTV только частично – за 28 дней после установки.

<div id="compare-inapp-event-raw-data-with-the-activity-view" />

<Accordion title="Сравните сырые данные по событиям в приложении с представлением «Активность»">

События в приложении отображаются на дэшборде как в представлении LTV, так и в представлении «Активность». Однако в каждом из них используется разная логика подсчета.  
При сверке количества событий с сырыми данными всегда сравнивайте их с дэшбордом «Активность» или представлением «Активность» в разделе «Мои дэшборды», поскольку в этих представлениях события отображаются по дню, когда они произошли.

Расхождения часто возникают, когда сырые данные отфильтрованы некорректно, особенно для событий ретаргетинга.

<div id="reconcile-raw-data-with-activity-event-metrics" />

#### **Сверка сырых данных с метриками событий в представлении «Активность»**

Чтобы сравнить итоговые значения по событиям в приложении:

1. **Выгрузите необходимые отчеты о сырых данных:**

* Неорганические внутренние события приложений.
* События ретаргетинга внутри приложений.
* Органические события в приложении

2. **Отфильтруйте события ретаргетинга, чтобы избежать двойного подсчета.**  
   В сценариях ретаргетинга возникает двойная атрибуция. Событие в приложении будет атрибутировано в пользу обоих источников:

* Медиаисточнику ретаргетинга (**первичная атрибуция**)
* Медиаисточнику, который привел к исходной установке (**вторичная атрибуция**)

Чтобы не учитывать одно и то же событие дважды в отчетах, отфильтруйте в сырых данных поле **Is primary attribution = True**.  
Примените этот фильтр перед агрегированием отчетов UA, чтобы учитывался только вариант с первичной атрибуцией. Это предотвращает завышение итоговых значений из-за дублирующихся событий ретаргетинга.

3. **Агрегируйте итоговые значения по событиям.**  
   Суммируйте события по отфильтрованным наборам.
4. **Сравните агрегированное итоговое значение** с количеством событий, отображаемым на **дэшборде «Активность»**.

</Accordion>
