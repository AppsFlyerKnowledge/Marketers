> **Краткий обзор**: Просмотр различных метрик пользователей — LTV, активность, Protect360 и удержание. Загрузите результаты в виде CSV-файлов для использования в ваших системах бизнес-аналитики. Сводная таблица предоставляет данные по нескольким приложениям в одном запросе. Используется для генерации вызовов Master API.

## О странице сводных отчетов

С помощью сводных таблиц вы формируете настраиваемые отчеты с метриками привлечения пользователей. В сводной таблице предусмотрено несколько предварительно настроенных отчетов, которые можно использовать в качестве основы для создания собственных. Отчеты, созданные одним пользователем аккаунта, доступны всем пользователям.

Доступны следующие предопределенные сводные отчеты:

* Медиа-источник по дате
* Полная иерархия
* Анализ затрат

**Примечание**: Чтобы данные кампании были видны в сводных таблицах, кампании должны иметь установки.

## Использование сводных таблиц

Создавайте и изменяйте сводные таблицы в интерфейсе пользователя. Для этого выполняйте описанные ниже действия.

**Чтобы использовать сводную таблицу**:

* В AppsFlyer в боковом меню выберите **Анализ** > **События**.  
  На экране появится список отчетов, определенных на данный момент.

**Чтобы добавить сводный отчет**:

1. Нажмите **Add pivot** (Добавить сводную таблицу).  
   Откроется окно новой сводной таблицы.
2. Введите имя сводной таблицы.
3. Кликните **Отправить**.  
   Откроется окно для добавления новой сводной таблицы.
4. Выберите приложения, параметры и метрики. Установите фильтры и настройки отображения значений.

## Характеристики и ограничения

<Accordion title="Характеристики и ограничения">

| Часовой пояс конкретного приложения | Да<br /><br />Исключение: Исключение! Во всех следующих случаях AppsFlyer игнорирует часовой пояс приложения и использует часовой пояс по умолчанию UTC+0:<ul><li>Отчет содержит данные по нескольким приложениям, и приложения имеют разные часовые пояса.</li><li>Все приложения имеют одинаковый часовой пояс, и часовой пояс хотя бы для одного из приложений изменился в течение отчетного периода. Чтобы определить отчетный период:<ul><li>дата\_начала Первая дата в диапазоне дат конверсии.</li><li>Дата окончания. Дата окончания: рассчитывается путем добавления количества дней в длительности отображения к последней дате в диапазоне дат конверсии. Пример: Последняя дата: 1 января 2019 г. Продолжительность отчета: 30 дней Дата окончания. 31 января 2019 г.</li></ul></li></ul> |
| Валюта приложения | Результаты всегда предоставляются в долларах США. |
| Органические данные | Включает |
| Неорганические данные | Включает |
| Обновление данных | Обновление данных: Ежедневно. Частота обновления данных, как у <Anchor target="_blank" href="/marketers/ru/docs/master-api-user-acquisition-metrics-via-api">Master API</Anchor>. |
| Доступ пользователей аккаунта | Да |
| Доход от ретаргетинга | Включает |
| Изменения в названиях кампаний | Сводная таблица Pivot не сопоставляет стоимость кампаний с последним сообщенным названием кампании. Это означает, что с каждым используемым названием кампании будет связана своя стоимость. |
| Данные ретаргетинга | <ul><li>В общем, используйте <Anchor target="_blank" href="/marketers/ru/docs/cohort-and-retention-dashboard">Cohort</Anchor>, чтобы просмотреть данные по ретаргетингу.</li><li>KPI активности для трафика после 1 февраля 2025 года включает объединенные данные (UA и ретаргетинг вместе).</li></ul> |
| Данные о затратах | AppsFlyer получает данные о затратах в основном через API затрат. Данные предоставляются интегрированными партнерами. <Anchor target="_blank" href="/marketers/ru/docs/roi360-cost-aggregation-overview#ad-networks-supporting-cost-api">Список параметров по интегрированным партнерам.</Anchor> |
| Показатель удержания | Чтобы получить показатель удержания, включите в отчет установки. |
| Максимальное количество строк в отчете | 200 тыс. |
| Исторические данные | <ul><li>Данные LTV: 25 месяцев (2 года + 1 месяц)</li><li>Данные об активности: 3 года</li></ul> |
| Среднее количество DAU и среднее количество MAU | При использовании среднего DAU или среднего MAU с агрегацией Sum по любой группировке (например, источник медиа или кампания) итоги могут включать дублирующиеся подсчеты пользователей. Это происходит, когда пользователь выполняет как установку, так и повторное вовлечение в выбранный период, что приводит к их появлению в нескольких группировках. |
