> **Краткий обзор:** Создавайте отчеты по данным атрибуции, чтобы сопоставлять данные на уровне пользователя по событиям установки/ ретаргетинга с данными из ваших систем.

<div id="creating-an-attribution-data-report" />

## Создание отчета по данным атрибуции

**Чтобы создать отчет по данным атрибуции, следуйте инструкциям, подробно описанным на вкладках ниже.**

**Примечание.** Для удобства чтения необходимые шаги разделены на вкладки. Для создания отчета необходимо выполнить все шаги.

<div id="perform-preliminary-steps" />

<Accordion title="Выполните предварительные шаги">

1. Перейдите на вкладку **Reports** (Отчеты) в **DCR.**
2. Нажмите кнопку **+ New report** (+ Новый отчет).
3. Выберите **Attribution data** (Данные атрибуции) в качестве типа исходных данных, затем нажмите **Next** (Далее) в правом нижнем углу экрана.
4. Введите имя отчета.
   * Это может быть любое имя, которое позволит вам идентифицировать этот отчет на платформе DCR.
   * **Важно!** Убедитесь, что имя этого отчета отличается от имен других отчетов в вашем аккаунте, иначе вы не сможете [сохранить отчет](/docs/data-clean-room-creating-attribution-data-reports#set-the-report-destination-and-save-the-report).
   * Требования к имени отчета:
     * Длина: 2-80 символов.
     * Допустимые символы:
       * буквы **(A–Z, a–z)**
       * цифры **(0–9)**, *имя не может начинаться с цифры*
       * дефис (-) *не может быть первым символом имени*
     * Недопустимые символы:
       * пробелы
       * все остальные символы или специальные символы

</Accordion>

<div id="select-sources" />

<Accordion title="Выбор источников">

Укажите данные, которые будут использоваться для отчета:

<div id="attribution-data-sources" />

#### **Источники данных атрибуции**

* **Приложения:** Выберите одно или несколько приложений в своем аккаунте AppsFlyer.
* **Типы атрибуции:** Выберите один или несколько типов данных атрибуции, которые будут использоваться в отчете:

| Установки | Установка регистрируется после того, как пользователь загрузит, установит и запустит мобильное приложение. |
| --- | --- |
| Повторные установки | Повторная установка регистрируется, когда пользователь устанавливает приложение, затем удаляет его и снова устанавливает в пределах окна реатрибуции.<ul><li>**Примечание.** Продолжительность окна реатрибуции можно задать в разделе Настройки > Настройки приложения.</li></ul> |
| Повторные вовлечения | Повторное вовлечение регистрируется, когда неактивный пользователь определенного приложения взаимодействует с кампанией ретаргетинга для этого приложения и впоследствии запускает его. |
| Реатрибуция | Реатрибуция регистрируется, когда бывший пользователь определенного приложения (который удалил его) участвует в кампании ретаргетинга для этого приложения и впоследствии переустанавливает его. |
| Органические установки | Органические установки — это установки, которые не атрибутированы к конкретному медиа-источнику.<ul><li>**Примечание.** Включение органических установок в отчет может значительно увеличить количество отсканированных строк.</li></ul> |

* **Период времени:** Выберите количество дней исторических данных, за которые DCR будет выполнять поиск событий атрибуции, сопоставленных с событиями вашего пользовательского источника (от 1 до 180 дней).

<div id="custom-sources" />

#### **Пользовательские источники**

При определении структуры отчета можно выбрать использование данных из любого из <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-sources">настроенных вами пользовательских источников</Anchor>.

</Accordion>

<div id="join-sources" />

<Accordion title="Объединение источников">

Для сопоставления данных между источниками каждый из **пользовательских** источников, используемых в отчете, должен включать <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-setting-up-cloud-services">идентификатор</Anchor>, сопоставленный с **ключевым идентификатором** в данных атрибуции.

<div id="what-is-a-key-identifier" />

#### **Что такое ключевой идентификатор?**

Вы можете сопоставить любой из этих идентификаторов данных атрибуции приложения в качестве **ключевого идентификатора:**

* Уникальный идентификатор приложения, сгенерированный AppsFlyer при установке, –
  * Этот идентификатор указывается во всех событиях, записанных AppsFlyer.
  * Новый идентификатор AppsFlyer генерируется в случае удаления приложения с последующей переустановкой.
* **Идентификатор клиента (CUID):** Уникальный идентификатор пользователя, обычно генерируемый и устанавливаемый владельцем приложения во время регистрации пользователя.
  * Для использования CUID для сопоставления данных ваше приложение должно быть настроено на <Anchor target="_blank" href="/marketers/ru/docs/customer-user-id-field-cuid">отправку CUID в AppsFlyer</Anchor> через SDK или межсерверный API (S2S).

<div id="important" />

> 🚧 **Важно!**
>
> Не все медиа-источники допускают сопоставление с использованием CUID. Настоятельно рекомендуется использовать идентификатор AppsFlyer.

<div id="mapping-schemes-directindirect" />

#### **Схемы сопоставления (прямые/косвенные)**

Если отчет включает в себя более одного пользовательского источника, только один из них необходимо **напрямую** сопоставить с ключевым идентификатором данных атрибуции. Другие пользовательские источники могут быть сопоставлены как **напрямую, так и косвенно,** как показано в следующем примере:

<div id="example" />

> 📄 **Пример**
>
> <Image align="center" alt="dcr_mapping_identifiers_attribution_data.png" src="https://files.readme.io/18d1ddd8305f790dc621f871695b8cfb30f5e5a5d758c219e76ec7822ec18f2f-9969690360849.png" />
>
> В сценарии, показанном выше:
>
> * Идентификатор пользовательского источника №1 **AF** напрямую сопоставляется с ключевым идентификатором данных атрибуции **af\_id.**
> * Пользовательский источник №2 сопоставляется косвенно: **user\_code** --> **AF** --> **af\_id.**
> * Пользовательский источник №3 отображается косвенно (посредством более длинной цепочки):
>   **user\_id** --> **user\_code** --> **AF** --> **af\_id.**
> * Идентификатор пользовательского источника №4 **ID** напрямую сопоставляется с ключевым идентификатором данных атрибуции **af\_id.**
>   * Обратите внимание, что его можно было бы сопоставить косвенно (через идентификатор пользовательского источника №3 **user\_id**), но любой из вариантов работает надлежащим образом.
>
> ✓ Эта схема сопоставления позволяет сопоставлять данные между всеми источниками, поскольку каждый пользовательский источник напрямую или косвенно сопоставляется с ключевым идентификатором данных атрибуции **af\_id.**

</Accordion>

<div id="determine-treatment-of-multiple-matching-events" />

<Accordion title="Определение обработки нескольких совпадающих событий">

<div id="note" />

> 📘 **Примечание**
>
> Если типы атрибуции, выбранные для этого отчета, **включают только установки и/или органические установки,** этот раздел не имеет значения. Перейдите к разделу **[Выбор параметров](/docs/data-clean-room-creating-attribution-data-reports#select-dimensions).**

**повторное вовлечение или реатрибуция,**, возможно, что данные атрибуции будут включать более одного события в рамках выбранного периода времени с одним и тем же ключевым идентификатором. В этом случае необходимо указать DCR, какие совпадающие события необходимо включить в отчет.

<div id="matching-all-events" />

#### **Сопоставление всех событий**

Наиболее полный метод сопоставления позволяет включить в отчет все совпадающие события. Чтобы достичь этого результата, необходимо сопоставить идентификатор в одном из пользовательских источников отчета с идентификатором данных атрибуции **install\_time.**

* Идентификатор в вашем источнике, сопоставленный с install\_time, должен иметь следующий формат: **гггг-мм-дд чч:мм:сс.**
* Если типы атрибуции, выбранные для отчета, включают повторные установки, повторные вовлечения или реатрибуцию, но вы не сопоставляете идентификатор с **install\_time**, вы должны выбрать для использования либо **последнее**, либо **первое** совпадающее событие в отчете.

<div id="matching-a-single-event" />

#### **Сопоставление одного события**

Если вы выбираете для отчета такие типы атрибуции, как **переустановка,**

Поведение сопоставления отдельных событий различается в зависимости от того, используется ли источник данных атрибуции AppsFlyer отдельно или объединяется с пользовательскими источниками.

* Когда источник данных атрибуции используется отдельно, AppsFlyer выбирает событие сопоставления с самым поздним значением `event_time` в периоде времени, соответствующем конкретному ключевому идентификатору.
* Если источник данных атрибуции объединен с пользовательскими источниками, в отчете необходимо выбрать, какое совпадающее событие использовать: **последнее** или **первое**.
  * **Последнее событие:** Событие атрибуции, включенное в отчет, — это последнее событие (в хронологическом порядке) в рамках заданного периода времени, которое соответствует определенному ключевому идентификатору.
  * **Первое событие:** Событие атрибуции, включенное в отчет, — это первое событие (в хронологическом порядке) в рамках заданного периода времени, которое соответствует определенному ключевому идентификатору.

Сделайте этот выбор на основе события, которое вы считаете наиболее важным для аналитических сведений, которые вы хотите получить из отчета.

<div id="note-1" />

> 📘 **Примечание**
>
> В случае дубликатов записей DCR выполняет дедупликацию записей с одинаковым `appsflyer_id`, выбирая самое позднее событие на основе `event_time`.

</Accordion>

<div id="select-dimensions" />

<Accordion title="Выбор параметров">

Напомним, что DCR не может предоставлять данные на уровне пользователя. Вместо этого предоставляются необходимые аналитические данные для принятия решений путем агрегирования (или группировки) данных по выбранным вами параметрам.

Параметр — это, как правило, атрибут, по которому вы классифицируете пользователей приложения (например, геоданные, дата установки, кампания и т. д.)

<div id="selecting-report-dimensions" />

#### **Выбор параметров для отчета**

Параметры отчета по данным атрибуции могут включать следующее:

* Любой [доступный параметр данных атрибуции](/docs/data-clean-room-creating-attribution-data-reports#available-attribution-data-dimensions)
* Любое поле в пользовательских источниках отчета, которое было <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-sources#3-define-the-source-structure">отнесено к категории параметров</Anchor>

**Выбор параметров для включения в отчет:**

1. Выберите один или несколько параметров в списке **Dimensions from sources** (Параметры из источников) слева и нажмите кнопку **Add** (Добавить) в центральной части экрана, чтобы добавить их в список **Report dimensions** (Параметры для отчета).  
   * Для поиска параметров в списках можно использовать строку поиска.
2. Чтобы удалить параметр, выберите его в списке**Report dimensions** (Параметры для отчета) и нажмите кнопку **Remove** (Удалить), чтобы вернуть его в список **Dimensions from sources** (Параметры из источников).
3. Повторяйте этот процесс, пока не добавите все параметры, которые хотите включить в отчет.

**Примечание.** По умолчанию все отчеты сгруппированы по параметру данных атрибуции **media\_source.** Если вы не хотите использовать этот параметр в своем отчете, вы можете удалить его из списка **параметров для отчета**.

<div id="optional-customizing-dimension-display-names" />

#### **[Необязательно] Настройка отображаемых имен параметров**

По умолчанию имена метрик отображаются в отчете под тем же именем, которое присвоено им в данных атрибуции или пользовательских источниках. При желании вы можете настроить имена метрик для своего отчета.

**Настройка отображаемых имен параметров:**

1. В списке **Report dimensions** (Параметры для отчета) наведите курсор на имя параметра, отображаемое имя которого вы хотите изменить.
2. Нажмите кнопку редактирования ![edit_button.png](https://files.readme.io/4c3822661beac49fad247c7f5958a535e46031238e975a5323a5550722c89c8a-10753875375377.png) справа от параметра.
3. Измените имя на отображаемое имя параметра, которое будет использоваться в отчете (до 50 символов).
4. Нажмите **ОК**, чтобы сохранить отображаемое имя, или **«X»**, чтобы отменить его.

<div id="preserving-privacy-while-grouping-by-dimension-regrouping" />

#### Сохранение конфиденциальности при группировке по параметрам (перегруппировка)

В зависимости от размера вашего набора данных, количества выбранных параметров и других факторов отчет может включать одну или несколько групп, содержащих слишком мало пользователей для включения в отчет. Если бы данные были представлены таким образом, это нарушило бы ограничения на предоставление данных на уровне пользователя.

* **Важно!** Минимальное количество пользователей, необходимое для разрешения формирования отчетов, зависит от медиа-источника.

Однако вместо того, чтобы полностью удалить или скрыть данные из отчета, DCR использует **механизм перегруппировки**, чтобы предоставить как можно больше детальной информации, сохраняя при этом конфиденциальность пользователей.

<div id="regrouping-example" />

> 📄 **Пример перегруппировки**
>
> Предположим, вы настроили отчет по следующим параметрам (по порядку):
>
> * **Параметры данных атрибуции:**
>   * по медиа-каналу —
>   * campaign (кампания)
>   * adset\_name
>   * ad\_id (идентификатор объявления)
> * **Параметры из пользовательского источника:**
>   * user\_type
>
> **Перед перегруппировкой**
>
> После первоначального анализа данных DCR определяет, что данные будут разбиты следующим образом:
>
>
>
> | медиаисточник | campaign (кампания) | название  <br />группы объявлений | идентификатор  <br />объявления | тип  <br />пользователя | доход  <br />D0 | доход  <br />D7 | количество | reportable? |
> | --- | --- | --- | --- | --- | --- | --- | --- | --- |
> | медиа-источник | UA\_100 | зеленый | kjh867 | buyer | 1 | 4 | 120 | ✓ |
> | медиа-источник | UA\_101 | зеленый | jkj987 | ultra | 2 | 23 | 220 | ✓ |
> | медиа-источник | UA\_200 | зеленый | lkh123 | beg | 6 | 7 | X | **X** |
> | медиа-источник | UA\_200 | зеленый | ilk945 | beg | 3 | 21 | X | **X** |
> | медиа-источник | UA\_200 | зеленый | plm654 | beg | 8 | 17 | X | **X** |
>
>
>
> В текущем виде последние 3 строки не подлежат включению в отчет, поскольку в каждой из них слишком мало пользователей. (Для включения этого медиа-источника в отчет требуется минимум **y** пользователей. Здесь у нас есть только **x**.)
>
> Согласно логике перегруппировки, DCR сначала «исключает» последний включенный в список параметр данных атрибуции (в данном случае **ad\_id**). Затем система снова анализирует данные, чтобы определить, какие строки подлежат включению в отчет.
>
> **После перегруппировки**
>
> После применения логики перегруппировки отчет выглядит следующим образом:
>
>
>
> | медиаисточник | campaign (кампания) | название  <br />группы объявлений | идентификатор  <br />объявления | тип  <br />пользователя | доход  <br />D0 | доход  <br />D7 | количество | reportable? |
> | --- | --- | --- | --- | --- | --- | --- | --- | --- |
> | медиа-источник | UA\_100 | зеленый | kjh867 | buyer | 1 | 4 | 120 | ✓ |
> | медиа-источник | UA\_101 | зеленый | jkj987 | ultra | 2 | 23 | 220 | ✓ |
> | медиа-источник | UA\_200 | зеленый | RESTRICTED | beg | 17 | 45 | y (x+x+x) | ✓ |
>
>
>
> **Результаты:**
>
> * Последняя строка теперь объединяет данные, которые ранее находились в 3 строках. Теперь объединенная строка содержит количество пользователей, равное **y**, и может быть включена в отчет.
> * Исключенный параметр теперь отмечен как RESTRICTED (ОГРАНИЧЕНО).
> * Если бы все еще имелись строки, не подлежащие включению в отчет (менее **y** пользователей), система DCR продолжила бы анализировать данные с использованием итеративного метода, исключая один параметр за другим до достижения одного из следующих результатов:
>   * в отчет можно включить все строки; или
>   * больше нет параметров данных атрибуции для исключения
>
> **Примечание.** По умолчанию DCR применяет перегруппировку только к [**параметрам данных атрибуции**](/docs/data-clean-room-creating-attribution-data-reports#available-attribution-data-dimensions) (не к параметрам из пользовательских источников). Если данные, сгруппированные по параметрам данных атрибуции, приведут к появлению строки, содержащей менее **y** пользователей, данные в этой строке будут отмечены как «ОГРАНИЧЕНО».
>
> * *Ниже приведена дополнительная опция, которую можно использовать для применения перегруппировки также и к параметрам из пользовательского источника.*

<div id="optional-managing-dimension-priority" />

#### **[Необязательно] Управление приоритетом параметров**

По умолчанию параметры данных атрибуции исключаются в порядке, обратном порядку их отображения в списке **параметров для отчета**. Однако вы можете изменить последовательность по умолчанию и/или применить перегруппировку к выбранным параметрам из пользовательского источника, чтобы сохранить наиболее важные для вас параметры.

**Изменение порядка исключения параметров:**

1. Нажмите кнопку **Manage dimension priority** (Управление приоритетом параметров).
2. Выберите параметр и перетащите его в нужное место в списке (или переместите его при помощи кнопок со стрелками справа).
   * Если параметр отмечен как **Highest priority** (Наивысший приоритет) (в верхней части списка), это значит, что он будет исключен последним, если потребуется перегруппировка.
3. [Необязательно] Чтобы применить перегруппировку к параметрам из пользовательского источника:
   1. Нажмите **Use advanced options to refine regrouping** (Использовать расширенные опции для оптимизации перегруппировки)
   2. Выберите параметры из пользовательского источника, к которым вы хотите применить перегруппировку.
   3. Выбранные параметры добавляются в список **Manage dimension priority** (Управление приоритетом параметров).
      * По умолчанию эти параметры добавляются в конец списка как **имеющие самый низкий приоритет** при перегруппировке. Однако вы можете изменить их порядок так же, как и с параметрами данных атрибуции, как описано выше.
4. Нажмите **ОК**, чтобы сохранить изменения.
   * Список **Report dimensions** (Параметры для отчета) на главном экране остается в исходном порядке, но измененный порядок сохранен. (Нажмите кнопку **Manage dimension priority** (Управление приоритетом параметров) еще раз, чтобы просмотреть или изменить свой выбор.)

</Accordion>

<div id="select-metrics" />

<Accordion title="Выбор метрик">

Метрики — это числовые данные, которые вы собрали в отношении пользователя приложения (примерами могут служить доход, количество открытий приложения, LTV и т. д.), и это может быть любое **числовое** поле данных из ваших источников, которое вы классифицировали как метрику.

**Выбор метрик для включения в отчет:**

1. Выберите одну или несколько метрик в списке **Metrics from sources** (Метрики из источников) слева и нажмите кнопку **Add** (Добавить) в центральной части экрана, чтобы добавить их в список **Report metrics** (Метрики для отчета).
   * Для поиска метрик в списках можно использовать строку поиска.
2. Для каждой метрики в списке **метрик для отчета** выберите, хотите ли вы, чтобы данные были представлены в отчете как:
   * сумма числовых значений; или
   * количество различных значений
3. Чтобы удалить метрику, выберите ее в списке**Report metrics** (Метрики для отчета) и нажмите кнопку **Remove** (Удалить), чтобы вернуть ее в список **Metrics from sources** (Метрики из источников).
4. Повторяйте этот процесс, пока не добавите все метрики, которые хотите включить в отчет.

<div id="optional-customizing-metric-display-names" />

#### **[Необязательно] Настройка отображаемых имен метрик**

По умолчанию имена параметров отображаются в отчете под тем же именем, которое присвоено им в данных атрибуции или пользовательских источниках. При желании вы можете настроить имена параметров для своего отчета.

**Настройка отображаемых имен метрик:**

1. В списке **Metrics from sources** (Метрики для отчета) наведите курсор на имя метрики, отображаемое имя которой вы хотите изменить.
2. Нажмите кнопку редактирования ![edit_button.png](https://files.readme.io/4c3822661beac49fad247c7f5958a535e46031238e975a5323a5550722c89c8a-10753875375377.png) справа от метрики.
3. Измените имя на отображаемое имя метрики, которое будет использоваться в отчете (до 50 символов).
4. Нажмите **ОК**, чтобы сохранить отображаемое имя, или **«X»**, чтобы отменить его.

<div id="optional-select-identifiers-to-count" />

#### **[Необязательно] Выбор идентификаторов для подсчета**

По умолчанию каждая строка отчета заканчивается столбцом, содержащим количество отдельных идентификаторов AppsFlyer, сгруппированных в данных этой строки.

**Если вы хотите добавить столбцы для отдельных подсчетов других идентификаторов из ваших источников, это можно сделать так:**

1. Выберите один или несколько идентификаторов в списке **Identifiers from sources** (Идентификаторы из источников) слева и нажмите кнопку **Add** (Добавить) в центральной части экрана, чтобы добавить их в список **Distinct count identifiers** (Отдельные идентификаторы для подсчета).
   * Для поиска идентификаторов в списках можно использовать строку поиска.
2. Чтобы удалить идентификатор, выберите его в списке **Distinct count identifiers** (Отдельные идентификаторы для подсчета) и нажмите кнопку **Remove** (Удалить), чтобы вернуть его в список **Identifiers from sources** (Идентификаторы из источников).
3. Повторяйте этот процесс, пока не добавите все идентификаторы, подсчет которых хотите включить в отчет.

</Accordion>

<div id="set-the-report-destination-and-save-the-report" />

<Accordion title="Чтобы задать место назначения отчета и сохранить отчет:">

DCR передает отчеты в выбранные вами облачные сервисы с помощью <Anchor target="_blank" href="/marketers/ru/docs/data-locker-for-marketers">AppsFlyer Data Locker</Anchor>. Таким образом, указание места назначения отчета подразумевает выбор или создание соединения с Data Locker.

* **Примечание.**  Получение отчетов DCR не требует премиум-подписки на Data Locker. Если вы заинтересованы в получении других отчетов AppsFlyer через Data Locker, свяжитесь с вашим менеджером или отправьте письмо по адресу [hello@appsflyer.com](mailto:hello@appsflyer.com).

**Чтобы задать место назначения отчета и сохранить отчет:**

1. Выберите из списка доступных подключений Data Locker в вашем аккаунте AppsFlyer.
   * Если в вашем аккаунте не определены подключения:
     * В вашем браузере откроется новая вкладка (со страницей AppsFlyer Data Locker)
     * Откроется окно **Новое подключение**. Следуйте <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-connections#завершить-подключение">этим инструкциям</Anchor> для создания подключения.
   * Если у вас уже есть подключения, но вы хотите использовать новое, кликните ![dcr_new_connection_data_locker_button.png](https://files.readme.io/9850a4b8ea4f40f6320903c545c51add7b90207538a27c83a3b02a41197ba567-14995870859281.png) button:
     * В вашем браузере откроется новая вкладка (со страницей AppsFlyer Data Locker)
     * Откроется окно **Новое подключение**. Следуйте <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-connections#завершить-подключение">этим инструкциям</Anchor> для создания подключения.
   * После создания подключения вернитесь на вкладку DCR в браузере и выберите только что созданное подключение из списка подключений Data Locker.
2. Нажмите **Save** (Сохранить), чтобы сохранить отчет.
3. Новый отчет теперь отображается на вкладке **Reports** (Отчеты) в **Data Clean Room.**

</Accordion>

<div id="when-does-the-report-run" />

## Когда запускается отчет?

После создания и сохранения отчета он запускается при обнаружении новых версий всех [пользовательских источников, которые он использует](/docs/data-clean-room-creating-attribution-data-reports#пользовательские-источники):

* Для источников, расположенных в **хранилищах данных** (BigQuery и Snowflake), DCR распознает создание новой версии источника, когда обнаруживает новое значение <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-sources#table-columns">в столбце `v` таблицы источника</Anchor>.
  * **Важно!** Чтобы обеспечить полноту отчета, обязательно заполняйте таблицу источника полным набором данных при каждом изменении значения столбца.
* Для источников, расположенных в **облачных хранилищах** (Amazon S3 и GCS), DCR распознает создание новой версии источника, когда обнаруживает, что <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-sources#обновление-источников-для-запуска-обработки-отчетов">новая версия файла источника была загружена</Anchor> вместе с сопутствующим файлом \_SUCCESS.

AppsFlyer постоянно сканирует новые версии источников для **текущей даты и 2 дней до нее.**
