> Краткий обзор: **Создавайте отчеты по внутренним событиям приложения, посвященные действиям пользователя после установки приложения. Извлекайте определенные параметры событий из необработанных данных о внутренних событиях приложения, при необходимости сопоставляйте данные с пользовательскими источниками, затем обрабатывайте и представляйте их в агрегированном виде.**

<div id="creating-an-in-app-event-report" />

## Создание отчета по внутренним событиям приложения

**Чтобы создать отчет по внутренним событиям приложения, следуйте инструкциям, подробно описанным на вкладках ниже.**

**Примечание.** Для удобства чтения необходимые шаги разделены на вкладки. Для создания отчета необходимо выполнить все шаги. *(Как указано, некоторые шаги не актуальны для отчетов, которые не используют пользовательские источники.)*

<div id="perform-preliminary-steps" />

<Accordion title="Выполните предварительные шаги">

1. Перейдите на вкладку **Reports** (Отчеты) в **DCR.**
2. Нажмите кнопку **+ New report** (+ Новый отчет).
3. Выберите **In-app events** (Внутренние события приложения) в качестве типа исходных данных, затем нажмите **Next** (Далее) в правом нижнем углу экрана.
4. Введите имя отчета.
   * Это может быть любое имя, которое позволит вам идентифицировать этот отчет на платформе DCR.
   * **Важно!** Убедитесь, что имя этого отчета отличается от имен других отчетов в вашем аккаунте, иначе вы не сможете **сохранить отчет**.
   * Требования к имени отчета:
     * Длина: 2-80 символов.
     * Допустимые символы:
       * буквы **(A–Z, a–z)**
       * цифры **(0–9)**, *имя не может начинаться с цифры*
       * дефис (-) *не может быть первым символом имени*
     * Недопустимые символы:
       * пробелы
       * все остальные символы или специальные символы

</Accordion>

<div id="select-sources" />

<Accordion title="Выбор источников">

Укажите исходные данные, которые будут использоваться для отчета:

<div id="in-app-event-sources" />

#### **Источники внутренних событий приложения**

* **Приложения:** Выберите одно или несколько приложений в своем аккаунте AppsFlyer.
* **Период времени:** Выберите количество дней исторических данных, за которые DCR будет выполнять поиск внутренних событий приложения (от 1 до 30 дней).
* **События:** Выберите одно или несколько внутренних событий приложения для включения в отчет.
  * Доступные события включают все внутренние события приложения **из выбранных приложений**, настроенных для передачи данных в AppsFlyer через SDK или межсерверный API (S2S).
* **Типы источников:** Выберите один или несколько типов данных о внутренних событиях приложения: 

| Установки | Внутренние события приложения, связанные с атрибуцией установок<ul><li>Установка регистрируется после того, как пользователь загрузит, установит и запустит мобильное приложение.</li></ul> |
| --- | --- |
| Повторное вовлечение | Внутренние события приложения, связанные с повторным взаимодействием<ul><li>Повторное вовлечение регистрируется, когда неактивный пользователь определенного приложения взаимодействует с кампанией ретаргетинга для этого приложения и впоследствии запускает его.</li></ul> |
| Реатрибуции | Внутренние события приложения, связанные с реатрибуцией<ul><li>Реатрибуция регистрируется, когда бывший пользователь определенного приложения (который удалил его) участвует в кампании ретаргетинга для этого приложения и впоследствии переустанавливает его.</li></ul> |

<div id="data-sources" />

#### **Источники данных**

1. [Необязательно] Добавьте дополнительные источники для использования в отчете. При выборе дополнительных источников обратите внимание на существенную разницу между отчетами, в которых **используются** и **не** используются пользовательские источники.
   * Отчет, **не использующий** пользовательские источники, извлекает определенные параметры и значения событий из необработанных данных по внутренним событиям приложения.
   * Отчет, **использующий** пользовательские источники, извлекает определенные параметры и значения событий из необработанных данных по внутренним событиям приложения, а затем сопоставляет эти данные с данными на уровне пользователя из ваших пользовательских источников (например, данными из ваших систем BI или CRM).
2. Выполните следующие шаги в зависимости от того, использует ли ваш отчет пользовательские источники:
   * Если в вашем отчете **не** используются пользовательские источники, перейдите к разделу **[Выбор параметров](/docs/data-clean-room-creating-in-app-event-reports#select-dimensions),** а затем продолжите выполнение шагов на всех оставшихся вкладках.
   * Если в вашем отчете **используются** пользовательские источники, продолжите выполнение шагов на вкладке [**Объединение источников**](#join-sources-only-for-reports-containing-custom-sources) (следующей) и на всех оставшихся вкладках.

</Accordion>

Следующий шаг актуален **только для отчетов, использующих пользовательские источники.**

<div id="join-sources-only-for-reports-containing-custom-sources" />

<Accordion title="Объединение источников (только для отчетов, содержащих пользовательские источники)">

Чтобы сопоставить данные между источниками, каждый из **пользовательских** источников, используемых в отчете, должен включать <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-setting-up-cloud-services">идентификатор</Anchor>, сопоставленный с **ключевым идентификатором** в данных по внутренним событиям приложения.

* Отчеты по внутренним событиям приложения включают **все** выбранные события, соответствующие ключевому идентификатору в течение выбранного периода времени.

<div id="what-is-a-key-identifier" />

#### **Что такое ключевой идентификатор?**

Вы можете сопоставить любой из этих идентификаторов данных по внутренним событиям приложения в качестве **ключевого идентификатора:**

* **Идентификатор AppsFlyer (af\_id):** Уникальный идентификатор приложения, сгенерированный AppsFlyer при установке, –
  * Этот идентификатор указывается во всех событиях, записанных AppsFlyer.
  * Новый идентификатор AppsFlyer генерируется в случае удаления приложения с последующей переустановкой.
* **Идентификатор клиента (CUID):** Уникальный идентификатор пользователя, обычно генерируемый и устанавливаемый владельцем приложения во время регистрации пользователя.
  * Для использования CUID для сопоставления данных ваше приложение должно быть настроено на <Anchor target="_blank" href="/marketers/ru/docs/customer-user-id-field-cuid">отправку CUID в AppsFlyer</Anchor> через SDK или межсерверный API (S2S).

<div id="important" />

> 🚧 **Важно!**
>
> Не все медиа-источники допускают сопоставление с использованием CUID. Настоятельно рекомендуется использовать идентификатор AppsFlyer.

<div id="mapping-schemes-directindirect" />

#### **Схемы сопоставления (прямые/косвенные)**

Если отчет включает в себя более одного пользовательского источника, только один из них необходимо **напрямую** сопоставить с идентификатором ключа внутреннего события приложения. Другие пользовательские источники могут быть сопоставлены как **напрямую, так и косвенно,** как показано в следующем примере:

<div id="example" />

> 📄 **Пример**
>
> ![dcr_mapping_identifiers_in-app events.png](https://files.readme.io/73d0e929663bda4e6f142c64d0228fdf1eeec3b02ef1560f6f03f2a089d00664-9969546429713.png)
>
> В сценарии, показанном выше:
>
> * Пользовательский идентификатор источника №1 **AF** напрямую сопоставляется с идентификатором ключа внутреннего события приложения **af\_id.**
> * Пользовательский источник №2 сопоставляется косвенно: **user\_code** --> **AF** --> **af\_id.**
> * Пользовательский источник №3 отображается косвенно (посредством более длинной цепочки):
>   **user\_id** --> **user\_code** --> **AF** --> **af\_id.**
> * Пользовательский **идентификатор** источника №4 напрямую сопоставляется с идентификатором ключа внутреннего события приложения **af\_id.**
>   * Обратите внимание, что его можно было бы сопоставить косвенно (через идентификатор пользовательского источника №3 **user\_id**), но любой из вариантов работает надлежащим образом.
>
> ✓ Эта схема сопоставления позволяет сопоставлять данные между всеми источниками, поскольку каждый пользовательский источник напрямую или косвенно сопоставляется с идентификатором ключа внутреннего события приложения **af\_id.**

</Accordion>

Остальные вкладки актуальны для **всех отчетов по внутренним событиям приложения,** независимо от того, включают ли они пользовательские источники.

<div id="select-dimensions" />

<Accordion title="Выбор параметров">

Напомним, что DCR не может предоставлять данные на уровне пользователя. Вместо этого предоставляются необходимые аналитические данные для принятия решений путем агрегирования (или группировки) данных по выбранным вами параметрам.

Параметр — это, как правило, атрибут, по которому вы классифицируете пользователей приложения (например, гео, дата установки, кампания и т. д.)

<div id="extracting-dimensions-from-event_value" />

#### **Извлечение параметров из event\_value**

Когда отчеты по внутренним событиям приложения передаются в AppsFlyer через SDK или API S2S, большая часть необработанных данных содержится в одном поле под названием **event\_value.** Это структурированное поле данных включает в себя все конкретные параметры внутренних событий приложения, настроенные для событий, которые ваши приложения отправляют в AppsFlyer.

Одним из основных преимуществ отчетов по внутренним событиям приложения является то, что они позволяют извлекать определенные параметры и их значения из поля **event\_value** для выбранных вами событий.

**Извлечение параметров из поля event\_value для использования в отчетах DCR:**

1. В списке **Dimensions from sources** (Параметры из источников) нажмите кнопку <Image alt="extract_dimension_button.png" src="https://files.readme.io/c238da4a1d2a15fe2249070747fa6247db63ab4129b1c72804b84550675214f3-10754426767761.png" width="123px" /> .

   Откроется окно **Extract field from event\_value** (Извлечение поля из event\_value).
2. В поле **Report field** (Поле отчета) введите имя извлеченного параметра, которое должно отображаться в отчете.
3. Из списка **Event\_value parameter** (Параметр event\_value) выберите параметр внутреннего события приложения, который должен быть сопоставлен по умолчанию с полем отчета (параметром), определенным вами в шаге 2.
   * Доступные параметры включают те, которые были настроены в **выбранных внутренних событиях приложения** **в выбранных приложениях**.
4. Сопоставление по умолчанию может отличаться в зависимости от приложения и/или события. В этом случае:
   1. Нажмите кнопку **Add exception** (Добавить исключение)
   2. Выберите приложение и событие, для которых поле отчета должно быть сопоставлено по-другому.
   3. Выберите параметр внутреннего события приложения, который следует сопоставить с полем отчета для этой комбинации приложения и события.
   4. Выполните следующие действия для настройки необходимого вам исключений.
5. Завершив настройку сопоставления для извлеченного параметра, нажмите **Save and add another** (Сохранить и добавить еще), чтобы извлечь еще один параметр из поля event\_value, или **Save** (Сохранить), чтобы вернуться на главный экран.

**Редактирование извлеченных параметров:**

1. В списке **Dimensions from sources** (Параметры из источников) или **Report dimensions** (Параметры для отчета) наведите курсор на имя параметра, который вы хотите изменить.
2. Нажмите кнопку <Image alt="more_options_button.png" src="https://files.readme.io/d52908bc376b10d60f12ec401b8ba13adf1946ca4ef27cb7a588fae33a603384-10755347815441.png" width="21px" /> справа от параметра.
3. Выберите **Edit extracted field** (Редактировать извлеченное поле).
4. При необходимости внесите изменения в имя **поля отчета** и/или сопоставление параметров.
5. Нажмите **Save** (Сохранить), чтобы сохранить изменения.

**Удаление извлеченных параметров:**

1. В списке **Dimensions from sources** (Параметры из источников) или **Report dimensions** (Параметры для отчета) наведите курсор на имя параметра, который вы хотите удалить.
2. Нажмите кнопку <Image alt="more_options_button.png" src="https://files.readme.io/d52908bc376b10d60f12ec401b8ba13adf1946ca4ef27cb7a588fae33a603384-10755347815441.png" width="21px" /> справа от параметра.
3. Выберите **Delete field** (Удалить поле).
   * **Внимание!** Если удалить извлеченное поле из списка **Report dimensions** (Параметры для отчета), определение извлеченного поля будет удалено. Чтобы удалить поле из отчета с сохранением определения, нажмите вместо этого кнопку **Remove** (Удалить).

<div id="selecting-report-dimensions" />

#### **Выбор параметров для отчета**

Параметры отчета по внутренним событиям приложения могут включать следующее:

* Параметры, извлеченные из поля event\_value
* [Параметры внутренних событий приложения по умолчанию](/docs/data-clean-room-creating-in-app-event-reports#default-inapp-event-dimensions)
* Любое поле в пользовательских источниках отчета, которое было <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-sources#3-define-the-source-structure">отнесено к категории параметров</Anchor> (если применимо)

**Выбор параметров для включения в отчет:**

1. Выберите один или несколько параметров в списке **Dimensions from sources** (Параметры из источников) слева и нажмите кнопку **Add** (Добавить) в центральной части экрана, чтобы добавить их в список **Report dimensions** (Параметры для отчета).
   * Для поиска параметров в списках можно использовать строку поиска.
2. Чтобы удалить параметр, выберите его в списке**Report dimensions** (Параметры для отчета) и нажмите кнопку **Remove** (Удалить), чтобы вернуть его в список **Dimensions from sources** (Параметры из источников).
3. Повторяйте этот процесс, пока не добавите все параметры, которые хотите включить в отчет.

**Примечание.** По умолчанию все отчеты группируются по параметру внутреннего события приложения **media\_source.** Если вы не хотите использовать этот параметр в своем отчете, вы можете удалить его из списка **параметров для отчета**.

<div id="optional-customizing-dimension-display-names" />

#### **[Необязательно] Настройка отображаемых имен параметров**

По умолчанию имена метрик отображаются в отчете под тем же именем, которое присвоено им в данных по внутренним событиям приложения или пользовательских источниках. При желании вы можете настроить имена метрик для своего отчета.

**Настройка отображаемых имен параметров:**

1. В списке **Report dimensions** (Параметры для отчета) наведите курсор на имя параметра, отображаемое имя которого вы хотите изменить.
2. Нажмите кнопку редактирования ![edit_button.png](https://files.readme.io/4c3822661beac49fad247c7f5958a535e46031238e975a5323a5550722c89c8a-10753875375377.png) справа от параметра.
3. Измените имя на отображаемое имя параметра, которое будет использоваться в отчете (до 50 символов).
4. Нажмите **ОК**, чтобы сохранить отображаемое имя, или **«X»**, чтобы отменить его.

**Примечание:** Если вы хотите изменить название **извлеченного измерения**, используйте шаги по редактированию извлеченных измерений (выше).

<div id="preserving-privacy-while-grouping-by-dimension-regrouping" />

#### **Сохранение конфиденциальности при группировке по параметрам (перегруппировка)**

В зависимости от размера вашего набора данных, количества выбранных параметров и других факторов отчет может включать одну или несколько групп, содержащих слишком мало пользователей для включения в отчет. Если бы данные были представлены таким образом, это нарушило бы ограничения на предоставление данных на уровне пользователя.

Однако вместо того, чтобы полностью удалить или скрыть данные из отчета, DCR использует **механизм перегруппировки**, чтобы предоставить как можно больше детальной информации, сохраняя при этом конфиденциальность пользователей.

<div id="regrouping-example" />

> 📄 **Пример перегруппировки**
>
> Предположим, вы настроили отчет по следующим параметрам (по порядку):
>
> * **Параметры внутренних событий приложения:**
>   * по медиа-каналу —
>   * campaign (кампания)
>   * adset\_name
>   * ad\_id (идентификатор объявления)
> * **Параметры из пользовательского источника:**
>   * user\_type
>
> **Перед перегруппировкой**
>
> После первоначального анализа данных DCR определяет, что данные будут разбиты следующим образом:
>
>
>
> | медиаисточник | campaign (кампания) | название  <br />группы объявлений | ad  <br />id | тип  <br />пользователя | доход  <br />D0 | доход  <br />D7 | количество | reportable? |
> | --- | --- | --- | --- | --- | --- | --- | --- | --- |
> | медиа-источник | UA\_100 | зеленый | kjh867 | buyer | 1 | 4 | 120 | ✓ |
> | медиа-источник | UA\_101 | зеленый | jkj987 | ultra | 2 | 23 | 220 | ✓ |
> | медиа-источник | UA\_200 | зеленый | lkh123 | beg | 6 | 7 | . | **X** |
> | медиа-источник | UA\_200 | зеленый | ilk945 | beg | 3 | 21 | . | **X** |
> | медиа-источник | UA\_200 | зеленый | plm654 | beg | 8 | 17 | . | **X** |
>
>
>
> В текущем виде последние три строки не подлежат включению в отчет, поскольку в каждой из них слишком мало пользователей. (Для включения этого медиа-источника в отчет требуется минимум **y** пользователей. Здесь у нас есть только **x**.)
>
> Согласно логике перегруппировки, DCR сначала «исключает» последний включенный в список параметр внутреннего события приложения (в данном случае **ad\_id**). Затем система снова анализирует данные, чтобы определить, какие строки подлежат включению в отчет.
>
> **После перегруппировки**
>
> После применения логики перегруппировки отчет выглядит следующим образом:
>
>
>
> | медиаисточник | campaign (кампания) | название  <br />группы объявлений | ad  <br />id | тип  <br />пользователя | доход  <br />D0 | доход  <br />D7 | количество | reportable? |
> | --- | --- | --- | --- | --- | --- | --- | --- | --- |
> | медиа-источник | UA\_100 | зеленый | kjh867 | buyer | 1 | 4 | 120 | ✓ |
> | медиа-источник | UA\_101 | зеленый | jkj987 | ultra | 2 | 23 | 220 | ✓ |
> | медиа-источник | UA\_200 | зеленый | RESTRICTED | beg | 17 | 45 | y (x+x+x) | ✓ |
>
>
>
> **Результаты:**
>
> * Последняя строка теперь объединяет данные, которые ранее находились в трех строках. Теперь объединенная строка содержит количество пользователей, равное **y**, и может быть включена в отчет.
> * Исключенный параметр теперь отмечен как RESTRICTED (ОГРАНИЧЕНО).
> * Если бы все еще имелись строки, не подлежащие включению в отчет (менее **y** пользователей), система DCR продолжила бы анализировать данные с использованием итеративного метода, исключая один параметр за другим до достижения одного из следующих результатов:
>   * в отчет можно включить все строки; или
>   * больше нет параметров внутренних событий приложения для исключения
>
> **Примечание.** По умолчанию DCR применяет перегруппировку только к **[параметрам внутренних событий приложения по умолчанию](/docs/data-clean-room-creating-in-app-event-reports#default-inapp-event-dimensions)** (а не к извлеченным параметрам внутренних событий приложения или параметрам из пользовательского источника). Если данные, сгруппированные по параметрам внутренних событий приложения по умолчанию, приведут к появлению строки, содержащей менее **y** пользователей, данные в этой строке будут отмечены как «ОГРАНИЧЕНО».
>
> * *Ниже приведена дополнительная опция, которую можно использовать для применения перегруппировки также и к параметрам из пользовательского источника.*

<div id="optional-managing-dimension-priority" />

#### **[Необязательно] Управление приоритетом параметров**

По умолчанию параметры внутренних событий приложения исключаются в порядке, обратном порядку их отображения в списке **параметров для отчета**. Однако вы можете изменить последовательность по умолчанию и/или применить перегруппировку к выбранным параметрам из пользовательского источника (если применимо), чтобы сохранить наиболее важные для вас параметры.

**Изменение порядка исключения параметров:**

1. Нажмите кнопку **Manage dimension priority** (Управление приоритетом параметров).
2. Выберите параметр и перетащите его в нужное место в списке (или переместите его при помощи кнопок со стрелками справа).
   * Если параметр отмечен как **Highest priority** (Наивысший приоритет) (в верхней части списка), это значит, что он будет исключен последним, если потребуется перегруппировка.
3. [Необязательно] Чтобы применить перегруппировку к параметрам из пользовательского источника (для отчетов, использующих пользовательские источники):
   1. Нажмите **Use advanced options to refine regrouping** (Использовать расширенные опции для оптимизации перегруппировки)
   2. Выберите параметры из пользовательского источника, к которым вы хотите применить перегруппировку.
   3. Выбранные параметры добавляются в список **Manage dimension priority** (Управление приоритетом параметров).
      * По умолчанию эти параметры добавляются в конец списка как **имеющие самый низкий приоритет** при перегруппировке. Однако вы можете изменить их порядок так же, как и с параметрами внутренних событий приложения, как описано выше.
4. Нажмите **ОК**, чтобы сохранить изменения.
   * Список **Report dimensions** (Параметры для отчета) на главном экране остается в исходном порядке, но измененный порядок сохранен. (Нажмите кнопку **Manage dimension priority** (Управление приоритетом параметров) еще раз, чтобы просмотреть или изменить свой выбор.)

</Accordion>

<Accordion title="Выбор метрик">

Метрики — это числовые данные, которые вы собрали в отношении пользователя приложения (примерами могут служить доход, количество открытий приложения, LTV и т. д.), и это может быть любое числовое поле данных из ваших источников, которое вы классифицировали как метрику.

<div id="extracting-metrics-from-event_value" />

#### **Извлечение метрик из event\_value**

Так же, как и для [параметров для отчета](/docs/data-clean-room-creating-in-app-event-reports#select-dimensions), вы можете извлекать параметры внутренних событий приложения из поля **event\_value** для использования в качестве метрик в своих отчетах.

**Извлечение параметров из поля event\_value для использования в отчетах DCR:**

1. В списке **Metrics from sources** (Метрики из источников) нажмите кнопку <Image alt="extract_metric_button.png" src="https://files.readme.io/93ca5970968816d452331df4ce5ff4cfb678cbb24f65eb99fe01bd3bb3016959-10755235273233.png" width="102px" /> .

   Откроется окно **Extract field from event\_value** (Извлечение поля из event\_value).
2. В поле **Report field** (Поле отчета) введите имя извлеченной метрики, которое должно отображаться в отчете.
3. Из списка **Event\_value parameter** (Параметр event\_value) выберите параметр внутреннего события приложения, который должен быть сопоставлен по умолчанию с полем отчета (метрикой), определенным вами в шаге 2.
   * Доступные параметры включают те, которые были настроены в **выбранных внутренних событиях приложения** **в выбранных приложениях**.
4. Сопоставление по умолчанию может отличаться в зависимости от приложения и/или события. В этом случае:
   1. Нажмите кнопку **Add exception** (Добавить исключение)
   2. Выберите приложение и событие, для которых поле отчета должно быть сопоставлено по-другому.
   3. Выберите параметр внутреннего события приложения, который следует сопоставить с полем отчета для этой комбинации приложения и события.
   4. Выполните следующие действия для настройки необходимого вам исключений.
5. Завершив настройку сопоставления для извлеченной метрики, нажмите **Save and add another** (Сохранить и добавить еще), чтобы извлечь еще одну метрику из поля event\_value, или **Save** (Сохранить), чтобы вернуться на главный экран.

**Редактирование извлеченных метрик:**

1. В списке **Metrics from sources** (Метрики из источников) или **Report metrics** (Метрики для отчета) наведите курсор на имя метрики, которую вы хотите изменить.
2. Нажмите кнопку <Image alt="more_options_button.png" src="https://files.readme.io/d52908bc376b10d60f12ec401b8ba13adf1946ca4ef27cb7a588fae33a603384-10755347815441.png" width="21px" /> справа от метрики.
3. Выберите **Edit extracted field** (Редактировать извлеченное поле).
4. При необходимости внесите изменения в имя **поля отчета** и/или сопоставление параметров.
5. Нажмите **Save** (Сохранить), чтобы сохранить изменения.

**Удаление извлеченных метрик:**

1. В списке **Metrics from sources** (Метрики из источников) или **Report metrics** (Метрики для отчета) наведите курсор на имя метрики, которую вы хотите удалить.
2. Нажмите кнопку <Image alt="more_options_button.png" src="https://files.readme.io/d52908bc376b10d60f12ec401b8ba13adf1946ca4ef27cb7a588fae33a603384-10755347815441.png" width="21px" /> справа от метрики.
3. Выберите **Delete field** (Удалить поле).
   * **Внимание!** Если удалить извлеченное поле из списка **Report metrics** (Отчет по метрикам), определение извлеченного поля будет удалено. Чтобы удалить поле из отчета с сохранением определения, нажмите вместо этого кнопку **Remove** (Удалить).

<div id="select-report-metrics" />

#### **Выбор метрик для отчета**

**Выбор метрик для включения в отчет:**

1. Выберите одну или несколько метрик в списке **Metrics from sources** (Метрики из источников) слева и нажмите кнопку **Add** (Добавить) в центральной части экрана, чтобы добавить их в список **Report metrics** (Метрики для отчета).
   * Для поиска метрик в списках можно использовать строку поиска.
2. Для каждой метрики в списке **метрик для отчета** выберите, хотите ли вы, чтобы данные были представлены в отчете как:
   * сумма числовых значений; или
   * количество различных значений
3. Чтобы удалить метрику, выберите ее из списка **метрик отчета** и используйте кнопку **Удалить** , чтобы вернуть ее в список **метрик из источников**.
4. Повторяйте этот процесс, пока не добавите все метрики, которые хотите включить в отчет.

<div id="optional-customizing-metric-display-names" />

#### **[Необязательно] Настройка отображаемых имен метрик**

По умолчанию имена параметров отображаются в отчете под тем же именем, которое присвоено им в данных по внутренним событиям приложения или пользовательских источниках. При желании вы можете настроить имена параметров для своего отчета.

**Настройка отображаемых имен метрик:**

1. В списке **показателей отчета** наведите указатель мыши на название метрики, отображаемое имя которой вы хотите изменить.
2. Нажмите кнопку редактирования ![edit_button.png](https://files.readme.io/4c3822661beac49fad247c7f5958a535e46031238e975a5323a5550722c89c8a-10753875375377.png) справа от метрики.
3. Измените имя на отображаемое имя метрики, которое будет использоваться в отчете (до 50 символов).
4. Нажмите **ОК**, чтобы сохранить отображаемое имя, или **«X»**, чтобы отменить его.

**Примечание.** Чтобы изменить имя **извлеченной метрики**, воспользуйтесь инструкциями по редактированию извлеченных метрик (выше).

<div id="optional-select-identifiers-to-count" />

#### **[Необязательно] Выбор идентификаторов для подсчета**

По умолчанию каждая строка отчета заканчивается столбцом, содержащим количество отдельных идентификаторов AppsFlyer, сгруппированных в данных этой строки.

**Если вы хотите добавить столбцы для отдельных подсчетов других идентификаторов из ваших источников, это можно сделать так:**

1. Выберите один или несколько идентификаторов в списке **Identifiers from sources** (Идентификаторы из источников) слева и нажмите кнопку **Add** (Добавить) в центральной части экрана, чтобы добавить их в список **Distinct count identifiers** (Отдельные идентификаторы для подсчета).
   * Для поиска идентификаторов в списках можно использовать строку поиска.
2. Чтобы удалить идентификатор, выберите его в списке **Distinct count identifiers** (Отдельные идентификаторы для подсчета) и нажмите кнопку **Remove** (Удалить), чтобы вернуть его в список **Identifiers from sources** (Идентификаторы из источников).
3. Повторяйте этот процесс, пока не добавите все идентификаторы, подсчет которых хотите включить в отчет.

</Accordion>

#### **График (только для отчетов без пользовательских источников)**

Отчеты без пользовательских источников запускаются в соответствии с заданным вами графиком.

**Чтобы определить график отчетов:**

1. Выберите, следует ли запускать отчет ежедневно или один или несколько дней в неделю.
2. Выберите время запуска отчета (часовой пояс — UTC).

<div id="important-1" />

> 🚧 **Важно!**
>
> Параметры планирования отключены для отчетов, которые используют пользовательские источники. Этот тип отчета запускается всякий раз, когда обнаруживаются новые версии всех <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-creating-attribution-data-reports#пользовательские-источники">используемых им пользовательских источников</Anchor>:
>
> * Для источников, расположенных в **хранилищах данных** (BigQuery и Snowflake), DCR распознает создание новой версии источника, когда обнаруживает новое значение <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-sources#table-columns">в столбце `v` таблицы источника</Anchor>.
>   * **Важно!** Чтобы обеспечить полноту отчета, обязательно заполняйте таблицу источника полным набором данных при каждом изменении значения столбца.
> * Для источников, расположенных в **облачных хранилищах** (Amazon S3 и GCS), DCR распознает создание новой версии источника, когда обнаруживает, что <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-sources#обновление-источников-для-запуска-обработки-отчетов">новая версия файла источника была загружена</Anchor> вместе с сопутствующим файлом \_SUCCESS.
>
> AppsFlyer постоянно сканирует новые версии источников для **текущей даты и 2 дней до нее.**

<div id="report-destination" />

#### **Место назначения отчета**

* **Примечание.** Получение отчетов DCR не требует премиум-подписки на Data Locker. Если вы заинтересованы в получении других отчетов AppsFlyer через Data Locker, свяжитесь с вашим менеджером или отправьте письмо по адресу [hello@appsflyer.com](mailto:hello@appsflyer.com).

**Чтобы задать место назначения отчета и сохранить отчет:**

1. Выберите из списка доступных подключений Data Locker в вашем аккаунте AppsFlyer.
   * Если в вашем аккаунте не определены подключения:
     * В вашем браузере откроется новая вкладка (со страницей AppsFlyer Data Locker)
     * Откроется окно **Новое подключение**. Следуйте <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-connections#завершить-подключение">этим инструкциям</Anchor> для создания подключения.
   * Если у вас уже есть подключения, но вы хотите использовать новое, нажмите на кнопку ![dcr_new_connection_data_locker_button.png](https://files.readme.io/9850a4b8ea4f40f6320903c545c51add7b90207538a27c83a3b02a41197ba567-14995870859281.png):
     * В вашем браузере откроется новая вкладка (со страницей AppsFlyer Data Locker)
     * Откроется окно **Новое подключение**. Следуйте <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-connections#завершить-подключение">этим инструкциям</Anchor> для создания подключения.
   * После создания подключения вернитесь на вкладку DCR в браузере и выберите только что созданное подключение из списка подключений Data Locker.
2. Нажмите **Save** (Сохранить), чтобы сохранить отчет.
3. Новый отчет теперь отображается на вкладке **Reports** (Отчеты) в **Data Clean Room.**
