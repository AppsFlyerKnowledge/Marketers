> **Краткий обзор.** Обогатите свои данные на уровне пользователей, сопоставив их с данными об атрибуции на уровне пользователей от AppsFlyer, чтобы создавать агрегированные отчеты и получать статистику, которые позволяют использовать ценность объединенных данных.

## Введение

На протяжении всей своей истории экосистема мобильного маркетинга использовала данные на уровне пользователей для получения статистики и оптимизации рекламных кампаний:

1. Медиа-источники предоставляли данные на уровне пользователей поставщикам услуг по измерению атрибуции (например, AppsFlyer), которые использовали их для атрибуции, а затем передавали рекламодателям.
2. Рекламодатели сопоставляли эти данные на уровне пользователей со своими собственными данными (например, из BI или CRM-систем), затем анализировали и группировали их по мере необходимости, чтобы получить совокупные сведения, необходимые для оптимизации кампаний.

С наступлением эры конфиденциальности пользователей доступ к данным о пользователях из медиа-источников стал существенно ограничен:

1. Медиа-источники предоставляют данные на уровне пользователя поставщикам услуг по измерению атрибуции (например, AppsFlyer), которые используют их для атрибуции; **однако теперь им запрещено передавать эти данные на уровне пользователя рекламодателям**.
2. В результате рекламодатели не могут сопоставить данные об атрибуции на уровне пользователей со своими собственными данными, как это было раньше, что не позволяет им получить необходимые сведения.

Это именно та «слепая зона», которую призвано исправить решение Data Clean Room (DCR) от AppsFlyer.

### Как это работает?

Вместо того чтобы передавать рекламодателю данные об атрибуции на уровне пользователя, чтобы ***рекламодатель*** сопоставил их со своими данными на уровне пользователя, ***DCR берет на себя работу по сопоставлению*** данных атрибуции на уровне пользователя с данными рекламодателя на уровне пользователя — по сути, перекладывая эту ответственность на AppsFlyer. Затем DCR анализирует и группирует эти данные, после чего передает их рекламодателю в агрегированном виде. Это позволяет рекламодателю получить необходимые ему агрегированные данные, **сохраняя конфиденциальность пользователей**.

### Как DCR получает данные?

В настоящее время DCR использует 2 различных типа данных:

* **Пользовательские исходные данные:** данные на уровне пользователя, загруженные в облачное хранилище для использования DCR. Эти данные поступают из внутренних систем рекламодателя (например, BI- или CRM-систем).
* **Данные атрибуции:** Данные на уровне пользователей, предоставленные AppsFlyer медиа-источниками для атрибуции

### Что делает DCR с полученными данными?

DCR работает в соответствии со стандартными принципами работы с базами данных. Другими словами, он объединяет данные из разных таблиц (или **источников**) в единый набор данных. Этот единый набор данных затем используется для создания **отчетов**, в которых используются объединенные данные:

* Для того чтобы сопоставить данные из разных источников и объединить их в единый набор, каждый источник должен иметь хотя бы одно общее с другим источником поле, идентифицирующее уникального пользователя приложения (**идентификатор**).
* Используя идентификаторы для сопоставления ваших данных на уровне пользователя с данными об атрибуции пользователя, DCR создает объединенный набор данных на уровне пользователя.
* Затем, чтобы предоставить информацию, сохраняя конфиденциальность пользователей, DCR обрабатывает эти данные для создания **агрегированных отчетов,** сгруппированных по определенным вами характеристикам (**параметрам**).

## Терминология DCR

Ниже приведены некоторые часто используемые термины DCR:

* **Коннектор:** Ваша (принадлежащий рекламодателю) корзина AWS или GCS, в которой хранятся данные DCR. Коннектор может включать папки для исходных данных, поступающих в DCR, и/или места назначения для отчетов на основе данных от DCR. Вы можете использовать один или несколько коннекторов для передачи данных в DCR и из него.
* **Источники:**
  * **Источник рекламодателя:** Ваш файл с данными первой стороны, который загружается в DCR (предназначен для сопоставления и обогащения данными атрибуции AppsFlyer). Новые версии исходных файлов можно загружать для обработки не чаще, чем раз в 6 часов. Когда вы задаете источник в платформе AppsFlyer DCR, вы определяете его **структуру** и **местоположение**:
    * **Структура источника:** Список полей данных в источнике и категория, которую вы присваиваете каждому из них для использования в отчетах (идентификатор, показатель или метрика).
    * **Расположение источника:** Папка облачного сервиса, из которой AppsFlyer получает исходный файл при каждом обновлении. Эта папка находится внутри корзины («коннектора»).
  * **Данные атрибуции:** Данные атрибуции на уровне пользователя из вашего аккаунта AppsFlyer (используются для сопоставления и обогащения данных рекламодателей в DCR)
* **Отчет:** Файл данных, исходящий из DCR после обработки. Отчеты создаются каждый раз, когда загружаются новые версии соответствующих исходных файлов. Когда вы настраиваете отчет в платформе AppsFlyer DCR, вы определяете его **структуру** и **место назначения**:
  * **Структура отчета:** Укажите источники рекламодателей и данные атрибуции, которые будут использоваться при создании отчета, идентификаторы, по которым они будут объединены, метрики, которые будут включены, и показатели, по которым будет сгруппирован отчет.
  * **Место назначения отчета:** Папка облачного сервиса, в которую AppsFlyer отправляет отчет при каждой обработке. Эта папка находится внутри корзины («коннектора»).

## Работа с DCR (процесс настройки)

AppsFlyer Data Clean Room (DCR) очень гибок в плане типов данных, которые вы хотите загружать, отчетов, которые вы получаете, а также сроков и частоты обработки. По этой причине решение предполагает довольно значительный процесс планирования и настройки, в котором, скорее всего, будут участвовать несколько человек в вашей организации.

Выполните следующие шаги, чтобы настроить DCR в соответствии с потребностями вашей организации:

1. Подумайте, какие отчеты вы хотите получать от DCR. Эти отчеты являются результатом обогащения ваших источников рекламодателя данными об атрибуции AppsFlyer. Определите источники данных от первой стороны, которые необходимо загрузить в DCR для создания этих отчетов.
2. <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-setting-up-cloud-services">Создайте базовую структуру облачного хранилища</Anchor> для поддержки этих источников и отчетов.
3. Определите запросы, которые будут извлекать данные и создавать файлы исходных данных; создайте прототипы файлов исходных данных.
4. Разработайте автопроцесс, который будет извлекать данные, создавать вложенные папки источников и регулярно загружать источники и <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-sources#_success-files">файлы \_SUCCESS</Anchor>.
5. Настройте <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-sources">источники</Anchor> в платформе AppsFlyer DCR.
6. Настройте <Anchor target="_blank" href="/marketers/ru/docs/data-clean-room-working-with-reports">отчеты</Anchor> в платформе AppsFlyer DCR.
7. Разработайте автопроцесс, который будет импортировать отчеты после их доставки DCR в ваше облачное хранилище.
