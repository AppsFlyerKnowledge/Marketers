<div id="aggregated-advanced-privacy-aap-framework" />

## Фреймворк агрегированной расширенной конфиденциальности (AAP)

Предлагаемый AppsFlyer фреймворк агрегированной расширенной конфиденциальности (Aggregated Advanced Privacy, AAP) исключает возможность отслеживания пользователей в приложениях и на веб-сайтах, принадлежащих разным компаниям, а также возможность однозначно идентифицировать пользователя или устройство. AAP использует уровень конфиденциальности фреймворка App Tracking Transparency (ATT) Apple в качестве минимального ориентира для своих пороговых значений сохранения конфиденциальности.

Этот фреймворк дает возможность рекламодателям контролировать доступность данных атрибуции уровня пользователя через платформу AppsFlyer.

С выходом iOS 14.5, и когда применение ATT стало обязательным для Apple: если AAP включен, данные атрибуции уровня пользователя по пользователям iOS 14.5+, не давшим согласие, недоступны рекламодателям и партнёрам. **Примечание**: Даже если AAP отключён, данные на уровне пользователя нельзя использовать для однозначной идентификации устройства.

AAP не влияет на доступность агрегированных данных атрибуции и аналитических отчетов для рекламодателей и партнёров.

<div id="aap-impacted-features" />

### Функции, на которые влияет AAP

Если AAP включен, это влияет на сырые данные, и некоторые поля будут ограничены («restricted») или недоступны. Будут затронуты данные, предоставляемые следующими инструментами:

* Отчет Data Locker
* Pull API необработанных данных
* push
* Страница экспорта Дэшборда
* Постбэки на сети
* <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_work_flow#legacy-use-only-gcd-api-for-deep-linking">API для получения данных о конверсиях (GCD)</Anchor> в контексте клиентского API для получения данных уровня пользователя

Включение AAP влияет на доступность данных следующим образом:

* **Данные атрибуции и мошенничество (Protect360):** <Anchor target="_blank" href="/marketers/ru/docs/about-raw-data-identifier-restrictions">Некоторые поля атрибуции ограничены или недоступны.</Anchor>
* **Данные о кликах, показах и заблокированных кликах (мошенничество):** <Anchor target="_blank" href="/marketers/ru/docs/about-raw-data-identifier-restrictions#identifier-restriction">Идентификаторы, связанные с пользователем и устройством</Anchor> недоступны.
* **Отложенный диплинкинг**: если вы реализуете отложенный диплинкинг в платных медиа, используйте <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/unifieddeeplink">API унифицированного диплинкинга (UDL)</Anchor>. Унаследованный API, который использует GCD, не может быть использован в контексте пользователей, не дающих согласие. В случае собственных медиа, отложенная глубокая ссылка для собственных медиа поддерживается через GCD и самый последний API отложенной глубокой ссылки.

## Принципы доступности данных в агрегированной расширенной конфиденциальности

Когда AAP применяется к данным конкретного пользователя, их доступность зависит от статуса ATT этого пользователя и медиа-источника, который его привлек.

**Определения:**

* **Данные атрибуции на уровне пользователя**: Данные записи, содержащие идентификаторы на уровне устройства, связанные с атрибуцией на уровне пользователя
* **Ограниченные данные атрибуции для рекламодателей:**
  * Доступно: Идентификаторы устройств. (IDFA доступен при наличии согласия пользователя).
  * Недоступно: Получение параметров атрибуции через ссылку атрибуции издателя (например, `pid` и `c`). <Anchor target="_blank" href="/marketers/ru/docs/about-raw-data-identifier-restrictions#unavailable-attribution-fields">Список полей, ограниченных и недоступных для рекламодателей</Anchor>, иначе говоря, ограниченный источник медиа.
* **Ограниченные данные атрибуции для партнеров:**
  * Доступно: Сводные данные о кампании.
  * Недоступно: данные уровня пользователя, по которым его можно идентифицировать, такие как AppsFlyer ID, пользовательские данные, ID клиента (CUID), ID клика, IDFA, IDFV, IMEI, User agent и IP-адрес.

Определенные здесь термины используются на схеме и в следующих разделах для описания данных, доступных рекламодателям и партнерам.

## Управление расширенной агрегированной конфиденциальностью

<div id="aap-central-switch" />

<Accordion title="Агрегированная расширенная конфиденциальность (AAP) — переключатель уровня приложения">

AAP — это переключатель на уровне приложения, который управляет настройками расширенной конфиденциальности для всех партнеров выбранного приложения. Переключатель AAP находится на странице **Настройки приложения**. Когда переключатель AAP включен, переключатели **Расширенная конфиденциальность** для всех партнеров выбранного приложения автоматически включаются и не могут быть изменены. Когда он выключен, рекламодатели могут перейти к каждой партнерской интеграции по отдельности и включить **расширенную конфиденциальность**.

![AAPcontrol.png](https://files.readme.io/ddc8140ada9278eab447ecdfa4d88c56e07a0ed54b10b71de1cc2352f9590d40-35847850639121.png)

<div id="aap-enabled" />

#### AAP включен

* Доступны агрегированные данные атрибуции. Например, на обзорных дэшбордах, в инструментах отчетности, таких как когортный отчет и Master API.
* [Настройки расширенной конфиденциальности партнёра](#partner-advanced-privacy-switch) включены и не могут быть изменены. Примечание! Они зафиксированы в положении.
* Доступность данных уровня пользователя рекламодателям и партнёрам ограничена, как указано в [предыдущем разделе](/docs/apply-aggregated-advanced-privacy-framework#принципы-доступности-данных-в-агрегированной-расширенной-конфиденциальности).

<div id="aap-disabled" />

#### AAP отключен

* Данные атрибуции уровня пользователя доступны рекламодателям.
* Режим расширенной конфиденциальности можно настраивать для каждого партнёра в индивидуальном порядке.

*Прежде чем отключать AAP, подумайте, не приведет ли это к тому, что данные атрибуции уровня пользователя станут доступны третьим лицам, и как они могут использовать эти данные. Проконсультируйтесь с юристом и другими специалистами по вопросу о том, как Apple определяет отслеживание. Информация в данной статье не может считаться рекомендациями юриста. Информация предоставляется только для ознакомления.*

**Чтобы настроить агрегированную атрибуцию, основанную на агрегированной расширенной конфиденциальности**:

1. В AppsFlyer в боковом меню выберите **Настройки** > **Настройки приложений**.
2. Включите или отключите фреймворк **агрегированной расширенной конфиденциальности (Aggregated Advanced Privacy)** в соответствии с необходимостью.
3. Нажмите **Сохранить**.

</Accordion>

<div id="partner-advanced-privacy-switch" />

<Accordion title="Расширенная конфиденциальность (AP) — переключатель уровня партнера">

Если AAP отключен, рекламодатели могут настроить режим расширенной конфиденциальности для каждой рекламной сети отдельно.

![APControl.png](https://files.readme.io/8e5a005cbadb5665cf255d39d6fa425298510f719b166c2013a2dfe57d4e982b-35847865312657.png)

**Чтобы отключить режим расширенной конфиденциальности для партнера:**

1. Убедитесь, что главный переключатель AAP на странице **Настройки приложения** выключен.
2. В боковом меню выберите **Сотрудничество** > **Активные интеграции**.
3. Выберите рекламную сеть.
4. На вкладке **Интеграция** выключите режим расширенной конфиденциальности.

**Изменение параметра AAP и его влияние на режим расширенной конфиденциальности партнера**

Как говорилось ранее, параметр AAP переопределяет заданную на уровне партнера настройку режима расширенной конфиденциальности (AP). Однако, если вы в дальнейшем отключите AAP (главный переключатель), настройки режима AP конкретных партнеров вернутся к прежним значениям. Например:

* Отключив AAP, вы отключили режим расширенной конфиденциальности (AP) у нескольких партнеров.
* Потом вы включили AAP. Как вы помните, когда AAP включен, он переопределяет настройки партнеров, и AP считается включенным у всех партнеров.
* Теперь вы снова отключили AAP. Начинают действовать настройки, заданные для партнеров. Поэтому у некоторых партнеров режим AP сразу будет выключен.

</Accordion>

## Влияние Агрегированной расширенной конфиденциальности на ваших партнёров

<div id="ad-networks" />

<Accordion title="Рекламные сети">

<div id="postbacks-to-ad-network-partners" />

#### **Постбэки к партнерам рекламной сети**

<Anchor target="_blank" href="/partners/ru/docs/advanced-privacy-guide-postback-macros-for-ad-networks">AAP влияет на обмен данными с рекламными сетями</Anchor> и согласуется с принципами AAP, применяемыми к рекламодателям в контексте рекламной сети. Обмен данными с рекламными сетями осуществляется через постбэки, которые будут разными для атрибутированной и неатрибутированной рекламной сети.

Описанные правила обмена данными применяются к конкретной рекламной сети, если включен один из следующих переключателей:

* AAP: переключатель на уровне приложения
* AP: переключатель на уровне партнера

<div id="postbacks-for-attributed-ad-networks" />

#### **Постбэки для атрибутированных рекламных сетей**

Тип постбэка для обмена данными с атрибутированной сетью зависит от согласия пользователя:

* **Пользователи, давшие согласие (на обработку данных):** регулярный постбэк с данными атрибуции уровня пользователя, включая идентификаторы.
* Пользователи, давшие согласие Постбэк расширенной конфиденциальности(AP) с ограниченными данными атрибуции. Он содержит данные кампании без идентификаторов.
  * **Необходимое условие:** чтобы рекламная сеть могла получать постбэки в режиме AP, она должна иметь интеграцию AP с AppsFlyer. Если интеграции нет, по пользователям, не давшим согласие, постбэки не отправляются.
  * **Исключение:** Для установок, атрибутируемых Apple Search Ads (ASA): когда рекламная сеть, не поддерживающая расширенную конфиденциальность, задает постбэк по установке как **Все медиа-источники и органический трафик**, Apple Search Ads (ASA) по-прежнему отправляет постбэк по установке в рекламную сеть, независимо от состояния переключателя расширенной конфиденциальности на стороне рекламодателя.

<Accordion title="Агентства">

**Доступность данных**: Влияние AAP на агентства аналогично влиянию на рекламодателей. Если агентству доступны сырые данные по конкретному приложению, и к данным определённого пользователя применяется AAP, они доступны как [ограниченные данные атрибуции для рекламодателей](/docs/apply-aggregated-advanced-privacy-framework#принципы-доступности-данных-в-агрегированной-расширенной-конфиденциальности).

**Агентство включает или отключает режим расширенной конфиденциальности рекламной сети:**

* Если AAP отключен, можно управлять режимом расширенной конфиденциальности каждого интегрированного партнёра.
* По умолчанию включать или отключать режим расширенной конфиденциальности могут только рекламодатели. Однако рекламодатель может явно разрешить агентству настраивать этот параметр для рекламных сетей, обслуживаемых этим агентством.

**Разрешение агентству настраивать режим расширенной конфиденциальности**

![agency_advanced_privacy.png](https://files.readme.io/ac4a1aae41e9e39b9759006db84ea14df7495d0a14c02df7dbfb8dd93a2d2c23-35847865322129.png)

**Чтобы разрешить агентству настраивать режим расширенной конфиденциальности**:

1. В боковом меню выберите **Сотрудничество** > **Активные интеграции**.
2. Выбирает агентство.
3. На вкладке **Разрешения** активируйте переключатель **Изменять** **настройки режима расширенной конфиденциальности**.
4. Нажмите **Сохранить.**
