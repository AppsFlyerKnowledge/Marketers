> **At a glance:** Кроссплатформенный отчет о конверсиях показывает полный путь пользователя к каждой кроссплатформенной конверсии, включая всю цепочку вовлеченности, которая способствовала конверсии, и контекст дохода, а не только последнюю точку взаимодействия.

## Об отчете

Кроссплатформенный отчет о конверсиях — это отчет о сырых данных, который содержит записи о конверсиях на уровне пользователя, связанные между платформами с помощью вашего <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/set-customer-user-id">идентификатора Customer User ID (CUID)</Anchor>. Это позволяет анализировать полный путь пользователя, который привел к конверсии, а не только последнюю точку взаимодействия.

Для получения дополнительной информации о процессе атрибуции на уровне пользователя и конфигурации см. <Anchor target="_blank" href="/marketers/ru/docs/beta-user-based-cross-platform-attribution">кроссплатформенная атрибуция на уровне пользователя</Anchor>.

## Поля отчета

Чтобы узнать, какие поля содержатся в отчете, загрузите <Anchor target="_blank" href="https://docs.google.com/spreadsheets/d/e/2PACX-1vRTFg6HXtHNYwegAjMysjybPbRk4IO8uflwvbGvR_xb11BcCrCWQ7i3xZD_Y2iiYSsx_MjTPN0E_Bmk/pub?gid=670907846&single=true&output=csv">образец отчета</Anchor>.

Образец отчета включает все поля отчета и их значения. Чтобы узнать определения полей, смотрите <Anchor target="_blank" href="/marketers/ru/docs/raw-data-field-dictionary">словарь полей</Anchor>.

Отчет содержит три группы полей:

* **Поля кроссплатформенной конверсии:** медиаисточник, кампания, рекламное объявление, гео, устройство, CUID, тип конверсии, доход, временная метка кроссплатформенной конверсии и связанные идентификаторы.
* **Поля ассистов (1, 2 и 3):** для каждой из трех позиций ассиста: соответствующие медиаисточник, кампания, группа объявлений, рекламное объявление, агентство, канал, тип и подтип вовлеченности, идентификатор сайта и время события. Для этих полей используется соглашение об именовании `<field>__assist_1`, `<field>__assist_2` и `<field>__assist_3`.
* **Поля обогащения:** поддерживают анализ lifetime value (LTV) на уровне пользователя и анализ на уровне события. Например, объедините эти поля с записями о конверсиях пользователя, чтобы построить представление LTV по каждому пользователю для разных платформ.

## Актуальность данных отчета

Отчёт выполняет пакетную обработку каждые 4 часа. Каждый запуск пакетной обработки обрабатывает события, поступившие в базу данных за предыдущий четырехчасовой интервал. Например, запуск пакетной обработки в 8:00 AM обрабатывает события, поступившие в базу данных между 3:00 AM и 7:00 AM.

Пакетная обработка распределяет события по соответствующим почасовым версиям. Например, события, поступившие в базу данных между 3:00 и 4:00 AM, отображаются в версии 3:00 AM.

> 📘 **Note**
>
> Обычно между фактическим возникновением события и его внесением в базу данных есть небольшая задержка. Отчет использует время внесения записи в базу данных, чтобы поддерживать точную и согласованную почасовую группировку.

### Пример: запуск пакетной обработки в 8 AM

| дата; | Версия отчета | Доступно в | Включает события, происходящие между | Включает события, поступившие в базу данных между |
| --- | --- | --- | --- | --- |
| 2025-10-01 | 3:00 | 9:00 | 2:00-4:00 | 3:00-4:00 |
| 2025-10-01 | 4:00 | 9:00 | 3:00-5:00 | 4:00-5:00 |
| 2025-10-01 | 5:00 | 9:00 | 4:00-6:00 | 5:00-6:00 |
| 2025-10-01 | 6:00 | 9:00 | 5:00-7:00 | 6:00-7:00 |

Несколько примечаний к этому примеру:

* Пакетная обработка не обрабатывает события за последний час перед запуском, чтобы оставить достаточно времени на обогащение событий связанным с ними CUID. В приведенном выше примере пакетная обработка в 8:00 AM обрабатывает события, поступившие в базу данных между 3:00 и 7:00. События, попавшие в базу данных между 7:00 и 8:00, не обрабатываются в рамках этого запуска.
* Отчет становится доступен через час после пакетного запуска, поскольку в течение этого часа внутренний процесс обновляет пакет. В примере выше пакетный запуск в 8:00 AM становится доступен в 9:00 AM.

## Подписаться на отчет

Чтобы подписаться на отчет:

1. В AppsFlyer в боковом меню выберите **Export** > **Data Locker**.
2. В панели **Содержимое Data Locker** прокрутите вниз до раздела **Расширенные отчеты**.
3. Выберите **Кроссплатформенные конверсии**.

## Доступ к данным отчета в вашем облачном хранилище

Путь к отчету состоит из следующей иерархии папок:

```text
<bucket-name>/<DataLocker connection name>/t=conversions_user_level_cross_platform/dt=<yyyy-mm-dd>/h=<hour>/
```

## Рекомендации для разработчиков бизнес-аналитики (BI)

При подключении базы данных или дэшборда к этому отчету учитывайте следующее:

* Каждая почасовая версия отчета содержит уникальные записи о конверсиях. Убедитесь, что вы выгружаете все отчеты каждый час или каждый день.
* Поля Assist (`__assist_1`, `__assist_2`, `__assist_3`) отражают вспомогательные вовлеченности, лежащие в основе каждой конверсии, на базе данных конверсии. Используйте их, чтобы восстановить последовательность точек взаимодействия, которая привела к каждой конверсии.
* Отчет содержит данные о доходе в трех валютах: `revenue_usd` (нормализованная), `revenue_value_original` (валюта события отчетности, см. `revenue_currency_original`) и `revenue_value_customer` (предпочтительная для вас валюта, см. `currency_customer`). Используйте тот вариант, который соответствует вашим потребностям в отчетности.
* Этот отчет не включает поля стоимости (cost, clicks, impressions). Вместо этого извлекайте их из <Anchor target="_blank" href="/marketers/ru/docs/set-up-and-use-roi360-cost-etl-reports">ETL-отчета по стоимости</Anchor>.
* Отчет предоставляет все данные приложения в одном файле. Используйте поле «Идентификатор приложения», чтобы разделить данные по приложениям, или настройте Data Locker на разделение по каждому приложению. Мы рекомендуем использовать <Anchor target="_blank" href="/marketers/ru/docs/data-locker-for-marketers#app-segregation">унифицированный тип сегрегации</Anchor>.
