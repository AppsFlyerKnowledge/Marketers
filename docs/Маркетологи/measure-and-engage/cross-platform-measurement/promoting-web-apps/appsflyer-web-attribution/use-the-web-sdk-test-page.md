> **At a glance:** Используйте тестовую страницу Web SDK, чтобы проверить установку Web SDK и запись событий в реальном времени. Запускайте его при первой интеграции SDK, а также каждый раз, когда добавляете или изменяете событие.

<div id="overview" />

## Информация о компании

Страница теста Web SDK открывает ваш веб-сайт в новой вкладке браузера с выделенной тестовой сессией. Вся активность Web SDK в этой вкладке, включая загрузки страниц, события и вызовы идентификатора, в реальном времени транслируется на тестовую страницу, где вы можете проверить каждое событие и его свойства. Это позволяет проверить вашу реализацию за несколько минут, не дожидаясь появления данных в отчетах.

Используйте ее, чтобы проверить следующее:

* Web SDK загружается на нужных страницах.
* Ваши события срабатывают с правильным именем, доходом и свойствами.
* Идентификатор ID пользователя клиента (CUID) задается после входа в систему или регистрации.

Запускайте тест при первой интеграции SDK или при изменении настроек события.

<div id="prerequisites" />

## Предварительные условия

Перед запуском теста убедитесь, что у вас есть:

* Веб-приложение в AppsFlyer. Дополнительную информацию см. в разделе <Anchor target="_blank" href="/marketers/ru/docs/adding-an-app-to-appsflyer#web">Создание веб-приложения в AppsFlyer</Anchor> статьи «Настройка измерения эффективности веб-кампаний».
* Web SDK AppsFlyer развернут на страницах, которые вы хотите проверить. Дополнительную информацию см. в разделе <Anchor target="_blank" href="/marketers/ru/docs/integrate-appsflyer-web-sdk">Интеграция Web SDK AppsFlyer</Anchor>.

<div id="run-a-test" />

## Запустить тест

Когда все предварительные условия выполнены, запустите тест следующим образом:

1. В AppsFlyer в боковом меню перейдите в **Настройки** > **Тестирование интеграции SDK**.
2. Выберите **Тест Web SDK**.
3. В диалоговом окне **Тестирование Web SDK**:
   * Выберите свое веб-приложение.
   * Поле **URL** предварительно заполняется URL-адресом веб-сайта, настроенным в приложении. По умолчанию тест запускается для этого URL-адреса. Измените его, чтобы протестировать определенную страницу.
4. Нажмите **Начать тест**. Ваш сайт откроется в новой вкладке браузера с отдельной тестовой сессией. Здесь ничего делать не нужно.
5. Вернитесь на страницу теста Web SDK. События на вкладке тестирования автоматически отображаются в таблице **События в реальном времени** по мере того, как вы просматриваете сайт и взаимодействуете с ним.

> 📘 **Note**
>
> Тест фиксирует активность только из той вкладки браузера, которую он открывает. Если открыть сайт напрямую, не запуская тест, события на этой странице не отображаются.

<div id="view-the-live-events-table" />

## Просмотр таблицы «События в реальном времени»

В каждой строке таблицы **События в реальном времени** отображаются временная метка, тип, название события и статус валидации.

| Тип события | Что это значит |
| --- | --- |
| `pageLoad` | Web SDK загрузил и записал посещение страницы. |
| `setCustomerUserId` | SDK задает идентификатор пользователя клиента (CUID). |
| `EVENT` | AppsFlyer зафиксировал определенное вами событие. В столбце **Название события** отображается название события, например покупка. |

Таблица **События в реальном времени** также поддерживает:

* **Сведения о событии:** Нажмите на строку, чтобы открыть панель Детали события и просмотреть все свойства, которые включает событие, например доход и значения события.
* **Поиск:** Используйте поле поиска, чтобы найти конкретное событие.
* **Экспорт:** Нажмите **Экспорт CSV**, чтобы загрузить результаты.

<div id="restart-or-clear-a-test" />

## Перезапуск или очистка теста

Используйте один из этих вариантов, чтобы перезапустить или очистить тест:

* **Перезапустить тест:** Очищает список событий и открывает новую вкладку браузера с новой тестовой сессией. Это можно использовать, чтобы начать новое тестирование.
* **Перезапустить с новым приложением / URL-адресом:** повторно открывает диалоговое окно настройки для тестирования другого веб-приложения или страницы.
* **Очистить журналы:** очищает только список событий. Текущая тестовая сессия и вкладка браузера остаются активными, поэтому новые события продолжают поступать.

<div id="common-testing-scenarios" />

## Распространенные сценарии тестирования

После каждого изменения настроек Web SDK или событий можно просто запускать тест. Это самый быстрый способ выявить проблемы до того, как они повлияют на ваши данные. Распространенные сценарии включают:

* **Первая интеграция Web SDK:** Откройте страницы, на которых вы установили SDK, и убедитесь, что для каждой из них появляется событие `pageLoad`.
* **Добавление или изменение события:** Вызовите событие на вашем сайте, например завершите покупку. Затем убедитесь, что в деталях события отображается строка EVENT с правильным названием события, доходом и свойствами.
* **Внедрение идентификатора пользователя клиента:** Зарегистрируйтесь или войдите на своем сайте и убедитесь, что появляется событие `setCustomerUserId`. Настройка CUID повышает точность атрибуции и объединяет пути пользователей на разных платформах.
