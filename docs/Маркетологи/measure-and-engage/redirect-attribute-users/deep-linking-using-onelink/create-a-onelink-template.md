> **Краткий обзор:** Создайте шаблон, который станет основой логики перенаправления для всех ссылок OneLink, которые вы создаете для различных маркетинговых кампаний. Шаблон необходим для создания ссылок и опыта конечных пользователей.

<div id="onelink-templates" />

## Шаблоны OneLink

<Embed title="Создание шаблона OneLink" typeOfEmbed="youtube" url="https://www.youtube.com/embed/d4AtCJ9122Q" providerUrl="https://www.youtube.com" />

Шаблон OneLink:

* Это не интерактивная ссылка для ваших конечных пользователей; это основа для создания множества настраиваемых ссылок. Обычно вам нужен только один шаблон на приложение (помимо тестирования), чтобы генерировать столько ссылок, сколько вы хотите, для всех ваших рекламных кампаний.
* Это место, где вы фиксируете свои решения о том, как перенаправлять пользователей, в зависимости от их платформы и от того, установлено ли у них ваше приложение.
* Представляет логику маршрутизации, лежащую в основе всех ссылок OneLink, которые вы создаете для различных маркетинговых кампаний. Сюда входят настройки перенаправления:
  * **Новых пользователей, у которых не установлено ваше приложение**: На правильный URL-адрес магазина приложений или веб-сайта
  * **Имеющихся пользователей, у которых уже есть ваше приложение**: Открытие приложения с помощью ссылок на приложения Android, универсальных ссылок iOS или схем URI. Это требует некоторой настройки разработчиком.
  * **Примечание**. Настройки перенаправления для веб-сайта или магазина приложений могут заменяться на уровне ссылки.

<Accordion title="Создание шаблона OneLink с логикой перенаправления для новых пользователей приложения">

**Чтобы создать шаблон OneLink:**

1. В AppsFlyer в боковом меню выберите **Вовлечение** > **Управление OneLink**.  
   Пакет OneLink – это функция уровня аккаунта, которая позволяет создавать шаблоны OneLink и настраиваемые ссылки для всех ваших приложений.  
   [![](https://files.readme.io/c5aacf61d1d1dc75ac7f0b9b6f681bb00e6521f6436fad3d2f073a42d4b0153f-4406696125713.png)](https://files.readme.io/c5aacf61d1d1dc75ac7f0b9b6f681bb00e6521f6436fad3d2f073a42d4b0153f-4406696125713.png) **Примечание**: Если у вас нет созданных шаблонов, откроется мастер онбординга. Следуйте указаниям в мастере и игнорируйте оставшуюся часть этой процедуры.
2. Нажмите значок меню > **Добавить шаблон OneLink**.  
   Откроется страница настройки шаблона OneLink.  
   <Image align="center" alt="OneLink_template_page_en-us.png" src="https://files.readme.io/d773d60cd2febcf6a8389e9586e8ca23a1515fc853e4d42d0db98661cacb387a-360009665478.png" />
3. В поле **Название шаблона OneLink** введите название.

   <div id="note" />

   > 📘 **Примечание**
   >
   > * Хорошее название шаблона OneLink должно включать **название приложения** (например, feed\_me), сценарий использования или интерфейс OneLink (например, pre\_launch\_landing\_page).
   > * Имя не должно содержать название кампании / канала или медиа-источник (поскольку это не фактическая ссылка для конечного пользователя, а просто базовый шаблон для создания множества ссылок), или название платформы (Android, iOS, поскольку шаблон OneLink обычно используется для разных платформ).
   > * Это название шаблона нужно только для внутреннего использования. Оно не влияет на ваши маркетинговые данные атрибуции и не видно пользователям.

4. В поле **Поддомен** введите имя <Anchor target="_blank" href="/marketers/ru/docs/appsflyer-knowledge-base-glossary#поддомен">поддомена</Anchor>.
   * Выберите поддомен, соответствующий вашему бренду. Например, если ваш сайт www.abcd.com, укажите abcd в качестве поддомена.
   * Пользователи увидят этот поддомен как часть URL-адреса ссылки. Например: `https://abcd.onelink.me/RPsv/37e5cd36`.
   * Когда на основе шаблона будут созданы настраиваемые ссылки, поддомен уже нельзя будет изменить.
   * Используйте только строчные буквы, цифры или дефис (-).
   * OneLink также поддерживает полностью брендированные домены, которые помогают улучшить эффективность кампании и повысить узнаваемость бренда. <Anchor target="_blank" href="/marketers/ru/docs/brand-onelink-with-your-domain">Подробнее</Anchor>
5. Выберите приложение для Android, приложение для iOS или и то, и другое.
6. (Необязательно) Включите Secure Shortlinks, если хотите защитить ссылки от перехвата с помощью дополнительных параметров. **Чтобы включить Secure Shortlinks:**

   В разделе **Secure Shortlinks** включите **Don't attribute clicks with added parameters**.

   Это означает следующее: после включения, если кто-то добавит параметр к короткой ссылке, созданной на основе этого шаблона, этот клик не будет атрибутирован. Пользователь перенаправляется в соответствии с настройками перенаправления шаблона; затрагивается только атрибуция.  

   **Пример:**

| Атрибуция | Результат |
| --- | --- |
| `[subdomain].onelink.me/[template_id]/[shortlink_id]` | Атрибуция выполняется как обычно. |
| `[subdomain].onelink.me/[template_id]/[shortlink_id]?param=value` | Был добавлен параметр, поэтому клик не атрибутируется. |

   **ПРИМЕЧАНИЯ**

   * Этот параметр применяется на уровне шаблона. Его нельзя включить или выключить для отдельных ссылок.
   * Для шаблонов, созданных до выхода этой функции, параметр отключен. Включите, если вам это необходимо. Для шаблонов, созданных после релиза, по умолчанию включено; отключите, если вам это не нужно.
7. Укажите, куда перенаправлять пользователей, **если приложение не установлено**.  
   * Если вы выбрали приложение для Android и приложение для iOS, шаблон по умолчанию настроен на отправку новых пользователей приложения в нужный магазин приложений.
   * Если вы выбрали только одно приложение, для Android или для iOS, шаблон будет настроен на отправку ВСЕХ пользователей (iOS и Android, новых и имеющихся) в один указанный пункт назначения.
   * Если выбрать приложение для Android вне Google Play, потребуется ввести URL-адрес, на который перенаправляются пользователи Android.
   * [Необязательно] **Перенаправьте пользователя в сторонние магазины приложений**, если приложение представлено в магазинах, отличных от Google Play. Убедитесь, что ваше приложение в сторонних магазинах имеет то же имя пакета, что и приложение для Android, выбранное в шаблоне OneLink.
   * [Необязательно] **Измените URL-адрес на другой**: В некоторых случаях вы можете предпочесть перенаправлять новых пользователей в мобильный веб-интерфейс, а не непосредственно в магазин приложений (или ваше приложение может отсутствовать в магазине). Для реализации введите этот URL-адрес в поле URL. **Внимание**: Если вы настроили и стороннюю переадресацию, и другой URL-адрес, по умолчанию будет перенаправление в сторонний магазин приложений.
   * [Необязательно] Включите опцию **Показывать блиц-приложение пользователям, использующим Частный узел** (доступно на iOS 14+). <Anchor target="_blank" href="/marketers/ru/docs/apple-app-clips-integration-guide">Подробнее о блиц-приложениях</Anchor>.
8. Пропустите раздел **Когда приложение установлено**. Об этом пойдет речь в [следующей процедуре](/docs/create-a-onelink-template#add-redirection-logic-for-existing-app-users).
9. [Необязательно] Изменить пункт назначения для **When link is clicked on desktop.**

* * В некоторых случаях пользователи могут перейти по вашей ссылке на настольном компьютере, особенно если она отправлена по электронной почте или в социальных сетях. Если вы ожидаете большой трафик с ПК по вашей ссылке, вы можете отправить этих пользователей не в магазин приложений, а на лэндинг, домашнюю страницу веб-сайта или на страницу, где они могут запросить ссылку на телефон по SMS.
* По умолчанию пользователи настольных компьютеров перенаправляются на веб- версию App Store или магазина Google Play – в зависимости от приложений, заданных в шаблоне.
  * * Чтобы изменить опцию магазина по умолчанию, выберите «Веб-URL для настольного ПК» и добавьте соответствующий URL-адрес веб-магазина. Добавьте домен магазина в список разрешенных для перенаправления.

10. [Необязательно] **Выберите приложения с других платформ**  
    Если у вас есть специальная версия приложения для следующего:
    * **Windows Phone**: активируйте переключатель и выберите приложение или выберите **Изменить URL-адрес на другой**.
    * **iPad**: включите переключатель и выберите приложение для iPad
    * **Amazon Kindle Fire**: активируйте переключатель и добавьте Amazon Store ASIN или URL-адрес страницы приложения.
11. Есть вопрос о шаблонах OneLink? Ознакомьтесь с разделом <Anchor target="_blank" href="/marketers/ru/docs/onelink-troubleshooting-and-faq#популярные-вопросы-о-шаблонах-onelink">Вопросы и ответы</Anchor>!

</Accordion>

<Accordion title="Логика перенаправления для существующих пользователей приложения">

Существующие пользователи приложения обычно ожидают, что их перенаправят непосредственно в приложение, а не в магазин приложений или на веб-страницу. Есть три технологии, позволяющие открыть приложение напрямую после клика:

* **iOS Uниверсальные ссылки**: Работают с iOS 9 и выше и обеспечивают удобное и безопасное взаимодействие при открытии приложения.
* **Android App Links**: Работают с Android 6 и выше и обеспечивают удобное и безопасное взаимодействие при открытии приложения. **Внимание**: Samsung OS не может открывать приложения с помощью Android App Links.
* **Схема URI**:  
  * Запасной метод:
    * Android: схема URI – эффективный альтернативный метод для тех случаев, когда приложение не открывается по ссылкам Android App Links, потому что они либо не работают, либо не заданы.
    * iOS: ограниченные альтернативные возможности для тех случаев, когда приложение не открывается по универсальным ссылкам iOS, потому что они либо не работают, либо не заданы. <Anchor target="_blank" href="/marketers/ru/docs/uri-scheme-fallback-for-ios">Подробнее</Anchor>
  * Основной способ открытия приложений на устройствах Samsung.
  * Это адрес, при переходе на который открывается ваше приложение, если оно установлено. Они похожи на ссылки на веб-сайты, но вместо веб-сайтов открывают приложения.
  * Должны быть одинаковыми для iOS и Android.

Для обеспечения наилучшего пользовательского интерфейса, безопасности и охвата устройств мы рекомендуем использовать как можно больше технологий. Если вы подключите все технологии для ссылок, OneLink автоматически применит лучший метод для каждого пользователя.

**Чтобы добавить логику перенаправления для имеющихся пользователей приложений в шаблон OneLink:**

1. В AppsFlyer в боковом меню выберите **Вовлечение** > **Управление OneLink**.
2. Выберите шаблон OneLink, который вы хотите изменить.
3. Нажмите на значок меню (⋮), затем нажмите **Редактировать шаблон OneLink**.
4. Прокрутите вниз до раздела **When app is installed** (Если приложение установлено). [![](https://files.readme.io/c0e8e5364f0b184f33d72e33f28df131d5a8bb6c377dc74f0ec190bcc6e63e75-18363965490833.png)](https://files.readme.io/c0e8e5364f0b184f33d72e33f28df131d5a8bb6c377dc74f0ec190bcc6e63e75-18363965490833.png)
5. Следуйте инструкциям для настройки iOS, Android и запасного варианта:

   <Tabs>
   <Tab title="Универсальные ссылки iOS">

   Универсальные ссылки имеют формат обычных веб-ссылок (например, https://yourbrand.onelink.me или https://www.yourbrand.com) и, таким образом, требуют настройки поддомена (это описано в [предыдущем руководстве](/docs/create-a-onelink-template#создание-шаблонов-onelink)). OneLink также поддерживает полностью <Anchor target="_blank" href="/marketers/ru/docs/brand-onelink-with-your-domain">брендированные домены</Anchor>, но для выполнения этого руководства это не обязательно.

   **Чтобы запустить приложение с помощью универсальных ссылок iOS**:

   1. Свяжитесь с вашим разработчиком iOS:
      * Дайте ему поддомен для этого шаблона OneLink.
      * Скажите ему, чтобы он следовал <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_ios_init_setup#procedures-for-ios-universal-links">этим инструкциям</Anchor>.
      * Разработчик вернет вам Team ID (также называемый префиксом Apple App ID, например, PF23MIWNTW).
      * Если приложение еще не опубликовано, разработчик также должен предоставить вам идентификатор пакета (например com.myapp.something).  
        <Image align="center" alt="" src="https://files.readme.io/c469a6c99515b0d76d075b0036ea118af16cd11b2ef134a63499acf0467895a0-18363965493521.png" />
   2. На странице шаблона OneLink нажмите **Change to launch the app using Universal Links**.
   3. В новом окне выберите **Launch the app using Universal Links** (Запуск приложения с помощью универсальных ссылок).
   4. В поле **Team ID** введите идентификатор команды, предоставленный разработчиком.
   5. Если приложение не опубликовано, введите также **идентификатор пакета**.
   6. Выберите **Сохранить изменения**.

   </Tab>

   <Tab title="Android App Links">

   App Links имеют формат обычных веб-ссылок (например, https://yourbrand.onelink.me или https://www.yourbrand.com) и поэтому требуют настройки поддомена (это описано в [предыдущем руководстве](/docs/create-a-onelink-template#создание-шаблонов-onelink)). OneLink также поддерживает полностью <Anchor target="_blank" href="/marketers/ru/docs/brand-onelink-with-your-domain">брендированные домены</Anchor>, но для выполнения этого руководства это не обязательно.

   **Прежде чем начать**:

   Запишите выбранный вами поддомен для этого шаблона OneLink.

   **Чтобы запустить приложение с помощью Android App Links**:

   1. Обратитесь к разработчику Android:   
      Попросите его сгенерировать отпечаток SHA256, следуя <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_android_init_setup#generating-a-sha256-fingerprint">этим инструкциям</Anchor>.  
      Обратитесь к разработчику Android:   
      пусть он сгенерирует отпечаток SHA256 согласно <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_android_init_setup#generating-a-sha256-fingerprint">этим инструкциям</Anchor>.  
       Например: `DC:65:43:67:F3:BD:02:52:AC:B4:50:F1:74:54: 23:49:4D:49:6C:E6:DF:56:BD:CB:53:06:11:5B:C9:4E:5D:0C`
   2. На странице шаблона OneLink нажмите **Change to launch the app using App Links** (Изменить на запуск приложения с помощью App Links).
   3. В новом окне выберите **Launch the app using App Links** (Запуск приложения с помощью App Links).
   4. В поле **отпечатка SHA256** введите отпечаток SHA256 от вашего разработчика.  
      Появится автоматически сгенерированный код для фильтра намерений.
   5. Обратитесь к разработчикам Android:   
      Передайте им автоматически сгенерированный код intent-filter.  
      Попросите их следовать <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_android_init_setup#adding-app-link-intent-filter-to-main-activity">этим инструкциям</Anchor> и подтвердить выполнение.

   </Tab>

   <Tab title="Схема URI">

   Схема URI в основном служит запасным вариантом как для пользователей iOS, так и для Android, и поэтому должна быть одинаковой.

   **Чтобы настроить схему URI для Android и iOS:**

   1. Свяжитесь с вашими разработчиками iOS И Android и вместе разработайте схему URI. Например: `feedmeapp://`

      <div id="h_01H9Q4E7VR4CAK0PJY269GQ9XJ" />

      <div id="tip" />

      > 👍 **Совет**
      >
      > * Ни Apple, ни Google не требуют, чтобы у схем приложений были уникальные имена. **Выберите имя схемы, уникальное для вашего бренда**, чтобы избежать конфликтов схем в разных приложениях. Хорошим названием схемы может быть идентификатор пакета приложения, например, **com.company.app**
      > * Чтобы OneLink работал и с iOS, и с Android, важно, чтобы **для обеих платформ была задана одна и та же схема для обеих платформ**. Вот инструкции для <Anchor target="_blank" href="https://help.contrast.co/hc/en-us/articles/200865293-URL-Scheme-Intro-for-App-Developers">iOS</Anchor> и <Anchor target="_blank" href="https://developer.android.com/training/app-links/deep-linking.html">Android</Anchor>.
      > * Схема URI не должна начинаться с http или https.

   2. Разработчик iOS должен внедрить схему URI в приложение согласно <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_ios_init_setup#procedures-for-uri-scheme">этим инструкциям</Anchor>.  
      **И**  
      Разработчик Android должен внедрить схему URI в приложение согласно <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_android_init_setup#procedures-for-uri-scheme">этим инструкциям</Anchor>.
   3. После этого разработчик подтверждает внедренную схему URI. Ожидайте, что это будет выглядеть следующим образом: `exampleapp://` или `exampleapp://home` или `exampleapp://main`, и т.д.
   4. На странице шаблона OneLink нажмите **Добавить схему URI для запуска приложения**.
   5. Выберите **Запуск приложения с помощью схемы URI**.
   6. Введите значение схемы URI.
   7. Выберите **Сохранить изменения**.
   8. Протестируйте схему URI (это можете сделать вы или ваш разработчик):
      1. Перейдите в <Anchor target="_blank" href="https://halgatewood.com/deeplink/">этот бесплатный общедоступный инструмент для тестирования</Anchor> на устройствах iOS и Android, на которых установлено ваше приложение.
      2. Нажмите на ссылку, сгенерированную в инструменте.  
         Если схема URI верна, приложение откроется.

   </Tab>
   </Tabs>

6. Нажмите **Update OneLink template** (Обновить шаблон OneLink).

<div id="note-1" />

> 📘 **Примечание**
>
> * Когда вы сохраняете или обновляете шаблон OneLink, AppsFlyer автоматически генерирует файл AASA и/или JSON-файл Digital Asset Links (Ссылки на цифровые активы) для проверки домена вашего приложения, а также размещает его. Это очень важно для правильной работы универсальных ссылок iOS и Android App Links.
> * Обновление шаблона OneLink может занять до 1 часа.

</Accordion>

<div id="customize-qr-codes" />

<Accordion title="Настройка QR-кода">

<Image align="center" alt="OnelinkQRFinal__1_.gif" src="https://files.readme.io/6eb996db8c8bcdb8ac46380151fc54c8ef5b686999aaaef3d1a951d627eadc70-11902870808081.gif" />

Вы можете настроить вид QR-кодов, созданных через OneLink:

* Добавление вашего логотипа в QR-код
* Изменение цвета QR-кода

**Внимание**: Настройка QR-кода выполняется на уровне шаблона, а не на уровне отдельной ссылки. Поэтому она затрагивает все QR-коды, созданные на основе отредактированного шаблона.

**Чтобы настроить вид QR-кода**:

1. В AppsFlyer в боковом меню выберите **Вовлечение** > **Настраиваемые ссылки OneLink**.
2. Наведите курсор на значок **Действия** шаблона, который требуется отредактировать, и нажмите **Настроить QR-код**.  
   Откроется редактор QR-кодов.
3. Введите URL-адрес файла с логотипом. Например, https://yourbrand.com/logo.png.  
   Требования к логотипу:

   * Формат PNG или JPG
   * Квадратный или круглый с прозрачным фоном
   * Минимальный размер: 400 x 400 пикс.
   * Для печати используйте изображение с максимальным разрешением
4. Задайте цвет QR-кода.
5. Нажмите **Сохранить**.

</Accordion>

<div id="h_favicon" />

<Accordion title="Настройте favicon для предпросмотра ссылок">

Favicon — это небольшой значок, который отображается рядом с заголовком вашей ссылки, когда ссылкой делятся в социальных сетях или приложениях для обмена сообщениями. Вы можете настроить его внешний вид, добавив здесь собственный значок. Он применяется ко всем ссылкам на основе этого шаблона и отображается на поддерживаемых платформах, когда для ссылки настроен пользовательский предпросмотр для социальных сетей.

<div id="note-2" />

> 📘 **Примечание**
>
> Этот favicon отображается в предпросмотре ссылок только на платформах, которые его поддерживают, и только если на уровне ссылки настроен **пользовательский предпросмотр (изображение и теги)**. <Anchor target="_blank" href="/marketers/ru/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#social-media-preview-og-tags">Узнать больше</Anchor>

**Чтобы настроить favicon для шаблона OneLink:**

1. В AppsFlyer в боковом меню выберите **Вовлечение** > **Управление OneLink**.
2. Выберите шаблон OneLink, который вы хотите изменить.
3. Нажмите значок меню (⋮), затем нажмите **Редактировать шаблон OneLink**.
4. Прокрутите страницу вниз до раздела **Favicon**.
5. В поле **Favicon Image URL** введите URL-адрес изображения favicon.
   * Поддерживаемый формат: ICO
   * Рекомендуемый размер значка: 32×32 или 64×64 пикселя
   * Размер файла не должен превышать 100 КБ.
   * URL-адрес должен быть общедоступным
6. Проверьте **предпросмотр**, чтобы убедиться, что значок отображается корректно.
7. Нажмите **Update OneLink template** (Обновить шаблон OneLink).

</Accordion>

## Спецификации и ограничения

<div id="key-traits-and-limitations" />

<Accordion title="Характеристики и ограничения">

| Специфика | Специфика |
| --- | --- |
| Агентства | Агентства не могут создавать шаблоны и ссылки OneLink. |
| Добавление и редактирование шаблонов OneLink | У пользователей аккаунта должно быть <Anchor target="_blank" href="/marketers/ru/docs/user-management">разрешение</Anchor> на добавление и редактирование шаблонов OneLink. |
| Шаблоны OneLink | До 600 шаблонов OneLink на аккаунт. |
| Десктоп | Когда в URL-адресе или шаблоне OneLink вы задаете перенаправление пользователей компьютеров на другой URL-адрес, этот веб-URL добавляется к ссылке в параметре `af_web_dp`. Если в вашей ссылке есть параметр `af_web_dp`, AppsFlyer не регистрирует клик, когда он приходит с компьютера. |
| Перенаправление в сторонние магазины приложений | В шаблоне OneLink можно задать несколько магазинов приложений, только если для всех магазинов имя пакета приложения одинаково. Подробнее о перенаправлении OneLink в сторонние магазины приложений для Android читайте <Anchor target="_blank" href="/marketers/ru/docs/bulletin-onelink-redirection-to-third-party-android-app-stores?query=3rd%20party%20store">здесь</Anchor>.<br /><br />**Примечание**:<ul><li>Huawei и другие сторонние магазины иногда требуют разные названия пакетов. В этом случае один и тот же шаблон OneLink нельзя использовать для нескольких магазинов приложений.</li><li>На некоторых устройствах Xiaomi есть магазин GetApps, который использует ту же схему URI, что и Google Play. Это означает, что если вы хотите перенаправить этих пользователей устройства в Google Play, но вашего приложения нет в Xiaomi, ссылка будет перенаправлять в GetApps.</li><li>Если имя пакета такое же, но отличается канал, переадресация будет работать, а атрибуция нет.</li><li><Anchor target="_blank" href="/marketers/ru/docs/set-up-multi-store-android-attribution">Узнайте подробнее</Anchor> об атрибуции и данных сторонних магазинов приложений.</li></ul> |
| Обновление шаблона | <ul><li>Внесение изменений в конфигурацию шаблона OneLink занимает до 1 часа.</li><li>Шаблоны Onelink нельзя редактировать, если связанное с ними приложение было удалено из аккаунта. В этом случае вы можете:<ul><li>Создать новый шаблон.</li><li>Обратиться к своему менеджеру по работе с клиентами AppsFlyer или написать нам по адресу hello@appsflyer.com, чтобы восстановить удаленное приложение.</li></ul></li></ul> |
| YouTube video player | См. <Anchor target="_blank" href="/marketers/ru/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#chrome-browser-on-ios">здесь</Anchor>. |

</Accordion>

Есть вопрос о шаблонах OneLink? Нажмите **Сохранить шаблон OneLink**. Обновите шаблон, если он отредактирован.   
Ваш шаблон OneLink создан, теперь его можно использовать для создания множества различных интерактивных ссылок (см. <Anchor target="_blank" href="/marketers/ru/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink">Ссылки OneLink и клиентский опыт</Anchor>).
