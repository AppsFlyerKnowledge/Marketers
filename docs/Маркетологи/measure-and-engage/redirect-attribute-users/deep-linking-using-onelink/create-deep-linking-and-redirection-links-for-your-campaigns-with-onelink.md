> **Краткий обзор:** Создавайте ссылки OneLink, которые обеспечивают пользователям именно тот опыт, который нужен вам. Пользователи, нажавшие на ссылку, перенаправляются в нужный магазин приложений, на веб-адрес или в само приложение, и происходит атрибуция.

## Ссылки OneLink и клиентский опыт

<Embed title="Ссылки OneLink для ваших кампаний" typeOfEmbed="youtube" url="https://www.youtube.com/embed/KZBrxGEjVUE" providerUrl="https://www.youtube.com" />

Пользователи взаимодействуют с вашим брендом через множество различных точек соприкосновения в интернете и офлайн. Независимо от того, откуда приходят ваши пользователи, вы можете создать ссылку, которая обеспечивает им идеальный опыт, от клика до установки приложения, диплинкинга и отложенного диплинкинга.

Шаги, необходимые для настройки ссылки, подробно описаны в следующем разделе, но в основном они включают следующее:

* Выбор клиентского опыта
* Общие настройки
* Конкретные настройки
* Настройки диплинкинга и переадресации
* Настройка дополнительных параметров

**Чтобы создать ссылку OneLink с определенным клиентским опытом:**

1. В AppsFlyer в боковом меню выберите **Вовлечение** > **Управление OneLink**.
2. Выберите **шаблон OneLink**, к которому нужно добавить ссылку.
3. Нажмите **Добавить ссылку**.
4. Выберите [опыт](/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#experiences), который вы хотите создать для своих пользователей:
5. Выберите медиа-источник или укажите настраиваемый. Это медиа-источник, под которым в AppsFlyer отражаются данные. Медиа-источник включается в вашу ссылку как значение параметра `pid`.

   <div id="note" />

   > 📘 **Примечание:**
   >
   > AppsFlyer блокирует ссылки атрибуции, которые используют зарезервированные имена<Anchor target="_blank" href="/marketers/ru/docs/self-reporting-networks-srns#srn-интегрированные-с-appsflyer">SRN</Anchor> в качестве значений PID в собственных медиа-источниках, таких как электронная почта и SMS. Это ограничение не применяется к ASRN.

6. Нажмите **Далее**.
7. Заполните раздел [Общие настройки](/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#general-settings).
8. Нажмите **Далее**.
9. [Необязательно] Выполните процедуры, относящиеся к создаваемому пользовательскому опыту:

   

| Опыт | Опции |
| --- | --- |
| <ul><li>Из соцсетей в приложение (social-to-app)</li><li>Из СМС в приложение (text-to-app)</li><li>В приложение по рекомендации (referral-to-app)</li><li>Настраиваемая ссылка</li></ul> | <ul><li>[Превью в социальных сетях](/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#social-media-preview-og-tags)</li><li>[Лендинг для приложения соцсети](/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#social-app-landing-page)</li></ul> |
| Из почты в приложение (email-to-app) | Если вы используете ESP, следуйте <Anchor target="_blank" href="/marketers/ru/docs/email-service-provider-esp-integration-guide">инструкциям по интеграции для ESP</Anchor>. |
| Из приложения в приложение (app-to-app) | Вы можете создавать динамические ссылки, которые работают в нескольких приложениях, с помощью <Anchor target="_blank" href="/marketers/ru/docs/cross-promotion-attribution-for-marketers">перекрестной рекламы</Anchor>. |
| В приложение по рекомендации (referral-to-app) | <ul><li>[Превью в социальных сетях](/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#social-media-preview-og-tags)</li><li>[Лендинг для приложения соцсети](/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#social-app-landing-page)</li><li>Вы можете динамически создавать реферальные ссылки с помощью SDK в своем приложении, <Anchor target="_blank" href="/marketers/ru/docs/user-invite-attribution">интегрировав приглашения пользователей</Anchor>.</li></ul> |

10. Нажмите **Далее**.
11. [Необязательно] В разделе **Диплинкинг и перенаправление** завершите [настройку диплинкинга / отложенного диплинкинга](/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#deep-linking-and-deferred-deep-linking). Пропустите этот раздел, если эта ссылка не предназначена для диплинкинга.
12. [Необязательно] В разделе **Диплинкинг и перенаправление** измените [настройки перенаправления](/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#redirection). Пропустите раздел, если настройки перенаправления из шаблона OneLink подходят.
13. Нажмите **Далее**.
14. В **Дополнительных параметрах** [добавьте к вашей ссылке предопределенные или пользовательские параметры](/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#additional-parameters) для более детального анализа. <Anchor target="_blank" href="/marketers/ru/docs/about-link-structure-and-parameters">Подробнее о параметрах атрибуции.</Anchor>
15. Нажмите **Создать ссылку**.
16. Убедитесь, что ваш <Anchor target="_blank" href="/marketers/ru/docs/set-up-your-domain-redirect-allowlist">список разрешенных перенаправлений</Anchor> содержит все домены, на которые вы хотите перенаправить пользователей.

<div id="experiences" />

<Accordion title="Опыт">

Вы можете создавать ссылки для следующего пользовательского опыта:

* **Из соцсетей в приложение (social-to-app)**: привлекайте пользователей в социальных сетях и направляйте их из постов в ваше приложение.
* **Из приложения в приложение (app-to-app)**: отправляйте пользователей в ваше приложение из рекламы, которую они видят в других приложениях.
* **По QR-коду в приложение (QR-to-app)**: используйте QR-коды, чтобы стимулировать установки приложения. Предлагайте пользователям отсканировать QR-код, когда они взаимодействуют с вашим брендом офлайн. Также QR-коды можно разместить в настольной версии сайта, в CTV- и ТВ-рекламе, чтобы направлять пользователей в приложение.
* **Из почты в приложение (email-to-app)**: используйте поставщиков электронной почты (ESP), чтобы взаимодействовать с пользователями по email и направлять их в приложение из папки Входящие.
* **Из СМС в приложение (text-to-app)**:  создайте ссылки для СМС-кампаний и рассылок и привлекайте пользователей с помощью текстовых сообщений.
* **В приложение по рекомендации (referral-to-app)**: Создавайте ссылки, с помощью которых пользователи и инфлюенсеры смогут приглашать других людей в ваше приложение или делиться контентом из приложения, например статьями.
* **Настраиваемая ссылка**: Для путей пользователей, которые не соответствуют ни одному из вышеупомянутых, можно создать настраиваемую ссылку OneLink. Тогда независимо от того, откуда приходят ваши пользователи — с настольных или мобильных компьютеров, онлайн или офлайн, из собственных или платных медиа, — вы сможете легко направить их в нужное место.

</Accordion>

<div id="general-settings" />

<Accordion title="Общие настройки">

Общие настройки — это раздел для создания ссылки OneLink, который применяется ко всем клиентским опытам.

**Чтобы завершить общие настройки**:

1. [Необязательно] Измените название медиа-источника.
2. [Необязательно] Измените название кампании.
3. [Необязательно] Включите **Ретаргетинг**, если планируете использовать ссылку для ретаргетинга имеющихся пользователей.

   Тогда вы сможете видеть повторное вовлечение пользователей, нажавших на вашу настраиваемую ссылку.

   Имеющиеся пользователи, которые переходят по ссылкам без ретаргетинга (UA), также запускают приложение и имеют такой же пользовательский интерфейс. Однако их повторные вовлечения регистрируются как регулярные сессии, что значит, что невозможно измерить успех собственной медиа-кампании.

   <div id="important" />

   > 🚧 **Важно!**
   >
   > Чтобы ретаргетинг работал, необходимо также включить ретаргетинг для приложения.

4. [Необязательно] Включите опцию **Игнорировать активных пользователей для ретаргетинга** и укажите окно неактивности.  
   К ссылке добавится параметр af\_inactivity\_window=[количество дней], и все пользователи, выполнявшие действия в течение указанного периода, игнорируются с точки зрения ретаргетинга.
5. Задайте интервал повторного вовлечения, чтобы определить, в течение какого времени после повторного вовлечения внутренние события приложения пользователя будут атрибутироваться медиа-источнику ретаргетинга.
   * Вы можете задать ценность, значение в днях (1-90), часах (до 23) или даже на весь период.
   * Окно повторного вовлечения добавляется в ссылку с помощью параметра af\_reengagement\_window.
6. [Необязательно] В подразделе **Брендирование ссылок**:
   * Выберите другой домен, отражающий ваш бренд. <Anchor target="_blank" href="/marketers/ru/docs/skan-modeled-data#revenue-ltv">Узнать больше</Anchor>
   * <span id="url-id"></span>Измените идентификатор URL, чтобы выделить предложение кампании. Идентификатор URL должен состоять не более чем из 50 символов и может содержать буквы и цифры. По умолчанию он состоит из 8 символов.

<div id="enable-retargeting-for-the-app" />

#### Включение ретаргетинга для приложения

Если ретаргетинг для приложения не был включен, нужно это сделать один раз. <Anchor target="_blank" href="/marketers/ru/docs/app-settings#настройки-атрибуции">Узнать больше</Anchor>

**Чтобы настроить ретаргетинг на уровне приложения:**

1. В AppsFlyer в боковом меню выберите **Настройки** > **Настройки приложения**.
2. В разделе **Атрибуция** включите **атрибуцию повторного вовлечения**.
3. Нажмите **Сохранить настройки**.

</Accordion>

<div id="social-media-preview-og-tags" />

<Accordion title="Предпросмотры в социальных сетях — теги OG">

При публикации ссылки теги Open Graph (OG) используются для формирования превью с заголовком, описанием и изображением.

Эти теги OG могут автоматически браться из URL-адреса сайта или магазина приложений, на который выполняется перенаправление. Однако иногда этот метод создания превью не работает. Поэтому мы рекомендуем настраивать превью для социальных сетей в ссылках OneLink. Это можно сделать в интерфейсе OneLink или, если ссылка создается не в интерфейсе OneLink, путем добавления в ссылку параметров тега OG.

**Чтобы создать превью для соцсетей в интерфейсе OneLink:**

1. В редакторе настраиваемых ссылок OneLink перейдите в раздел **Поделиться в социальных сетях**.
2. В разделе **Social media preview** выберите **Default preview (from website/store)**, чтобы использовать OG-теги из URL-адреса назначения, или **Custom preview (image and tags)**, чтобы задать свои.
3. Если вы выбрали **Пользовательский предпросмотр (изображение и теги)**, введите:
   * Название
   * Описание
   * URL-адрес изображения
4. [Необязательно] Проверьте поле **Template favicon**.
   * Здесь отображается favicon, настроенный в <Anchor target="_blank" href="/marketers/ru/docs/create-a-onelink-template#h_favicon">настройках шаблона</Anchor> OneLink. Он автоматически отображается в предпросмотре ссылок на поддерживаемых платформах.
   * Чтобы изменить favicon, перейдите в <Anchor target="_blank" href="/marketers/ru/docs/create-a-onelink-template#h_favicon">настройки шаблона</Anchor>.
   * Если favicon не отображается, значит, в шаблоне он еще не настроен. Вы все равно можете использовать Custom preview без favicon.

Чтобы добавить в ссылку параметры тега OG (если ссылка создана не в интерфейсе OneLink):

* Добавьте следующие обязательные параметры:
  * af\_og\_title (до 40 символов)
  * af\_og\_description (до 300 символов)
  * af\_og\_image

<div id="note-1" />

> 📘 **Примечание:**
>
> * Добавить параметры тега OG в ссылку можно вне интерфейса AppsFlyer.
> * Если вы добавляете отдельные теги OG для X (ранее Twitter), они переопределят обычное превью AppsFlyer.

</Accordion>

<div id="social-app-landing-page" />

<Accordion title="Лендинг для приложения соцсети">

<div id="important-1" />

> 🚧 **Важно!**
>
> Универсальные ссылки iOS теперь поддерживаются в Meta Ads.
>
> * Поскольку Meta теперь <Anchor target="_blank" href="/marketers/ru/docs/meta-ads-faq#are-ios-universal-links-and-android-app-links-supported-in-meta-ads">поддерживает универсальные ссылки</Anchor>, для платных объявлений Meta, поддерживающих универсальные ссылки, больше не требуется целевая страница приложения для соцсетей.
> * Целевая страница приложения для соцсетей необходима для собственных постов (неоплачиваемых объявлений).

Приложения для социальных сетей могут работать с перебоями у пользователей, которые используют универсальные ссылки iOS. Этого можно избежать:

* [**Рекомендуется**] Создать лендинг приложения для социальных сетей.  
  При создании лендинга для приложения в социальных сетях рекомендуем убедиться, что у вас настроена схема URI.  
  **Примечание:** X (ранее Twitter) не поддерживает URI-схемы для iOS. Для предотвращения проблем с запуском приложения следует использовать лендинг для приложений социальных сетей с Universal Links.
* [Альтернатива] <Anchor target="_blank" href="/marketers/ru/docs/onelink-troubleshooting-and-faq#принудительный-диплинкинг">Принудительное открытие приложения</Anchor> с помощью параметра `af_force_deeplink=true`.  
  **Внимание**: Этот параметр автоматически включается для Kakaotalk, Naver, Naver-Blog, Chrome, Weibo и Х (ранее Twitter).

Пользователи, нажимающие на объявления в приложениях для социальных сетей, перенаправляются на лендинг, созданный AppsFlyer. Оттуда они могут быть перенаправлены по диплинкам или продолжить установку приложения.

AppsFlyer предоставляет различные шаблоны лендинга приложений для социальных сетей. Расположение элементов в шаблонах фиксировано, но сами элементы можно настраивать, в том числе изображение или цвет фона, заголовки, тексты, иллюстрации, кнопки, тэги и др.

Лендинг приложений для социальных сетей может использоваться в следующих приложениях:

* Instagram
* Facebook / Facebook Messenger **(Примечание**: для Facebook и Facebook Messenger: если заданы и схема URI, и лендинг приложения для соцсетей, то лендинг не отображается.)
* LinkedIn
* Pinterest для iOS
* Snapchat
* X (ранее Twitter)
* WeChat

**Пользовательский опыт**

Когда пользователь нажимает на кнопку CTA на лендинге:

* **Если приложение установлено**: пользователь, нажавший на ссылку, запускает приложение.
* **Если приложение НЕ установлено**: пользователь попадает в соответствующий магазин приложений. После установки можно перенаправить пользователя по отложенному диплинку (см. статью [Диплинкинг и отложенный диплинкинг](/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#deep-linking-and-deferred-deep-linking)).

<div id="note-2" />

> 📘 **Примечание**
>
> Целевая страница приложения для социальных сетей поддерживает только короткий URL-адрес OneLink.

<div id="deep-linking-and-deferred-deep-linking" />

<Accordion title="Диплинкинг и отложенный диплинкинг">

Диплинкинг означает, что вы проводите ретаргетинг существующих пользователей приложения и направляете их непосредственно на конкретный экран в вашем приложении, без перехода сначала в магазин приложений или на главную страницу приложения. Эти пользователи атрибутируются как ретаргетинг.

Отложенный диплинкинг означает, что вы обеспечиваете новым пользователям такие же возможности диплинкинга, как и существующим пользователям. Но сначала новые пользователи направляются в магазин приложений, а после того, как они загрузят и запустят приложение, они направляются на конкретный интерфейс или страницу.

<div id="note-3" />

> 📘 **Примечание:**
>
> Настройка диплинкинга и отложенного диплинкинга требует участия ваших разработчиков Android и iOS.

**Чтобы настроить диплинкинг и отложенный диплинкинг для направления пользователей к определенному интерфейсу в приложении:**

1. Свяжитесь с вашими разработчиками iOS и Android и вместе определите **deep\_link\_value**для ваших ссылок.
   * Значение **deep\_link\_value** — это имя для определенного контента в приложении, на который будут перенаправлены пользователи. Разработчики реализуют желаемое поведение **deep\_link\_value** в коде.
   * Разработчики реализуют желаемое поведение в коде. Поделитесь с ними этим руководством, чтобы они могли понять технический процесс и посмотреть примеры.
     * Для <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_work_flow#implement-unified-deep-linking-udl">диплинкинга и отложенного диплинкинга</Anchor> новых или имеющихся пользователей, как уже установивших ваше приложение, так и пока этого не сделавших.  
       **Замечания по поводу UDL:**
       * Требуется SDK V6.1 и выше.
       * Окно атрибуции по кликам может составлять до 15 минут.
     * **Внимание**: Вместо UDL клиенты, уже применяющие OneLink для диплинкинга, могут использовать устаревшие методы для <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_android_gcd_legacy">Android</Anchor> и <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_ios_gcd_legacy">iOS</Anchor>.

       <div id="tips" />

       > 📄 **Советы**
       >
       > Значение **deep\_link\_value** может основываться на таких параметрах, как предлагаемый товар/услуга, идентификатор поста в соцсетях, путь URL и других.
       >
       > Важно совместно с разработчиками придумать наилучшую долгосрочную систему для **deep\_link\_value** и любых других параметров или значений. Это позволит свести к минимуму дополнительные обновления приложения. Обратитесь к разработчику с предложением использовать динамические значения, чтобы генерировать множество различных диплинков, ведущих на разный контент в приложении, без необходимости каждый раз менять код приложения.
       >
       > Например, для значения **deep\_link\_value** выбран тип фрукта, и разработчики сделали значения динамическими. Это означает, что вы можете вводить любые фрукты без необходимости дополнительной работы вашей команды разработчиков.
       >
       > `https://onelink-sample-app.onelink.me/H5hv?pid=Email&c=fruit_of_the_month``&deep_link_value=apples``...`
       >
       > `https://onelink-sample-app.onelink.me/H5hv?pid=Email&c=fruit_of_the_month``&deep_link_value=bananas``...`
       >
       > `https://onelink-sample-app.onelink.me/H5hv?pid=Email&c=fruit_of_the_month``&deep_link_value=peaches``...`

2. Получив подтверждение от разработчиков, что приложение работает в соответствии с выбранными параметрами и значениями, в разделе **Диплинкинг и перенаправление** на странице настройки ссылки введите **значение диплинка** в соответствии с тем, что вы решили с разработчиками.
3. [Необязательно] Если для диплинкинга требуется более одной интеракции в приложении (например, вы хотите направить пользователей к продукту и отдельно предложить им скидку), вы можете добавить к полезной нагрузке диплинка **дополнительное значение диплинка** (используя параметр deep\_link\_sub1). Вы можете добавить дополнительные параметры диплинка (deep\_link\_sub2-10) в разделе **Дополнительные параметры**.
   1. Свяжитесь со своими разработчиками iOS и Android и вместе распланируйте значения.
   2. Разработчики реализуют желаемое поведение в коде. Поделитесь этими руководствами по OneLink с разработчиками, чтобы они могли понять технический процесс и посмотреть примеры.

<div id="create-a-custom-impression-url" />

<Accordion title="Создание настраиваемой ссылки для отслеживания показов">

Настраиваемые ссылки для отслеживания показов позволят вам:

* Измерить <Anchor target="_blank" href="/marketers/ru/docs/about-conversion-rates#этапы-маркетинговой-воронки-и-коэффициенты-конверсии-1">коэффициент конверсии показов в клики</Anchor> для отображаемой рекламы.
* Получайте атрибуцию для показов.

**Необходимые условия:** Рабочий длинный URL-адрес OneLink. Короткие ссылки не поддерживаются.

**Кто задействован:**

Маркетолог и веб-разработчик

**Чтобы создать ссылки для отслеживания только показов:**

1. В AppsFlyer в боковом меню выберите **Вовлечение** > **Управление OneLink**.
2. Наведите курсор на дополнительные параметрыссылки, которую вы хотите проверить, и нажмите **Получить URL**.
3. Скопируйте длинный URL-адрес OneLink для редактирования.  
   Пример: `https://subdomain.onelink.me/j7rN?pid=email&c=Spring`
4. Замените поддомен (или весь брендированный домен, если он используется) на «impressions».    
   Пример: Если вы используете брендированную ссылку OneLink, которая выглядит как `https://app.alltrails.com/Waim?` , замените её на ссылку для показов `https://impressions.onelink.me/Waim?`.
5. Скопируйте URL-адрес для отслеживания показов и передайте вашему разработчику.
6. Попросите вашего веб-разработчика внедрить этот URL-адрес в логику веб-сайта.

Теперь у вас есть ссылка для отслеживания показов, которую можно использовать для подсчета показов на страницах вашего веб-сайта, **но не для атрибуции новых установок**. Для атрибуции по просмотрам выполните следующие шаги.

**Использование ссылок для отслеживания показов для атрибуции:**

1. Подготовьте ссылку для отслеживания показов, как описано выше.
2. Убедитесь, что <Anchor target="_blank" href="/marketers/ru/docs/measure-view-through-engagements">атрибуция по просмотрам включена</Anchor>.
3. [Необязательно] Если вы хотите изменить значение <Anchor target="_blank" href="/marketers/ru/docs/set-up-lookback-windows">окна атрибуции</Anchor> по просмотрам, по умолчанию составляющее 1 день, добавьте параметр `af_viewthrough_lookback` с новым значением. Например, `af_viewthrough_lookback=1d`.
4. Скопируйте URL-адрес для отслеживания показов и передайте вашему разработчику.
5. Попросите вашего веб-разработчика внедрить этот URL-адрес в логику веб-сайта.

Пример полной ссылки для отслеживания показов:

```http
https://impressions.onelink.me/j7rN?pid=email&c=Spring&af_viewthrough_lookback=1d
```

</Accordion>

<div id="deferred-deep-linking-with-ios-private-relay" />

<Accordion title="Отложенный диплинкинг на устройствах iOS с функцией «Частный узел» (Private Relay)">

C запуском iOS 15 Apple предоставляет пользователям iCloud+ функцию <Anchor target="_blank" href="https://www.macworld.com/article/348965/icloud-plus-private-relay-safari-vpn-ip-address-encryption-privacy.html">Private Relay</Anchor>, которая позволяет шифровать веб-трафик и скрывать свое точное местоположение, IP-адрес и содержимое веб-трафика. Если пользователи соглашаются на Private Relay, это может помешать атрибуции и отложенному диплинкингу. То есть, как только новый пользователь, не имеющий приложения, зайдет в App Store, установит и запустит приложение, Private Relay сможет предотвратить его отправку на определенную страницу в приложении.

Чтобы отложенный диплинкинг (DDL) продолжал работать должным образом, необходимо реализовать одно из следующих решений AppsFlyer:

* **[Рекомендуется] Решение на основе App Clip («блиц-приложений»)**: создайте блиц-приложение, которое предоставит вам данные атрибуции и будет направлять пользователей на указанный интерфейс App Clip аналогично отложенному диплинкингу. Блиц-приложение также может содержать сценарий для перенаправления пользователей в полную версию вашего приложения.
* **Решение на основе буфера обмена**: создайте лендинг, который копирует данные для отложенного диплинкинга из URL-адреса и корректно перенаправляет пользователя в приложение. **Внимание**: Это решение не помогает с атрибуцией.

<div id="app-clipbased-solution" />

<Accordion title="Решение на основе App Clip">

Это решение объединяет возможности коротких URL-адресов OneLink и технологии App Clips, доступной в iOS. Оно позволяет направлять пользователей на конкретные интерфейсы вашего продукта без установки полной версии приложения. Короткая ссылка OneLink предоставит вам данные атрибуции и будет направлять пользователей на указанный интерфейс блиц-приложения App Clip, аналогично отложенному диплинкингу. Блиц-приложение также может содержать сценарий для перенаправления пользователей в полную версию вашего приложения. **Внимание**: Если пользователи переустановят полное приложение из решения на основе App Clip, оно может быть зарегистрировано в AppsFlyer как органическая установка. 

<div id="flow" />

#### **Сценарий**

Сценарий работы отложенного диплинкинга на основе App Clips.

1. Рекламодатель создает мини-приложение и добавляет его в шаблон OneLink для пользователей, у которых включена функция Private Relay.
2. Пользователь нажимает ссылку OneLink.
3. Веб-обработчик AppsFlyer проверяет:
   * работает ли устройство под iOS 15+;
   * используется ли браузер Safari;
   * включена ли пользователем функция Private Relay.
4. Если AppsFlyer определяет, что это так, пользователю предлагается либо **Запустить мини-приложение**, либо **Открыть страницу в Safari**.
   * Если пользователь нажимает **Запустить мини-приложение**, отображается карточка App Clip.
   * Если пользователь нажимает «Открыть страницу в Safari», открывается целевая страница с предложением запустить App Clip.
5. Пользователь открывает блиц-приложение.
6. App Clip показывает пользователю интерфейс, заданный маркетологом и разработчиком приложения.
7. Если в App Clip есть сценарий перенаправления в полное приложение, пользователь попадет в App Store для загрузки полной версии приложения. После запуска приложения он увидит интерфейс, заданный разработчиком.

Необходимые условия: AppsFlyer SDK V6.4.0+

**Для настройки отложенного диплинкинга на основе App Clip**:

1. Сообщите разработчику, чтобы он следовал <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_ios_private_relay#app-clip-based-solution">инструкциям в хабе разработчиков для решений на основе App Clip</Anchor> и создал App Clip, обеспечивающий желаемый пользовательский опыт. и попросите создать мини-приложение для демонстрации пользователям нужного интерфейса. В нем также можно предусмотреть сценарий перенаправления пользователей в полную версию приложения.
2. Создайте или отредактируйте <Anchor target="_blank" href="/marketers/ru/docs/create-a-onelink-template">шаблон OneLink</Anchor> c <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_ios_init_setup#procedures-for-ios-universal-links">универсальными ссылками</Anchor> и [отложенным диплинкингом](/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#deep-linking-and-deferred-deep-linking).
3. В шаблоне OneLink активируйте **Display App Clip (Показывать блиц-приложение), если пользователь применяет Private Relay)**. Не включайте эту опцию, если у вас нет блиц-приложения.  
   **Внимание**: При внесении изменений в шаблон OneLink с универсальными ссылками, например, при добавлении (или удалении) App Clip, обновление файла AASA может занять несколько часов. Поэтому ссылки, которые вы создаете на основе этого шаблона, могут получить обновленную функциональность не сразу.
4. Создайте настраиваемую ссылку на основе шаблона OneLink.
5. В App Store Connect перейдите в раздел **App Clip Experience**, прокрутите вниз до **App URLs** (URL-адреса приложения) и введите или URL-адрес своего шаблона OneLink (домен + идентификатор шаблона, например: `yourbrand.onelink.me/GrbZ`), или конкретный короткий URL-адрес настраиваемой ссылки OneLink.  
    Например: `yourbrand.onelink.me/GrbZ`) или короткий URL конкретной пользовательской ссылки OneLink.  
    **Внимание**: Если вы укажете настраиваемую ссылку OneLink, решение на основе App Clip будет работать только у пользователей, переходящих по этой конкретной ссылке; другие ссылки, созданные на основе шаблона OneLink, работать не будут.

</Accordion>

<Accordion title="Решение на основе буфера обмена">

<div id="flow-1" />

#### **Сценарий**

Сценарий работы отложенного диплинкинга на основе буфера обмена.

1. Рекламодатель создает ссылку для отложенного диплинкинга с параметром `af_cp_lp=true`.
2. Пользователь нажимает эту ссылку.
3. AppsFlyer проверяет:
   * работает ли устройство под iOS 15+;
   * используется ли браузер Safari;
   * включена ли пользователем функция Private Relay.
   * Ссылка содержит параметр `af_cp_lp=true`.
4. Если AppsFlyer определит, что это так, загрузится лендинг со значком приложения, изображением и кнопкой с призывом установить приложение из App Store. Пользователь также видит сообщение, объясняющее процесс: URL-адрес копируется, чтобы обеспечить наилучший пользовательский опыт и перенаправить его на определенную страницу в приложении.  
   ![ios_15_ip_masking__1_.png](https://files.readme.io/c130314c98ebd42f50feaafd752c0cea954f42c5bfd99a6dbd94daf9e48c2ff4-30151216595345.png)
5. Пользователь нажимает **Get the app** (Установить приложение).
6. Пользователь направляется в App Store для установки приложения. Затем при первом запуске он перенаправляется на определенную страницу в приложении.

<div id="requirements" />

#### **Требования**

Чтобы реализовать отложенный диплинкинг с копированием и вставкой адреса лендинга, необходимо следующее:

* Пользователь должен использовать браузер Safari.
* Ссылка для отложенного диплинкинга должна содержать параметр `af_cp_lp=true`.
* SDK AppsFlyer для iOS V6+.
* Ваш разработчик приложений для iOS должен реализовать код, который вставляет данные для отложенного диплинкинга в URL-адрес из буфера обмена. Это не входит в функционал SDK AppsFlyer.
* Пользователь оставил флажок, установленный по умолчанию. Если флажок снят, URL-адрес не копируется, и отложенный диплинкинг работать не будет.

<div id="setup" />

#### **Настройки**

**Чтобы настроить решение DDL на основе буфера обмена**:

1. Ваш разработчик приложений для iOS должен:
   1. Следовать <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_ios_private_relay#clipboard-based-solution">инструкциям для разработчиков</Anchor> и интегрировать необходимый код в SDK AppsFlyer.
   2. Реализовать код, который вставляет данные для отложенного диплинкинга в URL-адрес из буфера обмена. Это не входит в функционал SDK AppsFlyer.
2. Добавьте параметр `af_cp_lp=true` в ссылки.   
   Для этого добавьте настраиваемый параметр в интерфейсе настраиваемой ссылки OneLink или просто добавьте этот параметр к любой из ваших ссылок.

Эти новые установки и повторные вовлечения атрибутируются SMS-кампании, что позволяет Марку проверить успех SMS-кампании в AppsFlyer.
