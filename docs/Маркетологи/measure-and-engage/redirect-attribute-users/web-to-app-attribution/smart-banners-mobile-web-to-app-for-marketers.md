## Смарт-баннеры

Cмарт-баннеры:

* **Отображаются в мобильной версии сайта вашего бренда**, чтобы повысить показатель конверсии пользователей с высокой мотивацией.
* Измеряют качество установок приложения, сделанных посетителями мобильной версии сайта.
* Обеспечивают точную мобильную атрибуцию Web Campaign-to-App (переходов в приложение из веб-кампаний) по ВСЕМ медиа-источникам, включая сети с самостоятельной атрибуцией (SRN).
* Выполняют <Anchor target="_blank" href="/marketers/ru/docs/appsflyer-attribution-model#типы-атрибуции-вовлечения-пользователей">атрибуцию по просмотрам, по кликам</Anchor> или по количеству показов:
  * **Клики:** пользователь нажимает на смарт-баннер и переходит к установке.
  * **Показы:** когда баннер загружается (пользователь видит баннер), в AppsFlyer отправляется событие показа.

Схема работы:

1. Пользователь нажимает на рекламное объявление и направляется в мобильную версию сайта рекламодателя.
2. В мобильной версии сайта рекламодателя [отображается](/docs/smart-banners-mobile-web-to-app-for-marketers#banner-group-display-logic) смарт-баннер.
3. Пользователь нажимает на смарт-баннер:
   * **если приложение не установлено**, пользователь перенаправляется в магазин приложений для установки этого приложения;
   * **если приложение установлено** и настроены универсальные ссылки iOS, Android App Links и/или ссылки URI, приложение запускается.
4. В приложении пользователь попадает на контент, связанный с рекламой.
5. Данный пользователь атрибутируется медиа-источнику, показавшему исходное рекламное объявление.

**Кто задействован**

* Веб-разработчику достаточно <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_smart_banner_v2#installation">вставить фрагмент кода в HTML-код сайта</Anchor>.
* Для всех остальных действий нужен только маркетолог.

---

**Необходимые условия**

* Аккаунт AppsFlyer, в котором есть хотя бы одно приложение.
* /docs/retargeting-attribution-guide#retargeting-settings

---

**Необходимое время**

Примерно 20 минут.

---

**Результат**

* При нажатии кнопки с призывом к действию (CTA) пользователи направляются в соответствующий магазин приложений или на веб-страницу в зависимости от типа их устройства.
* Пользователи мобильного приложения, нажимающие кнопку CTA, могут быть перенаправлены в приложение по диплинку.
* Пользователи атрибутируются по клику/установке к исходным медиа-источникам или к вашим собственным медиа-источникам.
* Эффективность баннера можно проверить на странице и карточках эффективности.

<div id="example" />

> 📄 **Пример**
>
> Марк работает маркетологом в успешной компании по доставке продуктов Feed Me.
>
> Марк хочет конвертировать посетителей мобильного сайта Feed Me в пользователей мобильного приложения.
>
> Для этого Марк использует смарт-баннеры с собственными визуальными эффектами и текстами.
>
> Смарт-баннеры работают на базе OneLink. Когда посетитель мобильного сайта нажимает кнопку CTA, **он автоматически попадает в соответствующий магазин приложений или на лэндинг**, где ему легко скачать приложение. Когда на кнопку CTA нажимает пользователь приложения, запускается приложение.
>
> Затем AppsFlyer **атрибутирует клики/установки к медиа-источнику и кампании, которые определил Марк**.

<div id="important" />

> 🚧 **Важно!**
>
> Используйте либо смарт-баннер AppsFlyer, либо iOS Safari Smart App Banner, но не оба одновременно. Использование баннеров обоих типов может вызвать проблемы с отображением мобильной версии сайта и расхождения в атрибуции.

## Настройки

Выполните следующие процедуры для настройки смарт-баннера, который:

* направляет пользователей с мобильной версии сайта через смарт-баннер в нужный магазин приложений или на нужный экран приложения в соответствии с типами их устройств;
* атрибутирует клики/установки вашим собственным медиа-источникам с помощью OneLink.

<div id="1-website-workplace-setup" />

<Accordion title="1. Настройка рабочей области сайта">

<div id="prepare-your-mobile-site-to-display-smart-banners-for-the-first-time" />

#### Подготовьте мобильную версию сайта к первому показу смарт-баннеров

1. В AppsFlyer в боковом меню выберите **Вовлечение** > **Из веба в приложение** > **Смарт-баннеры** > **К смарт-баннерам**.
2. Нажмите **Начать**. Мастер настройки проведет вас через все необходимые шаги (см. ниже). Для настройки других рабочих областей сайта см. ниже
3. Введите имя рабочей области сайта.
4. Нажмите **Создать**. Откроется рабочая область сайта.
5. Копируйте **фрагмент кода** баннера.
6. Внедрите фрагмент кода на свой сайт. Это нужно сделать один раз для каждого сайта.
   * Как добавить код через Google Tag Manager, Adobe Tag Manager, Shopify, Wix, Squarespace или WordPress, читайте в статье <Anchor target="_blank" href="/marketers/ru/docs/smart-banners-website-code-implementation-for-marketers">Внедрение кода смарт-баннеров на сайт (для маркетологов)</Anchor>.
   * Как добавить код через другие платформы или внести изменения в код в зависимости от задачи (например, чтобы добавить параметры, настроить диплинкинг, скрыть баннер или интегрировать PBA со смарт-баннерами, читайте в статье <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_smart_banner_v2">Внедрение кода смарт-баннеров на сайт (для разработчиков)</Anchor>.
7. [необязательно] Скопируйте **веб-ключ**. Этот ключ уже есть во фрагменте кода.
8. Нажмите **Продолжить**.

<div id="to-create-website-workplaces-after-the-first-time" />

#### Чтобы создать рабочие области сайта после первого раза

1. В AppsFlyer в боковом меню перейдите в раздел **ВовлечениеИз веба в приложение** > **Смарт-баннеры** > **Студия**.
2. Нажмите на меню опций.
3. Выберите **Новая рабочая область сайта**.
4. Введите имя рабочей области сайта.
5. Нажмите **Создать**. Откроется рабочая область сайта.
6. Копируйте **фрагмент кода** баннера.
7. Внедрите фрагмент кода на свой сайт. Это нужно сделать один раз для каждого сайта.
   * Как добавить код через Google Tag Manager, Adobe Tag Manager, Shopify, Wix, Squarespace или WordPress, читайте в статье <Anchor target="_blank" href="/marketers/ru/docs/smart-banners-website-code-implementation-for-marketers">Внедрение кода смарт-баннеров на сайт (для маркетологов)</Anchor>.
   * Как добавить код через другие платформы или внести изменения в код в зависимости от задачи (например, чтобы добавить параметры, настроить диплинкинг, скрыть баннер или интегрировать PBA со смарт-баннерами, читайте в статье <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_smart_banner_v2">Внедрение кода смарт-баннеров на сайт (для разработчиков)</Anchor>.
8. [необязательно] Скопируйте **веб-ключ**. Этот ключ уже есть во фрагменте кода.
9. Нажмите **Продолжить**.

<div id="2-banner-group-setup" />

<Accordion title="2. Настройка группы баннеров">

Группа баннеров содержит один или несколько баннеров. Здесь вы можете:

* Выбрать шаблон OneLink, используемый группой баннеров, в котором указаны мобильные приложения, на которые нужно перенаправлять посетителей вашего сайта.
* Задать определенную схему диплинкинга.
* Определить правила таргетинга, график, поведение и атрибуцию, используемые всеми баннерами в группе.
* Задать, какие страницы при их посещении активируют баннеры в группе.

**Чтобы настроить или продублировать группу баннеров:**

1. В AppsFlyer в боковом меню выберите **Вовлечение** > **Из веба в приложение** > **Смарт-баннеры**.
2. **Чтобы настроить группу баннеров в первый раз**
   1. Слева выберите **Add Banner Group** (Добавить группу баннеров).
   2. Выполните шаг 5 и далее.
3. **Чтобы настроить дополнительные группы баннеров**
   1. Перейдите на вкладку **Studio**.
   2. Нажмите **+ Новый**.
   3. Выполните шаг 5 и далее.
4. **Чтобы продублировать группу баннеров**
   1. Нажмите на значок **Дублировать** рядом со значком удаления.
5. Введите уникальное **имя для группы баннеров**. Оно должно отражать тему, в рамках которой эти баннеры объединены в группу (например, рекламируемое приложение).
6. Выберите шаблон OneLink для группы баннеров.
7. [необязательно] Задайте **схему URI** для группы баннеров в качестве резервного варианта для пользователей универсальных ссылок и Android App Links. Она редко оказывается нужна, так как по умолчанию значение берется из шаблона OneLink. Задавайте этот параметр для группы баннеров, только если вам нужно значение, отличное от указанного в шаблоне.
8. <span id="attributed-sources"></span>В основном и резервном параметре **Attributed sources** (Атрибутированные источники) укажите, каким источникам будут атрибутироваться новые установки при переходе с этой группы баннеров.   
    **Примечание по пересылке идентификатора клика:** FBCLID, GCLID, WBRAID и GBRAID автоматически пересылаются на исходящий URL, если они доступны на входящем URL. Для идентификаторов кликов Google, если параметр "ключевое слово" также найден, он помещает значение ключевого слова в исходящий URL в качестве значения af\_keywords.

   Обратитесь к следующей таблице, чтобы выбрать оптимальный вариант для настраиваемой ссылки.

<div id="param-table" />

| Вариант | Когда выбирать | Комментарии |

9. [Рекомендуется] Задайте значение используемого по умолчанию параметра атрибуции **Channel name** (Имя канала), чтобы все установки после перехода со смарт-баннера атрибутировались указанному каналу. Это позволяет агрегировать информацию из нескольких медиа-источников по одному каналу в **когортном отчете**, на **обзорном дэшборде**, в **отчете об удержании пользователей** и т. д.
10. <span id="2-banner-group-setup-step10"></span>[Необязательно] Включите **Ретаргетинг**, если вы планируете использовать группу баннеров для регистрации повторных вовлечений пользователей, кликнувших по баннеру. Подробнее о ретаргетинге см. в <Anchor target="_blank" href="/marketers/ru/docs/retargeting-attribution-guide">руководстве по атрибуции ретаргетинга</Anchor>.

    <div id="important-1" />

    > 🚧 **Важно!**
    >
    > Чтобы ретаргетинг работал, необходимо:
    >
    > * /docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#enable-retargeting-for-the-app


    Имеющиеся пользователи, которые переходят с баннера по ссылкам на базе OneLink без ретаргетинга (UA), также запускают приложение и имеют такой же пользовательский интерфейс. Однако их повторные вовлечения регистрируются как регулярные сессии, что значит, что невозможно измерить успех собственной медиа-кампании.
11. [Необязательно] Включите опцию **Игнорировать активных пользователей для ретаргетинга** и укажите окно неактивности. К ссылкам в группе смарт-баннеров добавится параметр af\_inactivity\_window=[количество дней], и все пользователи, выполнявшие действия в течение указанного периода, будут игнорироваться с точки зрения ретаргетинга.
12. Задайте интервал повторного вовлечения, чтобы определить, в течение какого времени после повторного вовлечения внутренние события приложения пользователя будут атрибутироваться медиа-источнику ретаргетинга.
    * Вы можете задать ценность, значение в днях (1-90), часах (до 23) или даже на весь период.
    * Окно повторного вовлечения добавляется в ссылку с помощью параметра af\_reengagement\_window.
13. <span id="dismissal-behaviour"></span>[Необязательно] Задайте значение параметра **Dismissal behavior** (Поведение после закрытия), т. е. минимальный временной интервал между закрытием пользователем одного баннера в группе и возможностью повторного показа этого баннера этому пользователю. Выберите один из вариантов:
    * По времени: 1 час, 1 день или 1 неделя.
    * Следующая сессия: то есть сессия, которая происходит в другой вкладке или в другом окне после того, как пользователь закрыл баннер.
    * Никогда: баннер больше не отображается. **Внимание**:
      * Если пользователь очищает кэш браузера или открывает сайт в режиме приватного просмотра, параметр Dismissal behavior (Поведение после закрытия) сбрасывается.
      * Поведение после закрытия применяется именно к тому баннеру, который пользователь закрыл. Другие баннеры в группе по-прежнему могут отображаться.
14. [Необязательно] Задайте значение параметра **Ограничение частоты показов**.  Ограничение частоты показов определяет, сколько раз каждый баннер в группе баннеров может быть продемонстрирован уникальному пользователю. Вы можете выбрать либо **Без ограничений** (когда баннеры показываются всегда), либо **Ограничить число показов баннеров**.

    Например, если группа состоит из трех баннеров, а ограничение частоты установлено на единицу, то каждый баннер в группе будет появляться один раз для каждого пользователя. В этом сценарии после трех посещений пользователь увидит все три баннера в группе. Однако, начиная с четвертого посещения, пользователь больше не увидит ни одного баннера из этой группы. При установке ограничения частоты на два раза каждый баннер в группе будет показан дважды для каждого пользователя, что в общей сложности потребует шести посещений, чтобы увидеть все баннеры в группе.
15. [Необязательно] Определите, в какой **операционной системе** показывать баннеры:
    * Все мобильные ОС.
    * Только Android или только iOS.
16. [Необязательно] **Определите время** активации группы баннеров: незамедлительно (по умолчанию) или задайте кампанию, ограниченную по времени.

## Просмотр данных об эффективности баннера

Вы можете просматривать и сравнивать эффективность баннеров на странице показателей эффективности.

Вы можете быстро проверить эффективность конкретных баннеров на индивидуальных карточках эффективности.

Данные об эффективности баннера включают следующее:

* Показы
* Закрытия баннера
* клики;
* Установки
* Реатрибуция
* Повторные вовлечения
* Показатель конверсии (CVR). Формула: Атрибуции / клики *100
* Показатель конверсии (CVR). Показатель кликабельности (CTR) Формула: Клики / показы *100

**Внимание**:

* Данные представлены по часовому поясу UTC.
* Обновление данных: <Anchor target="_blank" href="/marketers/ru/docs/about-data-freshness-and-timezone-support#continuous-aka-realtime">непрерывно</Anchor>.
* Данные отображаются по баннеру и шаблону OneLink. Это значит, что если баннер и шаблон OneLink настроены для нескольких приложений (например, сразу для Android и iOS), отображаемые данные об эффективности будут относиться к нескольким приложениям.
* CVR может быть выше ожидаемого, а иногда даже выше 100%, поскольку учитываются атрибуции как по просмотрам, так и по кликам.

<Accordion title="Логика отображения группы баннеров">

При определении того, какой смарт-баннер следует отображать (и следует ли), AppsFlyer принимает во внимание следующее:

## Вопросы и ответы

<div id="why-does-my-banner-not-display" />

<Accordion title="Почему мой баннер не отображается?">

Это связано с ограничением частоты показов, настроенным для группы баннеров. Ограничение частоты показов определяет, сколько раз баннер может быть продемонстрирован уникальному пользователю. Например, если частота показов ограничена тремя, а пользователь заходит на сайт четыре раза, в первые три визита он будет видеть баннер, а начиная с четвертого — не будет. Ограничение частоты показов можно отключить. Выберите значение или отключите ограничение частоты показов.

</Accordion>

<div id="can-i-use-my-own-font-for-my-banner" />

<Accordion title="Могу ли я использовать свой шрифт для баннера?">

Да. Вы можете установить для баннера свой собственный шрифт, используемый на вашем сайте, следуя [инструкциям в хабе разработчиков](https://dev.appsflyer.com/hc/docs/dl_smart_banner_v2#control-smart-banner-font).

* Для реализации требуется участие разработчика сайта.
* Шрифт будет применяться ко всем баннерам на сайте и ко всем текстовым элементам внутри баннера.
* Шрифт нельзя просмотреть в редакторе креативов.
* После внедрения [протестируйте свой баннер с креативом](/docs/smart-banners-mobile-web-to-app-for-marketers#4-testing).
* Если шрифт отображается некорректно, пересохраните баннер в [редакторе креативов](/docs/smart-banners-mobile-web-to-app-for-marketers#3-banner-setup).

</Accordion>

<div id="can-i-add-parameters-to-the-url-of-my-smart-banners" />

<Accordion title="Можно ли добавлять параметры в URL-адреса смарт-баннеров?">

Да, вызвав следующие две функции в вашем смарт-скрипте:

* <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_smart_banner_v2#showbanner">showBanner</Anchor>
* <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_smart_banner_v2#updateparams">updateParams</Anchor>

</Accordion>

<div id="do-smart-banners-support-deep-linking" />

<Accordion title="Поддерживают ли смарт-баннеры диплинкинг?">

Да. Чтобы его настроить, добавьте <Anchor target="_blank" href="/marketers/ru/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#deep-linking-and-deferred-deep-linking">параметр deep\_link\_value</Anchor> одним из следующих способов:

* В пользовательском интерфейсе AppsFlyer добавьте статический настраиваемый параметр атрибуции при [настройке баннера](/docs/smart-banners-mobile-web-to-app-for-marketers#3-banner-setup).
* Чтобы добавить параметр в URL-адрес перед показом баннера, используйте additionalParams в функции [showBanner](https://dev.appsflyer.com/hc/docs/dl_smart_banner_v2#showbanner%20target=).
* Чтобы добавить параметр в URL-адрес после показа баннера, используйте функцию <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_smart_banner_v2#updateparams">updateParams</Anchor>.

Убедитесь, что разработчик реализовал необходимое поведение deep\_link\_value.

</Accordion>

<div id="can-smart-banners-show-different-content-based-on-whether-or-not-users-have-the-app-installed" />

<Accordion title="Могут ли смарт-баннеры отображать различный контент в зависимости от того, установлено ли приложение у пользователя?">

Нет. Если вы не знаете, установлено ли приложение у пользователя, рекомендуем выбрать универсальный призыв к действию. Например: «Перейти к приложению» или «открыть приложение».

</Accordion>

<div id="do-original-incoming-url-parameters-remain-available-for-the-smart-banner-url-when-users-navigate-away-from-and-then-return-to-the-banners-landing-page" />

<Accordion title="Остаются ли доступными исходные параметры входящего URL для URL смарт-баннера, когда пользователи уходят с целевой страницы баннера, а затем возвращаются на нее?">

Да. Если в исходной входящей ссылке есть параметр utm\_source или pid, исходный URL-адрес сохраняется в течении сессии просмотра, и параметры применяются к исходящему URL-адресу баннера.

</Accordion>

<div id="can-i-set-my-banners-to-display-on-my-mobile-site-but-not-on-my-wrapperhybrid-app" />

<Accordion title="Можно ли настроить смарт-баннеры так, чтобы они отображались на мобильном сайте, но не были видны в приложении-обертке / гибридном приложении?">

Да. Если смарт-баннеры реализуются в приложении-обертке / гибридном приложении, и страница баннера загружается из приложения (а не из веб-браузера), не используйте функцию [showBanner](https://dev.appsflyer.com/hc/docs/dl_smart_banner_v2#showbanner%20target=), поскольку она показывает баннер в приложении. Вместо нее используйте функцию <Anchor target="_blank" href="https://dev.appsflyer.com/hc/docs/dl_smart_banner_v2#hidebanner">hideBanner</Anchor>.

</Accordion>

<div id="do-smart-banners-support-web-accessibility" />

<Accordion title="Поддерживают ли смарт-баннеры доступность в интернете?">

Мы стремимся к тому, чтобы все ваши пользователи, включая людей с ограниченными возможностями, могли получить полный доступ к смарт-баннерам и взаимодействовать с ним.

Поэтому мы стараемся обеспечить доступность наших смарт-баннеров в соответствии со стандартом WCAG 2.1, предоставляя соответствующие атрибуты HTML в элементах смарт-баннеров.

Однако определение соответствующих требований доступности для вашего использования смарт-баннеров является исключительно вашей обязанностью. Вы несете полную ответственность за то, чтобы используемые вами смарт-баннеры были доступны для всех пользователей в соответствии с требованиями к доступности веб-сайтов.

Обратите внимание, что различные изменения в смарт-баннерах могут повлиять на их соответствие требованиями доступности, в том числе, например, путем изменения цветов и размеров внутренних элементов баннера.

</Accordion>

<div id="if-a-smart-banner-is-deleted-from-a-banner-group-will-the-data-associated-with-that-banner-group-also-be-removed" />

<Accordion title="Если смарт-баннер будет удален из группы баннеров, будут ли удалены и данные, связанные с этой группой баннеров?">

Нет. Данные атрибуции не удаляются, если удаляется смарт-баннер.

</Accordion>
