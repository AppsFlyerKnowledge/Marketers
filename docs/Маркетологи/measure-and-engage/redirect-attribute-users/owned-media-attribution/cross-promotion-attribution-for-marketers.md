## Перекрестная реклама

Кампании перекрестной рекламы — один из лучших способов продвижения уже существующих приложений или направления пользователей к новым приложениям, выпущенным вашей компанией. Такие кампании могут повысить показатели конверсии и удержания по сравнению с большинством других источников трафика. Поскольку перекрестная реклама — это реклама в собственных медиа, вы можете использовать [сопоставление идентификаторов устройств](/docs/cross-promotion-attribution-for-marketers#атрибуция-кампании-перекрестной-рекламы) для детерминированной атрибуции новых установок. Атрибуция кампании перекрестной рекламы доступна для всех аккаунтов, независимо от вашего тарифного плана AppsFlyer.

На следующем изображении показан дэшборд продвигаемого приложения с разбивкой показателей для кампаний, проводимых в собственных медиа **(af\_cross\_promotion**) и других медиа-источниках. Вы можете видеть, что количество установок и коэффициент конверсии для кампании перекрестной рекламы значительно выше, чем для других медиа-источников.

[![CrossPromo_mediaSource](https://files.readme.io/e9a085a0fb987a559c4d35db956d3258c5ee783807eb5e2a222716f0259c1c16-4404613090321.png)](https://files.readme.io/e9a085a0fb987a559c4d35db956d3258c5ee783807eb5e2a222716f0259c1c16-4404613090321.png)

### Как работает перекрестная реклама?

1. Блок перекрестной рекламы выводится пользователю в существующем приложении, принадлежащем вашей компании. Реклама продвигает другое приложение, также принадлежащее вашей компании. Рекламный креатив может быть баннером, видеороликом или любым доступным для клика объектом.
2. [необязательно] <Anchor target="_blank" href="/marketers/ru/docs/cross-promotion-attribution-for-developers">SDK записывает и отправляет</Anchor> показы перекрестной рекламы в AppsFlyer.
3. Пользователь нажимает на рекламу.
4. SDK фиксирует клик и перенаправляет пользователя на страницу продвигаемого приложения в магазине приложений. Клик, записанный SDK, уже содержит рекламный идентификатор устройства.
5. После установки и запуска продвигаемого приложения на [дэшборде AppsFlyer](/docs/cross-promotion-attribution-for-marketers#дэшборд-продвигаемого-приложения) под медиа-источником **af\_cross\_promotion** появляется новый пользователь.
   * Чтобы изменить значение медиа-источника, разработчику необходимо добавить пользовательский параметр `pid` с нужным значением. **Примечание.** Для Android это работает только с SDK V6.4.2+.
   * Приложение, через которое продвигается установка, приложение-источник, отображается как **ID сайта**этого медиа-источника.
6. SDK автоматически генерирует событие в приложении.  
   Название события для Android —`af_cross_promotion`, а для iOS — `af_cross_promotion_clicked`.

## Атрибуция кампании перекрестной рекламы

AppsFlyer позволяет использовать сопоставление идентификаторов устройств в качестве метода атрибуции для регистрации и атрибуции установок от кампаний перекрестной рекламы. Вы можете атрибутировать как показы, так и клики, что позволит вам рассчитать <Anchor target="_blank" href="/marketers/ru/docs/about-conversion-rates#этапы-маркетинговой-воронки-и-коэффициенты-конверсии-1">коэффициент кликов</Anchor> или соотношение установок и показов.

Идентификатор устройства, используемый для сопоставления, зависит от следующего:

* Устройство пользователя и версия операционной системы
* Версия SDK AppsFlyer в приложении-источнике

| Сопоставление идентификаторов устройств для перекрестной рекламы | Версия устройства/ОС | Версия SDK | Примечания |
| --- | --- | --- | --- |
| IDFA | iOS 9 – 14.4 | V5.0.0+ |  |
| IDFV | iOS 14.5+ | V6.0.2+ | Идентификаторы IDFV собираются автоматически, от разработчика не требуется дополнительных действий. |
| ГАИД | Устройства Android с сервисами Google Play |  |  |
| OAID, Android ID, IMEI, Fire ID | Устройства Android без сервисов Google Play |  |  |

## Настройка перекрестной рекламы

Процесс настройки атрибуции кампаний перекрестной рекламы требует от маркетолога и разработчика совместной работы по внедрению дополнительного кода в SDK AppsFlyer.

Последовательность действий маркетолога и разработчика выглядит следующим образом:

| Шаг | Роль | Выручка | Подробности |
| --- | --- | --- | --- |
| 1 | Маркетолог | Определитесь с существующими приложениями, в которых будет проводиться кампания перекрестной рекламы. | Приложение-источник, атрибутированное к установке, будет отображаться в качестве **идентификатора сайта** на дэшборде продвигаемого приложения. |
| 2 | Маркетолог | Определите, хотите ли вы добавить <Anchor target="_blank" href="/marketers/ru/docs/about-link-structure-and-parameters">дополнительные параметры</Anchor>, такие как окно атрибуции, имя рекламного блока и параметры подписчика. Отправьте разработчику имена и значения этих дополнительных параметров. |  |
| 3 | Разработчик | Внедрите код в SDK. | <Anchor target="_blank" href="/marketers/ru/docs/cross-promotion-attribution-for-developers">Документация для разработчиков</Anchor>. |
| 4 | Маркетолог | На [дэшборде продвигаемого приложения](/docs/cross-promotion-attribution-for-marketers#дэшборд-продвигаемого-приложения) можно просмотреть трафик, полученный в результате кампании перекрестной рекламы, и соответствующим образом оптимизировать свои кампании. |  |
| 5 [Необязательно] | Маркетолог | Создайте [пользовательский дэшборд](/docs/cross-promotion-attribution-for-marketers#кастомизируемые-панели-управления) для сравнения трафика от кампании перекрестной рекламы и передачи данных пользователям аккаунта. |  |

## Просмотр данных о кампании перекрестной рекламы

### Дэшборд продвигаемого приложения

Дэшборд продвигаемого приложения позволяет определить, какие приложения-источники дают лучший трафик на продвигаемое приложение.

**Сравнение трафика из приложений-источников:**

1. Перейдите к **обзору**.
2. Выберите медиа-источник **af\_cross\_promotion** (или свой пользовательский медиа-источник).
3. Группируйте данные по **ID сайта**, чтобы просмотреть список приложений-источников.[![CrossPromo_SiteID](https://files.readme.io/e057085e90a4a8e56e6769a0af332785488d7757cb5430418e8db6b3cfa67210-4404613179025.png)](https://files.readme.io/e057085e90a4a8e56e6769a0af332785488d7757cb5430418e8db6b3cfa67210-4404613179025.png)

#### Анализ

Просмотр данных об установках, кликах, показах и коэффициентах конверсии нескольких существующих приложений, в которых размещается реклама одного и того же продвигаемого приложения, позволяет провести анализ смежности. Приложения-источники (ID сайта) с наилучшими показателями конверсии имеют наивысшую смежность с продвигаемым приложением, и их пользователи с наибольшей вероятностью установят его. Основываясь на этих данных, вы можете соответствующим образом оптимизировать свои кампании перекрестной рекламы.

> 📄 **Пример**
>
> Вы маркетолог игровых приложений в компании PlayIt Gaming International. У вас есть несколько успешных приложений, в том числе «Боулинг» (com.playit.bowling) и «Гольф» (com.playit.golfing). Вы только что запустили новое приложение под названием «Бильярд». Вы решили провести тесты перекрестной рекламы, чтобы узнать, сколько пользователей на самом деле нажимают на рекламу приложения «Бильярд» в одном из существующих приложений. Кампания хорошо работает в приложении «Боулинг», коэффициент конверсии составляет 7,92 %, поэтому вы решаете разместить рекламу и в приложении «Гольф».
>
> Если посмотреть на дэшборд, то можно увидеть, что коэффициент конверсии для приложения «Гольф» в 18,22 % намного выше, чем для приложения «Боулинг», что позволяет определить, что между приложением «Гольф» и продвигаемым приложением «Бильярд» существует большая смежность.
>
> [![CrossPromo_conversionRate](https://files.readme.io/347e3abacdff19a3c61b0a5712d3c656d33ddbf14988414ae2e13fc9c22f09b0-4404615475857.png)](https://files.readme.io/347e3abacdff19a3c61b0a5712d3c656d33ddbf14988414ae2e13fc9c22f09b0-4404615475857.png)
>
> Основываясь на этих данных, вы можете оптимизировать свою кампанию следующим образом:
>
> * Запустите полномасштабную кампанию перекрестной рекламы в приложении «Гольф».
> * Начните <Anchor target="_blank" href="/marketers/ru/docs/measure-view-through-engagements#процесс-атрибуции-по-просмотрам">атрибутировать показы</Anchor> в дополнение к кликам. Поскольку вы изначально настроили кампанию на измерение только кликов, установки пользователей, которые видят объявление без кликов, а затем устанавливают его, будут считаться органическими установками, а не неорганическими. Это означает, что у вас еще нет полной картины эффективности кампании для каждого приложения-источника.

### Кастомизируемые панели управления

Дэшборд продвигаемого приложения позволяет получить представление о том, какие приложения-источники обеспечивают наибольший трафик. Но как быть, если вы хотите оценить эффективность одного существующего приложения, которое используется для продвижения нескольких приложений? Именно здесь вам может помочь пользовательский дэшборд.

<Anchor target="_blank" href="/marketers/ru/docs/custom-dashboards">Пользовательский дэшборд</Anchor> позволяет просматривать информацию из нескольких продвигаемых приложений в одном месте, включая трафик от перекрестной рекламы. Кроме того, пользовательский дэшборд — это быстрый и простой способ передачи данных пользователям аккаунта.

> 📄 **Пример**
>
> Вы являетесь маркетологом компании eCommerce Apps, Ltd., и у вас есть очень успешное приложение под названием «Обувь». Сейчас вы запускаете 3 новых приложения: «Аксессуары», «Куртки и пальто» и «Спортивная обувь». Вы решили провести кампанию перекрестной рекламы в приложении «Обувь», чтобы выяснить, какое из ваших новых приложений лучше всего продвигается.
>
> Вы делите свою базу пользователей на 3 сегмента. Каждый раз, когда пользователь запускает приложение «Обувь», он/она видит 1 из 3 возможных рекламных объявлений: 1 для аксессуаров, 1 для курток и пальто и 1 для спортивной обуви.
>
> Чтобы просмотреть показатели для всех трех продвигаемых приложений в одном месте, вы создаете пользовательский дэшборд. На следующем изображении видно, что коэффициент конверсии в приложении «Спортивная обувь» составляет 20,23 %, а это значит, что у приложения «Обувь» гораздо большая смежность с приложением «Спортивная обувь», чем с двумя другими продвигаемыми приложениями.
>
