> **Краткий обзор.** Данные по эффективности SKAN обогащаются дополнительными точками данных. Аналогично данным на дэшборде SKAdNetwork. Агрегирование с использованием даты установки или даты прибытия постбэка.

## API для агрегированного отчета SKAN об эффективности

API возвращает метрики атрибуции, предоставленные Apple SKAdNetwork (реальные данные) и другие точки данных, используя дату установки или поступления постбэка. Отчет по своей структуре аналогичен данным, представленным на <Anchor target="_blank" href="/marketers/ru/docs/skadnetwork-skan-overview-dashboard-by-appsflyer">дэшборде SKAN</Anchor>.

<div id="using-skan-aggregated-performance-report-api" />

<Accordion title="Использование API для агрегированного отчета SKAN об эффективности">

**Для использования API для агрегированного отчета SKAN об эффективности**:

1. Получите токен API. Получить токен должен админ.
2. Дайте разработчику токен API, который будет использоваться в заголовке аутентификации.
3. Предоставьте разработчикам параметры, которые они должны ввести при вызове API, как описано в следующем разделе. Параметры определяют, что содержится в отчете, как он организован, а также устанавливают временные рамки отчетности.
4. Скажите своему разработчику, чтобы он следовал <Anchor target="_blank" href="https://dev.appsflyer.com/hc/reference/skan-agg-performance-report-api-get">API для агрегированного отчета SKAN об эффективности</Anchor> в хабе разработчиков.

#### Параметры

| Имя параметра | Формат | Обязательно |
| --- | --- | --- |
| `тип_даты` | Тип даты, используемый в диапазоне дат, ограниченном `start_date` и `end_date`<br /><br />Варианты:<ul><li>[По умолчанию] `install`: Дата установки, полученная AppsFlyer с использованием времени поступления постбэка и с учетом периода измерения.</li><li>`arrival`: Время прибытия постбэка. Примечание. Метрики органических установок имеют значение Н/Д.</li></ul>Данные Google Рекламы: Даты установки и поступления совпадают благодаря методологии отчетности Google Рекламы. | Нет |
| `дата_начала` | Диапазон дат установки ограничен значениями start\_date и end\_date. Внимание! Дата установки отличается от даты поступления постбэка.<ul><li>Самая ранняя дата установки в формате ГГГГ-ММ-ДД</li><li>Самая ранняя допустимая дата: 2020-11-01<br />Пример: `2020-11-05`</li></ul> | Да |
| `дата_выезда` | <ul><li>Дата последней установки в формате ГГГГ-ММ-ДД</li><li>Максимальное количество дней на вызов отчета: 90 дней</li><li>Пример: `2020-11-12`</li></ul> | Да |
| `тип_представления` | Отфильтруйте установки по типу следующим образом:<ul><li>`acquisition`: установки</li><li>`retargeting`: повторные загрузки</li><li>`unified`: Привлечение и повторные загрузки объединены.</li><li>[По умолчанию] `unified`</li><li>Метрики затрат, кликов и показов возвращаются в следующих, если `view_type=unified`</li></ul> | Нет |
| `моделируемые_значения_конверсии` | <ul><li>Доступно только, начиная с V2</li><li>Значение может быть либо `true` или `false`</li><li>Если true, постбэк включает смоделированные данные при заполнении декодированных столбцов метрик. [Посмотреть доступные поля](/docs/skan-aggregated-performance-report-api#report-structure-and-example)</li><li>Если `false`, постбэк представляет декодированные данные в том виде, в каком они были получены необработанными SKAN постбэками, без смоделированных данных.</li><li>Значение по умолчанию — `false`.</li></ul> | Нет |

</Accordion>

<Accordion title="Структура и пример отчета">

API возвращает файл CSV.

* Поля и метрики, доступные в отчете, перечислены в таблице ниже.
* Некоторые метрики (доход, вовлечение, конверсия) зависят от <Anchor target="_blank" href="/marketers/ru/docs/skan-conversion-studio">настроек измерения эффективности</Anchor> SKAN.
* В отчет включаются только внутренние события приложения, которые пользователи совершили за отчетный период. Таким образом, количество и последовательность столбцов внутренних событий приложения могут меняться от отчета к отчету. Не полагайтесь на последовательность столбцов при планировании процесса импорта данных.

<div id="specifications-and-limitations" />

<Accordion title="Спецификации и ограничения">

| Спецификация | Примечания |
| --- | --- |
| Актуальность данных | Доступность данных соответствует коэффициенту актуальности данных <Anchor target="_blank" href="/marketers/ru/docs/about-data-freshness-and-timezone-support#skan">SKAN</Anchor>. |
| Диапазон дат | <ul><li>При установке диапазона дат самой последней датой должна быть текущая дата: часовой пояс UTC минус 3 дня. То есть 31 марта следует использовать 28 марта.</li><li>Самая ранняя дата: 1 ноября 2020 г.</li><li>Максимальный диапазон запросов: 90 дней</li></ul> |
| Лимиты на предоставление данных | <ul><li>Запросы возвращают до 250 тыс. строк</li><li>10 вызовов в минуту</li></ul> |
| SRN: | <ul><li>Meta ads: данные доступны.</li><li>Google Реклама: установки могут быть зарегистрированы в течение 45 дней после установки благодаря методологии времени клика Google. Если вы запрашиваете данные Google за последние 45 дней ежедневно, это обеспечивает необходимый охват данных SKAN для Google.</li></ul> |
| Доступ рекламной сети | Если вы являетесь партнером по аналитике, попросите рекламодателя предоставить вам разрешение. |
| Доступ агентств | Не доступно |
| Часовой пояс приложения | Только UTC |
| Валюта приложения | Всегда доллары США |
| Органические данные | Рассчитывается как разница между всеми данными, передаваемыми SDK непосредственно в AppsFlyer, за вычетом неорганических данных, передаваемых постбэками SKAN |
| Неорганические данные | Рассчитывается с использованием постбэков SKAN, полученных AppsFlyer |
| Исторические данные | Самая ранняя поддерживаемая дата конверсии (установка или ретаргетинг): 1 ноября 2020 г. |
| Доступ пользователей аккаунта | Токен авторизации доступен пользователю с правами администратора на дэшборде. |
| Общие затраты | API SKAN может не включать метрику общей стоимости, если обычная атрибуция (обычный обзор) содержит кампании SKAN с самым низким уровнем детализации (например, реклама, страна или идентификатор сайта) с более чем 50 тысячами строк. |

</Accordion>
