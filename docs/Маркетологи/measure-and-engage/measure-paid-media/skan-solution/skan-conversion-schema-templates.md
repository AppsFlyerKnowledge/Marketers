> **Кратко:** шаблоны схем конверсии SKAN — это готовые к использованию шаблоны. Они упрощают настройку SKAN, предлагая шаблоны на основе сочетания данных по индустрии и данных конкретного приложения, а также инсайты по индустрии и практические рекомендации. Шаблоны схем конверсии SKAN доступны в Conversion Studio.

## Ключевые преимущества

* Эти шаблоны упрощают настройку SKAN, позволяя создать схему конверсии всего за несколько кликов.
* Используя практические рекомендации и инсайты индустрии, маркетологи могут точнее настроить свою схему и повысить уверенность в ее эффективности, используя шаблоны на основе отраслевых данных в сочетании с данными конкретного приложения.

## С чего начать?

1. В меню слева перейдите в **Настройки > SKAN Conversion Studio**
2. Нажмите кнопку **Отраслевые шаблоны**.
3. Откроется окно шаблона
4. Выберите отрасль или вертикаль из списка слева.
5. В правой части экрана отображается, как выглядит предложенная схема конверсии
   1. Используйте переключатель **Режим SKAN 4**, чтобы включить или отключить поддержку SKAN 4.  
      **Примечание:** для SKAN 4 рекомендуется использовать три окна активности, а для первого окна – приблизительные значения конверсии. Если параметр отключен, будут предложены только точные значения конверсии для первого окна.
   2. Используйте ? значки рядом с каждым измерением, чтобы увидеть объяснение, почему было предложено это событие или измерение, а также справочную информацию
6. Нажмите **Выбрать и настроить**.  
   **Примечание:** на этом этапе настройки ещё не будут сохранены.
7. Вы будете перенаправлены на страницу редактирования **Conversion Studio**
   1. Используйте <Anchor target="_blank" href="/marketers/ru/docs/skan-conversion-studio#компоненты-измерения">стандартные функции и инструменты Conversion Studio</Anchor>, чтобы настроить шаблон в соответствии с потребностями вашего приложения.

## Что такое шаблоны схем конверсии SKAN?

Шаблоны конверсии SKAN предлагают сопоставления значений конверсии для значимых активностей пользователя после установки, адаптированные по индустрии и вертикали. Предложения можно настроить в соответствии с потребностями конкретного приложения, сочетая инсайты на основе данных и экспертизу в индустрии.

### Структура шаблона

* **Стратегия**: определяет, на чем сосредоточиться — на событиях в приложении, измерении дохода или их сочетании. Стратегия предопределена, но ее можно настроить на странице редактирования Conversion Studio.
* **Версия SKAN**: указывает, какая версия SKAN поддерживается — SKAN4 или более ранние версии. По умолчанию поддерживается SKAN 4. Если SKAN 4 отключен, измерения грубых значений конверсии отключаются, и Conversion Studio переключается в режим «пользовательский».
* **Измерения**: шаблон предлагает измерять определенные активности после установки. Это включает конкретные события или диапазоны дохода, а также использование таких функций, как воронка и Единый источник истины (SSOT), которые предлагаются по умолчанию.
  * Рекомендуемые измерения можно настроить на странице редактирования Conversion Studio.
  * Предварительно выбранные события адаптированы для каждого шаблона.
  * Диапазоны дохода настраиваются на основе данных конкретного приложения с использованием продвинутых моделей рекомендаций по доходу. Если исторических данных недостаточно, для формирования рекомендаций используются данные по индустрии.

## Что такое схема конверсии SKAN?

Схема конверсии SKAN определяет настройки измерений для фреймворка SKAdNetwork (SKAN). Она определяет, какие метрики вовлеченности пользователей (например, события в приложении или доход) будут измеряться и отражаться в отчете. SKAdNetwork не сообщает напрямую о вовлеченности в приложение после установки. Вместо этого система сообщает о «значениях конверсии», которые разработчик приложений сопоставляет со значимыми активностями после установки. Это сопоставление называется схемой конверсии SKAN.

## На чём основаны эти шаблоны?

Шаблоны основаны на анализе схем конверсии по вертикалям на основе данных, а также на качественных исследованиях и инсайтах экспертов индустрии. Некоторые рекомендации основаны на данных конкретного приложения, как описано ниже.  
Основные этапы процесса создания шаблона:

1. **Отобрали ведущие приложения**: мы определили приложения для количественного анализа. Используя внутренние и внешние наборы данных, мы классифицировали приложения по иерархиям вертикалей. Для каждой субвертикали мы проанализировали десятки ведущих приложений и ранжировали их по объему SKAN-трафика, который они генерировали.
2. **Определили стратегию**: на основе отраслевых эталонных данных мы разработали стандартизированную стратегию, адаптированную для каждой вертикали. Проанализировав долю приложений в каждой вертикали, которые измеряют события, доход или и то и другое, мы выбрали стратегию для каждой вертикали. Мы также учли среднее количество событий и число приложений, использующих функцию воронки, чтобы определить количество событий для каждого шаблона и понять, подходит ли воронка.
3. **Создали группы событий**: мы сопоставили различные названия событий, заданные в приложениях, с предопределенными группами, каждая из которых отражает набор схожих бизнес-событий.
4. **Рекомендуемые события**: мы определили бизнес-события, которые чаще всего рекомендуется измерять в каждой вертикали. Используя группы событий, созданные на предыдущем этапе, мы проанализировали долю приложений, измеряющих каждое событие. После проверки отраслевыми экспертами и валидации по десяткам схем конверсии из ведущих Приложений мы выбрали оптимальное сочетание событий для каждого субвертикала.
5. **Определены диапазоны дохода**: мы предложили оптимальные диапазоны дохода, чтобы повысить точность отчетности по доходу. Когда пользователь открывает диалоговое окно шаблона, мы в реальном времени проверяем, подходит ли приложение для рекомендаций по доходу на основе наших продвинутых моделей. Если да, модель создает пользовательские диапазоны дохода с использованием данных приложения. Если нет, мы рекомендуем диапазоны дохода на основе данных индустрии, полученных в результате применения наших моделей рекомендаций по доходу к данным ведущих Приложений в этом вертикале.
6. **Сопоставлены события, характерные для приложения**: после того как приложение применяет определенный шаблон, мы сопоставляем релевантные события в приложении с заранее заданными названиями бизнес-событий в шаблоне категории. Затем приложение должно проверить, что выбраны правильные события.
