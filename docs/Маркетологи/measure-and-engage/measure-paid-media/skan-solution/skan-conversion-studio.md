## Основы работы с SKAN Conversion Studio

В процессе атрибуции SKAdNetwork (SKAN) устройство iOS отправляет постбэки SKAN, содержащие самые последние ценности, значения конверсий (CV) после каждого окна измерения.

Для SKAN 3 и ниже предусмотрен 1 постбэк, который приходит после завершения начального окна активности. Окно активности может составлять от 12 часов до 63 дней. CV ограничен 6 битами, что дает 64 возможных ценности, значения (0-63).

Для SKAN 4 предусмотрено 3 постбэка, которые поступают после завершения каждого из трех окон, на 2-й, 7-й и 35-й день соответственно. Для:

* Окно 1, точный CV ограничен 6 битами, что дает 64 возможных ценности, значения (0-63).
* В окнах 1-3 грубый CV ограничен уровнями низкий, средний или высокий. (В окнах 2 и 3 нет точных CV).

Эти ограничения CV могут потребовать сложного выбора, как использовать 64 возможных ценности, значения для точных CV и 3 возможных уровня для грубых CV.

Conversion Studio предоставляет максимальную гибкость для использования всех доступных ценностей, значений и битов. Вы точно определяете, какие данные измерения закодировать в CV, включая активность и продолжительность измерений в период после установки. Существует несколько режимов измерения, которые можно использовать для настройки параметров CV.

<div id="measurement-principles-and-definitions" />

<Accordion title="Принципы и определения измерений">

**Определения**

* **Окно измерения SKAN**: Актуально для SKAN 4+. Существует 3 временных периода (окна), в течение которых измеряется активность пользователя после установки:
  * Окно 1: 1-2 дня
  * Окно 2: 3-7 дней
  * Окно 3: 8-35 дней
  * Эти три окна измеряют три различные, неперекрывающиеся периода времени после установки. То есть, окно 2 измеряет дни с 3-го по 7-й после установки, а не с 0-го по 7-й.
* **Окно активности:** Актуально для SKAN 3 и ниже. Имеет фиксированную продолжительность, по умолчанию 24 часа, начиная с первого открытия приложения. Если вы используете SKAN 4+, но устройства пользователей или рекламные сети пока не поддерживают SKAN 4, окно активности составляет 48 часов.
* **Значение конверсии (CV)**: Показатель качества пользователя, сообщаемый в постбеках, отправляемых iOS в конце окон SKAN 4 или, для SKAN 3 и ниже, в конце окна активности. SDK (пакет средств разработки ПО) AppsFlyer настраивает CV для вас. Однако, если вы хотите настроить CV, используйте <Anchor target="_blank" href="/marketers/ru/docs/skan-cv-decode-map-your-cv-to-events">Decode</Anchor> для загрузки вашего файла сопоставления CV.
  * Для SKAN 4+ существуют как точные, так и приблизительные ценности, значения конверсии.
* **Вместимость ценностей, значений конверсии:** Количество CV, необходимое для отображения ваших настроек. Чем больше компонентов и элементов измерения вы выберете, тем больше потребуется вместимость ценностей, значений конверсии. Каждый выбранный диапазон или элемент настройки потребляет вместимость ценностей, значений конверсии. (И каждая дополнительная единица настройки, включенная в один компонент, потребляет её экспоненциально!) [Примеры максимально эффективного использования CV.](/docs/skan-conversion-studio#maximized-custom-cv-examples)
* Единый источник истины (SSOT): <Anchor target="_blank" href="/marketers/ru/docs/single-source-of-truth-ssot-guide-for-ios-attribution">Механизм для обозначения</Anchor> , был ли пользователь атрибутирован с помощью SKAN и другого метода атрибуции. Этот флаг используется для устранения дублирующих данных установки в необработанных данных SKAN и для расчета истинных показателей эффективности.
* **Компоненты измерения**:  
  * **Выручка:** Оценивает полученную выручку.
  * **Внутреннее событие приложения**: Измеряет конверсию (количество уникальных пользователей, совершивших событие),  
    вовлечение (количество раз, когда событие было выполнено), или и то, и другое.
  * **Воронка**: Оценивает возникновение событий в приложении на основе списка последовательных событий в воронке. Пользователь, выполнивший любое событие в воронке, считается выполнившим все предыдущие события.
  * **Приоритет**: Компонент, включающий выручку, внутреннее событие приложения, или и то, и другое.

**Принципы**

* **![Admin.png](https://files.readme.io/d67fdedd94c56e8da776e590b12883503f47d36f0d58b996c4c64cc5d0e9c675-16281491712785.png)Только для администратора:** Только администратор может сохранять настройки Conversion Studio. Пользователи аккаунта могут просматривать настройки.
* В любой момент активен только один режим.
* Для заданного режима AppsFlyer сопоставляет комбинации, определенные вашими настройками, с CV. Вы можете [просмотреть и скачать таблицу сопоставления](/docs/skan-conversion-studio#view-cv-mapping).
* В приложении AppsFlyer устанавливает CV после каждого измеримого действия пользователя, используя режим измерения, активный при первом запуске приложения.
* iOS учитывает <Anchor target="_blank" href="https://developer.apple.com/documentation/storekit/skadnetwork/receiving_postbacks_in_multiple_conversion_windows">анонимность пользователей Apple</Anchor> перед заполнением CV в постбэке.
* Действия пользователя, происходящие после завершения окна, не учитываются.
* Дэшборд и отчеты SKAN:
  * Структура и показатели дэшборда SKAN зависят от режима и конфигурации.
  * Макет обновляется ежедневно в зависимости от режима, активного в полночь UTC. Ожидается, что обновленный макет будет доступен к 05:00 UTC.
  * В SKAN 4, пользовательский и Decode органические данные о событиях в приложении и общей выручке недоступны.

<div id="s2s-principles" />

#### **Принципы S2S**

Измеримые действия могут быть зарегистрированы с помощью API [сервер-сервер (S2S)](/docs/skan-conversion-studio#report-events-by-servertoserver-api). Рассмотрите следующее для каждого режима:

* SKAN 4 и пользовательский: S2S всегда включен.
* Расшифровка: S2S не подходит для режима расшифровки и недоступен. В этом режиме AppsFlyer не устанавливает CV.
* [Устаревшие] Режимы выручки, конверсии и вовлечения: Перед отправкой событий необходимо включить [запись событий S2S](/docs/skan-conversion-studio#report-events-by-servertoserver-api).

## Настройка значений конверсии в SKAN Conversion Studio

В SKAN Conversion Studio доступны несколько режимов для установки значений конверсии:

* SKAN 4: Используйте различные компоненты измерения, такие как выручка, события в приложении, приоритет и единый источник истины, чтобы определить, что измеряется в течение каждого из трех окон измерения.
* Пользовательский: Используйте различные компоненты измерения, такие как выручка, события в приложении, приоритет и единый источник истины, чтобы определить, что измеряется в течение окна активности.
* [Устаревшие] Фиксированные режимы: Измерьте ценность пользователя, используя один из следующих методов измерения:
  * Вовлечение
  * Конверсия
  * Вовлеченность

Узнать больше о различных режимах измерения можно в следующих разделах.

> 🚧 **Важно!**
>
> Настройка значений конверсии в SKAN Conversion Studio должна выполняться администратором или пользователем учетной записи с правами **Управление** в **SKAN Conversion Studio**.

>
> *Примечание: пользователи, чей доступ ограничен определенными медиаисточниками и гео, могут не иметь возможности видеть или открывать SKAN Conversion Studio.

<div id="skan-4" />

<Accordion title="SKAN 4">

В SKAN 4 вы используете различные компоненты измерения, такие как выручка, события в приложении, приоритет и Единый источник истины, чтобы определить, что измеряется в течение каждого из трех окон измерения. Эти компоненты вместе создают режим измерения SKAN 4.

Если вы обновляете предыдущий режим SKAN до SKAN 4, текущее сопоставление схем переносится для точной конфигурации окна 1. AppsFlyer автоматически сопоставляет грубые значения для окон 1–3.

Чтобы вручную настроить SKAN 4, поэкспериментируйте с различными параметрами. По мере внесения изменений сводка **емкости значения конверсии** обновляется. Оптимизируйте настройки, чтобы сохранить наиболее значимые для вас данные, не превышая при этом емкость. См. [Расчёт емкости значений конверсии](/docs/skan-conversion-studio#conversion-value-capacity-formula).

![Счётчик емкости.png](https://files.readme.io/c976bbf52b8348ffa8de092f5f75eb66b137cc9fa63bc34d0b84e50fc7d112f7-4405725161233.png)

**Примечание: Если вы переходите на SKAN 4 с предыдущего режима SKAN, текущее сопоставление схем переносится для точных измерений, а AppsFlyer автоматически сопоставляет грубые значения. А если вы новичок в SKAN, AppsFlyer предоставляет начальное сопоставление по умолчанию.**

**![AppsFlyerAdmin_us-en.png](https://files.readme.io/d67fdedd94c56e8da776e590b12883503f47d36f0d58b996c4c64cc5d0e9c675-16281491712785.png) altAppsFlyerAdmin\_us-en.pngaltЧтобы вручную задать значения конверсии в Conversion Studio с использованием режима SKAN 4:**

1. На дэшборде AppsFlyer перейдите в **Настройки** > **SKAN Conversion Studio.**
2. Нажмите «Параметры» (⋮), чтобы отобразить меню параметров, и убедитесь, что включено **измерение SKAN**. **Примечание**! Если выключено, SDK (пакет средств разработки ПО) не вызывает функции iOS SKAN, такие как *registerAppForAdNetworkAttribution*, *updateConversionValue.*
3. Выберите режим измерения **SKAN 4.0**.
4. Нажмите **Продолжить**.  
   Открываются настройки для **Окна 1 (1-2 дня) точное** CV.
5. [Необязательно] Включите **Единый источник истины (SSOT)**.  
   Механизм SSOT отмечает (и удаляет дубли) установок, о которых сообщается более чем одним методом сопоставления атрибуции. <Anchor target="_blank" href="/marketers/ru/docs/single-source-of-truth-ssot-guide-for-ios-attribution">Узнать больше</Anchor>
6. Нажмите **+ Добавить измерение**, чтобы добавить различные [компоненты измерения](/docs/skan-conversion-studio#компоненты-измерения).  
   В следующих разделах подробно описаны параметры настройки и компоненты. Используйте их в качестве руководства при экспериментировании с различными настройками измерения SKAN:
   * Вовлечение
   * Внутреннее событие приложения
   * Воронка
   * Приоритет
7. Нажмите **Грубо** и повторите шаги 6–7, чтобы задать грубое CV для **Окна 1 (1–2 дня)**.   
   **Примечание**:
   * Доступны только компоненты измерения выручки и события в приложении.
   * Чтобы гарантировать отправку постбэка, низкий CV должен быть сессией пользователя.
8. [Необязательно] Включите **Блокировку окна** и задайте условие (время или грубое значение конверсии) для преждевременной блокировки окна SKAN. [Узнать больше](/docs/skan-conversion-studio#lock-window)
9. Кликните **Окно 2 (3–7 дней)** и повторите шаги 6–8, чтобы задать CV для окна 2.   
   **Примечание**:
   * Доступны только компоненты измерения выручки и события в приложении.
   * [Рекомендуется] Низкий CV должен быть сессией пользователя.
10. Кликните **Окно 3 (8–35 дней)** и повторите шаги 6–8, чтобы задать CV для окна 3.   
    **Примечание**:
    * Доступны только компоненты измерения выручки и события в приложении.
    * [Рекомендуется] Низкий CV должен быть сессией пользователя.
11. Нажмите **Сохранить**.
12. Убедитесь, что ваша карта постбэков событий приложения правильно сопоставляет настроенные вами события.

</Accordion>

<Accordion title="Компонент измерения приоритета">

Используйте компонент измерения приоритета, часть пользовательского режима, чтобы ранжировать пути действий пользователей в Приложение на основе вашей бизнес-логики, чтобы измерения с высоким приоритетом заменяли менее приоритетные. Это позволяет выбирать, что измерять на каждом ШАГЕ воронки конверсии.

Каждый приоритет (максимум 63) может содержать выручку, внутреннее событие приложения или и то, и другое. Когда пользователь совершает события в приложении, AppsFlyer определяет, какой приоритет соответствует этим действиям, и устанавливает CV соответствующим образом.

Для облегчения понимания давайте сравним использование пользовательский с и без компонента приоритета. **Без** приоритета AppsFlyer сопоставит все возможные комбинации измерений с CV. В то время как **с** приоритетом только те комбинации измерений, которые вы установили, сопоставляются с CV.

Принципы приоритета лучше всего разъясняются в [подробном примере](/docs/skan-conversion-studio#priority-measurement-detailed-example) в этой статье.

**Принципы приоритета**

* Можно установить от 1 до 63 приоритетов. Доступное количество зависит от вашего окна активности и настроек Единого источника истины.
* Приоритет 1 всегда имеет наивысший приоритет. Приоритет с наибольшим номером обладает самым низким приоритетом.
* Приоритет может включать компоненты [выручки](/docs/skan-conversion-studio#revenue-component) или [внутреннее событие приложения](/docs/skan-conversion-studio#inapp-event-component), или оба. Определенный приоритет может содержать несколько событий в приложении и потоков выручки.
* Воронка недоступна в применении с приоритетом. Однако, чтобы измерить конверсию пользователя во воронке, установите несколько событий в приложении в приоритете.
* Для использования компонента измерения приоритета, нельзя иметь настроенные другие компоненты, такие как события в приложении или выручка.

**Для настройки измерения с использованием приоритета:**

1. В AppsFlyer перейдите в **SKAN Conversion Studio.**
2. Выберите **Пользовательский**, нажмите **Продолжить**.
3. При необходимости нажмите **Удалить**, чтобы удалить текущие настройки.
4. Нажмите **+ Добавить измерение**. Выберите **Приоритет**.   
   Показывается приоритет 1.  
   [![CVmapping.png](https://files.readme.io/f0bc64c4fbb95462a17a1e6bb8d250d3396096b743b3d412cd0605d9b0a1079d-4756458366865.png)](https://files.readme.io/f0bc64c4fbb95462a17a1e6bb8d250d3396096b743b3d412cd0605d9b0a1079d-4756458366865.png)
5. Выберите компонент измерения из:
   * Вовлечение
   * Внутреннее событие приложения
6. Заполните поля в соответствии с пользовательским интерфейсом.
   * Учитывайте, что приоритет может состоять из выручки, внутреннего события приложения или обоих компонентов.
   * Диапазон значений для появления события и выручки может быть возрастающим или убывающим, но должен быть непрерывным. К примеру, следующие диапазоны являются непрерывными: 1-5, 5-8, 8-10 и так далее. Определенный диапазон может использоваться более одного раза, если он используется в составе уникальной комбинации и является тем же, что и последний приоритет с этим диапазоном. К примеру, 1-5, 1-5 + добавить в корзину.  
     **Пример увеличения и уменьшения выручки**

| Событие | Встречаемость | Вовлечение |
| --- | --- | --- |
| P1 событие\_a | 2-3 | 5–50 долларов США |
| P2 событие\_a | 2-3 | 0–5 долларов США |
| P3 событие\_a | 1-2 | 5–50 долларов США |
| P4 событие\_a | 1-2 | 0–5 долларов США |
| P5 событие\_a | 0-1 | 5–50 долларов США |
| P6 событие\_a | 0-1 | 0–5 долларов США |

7. Нажмите **Подтвердить.**  
   Отображается сообщение **Приоритет действителен**. Если это не так, исправьте приоритет перед тем, как продолжить.
8. Выполните одно из следующих действий:
   * Чтобы добавить приоритет, нажмите **+ Добавить приоритет.** Текущий приоритет 1 сдвигается вниз и становится приоритетом 2. Завершите настройку приоритетов, как описано ранее.
   * Чтобы удалить приоритет, кликните … > **Удалить.**
   * Чтобы изменить уровень приоритета, кликните **Параметры** (⋮) и выберите **Изменить порядок** или **Сделать самым низким приоритетом**.
   * Чтобы дублировать приоритет, кликните **Параметры** (⋮) и выберите **Дублировать**.
   * Нажмите **Сохранить**, чтобы завершить настройку приоритетов.

<div id="conversion-value-capacity-formula" />

<Accordion title="Формула емкости значений конверсии">

Как уже объяснялось, максимальное количество доступных значений конверсии составляет 64. Следующая формула вычисляет, какое количество доступных значений конверсии используется режимом.

```http
(длительность периода активности в часах / размер интервала в часах) * 
(количество диапазонов дохода + 1) * 
(количество диапазонов событий в приложении + 1) * 
(количество шагов в воронке + 1)
```

Отрегулируйте формулу, чтобы она включала все компоненты измерений.

</Accordion>

<Accordion title="Подробный пример настройки приоритета измерения">

В приложении для покупок рекламодатель хочет сосредоточить измерения на:

* Действия пользователей, не совершающих покупки
* Выручка от **платящих** пользователей

Таким образом, рекламодатель использует CV для более точного учета выручки. Эти требования к измерениям преобразуются в набор приоритетов, как указано в таблице ниже.

Учтите:

* Наивысший приоритет всегда равен 1. **Примечание**! Приоритетные номера не имеют прямого соответствия с CV. Сопоставления CV отображаются в пользовательском интерфейсе.
* Максимальное количество приоритетов — 63. Фактическое количество зависит от окна активности и от того, включён ли Единый источник истины.
* Каждый приоритет состоит либо из диапазона выручки, либо из диапазона встречаемости внутренних событий приложения, либо из того и другого.
* Диапазон значений: Нижнее значение границы не включается в диапазон, но верхнее значение включается. Например, диапазон $5-$10 не включает значение 5, но включает значение 10.

<Accordion title="API SKAN Conversion Studio">

Если у вас много приложений, для которых необходимы похожие настройки ценности, значения конверсии SKAN, создание схемы для каждого приложения отдельно в интерфейсе Conversion Studio может быть времязатратным и сложным. Для экономии времени и усилий вы можете однажды настроить схему SKAN в интерфейсе и использовать API SKAN Conversion Studio, чтобы применять эту же схему к разным приложениям. **Примечание**: API поддерживает только схемы, настроенные в интерфейсе с использованием SKAN 4 или пользовательских режимов измерения.

**Чтобы использовать API SKAN Conversion Studio**:

1. Получите <Anchor target="_blank" href="/marketers/ru/docs/managing-appsflyer-tokens">API токен</Anchor>. Администратор должен получить токен.
2. Передайте вашему разработчику токен API для использования в заголовке аутентификации.
3. Предоставьте вашим разработчикам идентификаторы приложений:
   * Приложение, для которого схема SKAN настроена в интерфейсе (то есть приложение, из которого вы хотите скопировать схему SKAN).
   * Все приложения, для которых вы хотите использовать ту же самую схему.
4. Сообщите вашему разработчику следовать <Anchor target="_blank" href="https://dev.appsflyer.com/hc/reference/skan-studio-config-overview-1">инструкциям API SKAN Conversion Studio</Anchor> в центре разработчика.

**Примечание**:

* API можно использовать для копирования схемы в одно Приложение за один вызов API. Однако ваш разработчик может создать скрипт для копирования схемы в несколько приложений.
* API SKAN Conversion Studio недоступен для Агентства.

</Accordion>

<div id="skan-schema-analysis" />

<Accordion title="Анализ схемы SKAN">

Узнайте, как используются ваши значения конверсии, выявляйте неэффективные конфигурации схемы и улучшайте настройку измерения SKAN на основе реальных данных об использовании.

Инсайты о распределении значений конверсии состоят из трех вкладок, которые помогают оптимизировать разные аспекты вашей схемы SKAN:

* Вкладка «Значения конверсии»
* Вкладка «Доход»
* Вкладка «События»

<div id="conversion-values-tab" />

#### **Вкладка «Значения конверсии»**

Показывает, какие значения конверсии действительно используются, а какие — нет.

Сбалансированное распределение значений конверсии позволяет вашей схеме SKAN эффективно фиксировать поведение пользователей. Неиспользуемые значения конверсии указывают на недоиспользованные комбинации измерений, что приводит к потере ёмкости SKAN и упущенным возможностям оптимизации.

* Отображает частоту каждого значения конверсии за последние 7 дней по постбэкам.
* Выделяет значения, по которым получено 0 постбэков.
* Помогает оптимизировать распределение значений и избежать неэффективного использования емкости измерения.
* Особенно полезно для приложений, использующих схемы на основе приоритетов.

**Порог для определения неиспользуемых значений**  
✅ Все CV используются  
⚠️ Если хотя бы у одного CV вообще нет постбэков, отображается этот значок ошибки.

<div id="revenue-tab" />

#### **Вкладка «Доход»**

Проверьте, соответствуют ли заданные вами бакеты дохода реальным расходам пользователей.

Точность дохода можно улучшить, оптимизировав предопределенные диапазоны дохода SKAN. SKAN сообщает среднее значение по каждому диапазону, что может не отражать фактические расходы пользователей. Несогласованные диапазоны приводят к расхождениям, что вызывает неточную отчетность по доходам и влияет на ROAS и распределение бюджета.

Диаграмма показывает распределение платящих пользователей по заданным вами бакетам дохода. Если есть расхождение между фактическими расходами пользователей и указанным средним доходом на платящего пользователя (ARPPU), система рекомендует пересмотреть схему.

* Показывает, включает ли ваша схема сопоставление дохода.
* Показывает, как платящие пользователи распределяются по диапазонам дохода.
* Выявляет расхождения между средним доходом на одного платящего пользователя (ARPPU) и фактическими расходами.
* Предлагает обновления схемы для повышения точности данных о доходе.
* Если ваше приложение соответствует требованиям модели рекомендаций по доходу Revenue Recommendation Model, также будет показан индивидуальный расчет точности ARPPU на основе вашей схемы.

**Порог ошибки в отчетности**

✅ Ошибка дохода ≤ 3%

⚠️ Ошибка дохода > 3%

<div id="events-tab" />

#### **Вкладка «События»**

Убедитесь, что события, сопоставленные со SKAN, происходят достаточно часто, чтобы приносить пользу.

Эта вкладка показывает, сопоставлено ли со SKAN хотя бы одно событие в приложении.

Диаграмма показывает процент установок, в которых сработало каждое сопоставленное событие в течение первого окна активности. События с низкой частотой или без срабатываний выделяются, помогая вам обеспечить оптимальное использование вашей схемы конверсии.

Если все выбранные события происходят в течение первого окна активности, это помогает избежать неиспользуемой емкости измерения и максимально использовать доступные значения конверсии.

* Появляется, если в схеме сопоставлено хотя бы одно событие.
* Скрыто, если ни по одному сопоставленному событию не было зафиксировано установок за последние 7 дней.
* Показывает процент установок, в которых сработало каждое сопоставленное событие в течение первого окна активности.
* Выделяет события, которые происходят редко или не происходят совсем.
* Помогает избежать недоиспользуемых событий, которые снижают потенциал схемы.

**Порог частоты событий**

✅ Все события ≥ 3 % установок

⚠️ Одно или несколько событий &lt; 3 %

Как SDK (пакет средств разработки ПО), так и <Anchor target="_blank" href="/marketers/ru/docs/server-to-server-events-api-for-mobile-s2s-mobile">API сервер-сервер (S2S)</Anchor> могут отправлять события в приложении на серверы AppsFlyer.

Поток S2S выглядит следующим образом:

* Событие, связанное с пользователем, происходит на серверах рекламодатель. Приложение может быть открыто или закрыто в это время.
* Серверы рекламодатель сообщают о событие в AppsFlyer через S2S.
* AppsFlyer вычисляет обновленную ценность, значение конверсии, а затем:
  * Если Приложение открыто на устройстве пользователя: SDK (пакет средств разработки ПО) уведомляется об обновленной ценности, значении. SDK (пакет средств разработки ПО) обновляет ценность, значение конверсии iOS на устройстве.
  * Если Приложение не открыто на устройстве пользователя: сервер ждет открытия Приложения, чтобы уведомить SDK (пакет средств разработки ПО) о ценности, значении конверсии. Это должно произойти до истечения срока действия окна активности. Если уведомление не удалось, событие игнорируется.

**Требуется версия SDK**

* Установите в Приложении последнюю версию SDK (пакет средств разработки ПО). **Примечание!** Никаких дополнительных действий со стороны разработчика не требуется.

**Чтобы реализовать отправку событий в приложении через API сервер-сервер:**

1. Выполните одно из следующих действий:
   * Если выбранный вами режим — SKAN 4 или пользовательский:
     * Никаких изменений настроек не требуется.
   * Если выбранный вами режим — выручка, конверсия или вовлечение:
     1. В AppsFlyer перейдите в **Настройки** > **SKAN Conversion Studio.**
     2. Нажмите «Параметры» (⋮).
     3. Включите **Запись внутренних событий приложения, отправленных через API сервер-сервер**.
2. Отправляйте события через S2S.

**Ограничение**

* Если вы реализуете *анонимизацию пользователей* для конкретного пользователя, то не сможете отправлять события по S2S для этого пользователя.

</Accordion>

<Accordion title="Добавьте SSOT к измерениям в фиксированном режиме">

<div id="note-2" />

> 📘 **Примечание**
>
> Фиксированные режимы недоступны для новых приложений с 23.06.2024. Все функции поддерживаются в пользовательском режиме и SKAN4.

Если у вас настроен режим измерения «Выручка» или «Вовлеченность», то Единый источник истины (SSOT, который дедуплицирует и точно передает данные iOS) не поддерживается. <Anchor target="_blank" href="/marketers/ru/docs/single-source-of-truth-ssot-guide-for-ios-attribution">Узнать больше о SSOT</Anchor>

**Чтобы включить SSOT при установленном режиме «Выручка» или «Вовлеченность»**:

1. В AppsFlyer перейдите в **Настройки** > **SKAN Conversion Studio**.
2. Прокрутите вниз до вашего активного режима измерения.
3. Нажмите **+ Добавить Единый источник истины**.
   * Переключатель «Единый источник истины» автоматически включается.
   * Диапазоны измерений в фиксированном режиме изменяются минимально, чтобы предоставить SSOT некоторое пространство для значений конверсии.
4. Нажмите **Сохранить.**

<div id="conversion-value-decrease" />

<Accordion title="Уменьшение ценности, значения конверсии">

В режиме [SKAN 4](/docs/skan-conversion-studio#skan-4) у вас есть возможность увеличивать или уменьшать ценность конверсии (CV). По умолчанию CV настроен на увеличение. Если включить возможность уменьшения ценности, значения конверсии, то постбэк будет содержать последнее ценность, значение в окне при отправке отрицательной выручки, даже если ранее оно было выше. Эта возможность актуальна для точных и грубых ценностей, значений конверсии во всех [трех окнах.](/docs/skan-conversion-studio#measurement-principles-and-definitions)   
**Примечание:** Ценность, значение выручки от рекламы никогда не станет отрицательной.

Чтобы включить уменьшение ценности, значения конверсии:

1. В AppsFlyer перейдите в **Настройки** > **SKAN Conversion Studio**.
2. Выберите режим измерения **SKAN 4.0**.
3. Нажмите параметры (⋮), чтобы открыть меню опций и:
   * Убедитесь, что параметр **Разрешить уменьшение конверсии** включен.   
     Примечание! Это будет доступно только следующим пользователям:
     * Внутренний набор для отслеживания конверсии
     * Пользователи с правом редактирования

<div id="examples" />

#### Примеры

**Примеры с отрицательной выручкой**

| CV | Вовлечение | Внутреннее событие приложения |
| --- | --- | --- |
| 3 | 20–30 долларов США |  |
| 2 | 10–20 долларов США | af\_add\_to\_cart |
| 1 | 0–10 долларов США |  |
| 0 | NA | Установить |

**Пример 1**

Пользователь совершил покупку на 5 долларов — вы увидите увеличение CV до 1  
Затем пользователь совершил покупку на 20 долларов — вы увидите увеличение CV до 3  
Затем пользователь совершил покупку на -10 долларов — вы увидите снижение CV до 1  
Затем пользователь создал внутреннее событие add\_to\_cart — вы увидите увеличение CV до 2

**Пример 2**

Пользователь совершил покупку на 25 долларов — вы увидите увеличение CV до 3  
Затем пользователь активировал af\_add\_to\_cart — он останется на CV 3  
Затем пользователь совершил покупку на -20 долларов — вы увидите снижение CV до 1

**Пример схемы внутреннего события**

| CV | Внутреннее событие приложения |
| --- | --- |
| 3 | af\_purchase |
| 2 | af\_add\_to\_cart |
| 1 | Сессия |
| 0 | Установить |

**Пример**

Пользователь выполнил сессию — вы увидите увеличение CV до 1  
Затем пользователь совершил событие покупки — вы увидите увеличение CV до 3  
Затем пользователь выполнил еще одну сессию — она останется на CV 3

<Accordion title="Поддержка анонимных пользователей">

Включение переключателя **Поддержка анонимных пользователей** гарантирует точное обновление ценностей, значений конверсии SKAN для <Anchor target="_blank" href="/marketers/ru/docs/apply-privacy-preserving-sdk-methods#анонимизация-пользовательской-информации">анонимных пользователей</Anchor>, при этом сохраняя их конфиденциальность.

<div id="important-1" />

> 🚧 **Важно!**
>
> Эта функция актуальна только для приложений, вызывающих <Anchor target="_blank" href="/marketers/ru/docs/apply-privacy-preserving-sdk-methods#анонимизация-пользовательской-информации">метод анонимизации пользователя</Anchor> для удаления и хеширования всей идентифицирующей информации. Для обеспечения точности отчетности SKAN эти приложения должны активировать переключатель **Поддержка анонимных пользователей**.

Зачем это необходимо?  
SKAN использует идентификаторы для обновления значений конверсии на основе активности после установки. Когда приложение вызывает **метод анонимизации пользователя** после вызова метода запуска, система может не связать некоторые события после установки с оригинальной установкой, что ведет к неточным обновлениям значений конверсии.  
Активируя переключатель **Поддержка анонимных пользователей**, система создает хешированные идентификаторы для всех пользователей при установке. Это позволяет приложению правильно связать активность пользователя с первоначальной установкой, даже если пользователь позже становится анонимным, обеспечивая точную отчетность.

<div id="ssot-mapping-patterns" />

<Accordion title="Шаблоны сопоставления «Единый источник истины» SSOT">

Когда в вашей схеме SKAN включен единый источник истины (SSOT), вы можете настроить структуру значений конверсии. Это позволяет лучше согласовать это с вашими целями отчетности и стратегическими потребностями атрибуции.

Шаблоны сопоставления определяют, как значения конверсии (CV) организованы для представления различных типов установки. К ним относятся установки, атрибутированные с помощью классических методов атрибуции AppsFlyer, а также неатрибутированные установки.  
AppsFlyer поддерживает два шаблона сопоставления:

<div id="half-and-half" />

#### **Половина и половина**

* Делит CV на две половины:
  * Нижняя половина отражает возрастающие уровни вовлеченности.
    * Логика: CV с `af_attribution_flag=false`
  * Верхняя половина дублирует нижнюю, но при этом явно помечает значения как атрибутированные с помощью классических методов атрибуции AppsFlyer.
    * Логика: дубликаты нижних CV с `af_attribution_flag=true`

<div id="pairing" />

#### **Попарное сопоставление**

* Группирует CV в пары.
  * Сразу за каждым CV следует другой, который отражает тот же уровень вовлеченности, но явно помечен как атрибутированный с помощью классической атрибуции.
  * Обеспечивает порядок CV по возрастанию и последовательно отражает рост уровней вовлеченности пользователей
  * Логика: за каждым CV следует его дубликат с пометкой `af_attribution_flag=true`

<div id="how-to-configure-mapping-patterns" />

#### Как настроить шаблоны сопоставления

Чтобы использовать шаблоны сопоставления:

1. Включите SSOT в схеме SKAN.
2. В редакторе схемы нажмите на меню **Еще варианты** (три точки).
3. Выберите **Шаблон сопоставления**.
4. Выберите предпочтительный шаблон:
   * **Пополам** (по умолчанию)
   * **Попарное сопоставление**
5. Проверьте обновлённый предварительный просмотр схемы и представление календаря.
6. Сохраните схему.

<div id="faq" />

#### **Часто задаваемые вопросы**

**В: Что происходит, если SSOT отключен?**  
О: Средство выбора шаблона сопоставления недоступно, если SSOT отключен.

**В: Можно ли вернуться к шаблону по умолчанию?**  
О: Да. **Half-and-half** используется по умолчанию, и его можно выбрать снова в любое время.

**В: Отражаются ли эти изменения в API схемы?**  
О: Да. Все выбранные шаблоны отражаются в API схемы SKAN как для маркетологов, так и для сетей.

**В: Могут ли у двух CV быть одинаковые события, но разные флаги SSOT?**  
О: Да. Теперь это считается допустимым поведением в соответствии с обновленной логикой валидации.
