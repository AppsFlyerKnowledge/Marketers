> **Краткий обзор.** Оптимизируйте рекламные кампании Meta, используя партнеров по управлению кампаниями Meta (ранее известных как партнеры по маркетингу Facebook), таких как Kenshoo, Bidalgo и Smartly. После настройки AppsFlyer отправляет им постбэки.

<div id="configure-meta-campaign-management-partners" />

## Настройка партнеров по управлению кампаниями Meta

**Необходимые условия.** Перед настройкой интеграции необходимо <Anchor target="_blank" href="/marketers/ru/docs/partner-integrations#contact-details">связаться с партнером</Anchor> и открыть у него аккаунт.

**Чтобы активировать интеграцию:**

1. **Чтобы активировать:** В AppsFlyer в боковом меню выберите**Сотрудничество** > **Маркетплейс партнеров**.  
   **Чтобы изменить**: В AppsFlyer в боковом меню выберите **Сотрудничество** > **Активные интеграции**.
2. Выберите соответствующее приложение.
3. Найдите партнёра (`rokuads_int`) и выберите его.
4. На вкладке **Интеграция** выберите приложение для интеграции и нажмите **Активировать партнера**.  
    **Примечание.** Этот переключатель должен быть <Anchor target="_blank" href="/marketers/ru/docs/partner-activation-deactivation">активирован</Anchor> все время, пока вы работаете с этим партнером.
5. Закончите настройку, как описано ниже:

## Настройка постбэков о внутренних событиях приложений

**Необходимые условия**:

Чтобы партнер мог получать постбэки, названия кампаний **должны** содержать префикс в виде имени партнера по управлению кампаниями Meta. Например, если имя партнера по управлению кампанией Meta — *Mcmpexample*, а сегмент — *Young\_Segment,* задайте название кампании как *mcmpexample\_Young\_Segment*.  
**Примечание:** Имя партнера по управлению кампанией Meta **чувствительно к регистру.**

**Чтобы настроить постбэки по внутренним событиям приложения**:

<Image align="center" alt="in-app_event_mapping.png" src="https://files.readme.io/ced254c1aa0ad454c1876cfc0bc85de20d275824efb34c9665ca144dabffaa2a-14050539243793.png" />

1. Активируйте **Постбэки по внутренним событиям приложения**.
2. Заполните необходимые параметры в соответствии с <Anchor target="_blank" href="/marketers/ru/docs/in-app-event-postback-configuration#методы-сопоставления">методом сопоставления</Anchor>.

   

| Имя параметра | Описание |
| --- | --- |
| <span id="appsflyer-event"></span>**Событие AppsFlyer** | Имя события, полученное AppsFlyer из SDK, интегрированного в приложение, или из межсерверного события.<br />**Совет**: Не нашли нужное вам событие?<ul><li>Убедитесь, что событие активировано на устройстве с неорганической установкой, и повторите поиск.</li><li>Введите его в поле **Событие AppsFlyer** и нажмите **Добавить другое**. Подробнее о <Anchor target="_blank" href="/marketers/ru/docs/in-app-event-postback-configuration#пользовательские-события">сопоставлении пользовательских событий</Anchor> читайте здесь.</li></ul> |
| <span id="mapped-to-partner-event"></span>**сопоставлено с событием партнёра** | Уникальное имя или идентификатор каждого события, определенные партнером. <Anchor target="_blank" href="/marketers/ru/docs/in-app-event-postback-configuration#методы-сопоставления">Возможны следующие настройки сопоставления</Anchor>:<ul><li>**Текстовое поле:** Получите соответствующий идентификатор события от партнера.</li><li>**Раскрывающийся список:** Выберите наиболее подходящее предопределенное событие партнера.</li><li>**Как есть**: События отправляются в исходном виде, без сопоставления названий событий.</li></ul> |
| <span id="for-users-from"></span>**для пользователей от** | Выберите вариант отправки для события.<ul><li>**Только этот партнёр**: постбэки отправляются только в том случае, когда событие атрибутируется этому партнеру, то есть когда пользователь, выполнивший событие, пришел от этого партнера.</li><li>**Все медиа-источники и органический трафик**: постбэки отправляются для событий, атрибутированных любому партнеру, а также для органических событий, то есть когда пользователь, выполнивший событие, пришел из любого медиа-источника.</li></ul> |
| <span id="including"></span>**включая** | Выберите, <Anchor target="_blank" href="/marketers/ru/docs/in-app-event-postback-configuration#данные-для-включения-в-постбэки">какие данные о событиях</Anchor> следует передать партнеру в постбэке:<ul><li>**Без значения и дохода**: Отправляется только само событие без каких-либо параметров (значений или доходов).</li><li>**Значение без дохода**: Отправляются все параметры, **кроме** значения дохода.</li><li>**Значение и доход**: Отправляются все параметры события, **включая** значение дохода (если оно есть в событии).</li></ul> |

3. [Необязательно] Нажмите ![conditional-iae-postbacks-icon.png](https://files.readme.io/5345c5ebe95b3f1a0d0858b88ce29f9965178ce750df86c04cb131a93d006a5e-14050481317393.png), чтобы <Anchor target="_blank" href="/marketers/ru/docs/in-app-event-postback-configuration#условные-постбэки-по-событиям-в-приложении">задать условия</Anchor> для отправки партнеру определенных событий в приложении.
4. [Необязательно] Нажмите **Добавить событие**, чтобы добавить в список еще одно событие от SDK или межсерверное.
5. Нажмите **Сохранить интеграцию**.

<div id="important-notes" />

> 📘 **Важные замечания**
>
> * Отключение атрибуции для Meta ads предотвращает отправку постбэков партнерам по управлению кампаниями Meta.
> * Сопоставление внутренних событий приложения с партнерами по управлению кампаниями Meta или отсутствие сопоставления не влияет на отправку внутренних событий приложения в Meta ads напрямую из аккаунта рекламодателя.
> * Для сопоставления событий в приложении могут потребоваться различные параметры настройки в зависимости от партнера по управлению кампаниями Meta.
> * Названия кампаний Meta ads и X Ads должны начинаться с имени аккаунта партнера по управлению Meta ads, как определено на платформе AppsFlyer, за которым следует подчеркивание «\_». Если кампании не имеют указанных названий, они видны рекламодателю, но не партнеру по управлению Meta ads. Имя партнера по управлению кампаниями Meta **чувствительно к регистру**.
