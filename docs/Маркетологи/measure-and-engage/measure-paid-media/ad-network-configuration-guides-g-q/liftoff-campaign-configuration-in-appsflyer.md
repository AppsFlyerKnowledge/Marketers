> **Краткий обзор:** Liftoff, интегрированный партнер рекламной сети AppsFlyer, — один из ведущих партнеров по спросу для брендов и разработчиков приложений. Liftoff поддерживает мобильную атрибуцию по кликам и просмотрам, а также ретаргетинг по кликам и просмотрам, который можно регистрировать в AppsFlyer.

<Image align="center" alt="" src="https://cdn.appsflyer.com/marketplace/static/logo/liftoff.png" />

<div id="important" />

> 🚧 **Важно!**
>
> Некоторые медиа-источники ограничивают передачу данных 3-м сторонам. AppsFlyer не может передавать сторонним платформам и сервисам данные на уровне пользователя, полученные через эти медиа-источники. Поэтому все установки из таких медиа-источников отправляются как органические.
>
> Для получения более подробной информации и списка медиаисточников, которые ограничивают передачу данных 3-м сторонам, кликните <Anchor target="_blank" href="/marketers/ru/docs/user-level-data-retention">здесь</Anchor>.

<div id="setting-up-liftoff" />

## Настройка Liftoff

**Необходимые условия.** Перед настройкой интеграции необходимо <Anchor target="_blank" href="/marketers/ru/docs/partner-integrations#contact-details">связаться с партнером</Anchor> и открыть у него аккаунт.

**Чтобы активировать интеграцию:**

1. **Чтобы активировать:** В AppsFlyer в боковом меню выберите **Сотрудничество**> **Маркетплейс партнеров**.  
   Чтобы отредактировать: Выберите **Совместная работа** > **Активные интеграции**.
2. Выберите соответствующее приложение.
3. На вкладке **Интеграция** выберите приложение для интеграции и нажмите **Активировать партнера**.
4. На вкладке **Интеграция** выберите приложение для интеграции и нажмите **Активировать партнера**.  
    **Обратите внимание:** Переключатель должен оставаться включённым (активированным) всё время, пока вы работаете с партнёром. Этот переключатель должен быть <Anchor target="_blank" href="/marketers/ru/docs/partner-activation-deactivation">включен</Anchor> все время, пока вы работаете с этим партнером.
5. Завершите настройку, используя соответствующие вкладки, как описано ниже. Для подробного описания заголовка окна для конфигурации партнера, нажмите <Anchor target="_blank" href="/marketers/ru/docs/set-up-an-integrated-partner#about-the-integrated-partner-page">здесь</Anchor>.

**Активация атрибуции по просмотрам**

Включите, если хотите атрибутировать установки по просмотрам от Liftoff. Слайдер окна атрибуции по просмотрам доступен на вкладке [**Ссылка атрибуции**](/docs/liftoff-campaign-configuration-in-appsflyer#attribution-link-tab).

<div id="default-postbacks" />

### Постбэки по умолчанию

Отправляйте автоматические постбэки в Liftoff после установок, отклоненных установок и повторных вовлечений пользователей. В этом разделе можно определить **источник пользователей**, который позволяет отправлять постбэки.

Выберите **Только этот партнер** для событий, поступающих только от пользователей, атрибутированных Liftoff.  
Выберите **Все источники, включая органические**, чтобы вся ваша база пользователей была доступна для отправки отчетов в Liftoff.

<div id="note" />

> 📘 **Примечание:**
>
> Как сеть, ориентированная на все установки, Liftoff предпочитает получать постбэки обо всех новых установках вашего приложения из любого источника, включая органический. Для этого выберите **Все источники, включая органические**, чтобы отправлять в Liftoff все постбэки по установкам.

**Чтобы настроить постбэки для внутренних событий приложения:**

1. Активируйте **Постбэки о событиях в приложении**
2. Выберите, что следует отправлять партнеру: только **избранные события** или **все**.
   * Примечание. Если вы выберете отправку всех событий, событие af\_app\_opened отправляться не будет.
3. Если вы хотите выбрать события вручную, кликните **Добавить событие**, чтобы добавить в список событие SDK.
4. Заполните следующие данные:

| Имя параметра | Description(Описание) |
| --- | --- |
| **SDK event name** (Имя события SDK) (требуется только при выборе вручную) | Имя события, полученное AppsFlyer из SDK или из межсерверного события.  <br />**Совет**. Если в списке нет нужного вам события, активируйте его на устройстве с неорганической установкой, и повторите поиск. |
| **Sending option (Вариант отправки)** | Выберите вариант отправки события:  <br />**Только от этого партнера** для событий, поступающих **только** от пользователей, атрибутированных Liftoff.  <br />**Все источники, включая органические**, чтобы партнер получал сведения о событиях всех пользователей, которые есть в вашей базе. |
| **Send event data (Отправить данные о событии)** | <ul><li>**Нет значений и нет дохода:** отправляет только само событие без значения.</li><li>**Значения, нет дохода:** отправляет все параметры, кроме значения дохода.</li><li>**Значения и доход**: отправляет все параметры события, включая значение дохода (если оно есть в событии).</li></ul> |

5. Нажмите **Сохранить**.

<div id="ad-network-permissions" />

### Ad Network Permissions (Разрешения для рекламной сети)

На этой вкладке вы можете выбрать разрешения, которые хотите предоставить Liftoff. Обратите внимание: даже если атрибуция для Liftoff отключена, вкладка разрешений остается активной, и вы можете предоставить Liftoff контроль.

Используйте эти переключатели, чтобы уполномочить рекламную сеть самостоятельно обрабатывать конфигурацию для вашего приложения:

* **Разрешение настраивать интеграцию**: разрешить партнеру управлять настройками на вкладке интеграции (за исключением постбэков по внутренним событиям приложений).
* **Разрешение настраивать постбэки по событиям внутри приложения**: разрешить партнеру сопоставлять себе постбэки по внутренним событиям приложений на вкладке интеграции.
* **Предоставление доступа к отчету об удержании пользователей**: партнер получает доступ только к собственным данным об удержании пользователей.
* **Разрешить доступ к агрегированным данным о лояльных пользователях** - только к собственным данным партнера о лояльных пользователях
* **Предоставить доступ к агрегированным данным о событиях в приложении** - только к собственным данным партнера о событиях в приложении
* **Предоставление доступа к агрегированным данным о доходе**: партнер получает доступ к данным только по атрибутированным ему доходам.
* **Разрешить доступ к дэшборду Protect360**: партнер получает доступ только к собственным данным Protect360, при условии что эта функция активирована для рекламодателя.

См. дополнительные сведения о предоставлении <Anchor target="_blank" href="/marketers/ru/docs/set-up-an-integrated-partner#permissions-tab">разрешений рекламной сети</Anchor>.

<div id="agency-permissions" />

### Разрешения агентства

Если вы работаете с Liftoff как с партнерским агентством, в этом разделе вы можете предоставить ему разрешения для самостоятельной настройки вашего приложения:

* **Основной переключатель** - установка в положение **ВКЛ.** :

  * Показывает доступные разрешения для агентства
  * Позволяет атрибутировать агентство с установками для данного приложения
  * Позволяет агентству просматривать данные о продвигаемой рекламе Meta и X Ads

  **Внимание: установки агентства, выполненные при выключенном переключателе, не атрибутируются агентству** и не отображаются ни на дэшборде агентства, ни в его данных (<Anchor target="_blank" href="/marketers/ru/docs/partner-activation-deactivation#разрешения-агентства">подробнее</Anchor>).

* **Allow access to your Protect360 dashboard (Разрешить доступ к панели управления Protect360)**
* **Разрешить доступ к отчетам по удержанию и когортам** - данные по удержанию и когортам, созданные только пользователями, привлеченными через агентство.
* **Разрешить доступ к агрегированным органическим данным**
* **Разрешить настройку постбэков по внутренним событиям приложений**: разрешить агентству сопоставлять себе постбэки по внутренним событиям приложений на вкладке интеграции.
  * **Разрешения на передачу событий** - выберите здесь предпочтительный вариант:  
    a) **Только этому партнеру** - отправлять только события от трафика, привлеченного в приложение самим агентством  
    b) **Все источники, включая органические** - отправлять события из всех источников вашего трафика, включая другие медиаисточники, агентства и органических пользователей
  * **Разрешить передачу дохода от событий** - разрешить агентству отправлять события вместе с данными об их денежной ценности
  * Предоставляя разрешения агентству, обязательно указывайте конкретные события. Кликните **Add event** и выберите событие из раскрывающегося списка. Выполните это действие для каждого события, которое нужно добавить в список.

Узнать больше о <Anchor target="_blank" href="/partners/ru/docs/about-agency-accounts">работе с агентствами</Anchor>.

</Accordion>

<div id="set-up-skadnetwork-integration-with-liftoff" />

## Настройка интеграции SKAdNetwork с Liftoff

**Чтобы получать данные SKAdNetwork от Liftoff:**

1. <Anchor target="_blank" href="/marketers/ru/docs/skadnetwork-skan-solution-guide">Для поддержки SKAdNetwork обновите SDK AppsFlyer до последней версии</Anchor>.
2. В AppsFlyer Conversion Studio <Anchor target="_blank" href="/marketers/ru/docs/skan-conversion-studio#настройка-значений-конверсии-в-skan-conversion-studio">настройте значения конверсии для измерения нужных вам событий</Anchor>.
3. Сообщите Liftoff цель вашей кампании и итоговое событие, по которому вы хотите оптимизировать кампании. Рекомендуется, чтобы итоговое событие коррелировало с предпочтительным для вас событием и происходило вскоре после установки.  
   Например:
   * **CPA-кампании:** сообщите нужное событие и цель CPA, которые будут использоваться для оптимизации кампаний SKAdNetwork.
   * **CPI-кампании:** сообщите цель CPI, которая будет использоваться для оптимизации кампаний SKAdNetwork.
4. Свяжитесь с вашей командой Liftoff по работе с клиентами, чтобы подтвердить, что постбэки SKAdNetwork отправляются со значениями конверсии.
5. [Необязательно] Чтобы передавать Liftoff идентификатор транзакции SKAdNetwork, включите параметр **Share Transaction ID in SKAdNetwork mode**.  
   Узнать больше об <Anchor target="_blank" href="/marketers/ru/docs/skadnetwork-skan-solution-guide#sending-postbacks-to-integrated-partners">ID транзакции.</Anchor>

<div id="product-feed-retargeting-with-liftoff" />

## Ретаргетинг по фиду продуктов с Liftoff

Чтобы атрибуция продуктовых событий работала корректно, Liftoff должен получать идентификаторы продуктов, связанные с каждым вашим событием. Например, идентификаторы конкретных продуктов, которые пользователи покупают или добавляют в корзину.

Эти идентификаторы должны быть связаны с уникальными идентификаторами, которые вы передаете в Liftoff в рамках фида продуктов. Liftoff по умолчанию поддерживает <Anchor target="_blank" href="/marketers/ru/docs/in-app-events-event-structure#предопределенные-параметры-событий">стандартное соглашение AppsFlyer для передачи этих данных</Anchor> через атрибуты af\_content\_id.

Если у вас нестандартное внедрение данных о событии, пожалуйста, свяжитесь с вашим CSM в Liftoff, чтобы узнать, возможна ли интеграция.
