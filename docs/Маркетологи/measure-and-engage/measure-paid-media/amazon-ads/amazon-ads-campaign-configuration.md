> **Краткий обзор:** Amazon Ads (amazondsp\_int) – это интегрированный партнёр AppsFlyer, являющийся <Anchor target="_blank" href="/marketers/ru/docs/self-reporting-networks-srns">SRN</Anchor>, и предоставляющий владельцам приложений возможность с помощью AppsFlyer измерять атрибуцию на основе кликов и просмотров для ТВ, планшетов и мобильных устройств.

## Активировать партнера

**Необходимые условия.** Перед настройкой интеграции необходимо <Anchor target="_blank" href="/marketers/ru/docs/partner-integrations#contact-details">связаться с партнером</Anchor> и открыть у него аккаунт.

**Чтобы активировать интеграцию:**

1. **Чтобы активировать:** В AppsFlyer в боковом меню выберите **Сотрудничество**> **Маркетплейс партнеров**.  
   Чтобы отредактировать: Выберите **Совместная работа** > **Активные интеграции**.
2. Выберите соответствующее приложение.
3. На вкладке **Интеграция** выберите приложение для интеграции и нажмите **Активировать партнера**.
4. На вкладке **Интеграция** выберите приложение для интеграции и нажмите **Активировать партнера**.  
    **Обратите внимание:** Переключатель должен оставаться включённым (активированным) всё время, пока вы работаете с партнёром. Этот переключатель должен быть <Anchor target="_blank" href="/marketers/ru/docs/partner-activation-deactivation">включен</Anchor> все время, пока вы работаете с этим партнером.
5. Завершите настройку, используя соответствующие вкладки, как описано ниже. Для подробного описания заголовка окна для конфигурации партнера, нажмите <Anchor target="_blank" href="/marketers/ru/docs/set-up-an-integrated-partner#about-the-integrated-partner-page">здесь</Anchor>.

## Завершите настройку в Amazon Ads.

Выполните следующие действия в Amazon Ads:

1. Проверьте, чтобы ваше приложение было правильно зарегистрировано в Amazon Ads. См. <Anchor target="_blank" href="https://advertising.amazon.com/help/GF97FJUFXBDM32P4">Регистрация приложений (Register apps)</Anchor> в документации Amazon Ads.
2. Когда вы создаёте кампании в Amazon Ads, проверьте, чтобы с кампанией были связаны соответствующие конверсии. См. <Anchor target="_blank" href="https://advertising.amazon.com/help/GMQBB4PRFK8C33AE">Назначение определения конверсии кампании (Assign a conversion definition to a campaign)</Anchor> в документации Amazon Ads.

## Настройка Amazon Ads

Интеграция с Amazon Ads поддерживает атрибуцию кликов и показов. Окно конфигурации содержит следующие вкладки: Интеграция, ссылка Атрибуции, стоимость, выручка от рекламы и Разрешения. Доступные вкладки для Amazon Ads — «Интеграция» и «Разрешения».

> 📘 **Примечание**
>
> Эта интеграция поддерживает приложения для Android, iOS и Fire. iOS также поддерживается через SKAN.

<div id="integration-tab" />

<Accordion title="Вкладка «Интеграция»">

На вкладке **Интеграция** есть ряд разделов, описанных ниже.

#### Активировать партнера

Чтобы настроить интеграцию, необходимо сначала [включить](/docs/amazon-ads-campaign-configuration#активировать-партнера) переключатель **Активировать партнёра**. Узнайте больше о <Anchor target="_blank" href="/marketers/ru/docs/partner-activation-deactivation#активировать-интеграцию-партнера">активации и деактивации партнерских интеграций</Anchor>.

#### Общие настройки

**Идентификатор рекламодателя Amazon**

Это уникальный ключ Amazon для рекламодателя, сгенерированный Amazon. Идентификатор рекламодателя Amazon необходим для завершения интеграции и обеспечения атрибуции на Amazon Ads. Чтобы найти идентификатор рекламодателя Amazon:

* **Для рекламодателей, использующих самообслуживание:** Ваш идентификатор рекламодателя находится в консоли отчетности Amazon Ads под вашим именем рекламодателя на вкладке «Рекламодатели» в «Менеджере кампаний Amazon DSP».
* **Для рекламодателей, использующих управляемые услуги:** Обратитесь к своему аккаунт-менеджеру Amazon, чтобы узнать ваш идентификатор рекламодателя.
* Если вы используете несколько рекламных аккаунтов Amazon для одного и того же приложения (и, следовательно, имеете несколько идентификаторов рекламодателей Amazon), настройте интеграцию следующим образом:
  1. В Amazon Ads выберите один рекламный аккаунт и назначьте его в качестве **исходного аккаунта (source account)**. Назначьте все остальные рекламные аккаунты **целевыми аккаунтами (destination accounts)**.
  2. Свяжитесь со специалистами Amazon по работе с учётными записями, чтобы настроить то же самое на их стороне.
  3. В AppsFlyer введите идентификатор рекламодателя Amazon, связанный с исходным аккаунтом. Это применит конфигурацию интеграции ко всем связанным целевым аккаунтам.

**Идентификатор приложения Amazon**

* **Для приложений Android:** Имя пакета. Например: `com.example.app`
* **Для приложений Fire ТВ или Fire tablet:** ASIN продукта (стандартный номер товара Amazon).
* **Для приложений iOS:** Идентификатор приложения в магазине приложений без части «`id`» (например, `12345678`).
* **Для** <Anchor target="_blank" href="/marketers/ru/docs/set-up-multi-store-android-attribution#единый-дэшборд-vs-отдельный-дэшборд-на-магазин">**приложений с единым дэшбордом**</Anchor> (дэшборды, объединяющие данные Google Play и магазина Amazon для одного и того же приложения AppsFlyer): Введите имя пакета Android в качестве идентификатора приложения.  
  **Примечание: <Anchor target="_blank" href="https://advertising.amazon.com/help/GF97FJUFXBDM32P4">Убедитесь, что приложение</Anchor> <Anchor target="_blank" href="https://advertising.amazon.com/help/GF97FJUFXBDM32P4">зарегистрировано</Anchor> как приложение Android в аккаунте Amazon Ads.**

#### Атрибуция установок

Установите окна атрибуции для кликов и просмотров установок (первые запуски). Обратите внимание, что только установки, выполненные в течение окна лукбэк, приписываются Amazon Ads.

**Примечание:** Атрибуция для повторных установок (любая установка, не являющаяся первоначальной настройкой на устройстве) не поддерживается.

1. Установите для параметра **окно лукбэк по кликам для установок** значение от 1 до 24 часов или от 1 до 14 дней.  
   **Примечание:** Amazon Ads рекомендует установить окно лукбэк по кликам на 14 дней, чтобы оно соответствовало их окну атрибуции и не допускало расхождений.
2. [Необязательно] Включите **атрибуцию по просмотрам установок** и задайте **окно атрибуции по просмотрам** на 1–24 часа.   
   **Примечание:** Amazon Ads рекомендует установить окно лукбэк по просмотрам на 14 дней, чтобы оно соответствовало их окну атрибуции и не допускало расхождений

#### Атрибуция повторного вовлечения

Включите переключатель **атрибуции повторных вовлечений** и установите разные окна атрибуции для атрибуции повторных вовлечений существующих пользователей, которые просмотрели, кликнули, ***или были вовлечены*** благодаря вашей рекламе. Обратите внимание, что к Amazon Ads можно отнести только повторные вовлечения в течение окна лукбэк.

1. [Необязательно] Включите **атрибуцию повторного вовлечения** и задайте окно лукбэк:
   * Установите **окно лукбэк по кликам для повторных вовлечений** на 1–23 часа или 1–14 дней.
2. [Необязательно] Включите **атрибуцию повторного вовлечения по просмотрам** и задайте окна лукбэк:
   * Установите **окно лукбэк по просмотрам для повторных вовлечений** на 1–23 часа или 1–14 дней.
3. Установите **окно повторного вовлечения** на 1–23 часа, 1–90 дней или **на весь срок**.

#### Игнорирование активных пользователей для ретаргетинга

Установите временной интервал, в течение которого будут <Anchor target="_blank" href="/marketers/ru/docs/set-retargeting-inactivity-window#период-неактивности">игнорироваться повторные вовлечения и повторные атрибуции</Anchor> пользователей, запустивших ваше приложение. Это означает, что их активность в течение указанного периода времени не регистрируется в AppsFlyer.

> 📘 **Примечание**
>
> Конверсии повторного вовлечения и реатрибуции пользователей, которые в заданный период времени были **неактивны**, **регистрируются**.

1. Включите **Игнорировать активных пользователей для ретаргетинга**.
2. Установите **окно бездействия** в диапазоне от 1 до 30 дней.  
   **Примечание:** Amazon Ads рекомендует установить окно бездействия на 7 дней, чтобы избежать расхождений.

#### Постбэки по внутренним событиям приложений

Настройте сопоставление событий приложения с событиями Amazon Ads, отправляемых через постбэки.

**Чтобы настроить постбэки по внутренним событиям приложения:**

1. Активируйте **постбэки по внутренним событиям приложения**.
2. Чтобы добавить в список событие, определенное в SDK, или межсерверное событие, нажмите **Добавить событие**. В таблице ниже описаны поля, которые необходимо заполнить:

| Имя параметра | Описание |
| --- | --- |
| **Событие AppsFlyer** | Имя события, полученное AppsFlyer из SDK, интегрированного в приложение, или из межсерверного события.<br />**Совет**: Не нашли здесь нужное событие?<ul><li>Убедитесь, что событие активировано на устройстве с неорганической установкой, и повторите поиск.</li><li>Введите его в поле **Событие AppsFlyer** и нажмите **Добавить другое**. Узнайте больше о <Anchor target="_blank" href="/marketers/ru/docs/in-app-event-postback-configuration#пользовательские-события">сопоставлении пользовательских событий</Anchor>.</li></ul> |
| **сопоставлено с событием партнёра** | Уникальное имя или идентификатор каждого события, определенное на стороне партнера. Выберите из списка предопределенных партнерских событий то, которое соответствует событию вашего приложения (событие AppsFlyer).<br /><br />**Примечания:**<ul><li>Вы можете выбрать ДРУГОЕ для событий, которые не соответствуют вашему событию приложения.</li><li>Если включено измерение повторного вовлечения, мы рекомендуем не сопоставлять событие `af_app_opened` вообще или сопоставлять его только с `OTHER`. Это предотвратит потенциальные дубликаты при отправке этого события.</li></ul> |
| **для пользователей от** | Выберите вариант отправки для события:<ul><li>**Только для этого партнера**: Отправляйте постбэки только если это событие связано с этим партнером.</li><li>**Все медиа-источники и органический трафик**: Отправляйте постбэки для событий, связанных с любым партнером, а также для органических событий.</li></ul> |
| **включая** | <ul><li>**Без данных (по умолчанию)**: Отправлять только само событие без каких-либо значений.</li><li>**Ценности, значения и выручка**: Отправьте все параметры события, **включая** ценность, значение выручки (если оно присутствует в событии).</li><li>**Ценности, значения без выручки**: отправляются все параметры, **кроме** значения дохода.</li></ul> |

   > 📘 **Примечание:**
   >
   > Если вы отправляете ваше внутреннее событие приложения в AppsFlyer через S2S, Amazon рекомендует включать IP-адрес. Это позволяет AppsFlyer отправлять код страны геолокации события в Amazon, что помогает с классификацией применения DMA. Это, в свою очередь, обеспечивает максимальную оптимизацию ваших внутренних событий приложения.

3. [Необязательно] Нажмите значок **Добавить условие**<Image alt="conditional-iae-postbacks-icon.png" src="https://files.readme.io/575c9ab0dd82a125319591072b17604a7f9d1b71fff6baff4124d99edc1a7fc7-16570673855121.png" width="30px" />, чтобы <Anchor target="_blank" href="/marketers/ru/docs/in-app-event-postback-configuration#условные-постбэки-по-событиям-в-приложении">установить условия</Anchor> для события.
4. Нажмите **Сохранить интеграцию**.

## Отложенная глубинная ссылка (диплинкинг)

* Диплинки не поддерживаются в Amazon Ads.
* Отложенные диплинки: оба метода отложенного диплинкинга AppsFlyer недоступны для Amazon Ads:
  * [UDL](https://dev.appsflyer.com/hc/docs/dl_work_flow#implement-unified-deep-linking-udl) (Унифицированный диплинк) – не поддерживается для SRN.
  * [GCD](https://dev.appsflyer.com/hc/docs/dl_work_flow#recommended-implement-extended-deferred-deep-linking) (Получение данных о конверсии) – не подходит для Amazon Ads, так как данные атрибуции рекламы Amazon [ограничены](/docs/amazon-ads-campaign-configuration#ограничения-сырых-данных).

## Ограничения сырых данных

Необработанные данные из Amazon Ads <Anchor target="_blank" href="/marketers/ru/docs/about-raw-data-identifier-restrictions#ограничения-медиа-источников">ограничены на платформе AppsFlyer</Anchor>. В итоге медиа-источник отмечается как «ограниченный», а сведения о кампании отсутствуют. Клики и показы с Amazon Ads не включаются в отчёты о сырых данных.

## Атрибуция CTV-to-Mobile (из CTV на мобильные устройства)

Amazon может атрибутировать установки мобильных приложений к кампаниям для CTV (подключённое телевидение), например, кампаниям, которые проводятся на Amazon Prime Video. Это происходит, когда пользователь, который видит рекламу на CTV, заходит в приложение Amazon на своём мобильном устройстве.

**Примечание:** Не существует **индикатора отчётности**, который явно показывает, что кампания проводится на CTV. Чтобы улучшить качество данных и измерение, мы рекомендуем включать `CTV` в название кампании, когда это применимо.

## Поддержка политики согласия Amazon в ЕС

Amazon Ads обновляет свою политику согласия пользователей в ЕС в преддверии вступления в силу <Anchor target="_blank" href="https://commission.europa.eu/strategy-and-policy/priorities-2019-2024/europe-fit-digital-age/digital-markets-act-ensuring-fair-and-open-digital-markets_en">Закона о цифровых рынках (DMA).</Anchor> Будучи партнером Amazon по атрибуции приложений, AppsFlyer адаптируется к этим изменениям в законодательстве, чтобы помочь рекламодателям получить максимальную отдачу от своей рекламы на Amazon. Поправки к закону вступают в силу 30 июня 2026 года.

> 📘 **Примечание**
>
> Обновленная политика согласия для стран ЕС применяется только к данным (установки, повторные вовлечения и события в приложении), поступающим от пользователей из стран ЕС, Великобритании или Швейцарии (CH).

Чтобы соответствовать требованиям, передавайте в AppsFlyer информацию о согласии на DMA тем же методом, который используется для <Anchor target="_blank" href="/marketers/ru/docs/support-google-eu-consent-policy">согласия DMA для Google</Anchor>.

### Методы согласия DMA

В настоящее время AppsFlyer поддерживает два метода отправки согласия DMA:

| Метод | Подробности |
| --- | --- |
| **Вручную** | Единственное поле, обязательное для Amazon, — это `ad_user_data_enabled`. |
| <Anchor target="_blank" href="https://iabeurope.eu/transparency-consent-framework/">**TCF**</Anchor> **(рамки прозрачности и согласия)** | Если вы используете Платформу управления согласием (CMP), убедитесь, что идентификатор поставщика Amazon Ads (**793**) включен в список разрешенных поставщиков. |

> 📘 **Примечание**
>
> Amazon также поддерживает сигналы согласия через <Anchor target="_blank" href="https://iabtechlab.com/gpp/">Платформу глобальной конфиденциальности (GPP)</Anchor>, но в настоящее время AppsFlyer не поддерживает этот метод.

## Характеристики и ограничения

| Специфика | Примечания |
| --- | --- |
| Агентства | Интеграция Amazon Ads в настоящее время не поддерживается для агентств, поэтому может управляться только из аккаунта рекламодателя. |
| Показы, клики и затраты | Данные о показах, кликах и затратах пока недоступны для этой интеграции. |
| Диплинки | [Диплинки не поддерживаются для этой интеграции](#отложенная-глубинная-ссылка-диплинкинг). |
| Переустановки и реатрибуция | Переустановка и реатрибуция не поддерживаются для этой интеграции. |
| Атрибуция предварительной загрузки | Измерение предварительной загрузки не поддерживается в рамках этой интеграции, но может быть реализовано через устаревшую интеграцию amazon\_int. |
| Ограничение постбэков | На Android, когда в поле `advertiserIdEnabled` задано значение "false", установка или повторное вовлечение не будут отправлены в Amazon, даже если доступен идентификатор рекламодателя. |
