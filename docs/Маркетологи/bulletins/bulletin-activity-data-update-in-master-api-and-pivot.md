| Раздел | Детали |
| --- | --- |
| Что нового? | Master API и Pivot переходят на использование тех же данных об активности, которые уже используются в Моих дэшбордах, AppsFlyer MCP, ИИ-ассистенте и агетствах, поэтому метрики активности будут совпадать везде, где вы их видите.<br /><br />Некоторые базовые значения, которые используются для фильтрации и группировки в данных об активности, меняются. Подробности см. ниже.<br /><br />Большинству клиентов ничего делать не нужно. |
| Дата вступления в силу | Октябрь 15, 2026 г. |
| Кого это касается | <ul><li>Все клиенты Master API и Pivot, которые анализируют метрики активности: `activity_average_dau`, `activity_average_dau_mau_rate`, `activity_average_arpdau`, `activity_sessions`, `activity_revenue`, `activity_event_counter_[event_name]`, `activity_sales_in_usd_[event_name]`, `activity_average_unique_users_[event_name]`.</li></ul>Примечание: изменение не затрагивает `activity_average_mau`.<ul><li>Когорты, LTV, удержание и другие типы данных не меняются. Если вы объединяете данные об активности с этими типами данных в одном отчете, некоторые значения, особенно медиаисточник / `pid`, могут не совпадать, пока эти типы данных не внесут такие же изменения.</li></ul> |
| Необходимые действия | Это изменение происходит автоматически, и большинству клиентов не нужно ничего делать.<br /><br />Если вы фильтруете или группируете отчеты об активности по любому из перечисленных ниже значений, проверьте эти фильтры после 15 октября 2026 г. Старые значения могут показывать другие результаты или вообще не показывать результаты. |
| Что вам нужно знать | Учитывайте следующие изменения:<ul><li>**После обновления значения метрик могут незначительно отличаться.** Данные об активности переходят в новый конвейер обработки данных, поэтому значения метрик могут немного измениться. Для метрик Уникальные пользователи, DAU и связанных метрик разница может составить до 3%. Это ожидаемое поведение в рамках изменения процесса обработки данных, а не ошибка данных.</li><li>**«Предустановка» и «предзагрузка» теперь объединяются в «загрузку»** для группировки `тип_атрибутируемого_ касания`. Фильтрация или группировка `attributed_touch_type` в Master API по значениям «предустановка» или «предзагрузка» больше не предоставляет отдельные результаты. Теперь этот трафик отображается как «загруженный».</li><li>**Значения null заменяются пустыми строками.** Это включает источник трафика organic/None (`pid` в Master API, Медиаисточник в Pivot), который теперь передается в виде пустой строки.</li><li>**Меняются названия двух медиаисточников:** `facebook` становится `Facebook Ads`, а `twitter` и `twitter_int` становятся `Twitter`. Названия всех остальных медиаисточников не меняются.</li><li>**Применяются новые ограничения на усечение полей:**<ul><li>`ad_id` (250 символов)</li><li>`ad_name` (256)</li><li>`event_name` (100)</li><li>`app_version` (64)</li><li>`agency` (32)</li><li>`keywords` (90)</li><li>`install_app_store` (50)</li><li>`os_version` (20)</li></ul></li></ul>В ходе этой миграции данные активности переносятся в более современную и масштабируемую инфраструктуру, что повышает надежность и эффективность, а также обеспечивает поддержку будущих улучшений продукта. |
