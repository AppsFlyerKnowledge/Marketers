> **Кратко:** метод UDL возвращает дополнительные параметры для диплинкинга существующих пользователей.

| **Что нового** | AppsFlyer SDK V6.6+ позволяет методу UDL возвращать дополнительные параметры для диплинкинга существующих пользователей (с установленным приложением). |
| --- | --- |
| **Дата вступления в силу** | 27 апреля 2022 г. |
| **Где** | Метод UDL для диплинкинга существующих пользователей с установленным приложением |
| **Описание** | **До изменения:** метод UDL возвращал только параметры `deep_link_value` и `deep_link_sub1-10` для диплинкинга существующих пользователей.<br /><br />**После изменения:** метод UDL возвращает все параметры, указанные в параметре ссылки, включая:<ul><li>`c`</li><li>`pid`</li><li>`path`</li><li>`scheme`</li><li>`host`</li><li>`af_c_id`</li><li>`af_adset`</li><li>`af_adset_id`</li><li>`af_ad`</li><li>`af_ad_id`</li><li>`af_ad_type`</li><li>`af_channel`</li><li>`af_dp`</li><li>`esp_name`</li><li>`ссылка`</li></ul> |
| **Что вы должны знать** | **Практическая рекомендация**: хотя эти параметры доступны для диплинкинга существующих пользователей, мы рекомендуем создавать новые ссылки, используя только параметры `deep_link_value` и `deep_link_sub1-10`, как указано в нашем <Anchor target="_blank" href="/marketers/ru/docs/create-deep-linking-and-redirection-links-for-your-campaigns-with-onelink#создание-ссылки-onelink">руководстве по диплинкингу</Anchor>.<ul><li>Это изменение предназначено только для клиентов, у которых уже есть ссылки, использующие устаревшие методы диплинкинга. Теперь эти клиенты могут реализовать метод UDL для диплинкинга и использовать эти дополнительные параметры для диплинкинга существующих пользователей, продолжая использовать те же ссылки. Создавать новые ссылки не требуется.</li><li>Требуется AppsFlyer SDK V6.6+</li></ul> |
