> **概要：** 借助My Dashboards中的活动指标，您可以准确、灵活、快速地评估任意时间范围内的应用表现，洞察用户互动趋势、收入情况，并及早发现问题。

> 📘 **注意**
>
> 净收入指标将在2026年7月至8月间逐步向客户推广。如果你还没看到他们，就不需要采取任何行动;这些文件将在这段时间内为您的账户开放。参见 <Anchor target="_blank" href="/marketers/zh/docs/bulletin-cohort-and-activity-metrics-update-in-my-dashboards">公告：My Dashboards 中的群组与活跃数据指标更新</Anchor>

## 关于活跃维度指标

My Dashboards中的活动指标可帮助您在统一视图中分析活动、LTV和群组数据，更全面地监测业务表现，获得更深入的洞察，包括：

* 基于实时数据分析**用户活跃度与用户粘性**。
* 衡量**事件表现、收入情况以及应用打开趋势**。  
  在单一面板中一站式查看**LTV、实际和群组**周期数据。
* **按日或按月**灵活自定义（活跃用户）报表拆分数据。

注意：在My Dashboards中，**活跃维度数据**（Activity）已更名为**实际**（Actual）。此调整旨在明确这些指标反映的是所选时间范围内的真实用户行为，而非基于LTV聚合的数据。同时，Actual也是应用打开（Sessions）、毛利润（Gross Profit）和总收入（Total Revenue）的默认统计周期。

## 面板信息

**活跃维度数据概览**

视图模板专为高层级监测而设计，可帮助营销人员快速评估应用表现、发现用户互动趋势、分析收入情况并及早识别问题，从而在各类推广活动和平台中实现数据驱动的快速决策。

**在面板中添加微件**

点击面板右上角的 **+ 新建**即可在面板中添加微件。可创建的微件类型如下：表格、KPI、图表、应用内事件表、应用内事件标、文本或自定义指标。如需了解详细操作步骤，请参见此处<Anchor target="_blank" href="/marketers/zh/docs/my-dashboards#add-widget">说明</Anchor>。

**在图表或表格中添加指标**

在图表设置或表格设置对话框中，单击指标+加号。

然后，您可以按维度添加分组并选择过滤条件。

如需了解详细操作步骤，请参见此处说明。

## 可用的活动指标

* 除了活跃用户、过去31天的活跃用户和DAU/MAU之外，其余所有指标均支持群组周期和LTV分析。

| **指标** | **描述** |
| --- | --- |
| 活跃用户 | <ul><li>在所选时间范围内至少打开过一次应用的独立活跃用户数量，基于应用打开数据统计，按照所选时间拆分方式呈现。</li><li>如果选择按日拆分，则显示为DAU。</li><li>如果选择按月拆分，则显示为MAU。</li><li>在折线图、柱状图或按日期分组的表格中展示时，均以DAU形式呈现。</li><li>如需了解原始DAU和MAU数据的查询方式，请参见：<Anchor target="_blank" href="/marketers/zh/docs/calculate-daily-and-monthly-active-users-dau-and-mau">计算日活和月活用户（DAU 和 MAU）</Anchor>。</li></ul> |
| 最近31天内的活跃用户 | 在过去31天內（非自然月）打开过相关应用至少一次的独立用户数量（仅统计一次）。 |
| DAU/MAU | 回访用户比例（用户粘性）。<br /><br />如果日活/月活比率超过50%，则表示在过去31天中，用户平均有15天打开过相关应用。<br /><br />日活/月活比率用于衡量用户粘性，并可让您快速了解用户留存的大致情况。<br /><br />计算方式为：日活用户 / 最近31天的活跃用户数 |
| 应用打开（Sessions） | 所选时间范围内应用打开的次数。 |
| 总收入 | 选定时间段内产生的收入。包括应用内购买收入和广告收入。 |
| 净收入 | 选定期间的净收入，从af\_net\_revenue事件参数汇总而来。对于使用 ROI360 的应用，店铺收入是扣除总收入后扣除应用商店费用和税费（净 = 总收入 - 商店费用 - 税费）;发送af\_net\_revenue的应用程序定义了计算。 |
| 首次访问 | 首次访问网页应用的次数。计入行数，conversion\_name = first\_visit。仅适用于网页应用。 |
| 重演 | 非自然回访网页应用的次数。计为conversion\_name=重访的行。仅适用于网页应用。 |
| 用户获取 | 支持跨平台归属或网页应用。对于网页应用，用户获取反映的是首次访问次数，除非设置了用户获取事件。对于移动应用来说，用户获取等于安装量。当同时查看多个应用时，用户获取 = 安装次数 + 首次访问次数（或客户端配置的自定义网页事件）。 |

## 可用应用内指标

| **指标** | **描述** |
| --- | --- |
| 转化率 | 完成该事件的独立用户数（归因到的转化）占比。计算方式为：事件独立用户数/归因到的转化量 x 100 |
| 独立用户数 | 完成该事件的独立用户数（即归因到的转化数） |
| 平均数量 | 单个独立用户数完成该事件的平均次数。<br /><br />计算方式为：事件数量/归因到的转化量 |
| eCPA | 实际 CPA（单次转化成本）。<br /><br />计算方式为：成本/事件独立用户数 |
| 数量 | 该事件的完成次数 |
| 收入 | 该事件所产生的收入 |
| ARPU | 每位用户的平均收入<br /><br />计算方式为：收入/独立用户数（即归因到的转化数） |
| 毛利润 | 收入 - 成本 |
| ROAS | 广告支出回报率（％）<br /><br />计算方式为：收入/成本 * 100 |
| ROI | 投资回报率（％）<br /><br />计算方式为：（收入 - 成本）/成本 * 100 |
| 净收入 | 该特定活动产生的净收入（扣除应用商店费用和税费后）。 |
| 净ARPU | 每位用户的平均净收入。<br /><br />计算方式为：净收入 / 独立用户数（用户数=归因用户数） |
| 净毛利润 | 净收入 - 成本 |
| 净ROAS | 广告支出回报率，基于净收入。<br /><br />计算方式为：净收入 - 成本 |
| 净ROI | 基于净收入计算的投资回报率。<br /><br />计算方式为：（收入 - 成本）/成本 * 100 |

**净收入指标**

净指标（净收入、净投资回报率、净ROAS、净ARPU、净毛利）显示的是净收入而非毛收入。净收入是指af\_net\_revenue中发送的任何数值，广告主定义计算方式（例如，扣除门店费用和/或税费后的收入、毛利润率或服务费后的收入）。对于使用 ROI360 的应用，AppsFlyer 计算为总收入减去应用商店费用和税费（净 = 总收入 - 商店费用 - 税费）。

价值来自你应用内事件的af\_net\_revenue参数，就像常规收入指标使用af\_revenue一样。价值以交易货币表示，以af\_currency（默认美元）表示。

值的填充方式：

* 如果 **ROI360门店收入** 在应用中启用后，AppsFlyer 会自动在其记录的应用内购买和订阅事件中填充af\_net\_revenue。
* 否则，这个值来自你在应用内事件中发送的af\_net\_revenue参数。
* 如果两者均未提供净收入，指标显示为N/A。

参见 <Anchor target="_blank" href="/marketers/zh/docs/about-roi360-store-revenue">关于ROI360门店收入</Anchor> 以及 <Anchor target="_blank" href="/marketers/zh/docs/in-app-events-event-structure">应用内事件 - 事件结构</Anchor>.

## 支持的筛选与分组维度

您可以通过以下维度对活动指标进行分组和筛选：

* 按日拆分
  * Ad
  * 广告 ID
  * 广告组
  * 即广告组的 ID
  * 应用
  * 归因类型
  * 归因到的广告触达类型
  * 广告系列
  * 广告系列ID
  * 渠道
  * 地理位置
  * 日期
  * Keywords（关键词）
  * 媒体渠道
  * 代理
  * Site ID
  * 平台
  * Sub Param 5（可配置参数5）
  * 来源
  * 交互类型
  * 互动目标位置
  * Install app store
* 按月拆分
  * 应用
  * 广告系列
  * 广告系列ID
  * 地理位置
  * 月份
  * 媒体渠道
  * 代理

## 特点与局限性

| **特点** | **说明** |
| --- | --- |
| 数据时效性 | 网页、电视或PC和控制台应用的队列和活动指标不支持实时。<br /><br />**注意：** CTV和PC及主机应用的LTV指标可实时获取——这一限制仅适用于活动和队列数据。 |
| 时间粒度 | 对于网页版、CTV以及PC和主机应用，队列和活动数据仅以每日细分方式提供。这些平台不支持每周和每月的拆解。 |
| 广告收入 | 不支持实时数据。 |
| 净收入指标 - 期间 | 支持活动和队列指标。不支持劳动价值分析。 |
| 净收入指标——数据新鲜度 | 不支持实时。数据从第二天开始开放。 |
| 净收入指标 - 广告收入 | 广告收入事件不计入净收入指标。<br /><br />**提示：** 要查看包含广告收入的净收入，可以创建一个自定义指标，将广告收入加到净收入上，例如：净收入 + 收入（事件：af\_ad\_revenue）。【Beta】在My Dashboards中设置自定义指标 |
| 净收入指标 - 归因来源 | 不支持 SKAN 和 SSOT。 |
| 净收入指标——平台 | 仅限安卓和iOS（移动端）。 |
| 时区 | 除以下指标仅支持UTC时区外，其余指标均支持本地时区：<ul><li>最近31天内的活跃用户</li><li>DAU/MAU</li><li>按月分组的活跃用户（MAU）</li></ul> |
| 图表 | 目前仅支持以折线图或柱状图形式展示**DAU**。 |
| 微件 | KPI和表格微件支持所有活动指标。 |
| 按日数据范围 | 单个视图最多支持62天 |
| 卸载事件 | 不包括在活跃维度数据中 |
| 历史数据 | 最多支持近3年的按日数据 |
| 地理分组 | 基于激活时的地理位置，最多支持前62个地理位置。 |
| 应用打开指标 | <ul><li>自2025年2月1日起，活跃维度数据已统一覆盖获客与再营销。</li><li>如需查看再营销视图，可在**归因类型**中筛**再互动**和**再归因**。</li></ul> |
| 统一视图指标 | 仅支持在统一视图中查看所有指标。 |
| 来自应用内事件的独立用户和活跃用户 | My Dashboards中**来自应用内事件的独立用户**和**活跃用户**基于统计估算算法得出，该算法可减少对用户的重复计数，从而在不同指标和视图中提供一致、可靠的用户活跃度衡量结果。 |
| 实际活跃用户与独立用户数： | 如果所选日期范围包含今天及之前的日期，且小部件未按日期分组，则今天的数据不会显示。 |
