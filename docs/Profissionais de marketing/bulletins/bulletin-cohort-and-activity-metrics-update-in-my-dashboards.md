| Secção | Atenção |
| --- | --- |
| **O que há de novo?** | A partir de **julho de 2026**, as métricas de cohort e atividade no **My Dashboards** serão atualizadas para uma infraestrutura de dados aprimorada, projetada para **dados prontos para IA**. Essas mudanças serão implementadas para os clientes ao longo dos meses de **julho e agosto de 2026**.<br /><br />Como parte dessa implementação gradual, é possível observar algumas alterações em alguns valores de métricas, assim como na disponibilidade de dados históricos e opções de segmentação.<br /><br />As atualizações incluem novos tipos de visualização e métricas para os dados de atividade, melhoram a precisão de usuários únicos para os dados de cohort e ampliam os dados históricos e as opções de segmentação para cohort e atividade. |
| **Data de entrada em vigor** | Julho a agosto de 2026 (lançamento gradual) |
| **Impacto** | Todos os anunciantes, agências e parceiros que utilizam métricas de cohort e atividade no **My Dashboards**. |
| **Ações necessárias** | Nenhuma ação é necessária. As mudanças serão aplicadas automaticamente. |
| **O que você deve saber** | **<span id="h_activity-retargeting-and-ua-view-types"></span>Os tipos de visualização "retargeting" e "UA" já estão disponíveis para atividade**<br /><br />Agora os dados de atividade podem ser filtrados e analisados por tipo de visualização, incluindo retargeting e UA.<ul><li>Os dados de retargeting já estão disponíveis desde fevereiro de 2025.</li><li>Os dados da UA foram disponibilizados em fevereiro de 2026.</li><li>Os dados do mesmo dia não estão incluídos nas visualizações de retargeting e UA. Eles são disponibilizados com 1 dia de atraso.</li></ul>**<span id="h_net-revenue-metrics"></span>As métricas de receita líquida já estão disponíveis para cohort e atividade**<br /><br />Os clientes que mensuram a receita líquida através do ROI360 ou usando o parâmetro de evento `af_net_revenue` nos eventos in-app agora verão:<ul><li>Receita líquida</li><li>ROAS líquido</li><li>ROI líquido</li><li>ARPU líquido</li><li>Lucro bruto/líquido</li></ul>Essas métricas só estão visíveis para os clientes que enviam dados de receita líquida.<br /><br />**<span id="h_ctv-app-support"></span>O suporte para aplicativos de CTV já está disponível para cohort e atividade**<br /><br />Agora as métricas de cohort e atividade foram disponibilizadas para aplicativos de CTV.<br /><br />**<span id="h_new-dimensions"></span>Novas dimensões já estão disponíveis para cohort e atividade**<br /><br />As seguintes dimensões foram disponibilizadas para segmentação de cohort e atividade:<ul><li>Platform</li><li>Sub 1</li><li>Os alertas do Protect360 são atualizados no horário UTC diário.</li></ul>**<span id="h_extended-historical-data"></span>Dados históricos ampliados para cohort**<br /><br />Para a maioria das métricas de cohort, o acesso aos dados já foi disponibilizado em **6 de maio de 2024**, adicionando cerca de 6 meses a mais no histórico.<br /><br />Isso não se aplica aos dados diários de usuários únicos, que foram disponibilizados em **3 de junho de 2025**.<br /><br />**<span id="h_unique-users-updated-calculation-method"></span>Método de cálculo atualizado para usuários únicos nas análises diárias por cohort**<br /><br />Agora as métricas abaixo usam um método de cálculo atualizado para a segmentação diária por cohort, como Dia 1, Dia 7, entre outras:<ul><li>Usuários únicos de eventos in-app</li><li>Retenção</li><li>Taxa de retenção</li><li>OPCIONAL</li></ul>**<span id="h_what-changed-and-why"></span>O que mudou e por quê**<br /><br />Agora os usuários são identificados no nível do dispositivo. Um usuário que reengajou várias vezes é contabilizado uma única vez, e não uma vez a cada reengajamento.<br /><br />Isso corrige a contagem excessiva anterior para aplicativos que executam campanhas de reengajamento.<br /><br />Se o seu aplicativo executa campanhas de reengajamento, talvez você observe uma diminuição no número diário de usuários únicos. Trata-se de uma correção em vez de uma redução no número de usuários reais ou na performance.<br /><br />O novo método usa uma abordagem de contagem probabilística, que tem uma margem de erro muito pequena, normalmente entre 1% e 2%. Esse comportamento é esperado e não representa um erro nos dados.<br /><br />**<span id="h_unique-users-data-availability"></span>Disponibilidade de dados**<ul><li>Os dados com granularidade diária já estão disponíveis desde **3 de junho de 2025**.</li><li>Os dados diários anteriores de usuários únicos não estão disponíveis no My Dashboards.</li><li>As granularidades semanal e mensal não serão afetadas. O histórico completo permanece disponível.</li></ul>**<span id="h_activity-unique-users-and-active-users-historical-availability"></span>Dados históricos sobre a disponibilidade de usuários únicos e usuários ativos para a atividade**<br /><br />Para datas anteriores a **3 de junho de 2025**, os usuários únicos e os usuários ativos na atividade só estão disponíveis por data.<br /><br />Os totais em um intervalo de datas foram disponibilizados em **3 de junho de 2025**.<br /><br />Isso se aplica a qualquer métrica calculada a partir do número de usuários únicos ou de usuários ativos. Essa é uma limitação permanente.<br /><br />**<span id="h_uninstalls-temporarily-unavailable"></span>As desinstalações estão temporariamente indisponíveis para cohort**<br /><br />A métrica de desinstalações está temporariamente indisponível.<br /><br />**O LTV não será afetado.**<br /><br />**<span id="h_ad-revenue-unified-in-utc"></span>Receitas de anúncios unificadas em UTC para todos os dashboards**<br /><br />Agora as métricas de receitas de anúncios em todos os dashboards são apresentadas em UTC, independentemente do tipo de integração ou das configurações de fuso horário no nível do aplicativo. Os dados históricos não serão afetados.<ul><li>Essa mudança se aplica à receita de anúncios coletada do tipo de integração `impression-level (SDK)`. Os dados de outros tipos de integração já eram relatados em UTC.</li><li>Fizemos essa mudança para padronizar a receita de anúncios coletada de múltiplas fontes e parceiros, a maioria dos quais reporta os dados em UTC.</li><li>Na data da mudança (20 de julho), se o seu aplicativo usar um fuso horário diferente de UTC nas configurações do aplicativo, você poderá notar um aumento nos números de receita de anúncios. Isso não é duplicação de dados nem dados novos, e nada é excluído. São os mesmos dados, apenas deslocados para um dia diferente para se alinhar ao UTC.</li></ul>**<span id="h_about-the-transition"></span>Sobre a transição**<br /><br />O objetivo dessa migração é levar os dados de cohort e atividade para uma infraestrutura mais moderna que melhore a confiabilidade e a performance dos dados, fornecendo recursos de análise específicos para IA e possibilitando melhorias futuras nos dados de atribuição agregados da AppsFlyer.<br /><br />Caso você precise consultar dados mais antigos, o dashboard de cohort e retenção permanecerá disponível. Use-o para acessar dados de cohort de usuários únicos anteriores a **3 de junho de 2025** ou para visualizar dados de desinstalações enquanto essa métrica ainda está sendo aprimorada. |
