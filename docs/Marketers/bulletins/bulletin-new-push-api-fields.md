| **What's new** | Three new fields have been added to the push API. They are:<br /><br />* engagement\_type<br />* event\_type<br />* store\_product\_page (new for Android)<br /><br />### engagement\_type<br /><br />The parameter can return the following values: preload, click\_to\_download, click\_to\_app, engaged\_click, engaged\_view, view, listening, or if not reported it will be empty<br /><br />More information on the new engagement types can be found [here](/docs/bulletin-engagement-types).<br /><br />### event\_type<br /><br />The parameter can return the following values: install, organic-install, install-in-app-event, organic-install-in-app-event, re-engagement, re-engagement-in-app-event, re-attribution, reinstall, organic-reinstall, re-attribution-in-app-event, skad-installs, skad-re-downloads, skad-in-app-events, skad-postbacks, skad-postbacks-copy.<br /><br />### store\_product\_page<br /><br />This parameter follows the current iOS values.<br /><br />For more information click [here](/docs/raw-data-field-dictionary#attribution::4c11e393).<br /><br />CALLSTART::Note::<br /><br />#### Note<br /><br />The **custom\_data** field has been changed to include a colon between the field name and the field value.<br /><br />CALLEND:: |
| --- | --- |
| **Effective date** | January 17, 2024 |
| **What this impacts** | Advertisers and agencies using the [push API](/docs/push-api-streaming-raw-data) |
