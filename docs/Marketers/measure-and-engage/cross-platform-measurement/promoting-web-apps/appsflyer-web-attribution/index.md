This section provides resources and guides for setting up and managing AppsFlyer Web Attribution and Web Performance Measurement.

<Cards>
  <Card title="Web Performance Measurement - Overview" href="/docs/web-performance-measurement-overview" icon="fa-solid fa-chart-line">
    Web Performance Measurement enables you to identify which media sources and campaigns drive users to your website and measure how those visits influence downstream actions over time. It enables you to capture and attribute user interactions end-to-end, supporting both user acquisition (first-time visitors) and re-engagement, from the initial visit through lifetime value measurement.
  </Card>
  <Card title="Migrate from PBA to Web Performance Measurement" href="/docs/migrate-from-pba-to-web-performance-measurement" icon="fa-solid fa-right-left">
    People-Based Attribution (PBA) is being replaced by Web Performance Measurement, AppsFlyer upgraded web measurement solution. This article covers what's changing, the migration steps, and the full field mapping for your reports and server-side integrations.
  </Card>
  <Card title="Onboard Web Performance Measurement" href="/docs/onboard-web-performance-measurement" icon="fa-solid fa-rocket">
    Follow the onboarding instructions in this guide to set up Web Performance Measurement. Once set up, you can measure and attribute website visits and web events to marketing sources, understand what drives meaningful website outcomes, and support cross-platform measurement.
  </Card>
  <Card title="Configure Web Performance Measurement settings" href="/docs/configure-web-performance-measurement-settings" icon="fa-solid fa-chart-line">
    Configure your web attribution settings to control how AppsFlyer attributes website visits, conversions, and user activity to marketing campaigns. Settings include attribution windows, user acquisition events, re-engagement rules, and domain exclusions.
  </Card>
  <Card title="Integrate AppsFlyer Web SDK" href="/docs/integrate-appsflyer-web-sdk" icon="fa-solid fa-code">
    Install the AppsFlyer Web SDK (also known as the pixel) on your website to report user visits and events to AppsFlyer, and set a persistent customer user ID (CUID) to unify journeys across platforms.
  </Card>
  <Card title="Use the Web SDK Test page" href="/docs/use-the-web-sdk-test-page" icon="fa-solid fa-code">
    Use the Web SDK Test page to validate the Web SDK installation and event recording in real time. Run it when you first integrate the SDK and whenever you add or change an event.
  </Card>
  <Card title="About traffic source resolution" href="/docs/about-traffic-source-resolution" icon="fa-solid fa-circle-info">
    Use traffic source resolution to identify the initial media source, campaign, and channel for each web visit, using the URL parameters and referrer data available at landing page load. This gives attribution the traffic-source context it needs to attribute downstream web events, including the user-acquisition event, accurately.
  </Card>
  <Card title="Choose attribution parameters for landing page URLs" href="/docs/choose-attribution-parameters-for-landing-page-urls" icon="fa-solid fa-diagram-project">
    Use consistent, complete URL parameters in your website landing page links to get the best campaign granularity while maintaining accurate attribution in Web Performance Measurement.
  </Card>
  <Card title="Server-to-Server (S2S) API for Web Performance Measurement" href="/docs/server-to-server-s2s-api-for-web-performance-measurement" icon="fa-solid fa-plug">
    The S2S API for Web Performance Measurement lets you send web visits and events to AppsFlyer directly from your server, bypassing browser limitations like ad blockers and cookie restrictions. Use it alongside the Web SDK or on its own to get more complete, higher-quality attribution data.
  </Card>
  <Card title="Export Web Performance Measurement report data from Data Locker" href="/docs/export-web-performance-measurement-report-data-from-data-locker" icon="fa-solid fa-box-archive">
    Export Web Performance Measurement data from Data Locker in two report types that enable you to analyze website performance at the right level. Use End User Events to analyze all visits and events, and use Conversions to count and attribute unique conversion anchors (first visits, revisits, and user-acquisition events).
  </Card>
</Cards>
