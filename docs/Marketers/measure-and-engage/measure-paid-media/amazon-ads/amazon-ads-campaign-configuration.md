> **At a glance:** Amazon Ads (amazondsp\_int) is an AppsFlyer <Anchor target="_blank" href="/marketers/docs/self-reporting-networks-srns">SRN</Anchor> integrated partner, providing app owners the ability to measure click and view-based attribution with AppsFlyer for TV, tablet, and mobile devices.

![mceclip0.png](https://files.readme.io/0a4c9078bd683c51bad40408c894f6e2b7314d7c369bd46ac90c3e622f62f0a7-11927906589329.png)

## Activate partner

**Prerequisite:** An account with the partner. If you don't have an account, contact the partner to open one before setting up the integration.

**To set up a new integration:**

1. In AppsFlyer, go to **Collaborate > Partner Integrations > Marketplace** tab.  
   (**To edit an existing integration:** Go to **Collaborate > Partner Integrations > Active integrations** tab.)
2. Select the relevant app.
3. Search for the partner and select **Integrate**.
4. In the **Integration** tab, turn on the **Activate partner** toggle.   
   **Note:** The toggle **must stay on (active) as long as you work with the partner**. <Anchor target="_blank" href="/marketers/docs/partner-activation-deactivation">Learn more</Anchor>
5. Complete the configuration using the relevant tabs, as described below. Learn more about <Anchor target="_blank" href="/marketers/docs/set-up-an-integrated-partner">partner integrations.</Anchor>

## Complete the setup in Amazon Ads

Complete the following steps in Amazon Ads:

1. Make sure your app is properly registered in Amazon Ads. See <Anchor target="_blank" href="https://advertising.amazon.com/help/GF97FJUFXBDM32P4">Register apps</Anchor> in the Amazon Ads documentation.
2. When you create campaigns in Amazon Ads, make sure to associate the relevant conversions with the campaign. See <Anchor target="_blank" href="https://advertising.amazon.com/help/GMQBB4PRFK8C33AE">Assign a conversion definition to a campaign</Anchor> in the Amazon Ads documentation.

## Setting up Amazon Ads

The integration with Amazon Ads supports click and impression attribution. The configuration window includes the following tabs: Integration, Attribution link, Cost, Ad revenue, and Permissions. The available tabs for Amazon Ads are Integration and Permissions.

> 📘 **Note**
>
> This integration supports Android, iOS, or Fire apps. iOS is also supported via SKAN.

<div id="integration-tab" />

<Accordion title="Integration tab">

The **Integration** tab includes a number of sections, as described below.

#### Activate partner

To configure the integration, you must first [turn on](/docs/amazon-ads-campaign-configuration#activate-partner) the **Activate partner** toggle. Learn more about <Anchor target="_blank" href="/marketers/docs/partner-activation-deactivation#activate-a-partner-integration">activating and deactivating partner integrations</Anchor>.

#### General settings

**Amazon advertiser ID**

This is a unique Amazon key for the advertiser, generated by Amazon. The Amazon advertiser ID is required to complete the integration and allow attribution to Amazon Ads. To find the Amazon advertiser ID:

* **For self-service advertisers:** Your advertiser ID is in the Amazon Ads reporting console under your advertiser name, in the "Advertisers" tab of the "Amazon DSP Campaign Manager".
* **For managed service advertisers:** Ask your Amazon account manager for your advertiser ID.
* If you use multiple Amazon ad accounts for the same app (and therefore have multiple Amazon Advertiser IDs), set up the integration as follows:
  1. In Amazon Ads, select one ad account and designate it as the **source account**. Designate all other ad accounts as **destination accounts**.
  2. Contact the Amazon account team to set it up on their backend.
  3. In AppsFlyer, enter the Amazon Advertiser ID associated with the source account. This will apply the integration configuration to all related destination accounts.

**Amazon app ID**

* **For Android apps:** The package name. For example: `com.example.app`
* **For Fire TV or Fire tablet apps:** The product ASIN (Amazon Standard Item Number)
* **For iOS apps:** The app store app ID without the "`id`" part (example:`12345678`).
* **For** <Anchor target="_blank" href="/marketers/docs/set-up-multi-store-android-attribution#single-dashboard-vs-dashboard-per-store">**single dashboard apps**</Anchor> (dashboards that combine data from both Google Play and Amazon store for the same AppsFlyer app): Enter the Android package name as the app ID.  
  **Note:** Make sure the app is <Anchor target="_blank" href="https://advertising.amazon.com/help/GF97FJUFXBDM32P4">registered</Anchor> as an Android app on the Amazon Ads account.

#### Install attribution

Set click-through and view-through attribution windows for installs (first launches). Note that only installs within the lookback window are attributed to Amazon Ads.

**Note:** Attribution for reinstalls (any install that isn’t the initial setup on the device) isn’t supported.

1. Set the **Install click-through lookback window** to either 1-24 hours or 1-14 days.  
   **Note:** Amazon Ads recommends setting the click-through lookback window to 14 days, to align with their attribution window and avoid discrepancies.
2. [Optional] Turn on **Install view-through attribution** and set the **Install view-through attribution window** to 1-24 hours.   
   **Note:** Amazon Ads recommends setting the view-through lookback window to 14 days, to align with their attribution window and avoid discrepancies

#### Re-engagement attribution

Turn on the **Re-engagement attribution** toggle and set the different attribution windows to attribute re-engagements of your existing users who viewed, clicked, ***or engaged*** with your ad. Note that only re-engagements within the lookback window may be attributed to Amazon Ads.

1. [Optional] Turn on Turn on **Re-engagement attribution** and set the lookback window:
   * Set the **Re-engagement click-through lookback window** to either 1-23 hours or 1-14 days.
2. [Optional] Turn on **Re-engagement view-through attribution** and set the lookback windows:
   * Set the **Re-engagement view-through lookback window** to either 1-23 hours or 1-14 days.
3. Set the **Re-engagement window** to either 1-23 hours, 1-90 days, or**Lifetime**.

#### Ignore active users for retargeting

Set a window timeframe to <Anchor target="_blank" href="/marketers/docs/set-retargeting-inactivity-window#inactivity-period">ignore re-engagements and re-attributions</Anchor> of users who launched your app. This means their activity during the window timeframe isn't recorded in AppsFlyer.

> 📘 **Note**
>
> Re-engagement and re-attribution conversions of users who were **dormant** in the set timeframe **are recorded**.

1. Turn on **Ignore active users for retargeting**.
2. Set the **Inactivity window** between 1-30 days.  
   **Note:** Amazon Ads recommends setting the inactivity window to 7 days to align with them and avoid discrepancies.

#### In-app event postbacks

Configure mapping of in-app events with Amazon Ads events, sent via postbacks.

**To configure in-app event postbacks:**

1. Turn on **In-app event postbacks**.
2. Click **Add event** to add an SDK or server-to-server event to the list. The following table describes the fields to complete:

| Parameter name | Description |
| --- | --- |
| **AppsFlyer event** | The name of the event, as received by AppsFlyer either from the SDK integrated into your app or from server-to-server events.<br />**Tip**: Don't see the event you are looking for?<ul><li>Make sure to activate the event on a device with a non-organic installation, and recheck.</li><li>Type it in **AppsFlyer event**, then click **Create custom**. Read more about <Anchor target="_blank" href="/marketers/docs/in-app-event-postback-configuration#custom-events">custom event mapping.</Anchor></li></ul> |
| **mapped to partner event** | The unique name or ID of each event, as defined on the partner's side. Select from the list of predefined partner events, the event that corresponds to your app event (the AppsFlyer event).<br /><br />**Notes:**<ul><li>You can select OTHER for events that don't directly correspond to your app event.</li><li>When re-engagement measurement is enabled, we recommend not mapping the `af_app_opened` event at all, or mapping it to `OTHER` only. This will prevent potential duplications when sending this event.</li></ul> |
| **for users from** | Select the sending option for the event:<ul><li>**This partner only**: Send postbacks only when this event is attributed to this partner.</li><li>**All media sources including organic**: Send postbacks for events attributed to any partner, as well as organic events.</li></ul> |
| **including** | <ul><li>**No data (default)**: Send only the event itself without any event values.</li><li>**Values and revenue**: Send all the event parameters, **including** the revenue value (if exists in the event).</li><li>**Values without revenue**: Send all the parameters **excluding** the revenue value.</li></ul> |

   > 📘 **Note**
   >
   > If you send your in-app event to AppsFlyer via S2S, Amazon recommends including the IP address. This allows AppsFlyer to send the country code of the event’s geo-location to Amazon, which helps with DMA regulation classification. This, in turn, ensures maximum optimization of your in-app events

3. ## Deferred deep linking

* Deep links aren't supported on Amazon Ads.
* Deferred Deep Links: both AppsFlyer methods for deferred deep links aren’t available for Amazon Ads:
  * [UDL](https://dev.appsflyer.com/hc/docs/dl_work_flow#implement-unified-deep-linking-udl) (Unified Deep Link) - isn’t supported for SRNs
  * [GCD](https://dev.appsflyer.com/hc/docs/dl_work_flow#recommended-implement-extended-deferred-deep-linking) (Get Conversion Data) - will not work for Amazon Ads, since Amazon Ads attribution data is [restricted](/docs/amazon-ads-campaign-configuration#raw-data-restrictions).

## Raw data restrictions

Raw data from Amazon Ads is <Anchor target="_blank" href="/marketers/docs/about-raw-data-identifier-restrictions#media-source-restrictions">restricted on the AppsFlyer platform</Anchor>. As a result, the media source is reported as “restricted” and campaign details are null. Clicks and impressions from Amazon Ads aren't included in raw data reports.

## CTV-to-Mobile attribution

Amazon may attribute mobile app installs to CTV (Connected TV) campaigns, such as those on Amazon Prime Video. This occurs when a user who views the CTV ad is logged into an Amazon app on their mobile device.

**Note:** There is **no reporting indicator** that explicitly shows the campaign as CTV. To improve visibility and measurement, we recommend including `CTV` in the campaign name when applicable.

## Support Amazon EU consent policy

Amazon Ads is updating its EU user consent policy in preparation for <Anchor target="_blank" href="https://commission.europa.eu/strategy-and-policy/priorities-2019-2024/europe-fit-digital-age/digital-markets-act-ensuring-fair-and-open-digital-markets_en">Digital Markets Act (DMA)</Anchor> enforcement. As Amazon's App Attribution Partner, AppsFlyer is adapting to these policy changes to help advertisers get the most out of their ads on Amazon. The updated policy takes effect on June 30, 2026.

> 📘 **Note**
>
> The updated EU consent policy applies only to data (installs, re-engagements, and in-app events) from users in the EU, UK, or Switzerland (CH).

To comply, send AppsFlyer DMA consent information using the same method used for <Anchor target="_blank" href="/marketers/docs/support-google-eu-consent-policy">Google's DMA consent</Anchor>.

### DMA consent methods

AppsFlyer currently supports two methods of DMA consent sharing:

| Method | Details |
| --- | --- |
| **Manual** | The only field required by Amazon is `ad_user_data_enabled`. |
| <Anchor target="_blank" href="https://iabeurope.eu/transparency-consent-framework/">**TCF**</Anchor> **(Transparency and Consent Framework)** | If you use a Consent Management Platform (CMP), make sure the Amazon Ads vendor ID (**793**) is included in the allowed vendors list. |

> 📘 **Note**
>
> Amazon also supports consent signals via the <Anchor target="_blank" href="https://iabtechlab.com/gpp/">Global Privacy Platform (GPP)</Anchor>, but AppsFlyer does not currently support this method.

## Traits and limitations

| Trait | Remarks |
| --- | --- |
| Agencies | Amazon Ads integration isn’t supported for agencies at this point, so can only be managed from the advertiser account. |
| Impressions, clicks, and cost | Impressions, clicks, and cost data aren’t available yet for this integration. |
| Deep links | [Deep links aren’t supported for this integration](#deferred-deep-linking). |
| Reinstall and re-attributions | Re-install and Re-attribution aren’t supported for this integration. |
| Preload attribution | Pre-load measurement isn’t supported as part of this integration, but can be achieved via the legacy amazon\_int integration. |
| Postback limitation | On Android, when the `advertiserIdEnabled` field is set to "false", the install or re-engagement will not be sent to Amazon even if advertiser ID is available. |
