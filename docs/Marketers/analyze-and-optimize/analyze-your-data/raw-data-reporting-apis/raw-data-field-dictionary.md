> **At a glance:** El diccionario de campos de datos (especificación de raw data) describe el contenido de los campos. Debe usarse para ayudarle a entender qué significan los campos, cómo se formatean y cuándo están disponibles.

<div id="overview" />

## Visión general

La tabla del diccionario de campos de raw data enumera los campos de raw data disponibles en varios reportes de AppsFlyer. La tabla se actualiza constantemente a medida que se agregan campos de raw data adicionales en AppsFlyer.

Las columnas de la tabla del diccionario son:

* **Grupo de campos:** Agrupación lógica basada en el uso del campo. ¡**Nota**! Los campos del grupo de ingresos por anuncios se muestran en los reportes de raw data, ya sea en sus propias columnas o incluidos como parte del **valor del evento**.
* **Nombre:**
  * Nombre del campo como aparece en los informes de Data Locker y Push API.
  * La notación [n] indica que existen varias instancias del mismo campo; la diferencia entre ellas es el número de instancia. Por ejemplo, Sub Param [n] significa Sub Param 1, Sub Param 2, ..., Sub Param 5. El rango de valores de n se indica como (n=1-5).
* **Nombre del campo**:
  * Nombre del campo utilizado en los reportes proporcionados a través de la página “Exportar datos” y “Pull API”.
  * La notación [n] indica que existen varias instancias del mismo campo; la diferencia entre ellas es el número de instancia. Por ejemplo, Sub Param [n] significa Sub Param 1, Sub Param 2, ..., Sub Param 5. El rango de valores de n se indica como (n=1-5).
* **Fuente**: la ubicación de origen original del contenido del campo, por ejemplo:
  * **Enlace**: enlaces de atribución (consulta <Anchor target="_blank" href="/marketers/es/docs/about-link-structure-and-parameters">la estructura y los parámetros del enlace de atribución de AppsFlyer</Anchor>) o mediante API desde las SRN, cuando corresponda.
  * **SDK**: recopilado a través del SDK en la aplicación.
  * **AF**: generado por AppsFlyer.
  * y otros.
* **Description**
  * Algunos campos tienen significados diferentes según el contexto del evento, por ejemplo como resultado de una campaña de UA o de retargeting.
* **Formato:** tipo y longitud del campo.
  * **String**: la longitud máxima del string. No recomendamos superar los 1024 caracteres de longitud ni las limitaciones de longitud del campo <Anchor target="_blank" href="/marketers/es/docs/about-link-structure-and-parameters#parámetros-de-enlace-de-atribución-ua-y-retargeting">indicadas aquí</Anchor>.
  * **Fecha y hora:**
    * String con el formato `yyyy-mm-dd hh:mm:ss`. Por ejemplo, `2019-09-17 00:09:25` La zona horaria utilizada para mostrar los datos depende de la herramienta de entrega de datos, como se indica a continuación:
      * Página de datos exportados: zona horaria seleccionada por la aplicación.
      * Push API: los campos de hora tienen una opción *selected\_time\_zone*, lo que significa que se usa la zona horaria específica de la app; de lo contrario, UTC.
      * Mater API: El valor predeterminado es la zona horaria seleccionable de la aplicación.
      * Data Locker: UTC
    * Los campos de fecha de los archivos CSV tienen el formato yyyy-mm-dd. Al abrir un archivo CSV en Excel, los campos de fechas se formatean según la configuración de fecha y hora de la computadora. Puedes cambiar el formato de visualización en <Anchor target="_blank" href="https://support.office.com/en-us/article/format-a-date-the-way-you-want-8e10019e-d5d8-47a1-ba95-db95123d273e#ID0EAACAAA=Windows">Excel</Anchor>. Para ver el valor sin formato, abre el archivo con un editor.
    * Push API:
      * Para campos de timestamp en UTC: formato `yyyy-mm-dd hh:mm:ss.sss`. Por ejemplo, `2019-09-17 00:09:25.123`
      * Para campos de timestamp en la zona horaria seleccionada: formato `yyyy-mm-dd hh:mm:ss.sss±th:tm`. Por ejemplo `2019-01-20 04:51:16.000+0000`
  * **Enum n char**: los campos Enum solo pueden contener valores específicos. Por ejemplo, la divisa de costo tiene 3 caracteres y solo puede contener códigos de divisa tal como se especifica.
  * **Enum 5 char boolean:** el valor del campo puede ser `TRUE` o `FALSE`

> * El CSV descargado contiene campos adicionales a los mencionados anteriormente:
>   * **Parte del esquema principal del reporte de AppsFlyer**:
>     * La mayoría de los reportes de AppsFlyer se crean a partir del mismo esquema y contienen los mismos campos.
>     * Algunos campos pueden completarse con valores nulos o vacíos, según el reporte y según si los datos se recopilan de ad networks, anunciantes, plataformas de dispositivos, etc.
>     * Al configurar tus sistemas de BI, es recomendable configurar todos los campos principales del esquema de AppsFlyer, incluso si un reporte determinado siempre los devuelve como valores nulos o vacíos. Esto te permite incorporar fácilmente los datos cuando estén disponibles.
>     * Si un campo no forma parte del esquema principal de reportes de AppsFlyer, solo estará incluido en reportes específicos. Por ejemplo, reportes de SKAN.
>   * **Método de entrega de reportes**: el CSV descargado indica si un campo determinado está disponible a través de Push API, Exportar datos/Pull API y Data Locker. **Nota**: Incluso si un campo forma parte del esquema principal de reportes de AppsFlyer, puede que no forme parte de los reportes entregados por un método específico. Por ejemplo, el campo de ubicación forma parte del esquema principal de AppsFlyer, pero solo aparece en reportes entregados mediante Data Locker, Pull API o la página Export Data; no mediante Push API.
