## Push API

Push API streams raw data generated by AppsFlyer attribution and SKAdNetwork (SKAN) attribution as messages to your servers. You can select the message types and content and set the destination endpoints.

The available message types, data freshness, and fields depend on the attribution framework (AppsFlyer or SKAN), as described in the sections that follow.

### AppsFlyer attribution messages

Message characteristics

| Characteristic | Details |
| --- | --- |
| Message type segregation | - Messages can be segregated by endpoint (maximum 6 endpoints per app) or you can determine the message type by examining the value of the fields listed:<br>  - event\_name<br>  - conversion\_type<br>  - campaign\_type<br>- The values of the fields, per message type, are indicated in the table that follows.<br>**Example:**<br>A message contains the following:<br>- conversion\_type=install<br>- campaign\_type=organic<br>- event\_name=install<br>Use the table to determine that this event is the install event of an organic user. |
| Data freshness | Messages are sent soon after the event is recorded on the AppsFlyer platform. This is typically within minutes. |
| Message contents (fields) | - Messages have a `key:value` structure.<br>- See AppsFlyer attribution [Push API](https://support.appsflyer.com/hc/articles/208387843-Raw-data-field-dictionary-V5-0-spec-#field-availability-by-reporting-tool) fields available.<br>- Each key represents a raw data field. See [description of raw data fields in AppsFlyer](https://support.appsflyer.com/hc/articles/208387843-Raw-data-field-dictionary-V5-#data-fields-dictionary).<br>- Blank or null keys aren't sent at all.<br>- The example contains both null and empty fields. Real postbacks have neither empty nor null fields. The example provided has a JSON format.<br>  - [iOS](https://docs.google.com/spreadsheets/d/e/2PACX-1vRMoTZpgttICSjjjXTh4JU5m9p3ky7Ej_MYc0kZ3vYs7sNq6u_wNvWBgjFLF_VjdRbY54aE5e-4keLY/pub?gid=0&single=true&output=csv)<br>  - [Android](https://docs.google.com/spreadsheets/d/e/2PACX-1vRMoTZpgttICSjjjXTh4JU5m9p3ky7Ej_MYc0kZ3vYs7sNq6u_wNvWBgjFLF_VjdRbY54aE5e-4keLY/pub?gid=233131974&single=true&output=csv) |
| Format of timestamp fields | - UTC timestamps: `yyyy-mm-dd hh:mm:ss.sss`. For example, displays as`2019-09-17 00:09:00.123`. An event took place at 18:00 Tokyo time. The event time is converted to UTC, which is 09:00. The time recorded is the UTC time.<br>- Selected time zone (app-specific) timestamps: `yyyy-mm-dd hh:mm:ss.sss±th:tm`. For example `2019-09-17 18:00:16.000+0900`. An event took place at 18:00 Tokyo time. The event time shown is recorded as 18:00+09:00. 09:00 is the Tokyo time zone. |

### SKAN attribution messages

This section describes the messages (report types) available for SKAN and how to identify the messages. Read this section, then [Set up SKAN attribution endpoint.](https://support.appsflyer.com/hc/articles/207034356#set-up-skadnetwork-attribution-endpoint)

Related reading: [SKAN raw data fields](https://support.appsflyer.com/hc/articles/360014261518). Push API messages have the equivalent structure and fields.

Message characteristics:

| Characteristic | Details |
| --- | --- |
| Message type segregation | - All messages are sent to 1 endpoint set by you.<br>- To determine the message type, use the event\_type field.<br>  <br>  Note: using the event\_type field, you can also determine the event\_name field and skad\_redownload field.<br>- The values of the event\_type field, are indicated in the [table that follows](/docs/push-api-streaming-raw-data#message-types-for-skan-attribution).<br>Example:<br>A message contains the following:<br>- event\_type: skad-re-download<br>From this, we can determine that:<br>- This is a re-download event<br>- The event\_name: install<br>- The skad\_redownload: true |
| Data freshness | - Installs, redownloads, and in-app events:<br>  - Processed daily<br>  - Sent to your endpoint on the day following receipt of the iOS postback by AppsFlyer<br>  - Expect to receive event messages 08:00–11:00 UTC (exact times fluctuate)<br>  - Example: Postbacks received on Monday are sent starting Tuesday 08:00 UTC<br>- Postbacks from iOS and Postbacks copy: Messages are sent soon after they arrive in AppsFlyer |
| Message examples | The spreadsheet contains message examples. The example provided has a JSON format. [SKAN example messages](https://docs.google.com/spreadsheets/d/e/2PACX-1vS0CO6W7jgx6zxMeSGIo-hbqLbFh3AO0OT6qp4cWmgdbWVMjLJ-2dermVz49jmAXexewiOGzR1YjGzu/pub?output=xlsx). |

## Set up Push API endpoints

> 🚧 Caution
>
> Don't use Push API for sending AppsFlyer-attributed data to third parties for the following reasons:
>
> - You can breach privacy regulations, like CCPA, if the user opted out of sending their data to third parties.
> - Some media sources restrict how user-level data provided by them is used, shared with third parties, or both. Make sure that you comply with the media source's terms of use.
>
> For example, [X Ads,](https://business.twitter.com/en/help/ads-policies/introduction-to-twitter-ads/twitter-ads-policies.html) [Snapchat,](https://www.snap.com/en-US/privacy/privacy-policy/) [Pinterest.](https://policy.pinterest.com/en/privacy-policy)
>
> Note: This caution doesn't apply to SKAN data. Use Push API to send SKAN data to third-party endpoints.

To set up Push API, complete the following action list.

| 2 | For AppsFlyer attribution, plan the endpoint settings using the [Push API planning checklist.](https://support.appsflyer.com/hc/articles/207034356#push-api-planning-checklist-for-appsflyer-attribution) | Not applicable |

### Server-side requirements (your server)

Ensure that your server complies with the following requirements:

#### Server-side requirements

|     |     |
| --- | --- |
| Endpoint URL | - Valid domain name<br>- Maximum number of unique endpoints per app:<br>  - AppsFlyer: 6 endpoints<br>  - SKAdNetwork: 3 endpoints |
| Endpoint return code | On receipt of a message, your endpoint must return an HTTP 200 status code. |
| Allowlist AppsFlyer servers | Allowlist AppsFlyer server [IP addresses](https://support.appsflyer.com/hc/articles/207447093-AppsFlyer-IPs-for-Whitelisting) in your firewalls and security systems to ensure communication with the endpoint. |
| TLS versions | - TLS 1.1<br>- TLS 1.2+ See [supported ciphers](https://support.appsflyer.com/hc/articles/360001288945#outgoing-messages-appsflyer-as-client) |
| Ports | Ports: 80, 443 |

> 📘 Note
>
> A timeout mechanism, having a 4-second duration, is used. If AppsFlyer doesn't get an OK message during this time AppsFlyer regards this as a message send failure.

### Set up AppsFlyer attribution endpoint

All team members with permissions to access the API can make changes to Push API settings. Other account users can view the settings.

#### Add an AppsFlyer attribution endpoint

1. In AppsFlyer, from the sidebar, open **Export > API Access.** Scroll down to the Push API section.
2. Click **Add Endpoint.**
3. Select an HTTP method: **POST** or **GET**
4. Enter the **Endpoint URL**.If you get the message _this URL is not safe_, contact AppsFlyer support.
5. Select one or more event types. **Note**: If the in-app event messages are disabled, it means no in-app events have been recorded until now.
6. Select the fields to populate the Push API message. Note:
   - Mandatory fields always sent: App ID, Event name, Event time, IDFA (iOS) or Advertising ID (Android)
   - Use the controls depicted in the following figure to select optional fields.  ![PushAPIFieldSelect1.jpg](https://files.readme.io/316bdfcb4740d870875176e7806f969c89784406c3abc5ca34c9fa0c675a5497-360007416298.jpg)
     - The most common fields are preselected by default. You can cancel the selections.
     - Select optional fields as needed.
     - Use **Clear all** to clear all optional fields.
     - We don't send null/empty fields and the associated key. Take this into account when planning your import/parsing processes.
7. Select one or more (up to 52 events) or **All** in-app events.
   - The list is populated by event types that have already been recorded. If an event is missing, send an event having this type using a test device.
8. Click **Save**.

The Push API is now active. Conversion data is sent to the endpoint.
9. Test the endpoint using the procedure that follows.

#### Test the endpoint

1. Click **Send Test.**

A test result message displays below the **Send Test** button.

A test message is sent to the endpoint. If the test fails, ensure that you have [allowlisted AppsFlyer IP addresses](https://support.appsflyer.com/hc/articles/207447093-AppsFlyer-server-IP-address-ranges-allowlisting-).

> 📘 Note
>
> A timeout mechanism, having a 2-second duration, is used. If AppsFlyer doesn't get an OK message during this time AppsFlyer regards this as a message send failure.

2. Verify that your endpoint received the test message.

[View a copy of the message sent.](https://docs.google.com/spreadsheets/d/e/2PACX-1vScQf189h3Ry0BU-ejbZYkMZCJRdXXYeOwuNxPEHwY77vCVYWW9P9xCTUSJKmTvVbp_yzLidXD0WGLm/pub?gid=0&single=true&output=csv)

### Set up SKAdNetwork attribution endpoint

All team members with permissions to access the API can make changes to Push API settings. Other account users can view the settings.

**To add a SKAdNetwork Push API endpoint:**

1. In AppsFlyer, from the sidebar, open **Export > API Access.** Scroll down to the Push API section.
2. Select **SKAdNetwork** as the attributing entity.
3. Click **Add Endpoint.**

> 📘 Note
>
> You can define 1-3 SKAdNetwork endpoints per app.

4. Select an HTTP method: **POST** or **GET**
5. Enter the **Endpoint** **URL**.If you get the message _this URL is not safe_, contact AppsFlyer support.
6. We don't send null/empty fields and the associated key. Take this into account when planning your import/parsing processes.
7. Click **Save**.

The Push API is now active. Data is sent to the endpoint.

### Configure authentication token

Using the [Push API Authentication Token](https://dev.appsflyer.com/hc/reference/put_tokens-app-app-id), clients can seamlessly integrate and secure their Push-API messages by adding a customizable authorization header with a requested token.

You can customize an authorization header that will be sent with your Push-API messages, by defining the token name and value associated with each app ID. This ensures that your messages are not only secure but also tailored to your specific requirements.

## Additional procedures—managing endpoints

All team members with permissions to access the API can make changes to Push API settings. Other account users can view the settings.

### Change an endpoint

**To modify endpoint settings:**

1. In AppsFlyer, from the sidebar, open **Export > API Access.** Scroll down to the Push API section.
2. Locate the endpoint to be modified.
3. Make the modifications.
4. Click **Save**.

### Delete an endpoint

**To delete an endpoint**:

1. In AppsFlyer, from the sidebar, open **Export > API Access.** Scroll down to the Push API access section.
2. Click **Delete endpoint**.
3. Click **Save.**

The endpoint is removed.

## Troubleshooting, traits, and limitations

<Accordion title="Test message fails">

If you don't receive the test message and you restrict access to your servers by IP address, ensure that you have [allowlisted all the AppsFlyer IP addresses](https://support.appsflyer.com/hc/articles/207447093-AppsFlyer-server-IP-address-ranges-allowlisting-).

</Accordion>

<Accordion title="Duplicate retargeting in-app events">

Retargeting in-app events are duplicated when a purchase event takes place as part of a retargeting campaign during the UA re-engagement window. This is done to attribute revenue to both the UA media source and the retargeting media source.

You will only get duplicate events if you have enabled both:

- Install in-app events
- Retargeting in-app events

[Identify and deduplicate in-app events](https://support.appsflyer.com/hc/articles/360016371077-Double-attribution-of-retargeting-events)

</Accordion>

<Accordion title="In-app event message selection is disabled">

![InappSelectionDisabled_us-en.png](https://files.readme.io/3fd283063aeaa9a6183a980689d7c77fc00b9d7023006a367b0d4f026928d128-360007246818.png)

- In-app event messages can only be selected after one in-app event has been recorded.
- Use a test device to generate an in-app event, or use the [S2S API](https://support.appsflyer.com/hc/articles/207034486) to do so manually.

</Accordion>

<Accordion title="Missing push messages and CloudFront">

Are you using Amazon CloudFront as your endpoint? If so, check if CloudFront is rejecting the message with reject code 421. If this is the case, see [Choosing How CloudFront Serves HTTPS Requests](https://docs.aws.amazon.com/en_pv/AmazonCloudFront/latest/DeveloperGuide/cnames-https-dedicated-ip-or-sni.html).

</Accordion>

<Accordion title="Endpoint error messages">

**Symptom:** The message _this URL is not safe_ displays when you set the endpoint URL.

**Action required**: Contact AppsFlyer support; include the app ID, endpoint URL, and a screenshot of the error message.

</Accordion>

### Can I include custom headers with the Push API request?

No. The Push API supports using the `Authorization` header for authentication tokens only. Additional custom headers — such as `consumer-key` — are **not supported**.

If you need to pass extra parameters, include them in the URL. For example:

```
https://your.server.com?consumer_key=abc456
```
