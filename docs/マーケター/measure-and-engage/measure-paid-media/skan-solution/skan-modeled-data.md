> **概要**：AppsFlyerは、SKAdNetworkの基本的なレポートでは取得できない集計データを、モデリングによって推定します。

## 概要

SKAdNetwork（SKAN）のレポートには、以下の制限があります。

* SKANは6ビットのCVを使用するため、使用できる値は0〜63の64種類に限られます。
* Appleは、ユーザーのプライバシーを保護するため、実際のCVを開示せず、nullとして返す場合があります。
* 取得できるデータは12〜72時間のアクティビティ期間内に限られ、ライフタイムバリュー（LTV）の全体像は分かりません。

SKANのモデリングによる推定データは、これらの課題を解消します。

* AppsFlyerは、機械学習、ベイズ統計、AppsFlyerが報告するデータ、SKANデータを組み合わせ、開示されていない情報を推定します。
* 広告主は、アプリやキャンペーンのLTVの全体像を、より詳しく把握できます。

**注意**：CVスキーマを変更すると、モデリングによる推定データが利用可能になるまで2日かかります。

## 推定データの種類と提供先

| データの種類 | 提供先 | 補足 |
| --- | --- | --- |
| nullのコンバージョン値 | <ul><li>Overview dashboardのSSOT（Single Source of Truth）ビュー</li><li>SKANダッシュボード</li><li>SKAN集計パフォーマンスレポートAPI</li><li>SKANポストバック到着日別集計API</li></ul> |  |
| 収益LTV | Overview dashboardのSSOTビュー | SSOTのData Lockerレポートでは最大30日分。ダッシュボードには引き続きD7を表示 |
| アプリ内イベントLTV | Overview dashboardのSSOTビュー | アプリ内イベントLTVのモデリングは、現在7日間までです。 |
| 地域 | Overview dashboardのSSOTビュー |  |

<div id="null-conversion-values" />

<Accordion title="nullのコンバージョン値">

Appleがプライバシー保護のために実際のCVを開示せず、CVがnullになる場合があります。 AppsFlyerでは、CVがnullの場合もインストールとしてカウントします。以下の点に注意してください。

* nullと0は、意味が異なります。
  * 0：ユーザーはアプリをインストールしましたが、アクティビティ期間中に計測対象の行動を実行していません。この場合、指標は正確であり、モデリングは行いません。
  * null：AppleがCVを開示していないため、ユーザーが何をしたか分かりません。
* CVがnullのインストールがあると、成果指標に偏りが生じる可能性があります。この偏りを補正し、アプリの成果をより正確に捉えるため、nullのCVに相当する0〜63の値を、モデリングによって推定します。
  * nullのモデリングには、過去14日間のうち少なくとも2日分のデータが必要です。

モデリングによるCVの推定：

* CVを取得できたSKANインストールの分布を基に、CVがnullのインストールをモデリングします。推定に使用するアルゴリズムは、複数の変数を考慮しながら動的に変化します。以下は、その仕組みの一例です。
  * 100件のインストールのうち、60件がnull、10件がCV=1、5件がCV=3、25件がCV=5だったとします。
  * CVがある40件の内訳は、CV=1が25%、CV=3が12.5%、CV=5が62.5%です。
  * nullの60件にも同じ分布を適用し、15件をCV=1、7件をCV=3、38件をCV=5と推定します。
* SKANダッシュボードとAPIの指標に含まれます。推定データを含まない元の指標も併せて提供され、*モデリングなし*と表示されます。
* アプリ、メディアソース、キャンペーン、広告セットの粒度のデータを使用します。これらの粒度で推定データを利用できない場合は、N/Aと表示されます。

CVに基づいて利用できる推定指標：

* 収益
* イベント発生回数
* eCPA
* ARPU
* ROI
* ROAS

</Accordion>

<div id="revenue-ltv" />

<Accordion title="収益LTV">

[![modeled_d7.png](https://files.readme.io/ec175800b52164844c56743a33fe412eef02c3b76975ca572819535bb5e5eff9-12183780248081.png)](https://files.readme.io/ec175800b52164844c56743a33fe412eef02c3b76975ca572819535bb5e5eff9-12183780248081.png)

SKANレポートだけで取得できる収益は、SKANの計測期間とConversion Studioの収益用CV設定で計測できる範囲に限られます。 SKANモデリングでは、インストール後30日目までの収益を推定できます。

**メリット**：

SKAN 3以前では、アクティビティ期間が終了した後のデータも推定できます。

SKAN 4以降では、以下のメリットがあります。

* データの即時性：2件目のSKANポストバックが届く前に、収益LTVを利用できます。ポストバックの遅延は24〜144時間です。
* 計測対象の拡大：2件目・3件目のポストバックの粗いCVをイベントやリテンションなどの計測に使いながら、収益LTVはモデリングで取得できます。
* データの補完：2件目のポストバックで収益を計測する場合、そのデータを収益LTVの推定に使用し、ポストバックの3段階の値より細かい粒度の収益データを提供します。

**注意点**：

* SKAN Conversion Studioで収益計測を設定したアプリでは、アプリ内購入と広告収益を対象に、収益LTV指標が表示されます。
* 収益LTVには、少なくとも14日分の収益データが必要です。たとえば、2022年11月1日に総収益を設定した場合、推定データの対象となる最初のインストール日は2022年11月14日です。データは、その8日後の2022年11月22日に表示されます。
* 収益LTVと派生指標は、インストール後［X］日（7、14、21、30日のいずれか）が経過した翌日に、SSOTダッシュボードのウィジェット、グラフ、表で以下のように利用できます。
  * 収益D[X]
  * ARPU D[X]
  * 粗利益D[X]
  * ROI D[X]
  * ROAS D[X]

</Accordion>

<div id="inapp-event-ltv" />

<Accordion title="アプリ内イベントLTV">

SKANフレームワーク単独で把握できる、インストール後のアプリ内イベントに関する情報は限られています。 SKANモデリングでは、アプリ内イベントの分析対象を広げ、インストール後7日目までの指標を提供します。

**メリット**：

SKAN 3以前では、アクティビティ期間が終了した後のデータも推定できます。

SKAN 4以降では、以下のメリットがあります。

* データの即時性：2件目のSKANポストバックが届く前に、アプリ内イベントLTVを利用できます。ポストバックの遅延は24〜144時間です。
* 計測対象の拡大：2件目・3件目のポストバックの粗いCVを収益やリテンション率などの計測に使いながら、アプリ内イベントLTVはモデリングで取得できます。
* データの補完：2件目のポストバックでアプリ内イベントを計測する場合は、そのデータを使ってイベント指標の推定精度を高めます。粗いCVのポストバックだけを使う場合より、詳しい計測結果を得られます。

**注意点**：

* 指標は、2024年3月7日以降に利用できます。
* ディメンションとして表示できるアプリ内イベントと、その指標の対象は、以下に限られます。
  * SKAN Conversion Studioで設定したイベント。
  * SKANのウィンドウ1の期間中に発生したイベント。
* アプリ内イベントのD7指標には、少なくとも14日分のアプリ内イベントデータが必要です。たとえば、2024年1月1日にSKAN Conversion Studioでアプリ内イベントを設定した場合、推定データの対象となる最初のインストール日は2024年1月14日です。データは、その8日後の2024年1月22日に表示されます。
* アプリ内イベントLTV指標（現在は7日間まで）と派生指標は、インストール後8日目に、SSOTダッシュボードのウィジェット、グラフ、表で以下のように利用できます。
  * イベントのユニークユーザー数D7
  * イベントのコンバージョン率D7
  * イベントeCPA D7
  * イベント収益D7
* 選択した期間に、インストールから7日経っていない日付が含まれる場合、D7指標に使用できるのはAppsFlyerのデータのみです。そのため、イベントのユニークユーザー数D2がD7を上回ることがあります。データを可視化するため、表に「ソース」または「アトリビューション方法」の階層を追加できます。

</Accordion>

<div id="geo" />

<Accordion title="地域">

SKANポストバックには、地域のディメンションが含まれません。そのため、SKANポストバックだけでは、SKANデータを地域別にグループ化できません。 AppsFlyerは、モデリングによってSKANインストールの地域を推定し、SKANデータを地域ディメンションで表示・グループ化できるようにします。

キャンペーン単位でAppsFlyerの従来のアトリビューションデータを利用できない場合、SSOTビューの地域別分布は推定されません。

地域の推定：

* ほかのAppsFlyerの方法でキャンペーンに帰属したインストールの地域別分布を考慮し、機械学習ツールで推定します。
* SSOTダッシュボードの地域ディメンションで利用できます。  
  **注意**：地域とアトリビューション方法の両方でグループ化すると、各地域のデータを、AppsFlyerのモデルによるものとSKANの重複のないインストールに分けて表示できます。 SKANの重複のないインストールは、モデリングによる推定値です。

注意点：

* AppsFlyerの地域モデリングの精度は、約90%です。地域を推定できない場合、SKANインストールはNoneに分類されます。 Noneは、地域が不明であることを意味します。

</Accordion>
