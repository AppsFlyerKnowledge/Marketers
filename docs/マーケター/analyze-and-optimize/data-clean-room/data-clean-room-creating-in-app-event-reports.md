> **概要：**

## アプリ内イベントレポートの作成

**アプリ内イベントレポートを作成するには、以下のタブに記載されている手順に従います。**

**注記：** これらの手順は、読みやすくするためにタブに分割されています。レポートを作成するには、すべての手順を完了する必要があります。*（説明のとおり、特定の手順はカスタムソースを使用しないレポートには関係ありません。）*

<div id="perform-preliminary-steps" />

<Accordion title="準備手順">

1. **Data Clean Room**の**レポート**タブに移動します。
2. **+ 新しいレポート**ボタンをクリックします。
3. ソースデータの種類として**アプリ内イベント**を選択し、画面右下隅にある**次へ**をクリックします。
4. レポートの名前を入力してください。
   * これには、DCRプラットフォームでレポートを識別するのに役立つ任意の名前を指定できます。
   * <strong>重要！</strong>レポート名がアカウント内の他のすべてのレポートと異なることを確認してください。そうでない場合は[レポートを保存](/docs/data-clean-room-creating-in-app-event-reports#configure-report-settings-and-save-the-report)できません。
   * レポート名の要件：
     * 文字数：2-80文字
     * 利用可能な有効文字：
       * 半角アルファベット<strong>（A-Z, a-z）</strong>
       * 数字<strong>（0-9）</strong> - *最初の文字には使用できません*
       * ハイフン（-） - *最初の文字には使用できません*
     * 無効な文字：
       * スペース
       * その他すべての記号または特殊文字

</Accordion>

<div id="select-sources" />

<Accordion title="ソースの選択">

レポートに使用するソースデータを指定します。

#### **アプリ内イベントのソース**

* **アプリ：** AppsFlyerアカウント内のアプリを1つ以上選択します。
* **データ期間：** 時間枠： DCRでアプリ内イベントを検索する履歴データの日数を選択します(1〜30日)。
* イベントイベント： レポートに含めるアプリ内イベントを1つ以上選択します。
  * SDKまたはサーバー間API(S2S)を介して AppsFlyerにデータを報告するように設定された選択したアプリのすべてのアプリ内イベントが、利用可能なイベントに含まれます。
*
  | インストール | インストールアトリビューションに関連するアプリ内イベント<br /><br />* インストールは、ユーザーがアプリをダウンロード、インストールし、初回起動したときに記録されます。 |
  | --- | --- |
  | リエンゲージメント | リエンゲージメントに関連するアプリ内イベント<br /><br />* リエンゲージメントは、特定のアプリの非アクティブなユーザーがアプリのリターゲティングキャンペーンに接触し、その後アプリを起動したときに記録されます。 |
  | リアトリビューション | リアトリビューションに関連するアプリ内イベント<br /><br />* リアトリビューションは、特定のアプリの元ユーザー（アンインストールしたユーザー）がアプリのリターゲティングキャンペーンに接触し、その後再インストールしたときに記録されます。 |

#### **データソース**

1. [オプション] レポートで使用するソースをさらに追加します。ソースを増やすかどうかを選択するときは、カスタムソースを **使用する**レポートと**使用しない**レポートとの大きな違いにご注意ください。
   * カスタムソースを**使用しない**レポートでは、アプリ内イベントのローデータから特定のイベントパラメータと値が抽出されます。
   * カスタムソースを使用するレポートでは、アプリ内イベントのローデータから特定のイベントパラメータと値が抽出され、このデータがカスタムソースのユーザーレベルのデータ（BIシステムやCRMシステムのデータなど）と照合されます。
2. レポートがカスタムソースを使用しているかどうかに基づいて、次の手順を実行します：
   * レポートでカスタムソースを**使用しない**場合は、**[ディメンションの選択](/docs/data-clean-room-creating-in-app-event-reports#select-dimensions)** に進み、残りのすべてのタブの手順に進みます。
   * レポートでカスタムソースを**使用する**場合は、[**ソースの結合**](#join-sources-only-for-reports-containing-custom-sources)の項目（すぐ下）と残りすべての項目の手順に進みます。

</Accordion>

次の手順は、**カスタムソースを使用するレポートにのみ**関連します。

<div id="join-sources-only-for-reports-containing-custom-sources" />

<Accordion title="ソースの結合（カスタムソースを含むレポートのみ）">

ソース間でデータを突合するには、レポートで使用される各**カスタム**ソースに、アプリ内イベントデータの<Anchor target="_blank" href="/marketers/ja/docs/data-clean-room-setting-up-cloud-services">キー識別子</Anchor>にマッピングされた**識別子**が含まれている必要があります。

* アプリ内イベントレポートには、選択した期間、キー識別子に一致するすべての選択されたイベントが含まれます。

#### **キー識別子とは何ですか？**

これらのアプリ内イベントデータ識別子のいずれかに**キー識別子**としてマッピングできます。

* **AppsFlyer ID (af\_id)：** インストール時にAppsFlyerによって生成された一意のアプリ識別子。
  * このIDは、AppsFlyerによって記録されたすべてのイベントに表示されます。
  * アプリを削除して再インストールすると、新しいAppsFlyer IDが採番されます。
* **customer\_user\_id (CUID - カスタマーユーザーID)：** 通常、ユーザー登録時にアプリ所有者によって生成および設定される一意のユーザー識別子。
  * CUIDを使用してデータをマッピングするには、SDKまたはサーバー間 API (S2S) を介して CUIDをAppsFlyerに送信するようにアプリが構成されている必要があります。

> 🚧 **重要：**
>
> すべてのメディアソースにおいてCUIDを使用した照合が許可されているわけではないため、AppsFlyer IDを使用することを強くお勧めします。

#### **マッピングスキーム（ダイレクト / インダイレクト）**

レポートで複数のカスタムソースが含まれる場合、アプリ内イベントキー識別子に**直接**マッピングする必要があるのはそのうちの 1つだけです。その他のカスタムソースは、次の例に示すように **直接的または間接的**にマッピングできます：

> 📄 **例**
>
> ![dcr_mapping_identifiers_in-app events.png](https://files.readme.io/73d0e929663bda4e6f142c64d0228fdf1eeec3b02ef1560f6f03f2a089d00664-9969546429713.png)
>
> 上記のシナリオでは、次のようになります：
>
> * カスタムソース #1 識別子 **AF** は、アプリ内イベントキー識別子 **af\_id** に直接マッピングされます。
> * カスタムソース #2 は間接的にマッピングされます： **user\_code** -> **AppsFlyer** --> **af\_id**
> * カスタムソース #3 は間接的に (より長いチェーンを通じて) マッピングされます：
>   **user\_id** --> **user\_code** --> **AppsFlyer** --> **af\_id.**
> * カスタムソース #4 識別子 **ID** は、アプリ内イベントキー識別子 **af\_id** に直接マッピングされます。
>   * 代わりに間接的に（カスタムソース#3識別子**user\_id**を介して）マッピングすることもできますが、どちらのオプションも正常に機能することに注意してください。
>
> ✓ このマッピングスキームは、各カスタムソースがアプリ内イベントキー識別子 **af\_id** に直接的または間接的にマッピングされるため、すべてのソース間でデータを照合するように機能します。

</Accordion>

残りの項目は、カスタムソースが含まれているかどうかに関係なく **すべてのアプリ内イベントレポート** に関連します。

<div id="select-dimensions" />

<Accordion title="ディメンションの選択">

ユーザーレベルのデータはDCRによってレポーティングできないことに注意してください。代わりに、選択したディメンションでデータを集計（またはグループ化）することで、必要な意思決定の分析情報を提供します。

ディメンションは通常、アプリユーザーを分類するための属性です（地域、インストール日、キャンペーンなど）。

#### **event\_valueからのディメンションの抽出**

アプリ内イベントがSDKまたはS2S APIを介してAppsFlyerに報告されると、ローデータの多くは**event\_value**と呼ばれる単一のフィールドに含まれます。この構造化データフィールドには、アプリからAppsFlyerに送信されるイベントに対して設定された、特定のアプリ内イベントパラメータがすべて含まれています。

アプリ内イベントレポートの主な利点のひとつは、選択したイベントの **event\_value**フィールドから特定のパラメーターとその値を抽出できることです。

**DCRレポートで使用するために event\_valueフィールドからディメンションを抽出します。**

1. **event\_valueからフィールドを抽出** ウィンドウが開きます。
2. **レポートフィールド** ボックスに、レポートに表示する抽出ディメンションの名前を入力します。
3. **Event\_valueパラメータ**リストから、手順2で定義したレポートフィールド（ディメンション）にデフォルトでマッピングするアプリ内イベントパラメータを選択します。
   * 使用可能なパラメーターには、**選択したアプリ**の**選択したアプリ内イベント**で設定されたパラメーターが含まれます。
4. デフォルトのマッピングはアプリやイベントによって異なる可能性があります。この場合は、次のようにします。
   1. [ 例外を追加する ] ボタンをクリックします。
   2. レポートフィールドを異なる方法でマッピングするアプリとイベントを選択します。
   3. このアプリ/イベントの組み合わせのレポートフィールドにマッピングするアプリ内イベントパラメータを選択します。
   4. 設定する例外の数だけ、これらの手順を行ってください。
5. 抽出されたディメンションのマッピング設定が完了したら、保存して別のディメンションを追加をクリックしてevent\_valueフィールドから別のディメンションを抽出するか、**保存**をクリックしてメイン画面に戻ります。

**抽出したディメンションの編集**

1. ソースからのディメンションまたは **レポートのディメンション**リストで、編集するディメンション名にカーソルを合わせます。
3. **抽出されたフィールドの編集**を選択します。
4. 必要に応じて、 **レポートフィールド** 名やパラメーターマッピングを変更します。
5. **保存**をクリックして変更を保存します。

**抽出したディメンションの削除**

1. ソースからのディメンションまたは**レポートのディメンション**リストで、削除したいディメンション名にカーソルを合わせます。
3. **フィールドの削除**を選択します。
   * **警告！レポートディメンション**リストから抽出したフィールドを削除すると、抽出されたフィールドの定義も削除されます。定義を保持したままレポートからフィールドを削除する場合は、フィールドを選択し、代わりに **削除**ボタンを使用します。

#### **レポートディメンションの選択**

アプリ内イベントレポートのディメンションには、次のものが含まれます：

* event\_valueから抽出したディメンション
* [デフォルトのアプリ内イベントのディメンション](/docs/data-clean-room-creating-in-app-event-reports#default-inapp-event-dimensions)
* レポートのカスタムソース内で <Anchor target="_blank" href="/marketers/ja/docs/data-clean-room-working-with-sources#3-define-the-source-structure">ディメンションとして分類</Anchor>されているフィールド（該当する場合）

**レポートに含めるディメンションを選択する：**

1. 左側の **ソースからのディメンション**リストで 1つ以上のディメンションを選択し、画面中央の**追加**ボタンを使用して**レポートディメンション**の一覧に追加します。
   * 検索バーを使用して、リスト内のディメンションを検索できます。
2. ディメンションを削除するには、**レポートディメンション**リストからディメンションを選択し、**削除**ボタンを使用して**ソースからのディメンション**リストに戻します。
3. レポートに含める各ディメンションを追加するまで、このプロセスを繰り返します。

**注記：** 注： デフォルトでは、すべてのレポートはアプリ内イベントディメンション **media\_source** でグループ化されます。レポートでこのディメンションを使用しない場合は、**レポートディメンション**リストから削除できます。

#### **[オプション] ディメンション表示名のカスタマイズ**

デフォルトでは、ディメンション名はアプリ内イベントデータまたはカスタムソースで名前が付けられているとおりにレポートに表示されます。必要に応じて、レポートのディメンション名をカスタマイズできます。

**ディメンションの表示名をカスタマイズする：**

1. **レポートディメンション**リストで、表示名を編集するディメンションの名前にカーソルを合わせます。
2. ディメンションの右側に表示される編集ボタン ![edit_button.png](https://files.readme.io/4c3822661beac49fad247c7f5958a535e46031238e975a5323a5550722c89c8a-10753875375377.png) をクリックします。
3. 名前をレポートで使用するディメンション表示名に変更します（最大50文字）。
4. **OK**をクリックして表示名を保存するか、**X** をクリックしてキャンセルします。

**注記：** 注： **抽出されたディメンション**名を変更する場合は、上記の抽出されたディメンションを編集する手順を使用します。

#### **ディメンションでグループ化（再グループ化）する際のプライバシー保護：**

データセットのサイズ、選択したディメンションの数、その他の要因によっては、レポートに、ユーザーが少なすぎてレポートを作成できないグループが 1つ以上存在する場合があります。データがこのようにレポートされた場合、ユーザーレベルのデータの提供に対する制限に違反しています。

ただし、DCRは、レポートからデータを完全に削除または非表示にする代わりに、 **再グループ化メカニズム** を使用して、ユーザーのプライバシーを維持しながら可能な限り詳細なデータを提供します。

> 📄 **再グループ化の例**
>
> 次のディメンションに従ってレポートを以下の順番通りに設定したとします：
>
> * **アプリ内イベントのディメンション：**
>   * media source
>   * campaign
>   * adset\_name
>   * ad\_id
> * **カスタムソースディメンション：**
>   * user\_type
>
> **再グループ化の前**
>
> データの初期分析後、DCRはデータが次のように分類されると判断します：
>
>
>
> | media  <br />source | campaign | adset  <br />name | ad  <br />id | user  <br />type | rev  <br />D0 | rev  <br />D7 | count（合計回数） | 出力可否 |
> | --- | --- | --- | --- | --- | --- | --- | --- | --- |
> | media\_source | UA\_100 | green | kjh867 | buyer | 1 | 4 | 120 | ✓ |
> | media\_source | UA\_101 | green | jkj987 | ultra | 2 | 23 | 220 | ✓ |
> | media\_source | UA\_200 | green | lkh12 | beg | 6 | 7 | x | **X** |
> | media\_source | UA\_200 | green | ilk945 | beg | 3 | 21 | x | **X** |
> | media\_source | UA\_200 | green | plm654 | beg | 8 | 17 | x | **X** |
>
>
>
> 現状では、最後の3行は、それぞれのユーザーが少なすぎるため、レポートできません。（このメディアソースをレポート可能にするには、少なくとも **y**人のユーザーが必要です。ここでは、**x**人しかいません。）
>
> 再グループ化のロジックに従って、DCRは最初に、最後にリストされたアプリ内イベントディメンション（この場合は **ad\_id**）を "削除" します。次に、データを再度分析して、レポート可能な行を確認します。
>
> **再グループ化の後**
>
> 再グループ化ロジックを適用すると、レポートは次のように表示されます：
>
>
>
> | media  <br />source | campaign | adset  <br />name | ad  <br />id | user  <br />type | rev  <br />D0 | rev  <br />D7 | count（合計回数） | 出力可否 |
> | --- | --- | --- | --- | --- | --- | --- | --- | --- |
> | media\_source | UA\_100 | green | kjh867 | buyer | 1 | 4 | 120 | ✓ |
> | media\_source | UA\_101 | green | jkj987 | ultra | 2 | 23 | 220 | ✓ |
> | media\_source | UA\_200 | green | Restricted（制限有り） | beg | 17 | 45 | y (x+x+x) | ✓ |
>
>
>
> **結果：**
>
> * 最後の行は、それまで3行に分かれていたデータを統合したものです。これで、結合された行のユーザー数は **y** に等しくなり、レポートできるようになります。
> * 削除されたディメンションは、RESTRICTED（制限有り）としてサポートされます。
> * レポートできない行（ユーザー数 **y** 未満）がまだ存在する場合、DCR は反復的にデータを分析し続け、次のいずれかになるまで次々にディメンションを削除します：
>   * すべての行をレポートできるようになる、もしくは
>   * アプリ内イベントのディメンションを使い果たして排除します
>
> **注記：** 注： デフォルトでは、DCRは **[デフォルトのアプリ内イベントディメンション](/docs/data-clean-room-creating-in-app-event-reports#default-inapp-event-dimensions)** にのみ再グループ化を適用します（アプリ内イベントディメンションまたはカスタムソースディメンションには適用されません）。デフォルトのアプリ内イベントディメンジョンでグループ化されたデータのユーザーが **y** 人未満を含む行になった場合、その行のデータは RESTRICTED としてレポートされます。
>
> * *カスタムソースディメンションにも再グループ化を適用するために使用できる高度なオプションについては、以下を参照してください。*

#### **[オプション] ディメンションの優先度の管理**

デフォルトでは、アプリ内イベントディメンションは **レポートディメンション**リストに表示される順序とは逆の順序で削除されます。ただし、デフォルトの順序を変更したり、選択したカスタムソースディメンション（該当する場合）に再グループ化を適用して、最も重要なディメンションを保持することができます。

**ディメンションを削除する順序を変更する：**

1. **ディメンション優先度の管理** ボタンをクリックします。
2. ディメンションを選択し、リスト内の目的の位置にドラッグします（または、右側の矢印ボタンを使用して移動します）。
   * **優先度：最高** とラベル付けされたディメンション（リストの一番上）は、再グループ化が必要な場合に一番最後に削除されるディメンションであることを意味します。
3. [オプション] カスタムソースディメンションに再グループ化を適用します（カスタムソースを使用するレポートの場合）
   1. **詳細オプションを使用して再グループ化を絞り込む** をクリックします。
   2. 再グループ化を適用するカスタムソースディメンションを選択します。
   3. 選択したディメンションが **ディメンション優先度の管理** リストに追加されます。
      * デフォルトでは、これらのディメンションはリストの一番下に再グループ化の**優先度：最低** として追加されます。ただし、上記のようにアプリ内イベントディメンションと同様に並べ替えることができます。
4. **OK** をクリックして変更を保存します。
   * メイン画面の **レポートディメンション**リストは元の順序のままですが、修正された順序は保存されています。（選択内容を確認または編集する場合は、**ディメンション優先度の管理** ボタンをもう一度クリックします。）

</Accordion>

<div id="select-metrics" />

<Accordion title="メトリックの選択">

指標は、アプリユーザーに関して収集した数値データ（収益、アプリ起動数、LTVなど）であり、指標として分類したソースからの任意の数値データ項目を使用できます。

#### **event\_valueからのメトリックの抽出**

[レポートディメンション](/docs/data-clean-room-creating-in-app-event-reports#select-dimensions)と同様に**event\_value**フィールドからアプリ内イベントパラメータを抽出して、レポートのメトリックとして使用できます。

**DCRレポートで使用するために event\_valueフィールドからディメンションを抽出します。**

1. **event\_valueからフィールドを抽出** ウィンドウが開きます。
2. **レポートフィールド** ボックスに、レポートに表示する抽出メトリック名を入力します。
3. **Event\_valueパラメータ**リストから、手順2で定義したレポートフィールド（メトリック）にデフォルトでマッピングするアプリ内イベントパラメータを選択します。
   * 使用可能なパラメーターには、**選択したアプリ**の**選択したアプリ内イベント**で設定されたパラメーターが含まれます。
4. デフォルトのマッピングはアプリやイベントによって異なる可能性があります。この場合は、次のようにします。
   1. [ 例外を追加する ] ボタンをクリックします。
   2. レポートフィールドを異なる方法でマッピングするアプリとイベントを選択します。
   3. このアプリ/イベントの組み合わせのレポートフィールドにマッピングするアプリ内イベントパラメータを選択します。
   4. 設定する例外の数だけ、これらの手順を行ってください。
5. 抽出されたメトリックのマッピング設定が完了したら、保存して別のディメンションを追加をクリックしてevent\_valueフィールドから別のメトリックを抽出するか、**保存**をクリックしてメイン画面に戻ります。

**抽出したメトリックの編集**

1. ソースからのメトリックまたは **レポートのメトリック**のリストで、編集するメトリック名にカーソルを合わせます。
3. **抽出されたフィールドの編集**を選択します。
4. 必要に応じて、 **レポートフィールド** 名やパラメーターマッピングを変更します。
5. **保存**をクリックして変更を保存します。

**抽出したメトリックの削除**

1. ソースからのメトリックまたは **レポートのメトリック**のリストで、削除するメトリック名にカーソルを合わせます。
3. **フィールドの削除**を選択します。
   * **警告！レポートのメトリック**リストから抽出したフィールドを削除すると、抽出されたフィールドの定義も削除されます。定義を保持したままレポートからフィールドを削除する場合は、フィールドを選択し、代わりに **削除**ボタンを使用します。

#### **レポートの指標を選択する**

**レポートに含める指標を選択する：**

1. 左側の **ソースからの指標**リストで 1つ以上のメトリックを選択し、画面中央の**追加**ボタンを使用して、**レポートメトリック**の一覧に追加します。
   * 検索バーを使用して、リスト内のディメンションを検索できます。
2. **レポート指標**リストのメトリックごとに、データを次のいずれかとしてレポートするかどうかを選択します：
   * 数値の合計、または
   * 個別の値の数
3. 指標を削除するには、**レポート指標**リストからメトリックを選択し、**削除**ボタンを使用して **ソースからの指標**リストに戻します。
4. レポートに含める各メトリックを追加するまで、このプロセスを繰り返します。

#### **[オプション] 指標の表示名のカスタマイズ**

デフォルトでは、メトリック名はアプリ内イベントデータまたはカスタムソースで名前が付けられているとおりにレポートに表示されます。必要に応じて、レポートの指標名をカスタマイズできます。

**指標の表示名をカスタマイズする：**

1. **レポート指標**リストで、表示名を編集する指標の名前にカーソルを合わせます。
2. ディメンションの右側に表示される編集ボタン ![edit_button.png](https://files.readme.io/4c3822661beac49fad247c7f5958a535e46031238e975a5323a5550722c89c8a-10753875375377.png) をクリックします。
3. 名前をレポートで使用するディメンション表示名に変更します（最大50文字）。
4. **OK**をクリックして表示名を保存するか、**X** をクリックしてキャンセルします。

**注記：** 注： **抽出されたメトリック**の名前を変更する場合は、上記の抽出されたメトリックを編集する手順を使用します。

#### **[オプション] カウントする識別子を選択する**

デフォルトでは、レポートの各行は、その行のデータにグループ化された個別のAppsFlyer IDの数を含む列が最後（一番右）で終わります。

**ソースからの他の識別子の個別のカウントの列を追加する場合は、次のようにします：**

1. 左側の **ソースの識別子**リストで 1つ以上の識別子を選択し、画面中央の**追加**ボタンを使用して、それらを**個別のカウント識別子**の一覧に追加します。
   * 検索バーを使用して、リスト内の識別子を検索できます。
2. 識別子を削除するには、**個別のカウント識別子**リストから識別子を選択し、**削除**ボタンを使用して**ソースからの識別子**リストに戻します。
3. レポートにカウントする各識別子を追加するまで、このプロセスを繰り返します。

</Accordion>

<div id="configure-report-settings-and-save-the-report" />

<Accordion title="レポート構成の設定およびレポートの保存">

#### **スケジュール（カスタムソースのないレポートのみ）**

カスタムソースのないレポートは、定義したスケジュールに従って実行されます。

**レポートスケジュールの定義**

1. レポートを毎日実行するか、毎週 1 日以上実行するかを選択します。
2. レポートを実行する時刻を選択します (タイムゾーンは UTC)。

> 🚧 **重要！**
>
> スケジュールオプションは、カスタムソースを使用するレポートでは無効です。このタイプのレポートは、すべての<Anchor target="_blank" href="/marketers/ja/docs/data-clean-room-creating-attribution-data-reports#カスタムソース">使用するカスタムソース</Anchor> の新しいバージョンが検出されるたびに実行されます。
>
> * **データウェアハウス**（BigQuery および Snowflake）のソースの場合、DCR は、ソースの表の<Anchor target="_blank" href="/marketers/ja/docs/data-clean-room-working-with-sources#table-columns">`v`vv列に新しい値が検出すると、ソースの新しいバージョンが作成されたことを認識します。</Anchor>
>   * <strong>重要！</strong>レポートを完全なものにするには、列の値が変更されるたびに、ソースの表に完全なデータを入力するようにしてください。
> * **クラウドストレージバケット**（Amazon S3 および GCS）のソースの場合、DCR は、ソースファイルの新しいバージョンが付随する \_SUCCESS ファイルとともに<Anchor target="_blank" href="/marketers/ja/docs/data-clean-room-working-with-sources#ソースを更新してレポート処理をトリガーします">アップロードされた</Anchor>ことを検出すると、ソースの新しいバージョンが作成されたことを認識します。
>
> AppsFlyerは、**現在の日付と2日前**のソースの新しいバージョンを継続的にスキャンします。

#### **レポート接続先**

DCRは <Anchor target="_blank" href="/marketers/ja/docs/data-locker-for-marketers">AppsFlyer Data Locker</Anchor>を使用して、選択したクラウドサービスにレポートを格納します。したがって、レポートの送信先を指定するには、Data Lockerの接続を選択または作成する必要があります。

* **注意：** DCRレポートの受信にData Lockerの有料契約は必要ありません。Data Lockerによるその他のAppsFlyerレポートの受信についての詳細は、CSMにお問い合わせいただくか、 [hello@appsflyer.com](mailto:hello@appsflyer.com) にメールを送信してください。

**レポートの接続先を設定してレポートを保存する：**

1. AppsFlyerアカウントで利用可能なData Locker接続のリストから選択します。
   * アカウントに接続が定義されていない場合：
     * ブラウザに新規タブが開きます（AppsFlyerのData Lockerページが表示されます）。
     * **新規接続** ダイアログが開きます。<Anchor target="_blank" href="/marketers/ja/docs/data-clean-room-working-with-connections#接続を完了します-1">こちらの手順</Anchor>に従って作成してください。
   * 既存の接続があるが新しい接続を使用したい場合は、  ![dcr_new_connection_data_locker_button.png](https://files.readme.io/9850a4b8ea4f40f6320903c545c51add7b90207538a27c83a3b02a41197ba567-14995870859281.png) ボタンをクリックします：
     * ブラウザに新規タブが開きます（AppsFlyerのData Lockerページが表示されます）。
     * **新規接続** ダイアログが開きます。<Anchor target="_blank" href="/marketers/ja/docs/data-clean-room-working-with-connections#接続を完了します-1">こちらの手順</Anchor>に従って作成してください。
   * 接続の作成後、ブラウザのDCRタブに戻り、Data Locker接続一覧から新しく作成した接続を選択します。
2. **保存**をクリックしてレポートを保存します。
3. 新しいレポートが**Data Clean Room**の**レポート**タブに表示されます。

</Accordion>
