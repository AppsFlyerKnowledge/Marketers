> **概要：** AppsFlyer SDKのバージョン管理ポリシーと、サポート対象バージョンについてご紹介します。

## バージョン管理について

長年にわたり、AppsFlyerはSDKの多くのバージョンをリリースしてきました。各SDKバージョンは、特定のAPIバージョンを呼び出します。バージョン管理ポリシーの目的は、各APIがどのSDKバージョンをどれだけの期間サポートするかを定めることです。

## バージョン管理が必要な理由

バージョン管理には、主に以下の目的があります。

* アプリに組み込んでいるSDKバージョンのAPIが、いつサポート対象外になるかを事前に把握できます。バージョンの普及には時間がかかり、ユーザーが新しいアプリバージョンにアップグレードするまでに時間を要する場合があるため、これは重要なポイントです。
* 安定性が向上します（後方互換性は2.5年間）。これにより、非常に古いSDKバージョンを使用した際の予期しないエラーを防げます。
* SDKのアップグレードが必要な新機能を利用できるようになります。

## SDKバージョンのライフサイクル

APIバージョンは、2.5年間の動作が保証されます。 SDKの新しいメジャーバージョンまたはマイナーバージョンがリリースされるたびに、AppsFlyerは1つ前のマイナーバージョン（そのすべてのパッチバージョンを含む）のサポート終了日を設定します。

<strong>iOS・Android向けのレガシーSDKバージョンは、6か月ごとの固定サイクルでサポートが終了します。</strong>このサイクルは事前に十分な猶予を持って通知することで、チームが計画的に準備を進め、アプリの機能を中断なく維持できるようにするためのものです。最新のSDKにアップグレードすることで、最新機能の利用、安定性の向上、継続的なサポートを受けられるようになります。

> 🚧 **重要：**
>
> スムーズな移行のため、サポート終了日を迎える前に、最新のSDKバージョンへアップデートすることをお勧めします。

## サポート終了と非推奨の違い

AppsFlyerでは、サポートレベルおよびデータ計測への影響を明確にするため、SDKバージョンを**非推奨**と**サポート終了**の2つに区別しています。

* **非推奨バージョン：** 重大なバグなど既知の問題により、利用が推奨されなくなったSDKバージョンです。これらのバージョンからも引き続きAppsFlyerへのデータ送信は可能ですが、使用し続けることは推奨されません。サポート対象のバージョンへのアップグレードを強くお勧めします。
* **サポート終了バージョン：** すべてのプラットフォームにおいて計測が完全に停止するSDKバージョンです。 Android・iOSのいずれにおいても、インストール、セッション、アプリ内イベントは計測されません。これらのバージョンからのトラフィックは（AppsFlyer側で個別に除外されている場合を除き）すべて400ステータスコードを受け取ります。つまり、SDK自体は通常どおりAPIコールを送信しようとしますが、AppsFlyerのサーバー側で拒否されるため、データは処理されません。

## SDKバージョンの終了はどうなりますか？

SDKバージョンがサポート終了日を迎えると、AppsFlyerのサーバーはインストール、セッション、アプリ内イベントの計測を行わなくなります。該当のエンドポイントに届いたイベントは、そのまま拒否されます。

バージョンの普及には時間がかかるため、サポート終了日よりも十分前に、開発担当者が最新のSDKバージョンへ**アップグレードすることを強くお勧めします**。
