<span class="af-tag af-tag--beta-feature">Beta feature</span>

> **At a glance:** Agent Hubは、AIを活用したエージェントを一元管理するAppsFlyerのプラットフォームです。マーケティング施策に役立つ分析結果を、普段の業務環境に直接、能動的に届けます。エージェントは継続的にデータを分析し、チームで利用する環境に有益な結果や具体的なアクションの提案を届けます。

<div id="about-agent-hub" />

## Agent Hubについて

各エージェントは、データの分析から結果の導出、チームの業務環境への配信まで、マーケティング業務を一貫して担当します。 Agent Hubでは、マーケティング施策の最適化や成長機会の発見を支援する、AppsFlyerが開発したさまざまなエージェントを利用できます。また、自分で定義した業務を担当するカスタムエージェントも利用できます。すべてのエージェントは誠実に業務を遂行し、チームの意思決定を支援します。

<div id="agent-hub-page" />

## Agent Hub画面

Agent Hub画面は、［**マイエージェント**］と［**アクティビティ**］の2つのタブで構成されています。これらのタブでエージェントを管理し、完了した実行の結果を確認できます。

［**マイエージェント**］では、エージェントの設定、有効化、管理を行います。［**アクティビティ**］では、完了した実行の結果や過去の実行を確認し、フィードバックを送信できます。また、AI Assistantで分析・判断の過程を確認できます。

<Accordion title="マイエージェント">

［**マイエージェント**］タブには、アカウントで利用できるエージェントが表示されます。

このタブでは、以下の操作が可能です。

* 利用可能なエージェントの確認。
* エージェントの設定と有効化。
* 有効化済みのエージェントの管理。
* エージェントカードでの最新の実行状況の確認。

<div id="prerequisites-and-permissions" />

#### 事前準備と権限

Agent Hubの一部の機能は、利用する通知先に応じて追加の設定が必要です。

<div id="slack-optional" />

##### Slack（任意）

Slackの設定が必要なのは、エージェントの結果をSlackで受信する場合のみです。

* 組織によるAppsFlyerのSlackアプリの承認。以下の手順で設定します。
  * Agent Hubに移動し、利用するエージェントを選択します。
  * エージェントの設定カード内で［**Slackに接続**］をクリックします。

結果をSlackに配信するエージェントを利用する場合は、エージェントの設定前に、組織内に専用のSlackチャンネルを作成し、そのチャンネルにAppsFlyer Agent HubのSlackアプリを招待してください。チャンネル名は、エージェントの設定時に必要です。

チャンネルにアプリを招待するには、以下の手順を実行します。

1. 通知を受信するSlackチャンネルで、次のコマンドを入力します： **/invite**
2. ［**Add Apps to this channel**］（このチャンネルにアプリを追加）を選択します。

［**AppsFlyer Agent Hub**］を選択し、［**Add**］（追加）をクリックします。

* 以下のロールには、すべての機能へのアクセス権限が自動的に付与されます。
  * 管理者
  * マーケティングマネージャー
  * チームマネージャー
  * マーケティングリーダー

* **その他のロール：** ［<Anchor target="_blank" href="/marketers/ja/docs/user-management">ユーザー管理</Anchor>］で［AIツール］の機能を有効にする必要があります。

<div id="email-optional" />

##### メール（任意）

* メールの送信先に指定できるのは、AppsFlyerアカウントに紐づいたメールアドレスのみです。
* ユーザーは、AppsFlyerのメール配信に登録している必要があります。詳しくは<Anchor target="_blank" href="/marketers/ja/docs/notifications#どのような通知を受け取ることができますか">こちら</Anchor>をご確認ください。

注意：各エージェントには、最大5件のメールアドレスを設定できます。

<div id="set-up-an-agent" />

#### エージェントの設定

エージェントを設定して有効化すると、スケジュールまたは手動で実行できるようになります。 Slackやメールなど、エージェントの結果の配信先も設定できます。

最新の実行状況は、［**マイエージェント**］タブのエージェントカードで直接確認できます。完了した実行の結果や過去の実行を確認するには、［**アクティビティ**］タブをクリックします。

以下の手順でエージェントを設定し、有効化します。

1. AppsFlyerにログインします。
2. 左側のメニューから［**Agent Hub**］に移動します。
3. 設定して有効化するエージェントで、［**有効化**］をクリックします。
4. 次の画面で、必要なエージェントの設定を行います。
5. 必要に応じてメールアドレスを追加するか、Slackワークスペースに接続します。
   1. Slackチャンネルが設定済みであることを確認してください。[事前準備](#事前準備と権限)をご確認ください。
6. 実行スケジュールを選択します（現在はUTCを使用しています。ほかのタイムゾーンも近日中に追加予定です）。
7. ［**エージェントを有効化**］をクリックします。

［**マイエージェント**］にエージェントが表示されます。利用可能なすべてのエージェントと各エージェントの機能については、以下の**事前設定済みエージェント**と**カスタムエージェント**をご確認ください。

</Accordion>

<Accordion title="アクティビティタブ">

［**アクティビティ**］タブには、完了したエージェントの実行結果が表示されます。このタブは、アカウント内に実行結果があるエージェントが1つ以上存在する場合に表示されます。

このタブでは、エージェントの最近のアクティビティや過去の結果を確認し、フィードバックを送信できます。また、特定の実行についてAI Assistantに質問できます。

［アクティビティ］タブには、以下の2つのセクションがあります。

| セクション | 参照： |
| --- | --- |
| 最新のアクティビティ | 各エージェントインスタンスで、直近に完了した実行が表示されます。 |
| 過去の実行 | 過去30日間に完了した実行が表示されます。 |

以下の条件でアクティビティを絞り込めます。

* アプリ
* エージェントインスタンス

注意：エージェントのフィルターは、エージェントの種類ではなく、個別のエージェントインスタンスに基づきます。

<div id="view-activity-output" />

#### アクティビティの結果の確認

アクティビティの結果を確認するには、以下の手順を実行します。

1. ［**Agent Hub**］に移動します。
2. ［**アクティビティ**］タブをクリックします。
3. 該当するアプリまたはエージェントインスタンスのフィルターを選択します。
4. 実行をクリックして展開します。

展開すると、Slackまたはメールで配信されたものと同じ結果が表示されます。

展開した実行では、以下の操作が可能です。

* 結果のコピー。
* 肯定的または否定的なフィードバックの送信。
* テキストでのフィードバックの追加。
* ［**アクティビティを分析**］をクリックし、実行についてAI Assistantに質問。

<div id="analyze-activity-with-ai-assistant" />

#### AI Assistantを使用したアクティビティの分析

［**アクティビティを分析**］を使用すると、完了した特定のエージェントの実行についてAI Assistantに質問できます。

［**アクティビティを分析**］は、すべてのエージェントで利用できます。 AI Assistantは、選択した実行の情報を引き継いだ状態で開きます。エージェントが結果を導いた過程、使用したデータ、考慮した要因や除外した要因を理解するのに役立ちます。

エージェントと一般的な内容をやり取りするチャットではありません。 AI Assistantが回答するのは、選択した実行に関する質問のみです。エージェントの新たな業務の実行、対象の実行に含まれないデータへのアクセス、予測は行いません。

実行についてAI Assistantに質問するには、以下の手順を実行します。

1. ［**Agent Hub**］に移動します。
2. ［**アクティビティ**］タブをクリックします。
3. 実行をクリックして展開します。
4. ［**アクティビティを分析**］をクリックします。
5. 候補として表示された質問を選択するか、自分で質問を入力します。

たとえば、以下のような質問ができます。

* 分析・判断の過程を順に説明してください。
* どのデータに基づいていますか？
* なぜこの分析結果を優先したのですか？
* どのような要因を考慮しましたか？
* どのような要因を除外しましたか？

<div id="supported-and-unsupported-questions" />

##### 対応している質問と対応していない質問

| 質問できる内容 | 質問できない内容 |
| --- | --- |
| エージェントが結果を導いた過程 | 対象の実行に含まれていないデータ |
| エージェントが実行に使用したデータ | 対象の実行に含まれていない新たな分析 |
| 分析結果を優先した理由や除外した理由 | 将来の予測 |
| 選択した実行の背景と分析・判断の過程 | 対象の実行の範囲を超える一般的な最適化の提案 |

<div id="notes" />

#### 注

［**アクティビティ**］タブと［**アクティビティを分析**］を使用する際は、以下の点にご注意ください。

* アカウントでAI Assistantが有効になっている必要があります。 AI Assistantが無効な場合は、［**アクティビティを分析**］を利用できません。<Anchor target="_blank" href="/marketers/ja/docs/account-settings#agent-hub">アカウント設定</Anchor>をご確認ください。
* アクティビティの履歴に表示されるのは、過去30日間に完了した実行のみです。
* エージェントを削除すると、結果、分析で得られた知見、分析・判断の過程のデータを含む過去のアクティビティも削除されます。この操作は取り消せません。
* AI Assistantが回答するのは、選択した実行に関する質問のみです。新たな分析、対象の実行に含まれないデータへのアクセス、予測は行いません。

</Accordion>

<div id="agent-types" />

## エージェントの種類

Agent Hubには、自分で定義した業務に合わせて設定するカスタムエージェントと、そのまま有効化して利用できる事前設定済みエージェントの2種類があります。

<div id="h_01M3PDTFQDFQNMHTWKP23JV1A8" />

<Accordion title="［クローズドベータ版］カスタムエージェント">

Agent Hubの事前設定済みエージェントが、あらかじめ定義された特定のタスクを実行するのに対し、カスタムエージェントは、個別の要件に合わせて定義した業務を実行します。タスクを自然な言葉で記述し、アプリを選択します。その後、エージェントが作成したプランを確認し、結果の配信方法とタイミングを指定します。エージェントは、必要なタイミングまたはスケジュールに従って業務を一貫して実行し、結果を配信します。

データを分析し、指定されたタスクを実行して、求められた結果を届けます。たとえば、順位付きのリスト、週次のパフォーマンスサマリー、根本原因の調査、根拠に基づく提案、複雑な個別分析などに対応します。業務に応じた形式で結果が出力されます。

チームのアナリストに依頼するように業務を伝えると、エージェントは同じように対応します。理解した内容を確認し、業務の進め方や各用語の定義を提示したうえで、承認を得てから実行します。

<div id="create-a-custom-agent" />

#### カスタムエージェントの作成

エージェントの定義、プランの確認、設定と有効化の3つのステップで作成します。

<div id="step-1-define-the-agent" />

##### ステップ1：エージェントの定義

1. AppsFlyerの左側のメニューから［**Agent Hub**］に移動します。
2. カスタムエージェントのカードで［**作成**］をクリックします。
3. ［**アプリを選択**］でアプリを選択します。 1つのエージェントに指定できるアプリは1つです。
4. （任意）［**地域**］と［**メディアソース**］のフィルターを設定します。すべてを対象にする場合は、空欄のままにします。
5. ［**タスク**］に業務の内容を記述するか、用意されているプロンプトをクリックし、必要に応じて編集します。
6. ［**プランを生成**］をクリックします。

<div id="step-2-review-the-agent-plan" />

##### ステップ2：エージェントの実行プランの確認

エージェントは、タスクをプランにまとめ、実行前に提示します。この段階で、タスクの解釈が誤っていないか、定義がチームの計測方法と一致しているかを確認します。

| プランのセクション | 確認する内容 |
| --- | --- |
| 目的 | 業務の内容を1文でまとめたもの。 |
| エージェントの実行プラン | エージェントが業務を進める方法。 |
| 定義 | タスクに含まれるすべての指標、期間、しきい値の明確な定義。「Day 7のリテンション」の意味、「大幅な低下」の基準、対象となるメディアソースなど。自分の定義と異なる箇所があれば編集してください。 |
| フィルター | エージェントが対象とするアプリ、地域、メディアソース。 |

ここでは、以下の操作が可能です。

* ［**編集**］で各項目を変更し、［**変更を保存**］をクリックします。
* ［**最初からやり直す**］でタスクの入力に戻ります。
* ［**プランを承認**］で次に進みます。

<div id="step-3-configure-and-deploy" />

##### ステップ3：設定と有効化

1. ［**エージェント名**］を入力します。
2. ［**結果の受信方法を選択**］で、［**Slack**］、［**メール**］、またはその両方を選択します。
   * Slack：ワークスペースが未接続の場合は［**Slackに接続**］をクリックし、チャンネルを選択します。
   * メール：AppsFlyerユーザーのメールアドレスを最大5件指定できます。
3. ［**実行スケジュール**］で、いずれかの選択肢を選択します。
4. ［**エージェントを有効化**］をクリックします。

スケジュールはUTCで実行されます。

［**マイエージェント**］にエージェントが表示されます。カードには最新の実行状況が表示されます。完了した実行は［**アクティビティ**］に表示され、アプリとエージェント名で絞り込めます。

<div id="h_01M3PDTFQESQY349XK0SNH5NB8" />

<Accordion title="カスタムエージェントが扱うデータ">

カスタムエージェントには、イベント単位のデータと集計データの2つのデータソースがあります。タスクに応じて自動で選択されるため、指定する必要はありません。タスクによっては、1回の実行で両方のデータソースを使用します。まれに、そのような実行では、同じ指標でもデータソースごとに値がわずかに異なる場合があります。実行時に使用されたデータソースを確認するには、［**アクティビティを分析**］機能で、エージェントの分析・判断の過程を確認してください。

<strong>イベント単位のデータ。</strong>エンゲージメントからアプリ内の行動まで、ファネル全体にわたるイベントのローデータです。独自の指標や比率を定義し、個々のユーザー単位で分析し、イベントの発生順序を追跡できる点が、カスタムエージェントとダッシュボードの違いです。

| 対象データ | 詳細 |
| --- | --- |
| エンゲージメント | クリックとインプレッション |
| インストールとリエンゲージメント | コンバージョン |
| セッション | アプリ起動イベント |
| SKANアプリ内イベント | アプリ内購入収益を含む |
| ディメンション | メディアソース、キャンペーン、市区町村レベルまでの地域、デバイス、OSバージョン、アプリバージョン、広告、サイトID、その他のイベントローデータの項目 |
| データの対象期間 | 過去30日間 |

<strong>ActivityデータとCohortデータ（集計データ）。</strong>コストを含む、マイダッシュボードで利用可能なすべてのデータ。

| 対象データ | 詳細 |
| --- | --- |
| 指標 | インストール、コンバージョン、初回訪問、セッション、イベント数、ユニークユーザー数、アクティブユーザー数、収益、純収益、ユーザーあたりの平均収益（ARPU）、ユニークユーザーあたりの収益、ユニークユーザーあたりの回数、リテンション率 |
| アプリ内イベント、コンバージョン、アンインストール、セッション | 回数、ユニークユーザー数、収益、純収益、初回イベント数 |
| コスト指標 | 広告費（コスト）、eCPI、ROAS、ROI |
| ディメンション | メディアソース、チャネル、キャンペーンIDとキャンペーン名、広告セットIDと広告セット名、広告IDと広告名、サイトID、代理店、キーワード、sub\_param\_1、エンゲージメントのカテゴリ・種類・遷移先、統合アプリID、プラットフォーム、インストール元のアプリストア、アプリバージョン・OSバージョン・国コード（コンバージョン）、集計イベントの種類（コンバージョン、セッション、アプリ内イベント、アンインストール）、イベント名、コンバージョン名とコンバージョンの種類、収益化の種類、is-attributed、is-organic、is-primary-attribution、イベント日（Cohortのみ）、イベント日（コンバージョン）、コンバージョン後の経過日数、顧客の通貨 |
| データの対象期間 | Activityは3年間、Cohortは2年間 |

集計データは、米ドルとアカウントの通貨で表示されます。 Cohortの集計データは日次単位です。

<strong>現在の制限事項。</strong>これらの制限は一時的なものであり、カスタムエージェントのベータ版終了に伴い変更される予定です。

* エンゲージメントとコストは、異なるデータソースに含まれています。クリックとインプレッションはイベント単位のデータにのみ含まれ、コストは集計データにのみ含まれます。エージェントは両者を結合できないため、CPC、CPM、CTR、IPM、CPAなど、これらを組み合わせる指標の結果は返されません。エンゲージメントデータを必要としないコストベースの指標（広告費、eCPI、ROAS、ROI）は、通常どおり利用できます。
* 対象外のデータ：Audiences、SKAdNetwork、SSOT、Protect360、Creative、Incrementalityで生成されるデータ、広告収益、サブスクリプション収益（収益の対象はアプリ内購入のみ）。
* ダッシュボードで定義したカスタム指標やカスタムディメンションは含まれません。
* 集計ディメンションのうち、プラットフォーム、sub\_param\_1、エンゲージメントの遷移先、エンゲージメントの種類、流入元（オーガニックまたは非オーガニック）については、2025年6月以降のデータのみが含まれます。
* データがない場合、エージェントはN/Aではなく0を表示します。
* 「初回訪問」と「再訪問」は、Webアプリでのみ利用できます。

<div id="note" />

> 📘 **注記**
>
> イベントローデータの数値とダッシュボードのデータには、差異が生じる場合があります。イベント単位の数値（ローデータ）と集計値（ダッシュボード）は、必ずしも一致しません。両者に小さな差異が生じることは想定されています。集計値は、同じアプリと日付のマイダッシュボードの数値と一致するはずです。

</Accordion>

<div id="h_01M3PDTFQEF8ZPV4PP04YGNGBK" />

<Accordion title="的確なタスクの記述">

エージェントが作成するプランの質は、依頼内容の明確さに左右されます。該当する情報をできるだけ多く含めてください。

1. <strong>業務の内容。</strong>実行してほしいことを、わかりやすい言葉で記述します。「比較する」「順位付けする」「注意すべき点を示す」「見つける」「提案する」「要約する」などの動詞を使うと効果的です。
2. **対象期間。**「直近の完了した1週間」や「過去14日間とその前の14日間を比較」など、期間を明確に指定します。当日のデータはまだ一部しか揃っていないため、対象から除外してください。
3. <strong>対象範囲。</strong>対象となる地域、メディアソース、キャンペーン、プラットフォームを指定します。タスクの入力欄の上にあるフィルターで、地域とメディアソースを設定することもできます。
4. **指標としきい値。** KPIの名称と定義を指定します。「前週比で10%を超える低下を大幅な低下とする」のように記述すると、エージェントが適用できる基準になります。
5. <strong>求める出力。</strong>出力形式が重要な場合は、「広告費順に並べた表」「重要な分析結果を3つ示す短いサマリー」「注意すべき点のみを示し、説明文は不要」など、具体的に指定します。
6. <strong>目的・背景。</strong>背景を1文添えると、エージェントが優先順位を判断しやすくなります。

設定の詳細については、上記の**事前準備と権限**をご確認ください。

</Accordion>

<div id="h_01M3PDTFQE6GP95M541FYHG15N" />

<Accordion title="実行結果の確認と改善">

完了した実行は［**アクティビティ**］に表示され、Slackまたはメールで配信されたものと同じ内容を確認できます。実行結果から、出力のコピー、高評価または低評価の送信、テキストでのフィードバックの追加が可能です。また、［[アクティビティを分析](#ai-assistantを使用したアクティビティの分析)］を開いて、結果を導いた過程をAI Assistantに質問できます。

結果が空欄だったり、意図に合わなかったりする場合は、タスクを変更する前に分析・判断の過程を確認してください。［[アクティビティを分析](#ai-assistantを使用したアクティビティの分析)］で、使用したデータ、結果を導いた理由、プランのどこを変更すべきかを質問します。原因を確認せずにタスクを書き直すと、別の誤った回答が返されることが多くなります。そのうえでプランまたはタスクを編集し、エージェントを再実行します。

分析・判断の過程も空欄の場合は、まだ存在しないデータをリクエストした可能性があります。上記の**制限事項**を確認し、プロンプトを修正して再試行してください。

詳しくは、上記の[Agent Hub画面](#agent-hub画面)と[AI Assistantを使用したアクティビティの分析](#ai-assistantを使用したアクティビティの分析)をご確認ください。

<Accordion title="事前設定済みエージェント">

事前設定済みエージェントは、そのまま有効化して利用できます。エージェントを選択して設定すると、データに対する処理が実行されます。以下の表で、各エージェントの機能の概要を確認できます。有効化する前に、各セクションを展開して詳細を確認してください。

<div id="h_01M3PDTFQET68PRA9CN49CQ8Q7" />

<Accordion title="クリエイティブの活用機会を発見">

**業務内容：** 成果の高いクリエイティブを特定し、まだ配信されていない配信先を示します。エージェントは、過去30日間のすべてのパートナーにおけるクリエイティブの成果を評価し、優秀なものを順位付けします。その後、各パートナーで、それらのクリエイティブのうち未配信のものを確認します。追加すべき具体的な配信先のリストが、各提案の根拠となる数値とともに提示されます。

**対象データ：** 過去30日間の、各パートナーにおけるクリエイティブ単位の広告費とROAS。 Creative optimizationが必要です。

**実行結果：** 成果の高いクリエイティブと、その広告費およびROAS。さらに、各パートナーで未配信のクリエイティブと、それらを追加すべき理由。 Slackまたはメールで配信されます。

**実行頻度：** 標準のスケジュールの選択肢から設定するか、必要なタイミングで実行できます。

</Accordion>

<div id="h_01M3PDTFQE2WB2SNWBCS81C2DE" />

<Accordion title="パフォーマンスサマリーを作成">

**業務内容：** 通常は手作業でまとめている、上司や関係者向けのパフォーマンス報告を作成します。エージェントは、選択したKPIに基づいて集計分析データを読み取り、対象期間の傾向、成果の高い施策、重要な変化を特定します。これらを提案付きのサマリーにまとめ、そのまま共有できる形にします。

**対象データ：** アプリ、地域、メディアソースなどを横断した集計分析データ。プレミアムプランの契約は不要です。

**実行結果：**

* 文章によるサマリー：主要な成果、注意が必要な点、顕著な変化、推奨される次のアクション。
* 選択したKPIに基づいてエージェントが作成するマイダッシュボードのビュー。サマリーの根拠となる数値を詳しく確認できます。

どちらもSlackまたはメールで配信されます。

**実行頻度：** 設定可能です。一般的には週次が選択されます。

**設定方法：** アプリ、対象のKPI、グループ化の粒度、追加のフィルター（メディアソース、地域、代理店）を選択します。

**補足情報：** サマリーと併せて作成されるマイダッシュボードのビューは、AIが生成した一時的なビューです。［**マイダッシュボード**］>［**AI生成**］に表示されます。実行のたびに最新データで上書きされ、保存しない場合は30日後に削除されます。

</Accordion>

<div id="h_01M3PDTFQEB9MKH44X5XX4AGDT" />

<Accordion title="詳細な調査・分析">

**業務内容：** 何が変化し、その原因は何かを週次で調査します。毎週月曜日に、直近の完了した2週間（月曜日から日曜日）を比較します。パートナー、地域、OSバージョン、SDKバージョンを横断してイベント単位のローデータを詳しく調べ、集計ダッシュボードでは見えない変化を特定します。パフォーマンスの変化に見える設定上の問題も対象です。

**対象データ：** 十分な時間が経過し、データが揃ったイベント単位のローデータ。一部しか揃っていないデータや、まだ確定していないデータを避けるため、当週は意図的に除外します。たとえば、1月26日（月）には、1月12～18日と1月5～11日を比較します。プレミアムプランの契約は不要です。

**実行結果：** 前週比で見られた重要な変化、その要因、調査中に見つかった設定上の問題をまとめたレポート。 Slackまたはメールで配信されます。

**実行頻度：** 週次で月曜日に実行するか、必要なタイミングで実行できます。

</Accordion>

<div id="h_01M3PDTFQEPFMS38RWXT923VX7" />

<Accordion title="パフォーマンスの異常を検出">

**業務内容：** 主要なKPIを毎日監視し、通常とは異なる変化が発生した場合に通知します。 エージェントは、各指標を想定される範囲と比較し、大幅な上昇や低下を検出します。特定のパートナーでのCPIの急上昇、ある地域でのIPMの低下、キャンペーンの成果の急落など、何がどこで変化したかを説明します。

**対象データ：** パートナー、キャンペーン、地域を横断した日次のKPIデータ。プレミアムプランの契約は不要です。

**実行結果：** 変化の内容を文章で説明するアラート。どの指標が、どの程度、どのパートナー・キャンペーン・地域で変化したかと、その推定原因を示します。 Slackまたはメールで配信されます。異常がない日は通知されません。

**実行頻度：** 標準のスケジュールの選択肢から設定するか、必要なタイミングで実行できます。

</Accordion>

<div id="h_01M3PDTFQEFHYR29GN1XMRM16N" />

<Accordion title="設定の問題を検出">

**業務内容：** 計測設定を点検し、気づかないうちにデータの品質を低下させる不備を通知します。 エージェントは、SKAdNetworkやコストの連携が無効になっていないか、確率論的モデリングによるビュースルーアトリビューションが無効になっていないかなど、設定上の問題を確認します。キャンペーンの評価を誤らせる前に、問題を発見できます。

**対象データ：** アプリとパートナーを横断した連携状況と設定状況。プレミアムプランの契約は不要です。

**実行結果：** 見つかった各問題、発生箇所、修正方法を一覧にしたアラート。 Slackまたはメールで配信されます。

**実行頻度：** 標準のスケジュールの選択肢から設定するか、必要なタイミングで実行できます。

</Accordion>

<div id="h_01M3PDTFQEP6E7D4TF5G4PX1KV" />

<Accordion title="アプリのリリースを監視">

**業務内容：** 開発チームからの連絡を待たずに、自社アプリのリリース情報を把握できます。エージェントは、iOSとAndroidのアプリストアでのリリースを監視し、新しいバージョンが公開された際に通知します。また、段階的な公開の進捗を追跡し、新機能、アプリ内の挙動の変更、イベントの追加や削除など、マーケティングに関わる変更点を示します。 これにより、アプリの実際の内容に合わせてUAキャンペーンを調整できます。

**対象データ：** 自社アプリのアプリストアのリリースデータと、アプリ内イベントの定義。プレミアムプランの契約は不要です。

**実行結果：** バージョン、段階的な公開の状況、マーケティングに関わる変更点の概要を含むリリース通知。 Slackまたはメールで配信されます。

**実行頻度：** 標準のスケジュールの選択肢から設定するか、必要なタイミングで実行できます。

</Accordion>

<div id="h_01M3PDTFQEEKJQTRKEC9GK4TE6" />

<Accordion title="不正対策を最適化（Protect360）">

**業務内容：** トラフィックに含まれる不正の初期兆候を見つけ、対応方法を提示します。エージェントはProtect360のデータを分析して新たな不正パターンを検出し、重要な結果を報告します。また、パフォーマンスを損なわずに不正のリスクを減らすアクションを提案します。

**対象データ：** Protect360のデータ。 Protect360と、Protect360のクローズドベータ機能が必要です。

**実行結果：** Protect360ダッシュボード内に表示される分析結果と提案。

**実行頻度：** 週次で月曜日に実行するか、必要なタイミングで実行できます。

</Accordion>

<div id="h_01M3PDTFQEP2RQW39AD8127J19" />

<Accordion title="Web計測の健全性チェック">

**業務内容：** Webアプリでのイベント収集と、コンバージョンのマーケティング流入元へのアトリビューションを点検します。 レポートでは、正常に機能している項目を示し、アトリビューションの精度に影響する可能性のある問題を指摘したうえで、実装の改善を提案します。

**対象データ：** 選択したWebアプリのアトリビューション設定と、直近のSDKまたはサーバー間通信のデータ。データ収集、イベントと収益、キャンペーンリンク、リファラ、ユーザー識別、クロスプラットフォームの設定を確認します。デフォルトの分析期間は7日間です。

**実行結果：** 確認済みで問題のない項目と、推奨される改善点の2つのセクションで構成されたレポート。各結果には、根拠となる数値、推奨される修正方法、影響の大きさに応じた緑・黄・赤のステータスが含まれます。

**実行頻度：** 標準のスケジュールの選択肢から設定するか、必要なタイミングで実行できます。

</Accordion>

## よくある質問

<Accordion title="独自のエージェントを作成できますか？">

はい。カスタムエージェントでは、実行してほしい業務を自分で定義できます。上記の[**カスタムエージェント**](#h_01M3PDTFQDFQNMHTWKP23JV1A8)をご確認ください。

</Accordion>

<Accordion title="Agent Hubは、すべてのアカウントタイプで利用できますか？">

いいえ。現在、Agent Hubを利用できるのは広告主のみです。

</Accordion>

<Accordion title="すべてのユーザーが、すべてのエージェントを利用できますか？">

利用可能なエージェントは、AppsFlyerの契約プランとプレミアム製品へのアクセス権によって異なります。詳しくは、担当のCSMにお問い合わせください。

</Accordion>

<Accordion title="管理者は、アカウントでAgent Hubを無効にできますか？">

はい。管理者は、［**アカウント設定 > AI機能**］でAgent Hubの利用可否を管理できます。

デフォルトでは、アカウントでAgent Hubを利用できます。

管理者がAgent Hubを無効にすると、以下の変更が適用されます。

* すべてのユーザーがAgent Hubにアクセスできなくなります。
* 既存のすべてのエージェントが完全に削除され、復元できなくなります。
* 実行中のエージェントの処理が停止します。

その後、管理者がAgent Hubを再び有効にすると、ユーザーは再度アクセスできるようになります。ただし、エージェントは最初から作成して有効化する必要があります。

詳しくは、<Anchor target="_blank" href="/marketers/ja/docs/account-settings#agent-hub">アカウント設定</Anchor>をご確認ください。

</Accordion>

<Accordion title="通知はどこで受信できますか？">

メールまたはSlackで受信できます。メールで通知を受信するには、通知センターで［AI機能］の通知を購読する必要があります。

</Accordion>

<Accordion title="Agent Hubのメール通知が届かないのはなぜですか？">

メール通知の事前準備を完了してもAgent Hubのメールが届かない場合は、過去にAppsFlyerからのメール配信を解除した可能性があります。 AppsFlyerサポートにお問い合わせください。

</Accordion>

<Accordion title="AppsFlyerは、私のデータをAIモデルの学習に使用しますか？">

いいえ。 AppsFlyerは、お客様のデータをAIモデルの学習に使用しません。 AIの結果には、不正確な情報や情報の不足が含まれる場合があります。アクションを実行する前に、結果を確認してください。

</Accordion>
